# **A. ОДНОМЕРНЫЕ КЛЕТОЧНЫЕ АВТОМАТЫ**

## **1. Понятие клеточного автомата**

### **1.1. Определение**
* **Клеточный автомат:** дискретная модель: решётка клеток (1D, 2D, ...), у каждой клетки — состояние из конечного множества; время дискретно (поколения)
* **Локальное правило:** новое состояние клетки — функция от состояний окрестности радиуса r (клетки на расстоянии ≤ r); правило одинаково для всех клеток
* **Синхронность:** все клетки обновляются одновременно — шаг автомата применяет правило ко всей решётке сразу; локальные правила + синхронность = глобальная эволюция
* **Окрестности на плоскости:** фон Неймана (4 соседа: вверх/вниз/влево/вправо), Мура (8 соседей: плюс диагонали)
* **Связь с b.md:** автомат — формальная система (b.md C.1): состояния — формулы, локальное правило — правило вывода, эволюция — вывод; отличие — параллельность и отсутствие «цели» (вывода нет, есть только динамика)
* **В коде:** состояния — строка (1D) или сетка (2D); шаг — `elementary_step` (A.2), `life_step` (B.1)

### **1.2. Место в теории**
* **Идея:** простые локальные правила, сложное глобальное поведение — «эмерджентность»: сложность не заложена в правилах явно (см. B: фигуры «Жизни», шоссе муравья, пробки)
* **Связь с b.md:** конечное состояние — данные, эволюция — вычисление; универсальные автоматы (A.4, B.1.3) — «компьютеры» в смысле b.md 9.2 (универсальная машина)
* **В коде:** (без методов — понятийный раздел)

## **2. Элементарные одномерные автоматы**

### **2.1. Определение**
* **Элементарный КА:** 1D, состояния {0, 1}, окрестность радиуса 1 (клетка и её соседи слева и справа), детерминированная локальная функция f: {0, 1}³ → {0, 1}
* **Правило:** номер 0..255 — вектор значений f на всех 8 наборах (три бита: левый, клетка, правый; старший бит — набор 111, младший — 000); это ровно номер булевой функции от 3 переменных (c.md A.1.2) — правило 90 = 01011010₂
* **Границы:** конечная строка; «море нулей» вокруг — клетки вне строки считаются 0
* **В коде:** `elementary_step(rule, line)` — одно поколение: строка `next[i] = f(line[i−1..i+1])` с нулями на границах

### **2.2. Эволюция**
* **Начало:** одна 1 в море нулей (или случайная строка); эволюция — последовательность поколений
* **Замечание:** из одной 1 вырастает «треугольник» — симметрия начала сохраняется в силу симметрии окрестности
* **В коде:** `elementary_run(rule, line, generations)` — поколения подряд; строка растёт на один ноль с каждой стороны за поколение — «море нулей» вокруг (границы, 2.1); `elementary_print` — печать треугольником (A.3: по нему классифицируют поведение)

## **3. Классы поведения Вольфрама**

### **3.1. Классы**
* **Классификация (Вольфрам, 1983):** все 256 правил по характеру эволюции из случайной строки:
  * класс 1: затухание — всё приходит к однородному состоянию (правило 0);
  * класс 2: стабильность — устойчивые или периодические структуры (правило 4);
  * класс 3: хаос — апериодические, «шумные» структуры (правило 30);
  * класс 4: сложность — взаимодействующие структуры, локальная упорядоченность (правило 110)
* **Смысл:** одинаковые по сложности правила дают качественно разные поведения; класс 4 — «между порядком и хаосом» — редок и интересен (универсальность, 4)
* **В коде:** `evolution_period(rule, line, gens)` — период повторяющейся строки (1 — фиксированная точка, k — период k, 0 — не стабилизировалась за gens): машинная характеристика класса

### **3.2. Примеры**
* **Правило 90:** next[i] = left ⊕ right — треугольник Паскаля по mod 2 (серпинский треугольник); класс 3
* **Правило 30:** известный «хаос» — генератор случайности (использовался в Mathematica); класс 3
* **Правило 110:** класс 4 (A.4)
* **В коде:** `elementary_run(90, "1", 8)` — треугольник; `elementary_print` — печать

## **4. Универсальность (правило 110)**
* **Теорема (Кук, 2004):** правило 110 универсально по Тьюрингу — в его эволюции можно моделировать любую вычислимую функцию (b.md 9.2: универсальная машина — «компьютер»)
* **Идея:** в эволюции правила 110 из случайных данных возникают «частицы» — устойчивые паттерны, движущиеся и сталкивающиеся; столкновения кодируют логические операции
* **Следствие:** поведение правила 110 с произвольного входа неразрешимо (проблема остановки, b.md 9.5) — простейший элементарный КА вычислительно полон
* **Смысл:** универсальность — не свойство сложных систем: достаточно одной локальной функции от 3 бит
* **В коде:** `elementary_run(110, ...)` — наблюдение частиц на печати поколений

# **B. ДВУМЕРНЫЕ КЛЕТОЧНЫЕ АВТОМАТЫ**

## **1. Игра «Жизнь» (Conway)**

### **1.1. Правила**
* **Клетки:** {0, 1} (мертва/жива); окрестность Мура (8 соседей); синхронное обновление (A.1.1)
* **Обобщённая форма (B/S-нотация):** живая клетка выживает, если число живых соседей ∈ S (survival); мёртвая рождается, если ∈ B (birth)
* **«Жизнь»:** B = {3}, S = {2, 3} — выживание при 2–3 соседях, рождение при ровно 3
* **В коде:** `life_step(grid, birth, survival)` — параметры-множества (правила игры — аргументы, не константы); `life_print` — печать сетки

### **1.2. Фигуры**
* **Стабильные (still lifes):** блок (квадрат 2×2) — не меняется: каждая клетка имеет ровно 3 соседей
* **Осцилляторы:** мигалка (blinker) — «палочка» 3 клетки, период 2: горизонтальная ⟷ вертикальная
* **Космические корабли (spaceships):** планер (glider) — 5 клеток; за 4 поколения возвращается к исходной форме, сдвинутой на 1 клетку по диагонали — «движение» из правил без движения
* **Смысл:** глобальное поведение (устойчивость, периодичность, перемещение) не заложено в правилах явно — эмерджентность (A.1.2)
* **В коде:** тесты: блок устойчив за 1 шаг, мигалка периодична с периодом 2, планер за 4 шага сдвинут на (1, 1)

### **1.3. Универсальность**
* **Теорема:** «Жизнь» универсальна по Тьюрингу — на её поле строятся конструкции, моделирующие машину Тьюринга (логические вентили, память из «пистолетов» — ср. c.md B.1: схемы из вентилей)
* **Следствие:** неразрешимы вопросы о «Жизни» (выживет ли конфигурация) — b.md 9.5 на двумерном автомате
* **Смысл:** правила игры (B3/S23) — пример универсальной формальной системы (A.4)

## **2. Мир «Ва-Тор» (Wa-Tor)**

### **2.1. Модель**
* **Мир:** 2D клетки трёх видов — вода, рыбы, акулы; время дискретно; синхронные шаги (A.1.1)
* **Рыбы:** каждый шаг двигаются в случайную соседнюю воду; по достижении возраста fish_breed размножаются: потомок остаётся на месте, родитель уходит (возраст обнуляется); без хода — ждут
* **Акулы:** двигаются к соседней рыбе (съедают, «сытость» восстанавливается), иначе — в случайную воду; за каждый шаг голодают, после shark_starve шагов без еды умирают; по достижении возраста shark_breed размножаются (как рыбы)
* **В коде:** `wator_step(world, fish_breed, shark_breed, shark_starve, rng)` — параметры модели аргументами (не константы); клетка — `WatorCell` (вид, возраст, голод)

### **2.2. Динамика популяций**
* **Эмерджентные циклы:** численности рыб и акул колеблются периодически — «хищник–жертва» (дискретный аналог уравнений Лотки-Вольтерра), хотя правила — только движение и размножение
* **Смысл:** экологическое моделирование: параметры (время размножения, голод) определяют, выживет ли популяция; локальные правила, глобальная динамика (A.1.2)
* **В коде:** `wator_counts(world)` — (рыбы, акулы); `wator_run(world, steps, ...)` — динамика численностей по шагам

### **2.3. Случайность**
* **Единственный недетерминизм:** выбор направления движения (и порядок обработки клеток); остальные правила детерминированы
* **Воспроизводимость:** шаг принимает генератор (std::mt19937) — один seed, один мир; разные seed — разные миры (ср. случайность в модели Нагеля-Шрекенберга, C.1)
* **В коде:** `wator_step` — клетки обрабатываются в случайном порядке (без «направленного смещения»); тесты — на детерминированных ситуациях

## **3. Муравей Лэнгтона**

### **3.1. Правила**
* **Мир:** бесконечная клеточная плоскость; клетки двух цветов (0, 1); муравей — позиция и направление (4 стороны света)
* **Шаг:** по цвету клетки — поворот (направо/налево) и перекраска клетки, затем шаг вперёд
* **Классика:** белая клетка — повернуть направо, перекрасить в чёрный; чёрная — налево, перекрасить в белый
* **Обобщение:** k цветов; правило — для каждого цвета пара (поворот, следующий цвет): цвета перекрашиваются по правилу, а не просто инвертируются
* **В коде:** `ant_step(grid, x, y, dir, rule)` — шаг; `ant_run(grid, x, y, dir, rule, steps)` — траектория (координаты муравья) с ростом сетки по мере выхода за края

### **3.2. Поведение**
* **Хаос → шоссе:** сначала траектория хаотична (порядка сотни шагов), затем муравей выходит на «шоссе» — периодический цикл из 104 шагов, уходящий по диагонали в бесконечность
* **Следствия:** любая конечная конфигурация «зарастает» и муравей всё равно строит шоссе; классический муравей (2 цвета) — детерминирован, но «сложен»; с большим числом цветов муравей Лэнгтона универсален по Тьюрингу
* **Смысл:** простейший автомат (поворот по цвету!) порождает нерегулярное поведение и бесконечное движение — минимальный «алгоритм» с нетривиальной динамикой
* **В коде:** `ant_run` — печать траектории и размера сетки после N шагов; проверка первых шагов в тестах

# **C. МОДЕЛИ ТРАНСПОРТНЫХ ПОТОКОВ**

## **1. Модель Нагеля-Шрекенберга**

### **1.1. Определение**
* **Дорога:** 1D клеточный автомат (A.1): клетка — участок дороги; машина в клетке имеет скорость 0..v_max (0 — стоит, −1 — клетка пуста); дорога кольцевая
* **Шаг (4 правила, синхронно):**
  1. разгон: v ← min(v + 1, v_max) — водитель хочет ехать быстрее;
  2. торможение: v ← min(v, g), где g — расстояние до впереди идущей машины — не врезаться;
  3. случайность: с вероятностью p скорость падает на 1 (не ниже 0) — «невнимательность»/«лёгкое торможение»;
  4. движение: машина смещается на v клеток вперёд
* **Параметры:** v_max (максимальная скорость) и p (вероятность торможения) — аргументы, не константы
* **Частный случай:** v_max = 1, p = 0 — элементарный КА с правилом 184 («дорожное» правило): машина едет, если клетка впереди пуста
* **В коде:** `nagel_step(road, vmax, p, rng)` — новый профиль дороги; `nagel_avg_speed(road, vmax, p, rng, steps)` — средняя скорость

### **1.2. Поведение и пробки**
* **Пробки из ниоткуда:** при высокой плотности машин и p > 0 возникают «фантомные» пробки — медленные кластеры, движущиеся против потока; причина — только правило 3 (случайность), внешних причин нет
* **Детерминированный предел:** при p = 0 пробок нет — поток максимален: машины движутся вперёд без остановок
* **Механизм:** правило 2 (торможение) сжимает поток перед медленной машиной — затор разрастается назад; правило 3 даёт первую «медленную» машину
* **Смысл:** прикладной клеточный автомат (транспортное моделирование); те же принципы, что в A и B: локальные правила + синхронность = глобальное поведение (пробки — эмерджентны, A.1.2)
* **В коде:** `nagel_step`/`nagel_avg_speed` — плотность/вероятность задают наблюдаемое поведение; тесты: при p = 0 средняя скорость максимальна
