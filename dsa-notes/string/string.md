## **A. СТРОКОВЫЕ КОНТЕЙНЕРЫ И ПРЕДСТАВЛЕНИЯ**
> `a/a.md` · `a/a.cpp` · `struct StringContainers`

### **1. Стандартные контейнеры**
* **`std::string`:** динамический массив символов; SSO для `n ≤ k` (обычно `k = 15–22`); амортизированный `push_back` `O(1)`; `find` `O(n·m)` худший; `substr` `O(m)` копирование; member functions: `append`, `substr`, `find`, `replace`, `insert`, `erase`, `compare`
* **`std::string_view` (C++17):** легковесная read-only view `O(1)` копирование; не владеет данными; для параметров функций; `remove_prefix`, `remove_suffix`
* **`std::basic_string<T>`:** шаблонная версия для произвольных типов символов
* **`std::wstring, std::u16string, std::u32string`:** Unicode (UTF-16, UTF-32)
* **C-строки:** null-terminated `char[]`; `strlen` `O(n)`; безопасные: `strncpy`, `snprintf`, `strlcpy`, `strcmp`
* **`std::stringstream, std::ostringstream, std::istringstream`:** форматирование, преобразование типов, парсинг

### **2. Продвинутые структуры**
* **Rope:** сбалансированное бинарное дерево строк; вставка/удаление `O(log n)`; для строк `> n₀` символов (параметр); применяется в текстовых редакторах
* **Gap Buffer:** массив с «разрывом» в позиции курсора; вставка `O(1)` амортизированно; удаление `O(1)` в позиции курсора; применяется в Emacs
* **Piece Table:** два буфера (original + modified); легковесные модификации; применяется в VS Code

### **3. Память и оптимизации**
* **SSO (Small String Optimization):** хранение малых строк (`n ≤ k`) прямо в объекте (внутренний буфер); избегание heap-аллокаций; порог `k` зависит от реализации (`15–22` символов)
* **String interning:** пул уникальных строк; экономия памяти при дублировании; `O(1)` сравнение через указатель
* **Copy-on-Write (COW):** копирование при записи; исторически в `std::string` (GCC/libstdc++ до C++11); сейчас редко, но концептуально важно

## **B. ПОИСК ПОДСТРОКИ (STRING MATCHING)**
> `b/b.md` · `b/b.cpp` · `struct StringMatching`

### **1. Наивный поиск (Naive)**
* Перебор всех `n − m + 1` позиций; проверка `m` символов
* **Сложность:** `O(n·m)` худший, `O(n)` средний при случайных строках
* **Применение:** короткие паттерны; baseline для сравнения

### **1.5. Bitap Algorithm (Shift-Or/Shift-And)**
* **Идея:** битовое представление состояний; `bitmask[j]` = 1 если `j`-й символ паттерна совпал
* **Shift-Or:** отрицательное состояние = совпадение; `O(n·⌈m/w⌉)` где `w` — размер машинного слова
* **Применение:** поиск с нечётким соответствием (до `k` ошибок); для небольших алфавитов и паттернов `m ≤ w`

### **2. Префикс-функция и KMP**
* **Префикс-функция `π[i]`:** длина наибольшего proper-префикса `s[0..i]`, являющегося суффиксом `s[0..i]`
* **Вычисление:** `O(n)` — один проход; при несовпадении `π[i] = π[π[i−1]]` (цепочка откатов)
* **KMP поиск:** `O(n + m)` — построение `π` для `pat + '#' + text`; при несовпадении переход на `π[mismatch]`
* **Свойство периода:** строка `s` длины `n` имеет период `p = n − π[n−1]` если `n mod p == 0`

### **3. Z-функция (Z-algorithm)**
* **Определение:** `z[i]` = длина наибольшего префикса `s[i..n)`, совпадающего с `s[0..)`
* **Вычисление:** `O(n)` — алгоритм с «окном» `[L, R]`; при `i ∈ [L, R]` — переиспользование `z[i − L]`
* **Применение:** поиск паттерна `O(n + m)` (z для `pat + '#' + text`); проверка вхождения префикса; периодичность; longest common prefix

### **4. Rabin-Karp (rolling hash)**
* **Идея:** хеш паттерна `h(pat)` vs хеш окна `h(text[i..i+m−1])`; совпадение хешей → проверка символов
* **Rolling hash:** `h(s[i+1..i+m]) = (h(s[i..i+m−1]) − s[i]·p^{m−1})·p + s[i+m]` `O(1)` на шаг
* **Сложность:** `O(n + m)` ожидаемо, `O(n·m)` худший (коллизии); двойное хеширование → детерминированный `O(n + m)`

### **5. Бойер-Мур (Boyer-Moore)**
* **Bad character rule:** сдвиг паттерна так, чтобы символ текста совпал с последним вхождением в паттерне
* **Good suffix rule:** сдвиг на основе совпавшего суффикса
* **Сложность:** `O(n·m)` худший, `O(n/m)` лучший; на практике один из самых быстрых для больших алфавитов

### **5.5. Border array и обобщения**
* **Border array:** обобщение префикс-функции; `ba[i]` = длина наибольшего border `s[0..i]`; связь с периодичностями
* **Связь с Z-функцией:** `z[i]` и `π[i]` связаны через border array; вычисление одного через другой `O(n)`
* **Применение:** определение периодов строки, поиск повторяющихся подстрок

### **6. Специализированные алгоритмы**
* **Алгоритм Манакера:** поиск всех палиндромов за `O(n)` через расширение от центров с использованием уже вычисленной симметрии
* **Two-way (Крочемор-Перрин):** гарантированно `O(n + m)` без риска деградации; разбиение паттерна на две части
* **Apostolico-Giancarlo:** оптимизация KMP с пропуском уже проверенных позиций
* **Commentz-Walter:** множество паттернов через trie + скользящее окно

### **7. Поиск с шаблонами**
* **Wildcard Pattern Matching:** символы `*` (любая последовательность) и `?` (любой символ); ДП `O(n·m)`
* **Regular Expression Matching:** NFA/DFA построение (Thompson's construction); regex с обратными ссылками; `O(n·m)` через ДП или `O(n)` через автомат

## **C. СТРОКОВЫЕ РАССТОЯНИЯ И РЕДАКТИРОВАНИЕ**
> `c/c.md` · `c/c.cpp` · `struct StringDistances`

### **1. Расстояние Левенштейна (Edit Distance)**
* **Операции:** вставка `+c_i`, удаление `+c_d`, замена `+c_r` (параметризованные стоимости)
* **ДП:** `dp[i][j]` = min cost `s[0..i) → t[0..j)`; `O(n·m)` время, `O(min(n,m))` память (rolling array)
* **Восстановление:** через `prev[i][j]` — обратный путь

### **2. Расстояние Дамерау-Левенштейна**
* Добавлена **транспозиция** (обмен соседних символов) за `+c_t`
* **ДП:** `dp[i][j]` + проверка `i > 1, j > 1: s[i−2] == t[j−1] ∧ s[i−1] == t[j−2]`

### **3. Расстояние Хэмминга**
* Для строк одинаковой длины `n`: `d(s,t) = Σ_{i=0}^{n−1} [s[i] ≠ t[i]]`
* **Сложность:** `O(n)`

### **4. Расстояние Джарро-Винклера**
* Для коротких строк/имён; учитывает префикс: `jw = jaro + prefix_bonus · (1 − jaro)`
* **Применение:** fuzzy matching в базах данных

### **5. Другие метрики сходства**
* **Cosine similarity:** `cos(s,t) = (s·t) / (‖s‖·‖t‖)` через N-gram векторы
* **Jaccard similarity:** `|A ∩ B| / |A ∪ B|` для наборов N-грамм
* **Sørensen–Dice coefficient:** `2·|A ∩ B| / (|A| + |B|)`
* **LCS (Longest Common Subsequence):** `dp[i][j]` через `dynamic.md` (C.12); `O(n·m)` время, `O(min(n,m))` память
* **Longest Common Substring:** суффиксный массив + LCP `O(n log n)` или суффиксный автомат `O(n)`

### **6. Оптимизации**
* **Min Cost String Conversion:** редактирование с произвольными стоимостями операций
* **Ukkonen:** оптимизация edit distance для малых расстояний `O(n·d)` где `d` — расстояние
* **Bit-parallel DP:** ускорение через битовые операции; `O(n·m/w)` где `w` — размер слова
* **Four Russians method:** блочное разбиение `O(n·m / log²(n·m))`

## **D. ХЕШИРОВАНИЕ СТРОК**
> `d/d.md` · `d/d.cpp` · `struct StringHashing`

### **1. Полиномиальное хеширование**
* **Формула:** `h(s) = (Σ_{i=0}^{n−1} s[i] · p^i) mod m` где `p` — основание, `m` — модуль
* **Префиксные хеши:** `pref[i+1] = pref[i] · p + s[i]`; хеш подстроки `s[l..r)`: `h = pref[r] − pref[l] · p^{r−l}`
* **Rolling hash:** добавление/удаление символа за `O(1)`

### **2. Двойное хеширование**
* Два хеша с разными `(p₁, m₁)` и `(p₂, m₂)`; вероятность коллизии `O(1/(m₁·m₂))`
* **Применение:** детерминированный поиск подстроки `O(n + m)`

### **3. Применения**
* Сравнение подстрок за `O(1)`
* Поиск палиндромов: хеш прямого + обратного суффикса
* Поиск различных подстрок: хеш + set `O(n² log n)`
* Проверка изоморфизма: сортировка позиций по символам
* Циклические сдвиги и минимальный сдвиг

### **4. Коллизии и безопасность**
* **Birthday paradox:** вероятность коллизии для `k` хешей из `m` значений ≈ `k²/(2m)`
* **Universal hashing:** `h(s) = (Σ s[i] · a^{i}) mod m` где `a` — случайный; вероятность коллизии для любой пары `≤ 1/m`
* **Cryptographic hashes:** SHA-256, MD5 для строк; детерминированность, стойкость

## **E. СТРОКОВЫЕ АВТОМАТЫ И СТРУКТУРЫ**
> `e/e.md` · `e/e.cpp` · `struct StringAutomata`

### **1. Префиксное дерево (Trie)**
* **Структура:** дерево, где ребро — символ; путь от корня = префикс
* **Операции:** вставка/поиск/удаление `O(m)` где `m` — длина строки
* **Память:** `O(Σ·n·m)` худший; оптимизация — radix tree (сжатие путей)
* **Применения:** autocomplete, word break, IP routing, spell checker

### **2. Специализированные Trie**
* **Radix Tree (Patricia Tree):** сжатый trie; рёбра = строки; `O(n)` памяти; поиск `O(m)`
* **Suffix Trie:** trie всех суффиксов; `O(n²)` памяти; редко используется напрямую
* **Ternary Search Trie:** каждая вершина — 3 указателя (меньше, равно, больше); экономия памяти vs обычный trie

### **3. Алгоритм Ахо-Корасик**
* **Построение:** trie + failure links через BFS; `O(Σ·|P|)` где `|P|` — суммарная длина паттернов
* **Множественный поиск:** `O(n + Σ·|P| + k)` где `k` — число вхождений; один проход по тексту
* **Применение:** intrusion detection, bioinformatics, множественный поиск паттернов

### **4. Дерево палиндромов (Palindromic Tree / Eertree)**
* **Структура:** хранит все различные палиндромные подстроки; `≤ n` вершин; два корня (для нечётных и чётных)
* **Построение:** online `O(n)` с suffix links для палиндромов
* **Применения:** число различных палиндромов, longest palindromic prefix/suffix, подсчёт вхождений

### **5. Суффиксный массив (Suffix Array)**
* **Определение:** отсортированный массив индексов суффиксов
* **Построение:** naive `O(n² log n)`; prefix doubling `O(n log n)`; SA-IS `O(n)`
* **LCP массив (Kasai):** `lcp[i]` = длина LCP `sa[i]` и `sa[i−1]`; `O(n)` построение
* **Применения:**
    * Поиск подстроки: бинарный поиск `O(m log n)`
    * Число различных подстрок: `n(n+1)/2 − Σ_{i=1}^{n−1} lcp[i]`
    * Longest repeating substring: `max(lcp[i])`
    * Longest common substring: через `lcp` на конкатенации `s₁ + '#' + s₂`

### **6. Суффиксное дерево (Suffix Tree)**
* Компактное Trie всех суффиксов; `O(n)` вершин и рёбер
* **Построение:** Укконен `O(n)` (online, suffix links, active point)
* **Применения:** всё от суффиксного массива + поиск паттерна `O(m)`, LCS `k` строк, longest common substring

### **7. Суффиксный автомат (Suffix Automaton)**
* Минимальный DFA, accept все подстроки; `≤ 2n−1` вершин, `≤ 3n−4` рёбер
* **Построение:** online `O(n)` с терминальными ссылками
* **Применения:**
    * Число различных подстрок: `Σ_v (len[v] − len[link[v]])`
    * Кратчайшая строка, не входящая в текст
    * Количество вхождений подстроки (предподсчёт `occ`)

### **8. Декомпозиция Линдона**
* **Линдон строка:** лексикографически наименьший суффикс; декомпозиция строки на линдон-множители `O(n)` — алгоритм Дюваля
* **Применение:** наименьший циклический сдвиг строки `O(n)`; сортировка строк за `O(n)` через линдон-дерево

## **F. АНАЛИЗ И ПРЕОБРАЗОВАНИЕ СТРОК**
> `f/f.md` · `f/f.cpp` · `struct StringAnalysis`

### **1. Статистический анализ**
* **Частотный анализ:** подсчёт символов `O(n)`; top-K через heap `O(n log k)` или bucket sort `O(n)`
* **N-gram анализ:** генерация подстрок длины `k` — `O(n·k)`; применение для предсказания и классификации

### **2. Проверка свойств**
* **Уникальность:** bitmask `O(n)` для ASCII; set `O(n log n)` для Unicode
* **Изограммы и панграммы:** isogram — слово без повторяющихся букв; pangram — текст со всеми буквами алфавита
* **Палиндромность:** два указателя `O(n)` или хеш `O(n)`; проверка перестановки в палиндром
* **Анаграммы:** сортировка `O(m log m)` или frequency counting `O(m)`

### **3. Трансформации**
* **Регистр:** capitalize, lower, upper, title case, switch case
* **Форматы:** CamelCase ↔ snake_case, kebab-case, dot case
* **Перестановки:** reverse letters, reverse words, alternative string arrange
* **Разделение:** join, split, tokenization, strip (удаление пробелов)

### **4. Периодичность и повторы**
* **Период строки:** через префикс-функцию: `p = n − π[n−1]` если `n mod p == 0`;最小 период строки
* **Тандемные повторы:** два вхождения подстроки подряд; Main-Lorentz `O(n log n)` divide-and-conquer; Crochemore's algorithm `O(n log n)`
* **Квадраты в строках:** два вхождения одной подстроки; алгоритмы поиска квадратов `O(n log n)` через suffix array

### **5. Минимальный циклический сдвиг и сортировка**
* **Booth's algorithm:** `O(n)` через KMP-подобный подход; лексикографически наименьший циклический сдвиг
* **Лексикографически наименьший/наибольший суффикс:** через суффиксный массив `O(n)`
* **Сортировка циклических сдвигов:** через SA-IS `O(n)`

### **6. Текстовая обработка**
* **Text Justification:** выравнивание текста по ширине с переносом слов
* **Удаление дубликатов:** in-place удаление через два указателя `O(n)`
* **Волнообразные преобразования:** zigzag conversion

## **G. СЖАТИЕ СТРОК**
> `g/g.md` · `g/g.cpp` · `struct StringCompression`

### **1. Безпотерные алгоритмы**
* **RLE (Run-Length Encoding):** `aaabbc → 3a2b1c`; `O(n)` время; эффективно при длинных сериях (`σ` small)
* **Хаффман:** префиксные коды; дерево через priority queue `O(n log n)`; canonical Huffman codes
* **LZ77:** sliding window compression; `(offset, length, next_char)`; `O(n)` время; применяется в gzip/Deflate
* **LZ78:** growing dictionary; `(index, next_char)`; `O(n)` время
* **LZW (Lempel-Ziv-Welch):** словарное сжатие; применяется в GIF, UNIX compress

### **2. Преобразования для сжатия**
* **BWT (Burrows-Wheeler Transform):** циклические сдвиги → столбец; повышает сжимаемость; `O(n log n)` через суффиксный массив; применяется в bzip2
* **Move-to-Front transform:** преобразование символов в индексы последнего вхождения
* **Delta encoding:** разность между последовательными значениями

### **3. Специализированные алгоритмы**
* **Алгоритм Крочемора:** для сжатия строк; на основе LZ77 с оптимизациями; `O(n)` на практике

## **H. ВАЛИДАЦИЯ И ПАТТЕРНЫ**
> `h/h.md` · `h/h.cpp` · `struct StringValidation`

### **1. Валидация данных**
* **Email:** регулярные выражения или DFA; проверка `O(n)`
* **Телефоны:** E.164 формат, национальные форматы; проверка `O(n)`
* **ID:** Luhn algorithm (кредитные карты, ISBN, штрихкоды); `O(n)`
* **Кредитные карты:** номер + checksum; `O(n)`
* **Штрихкоды:** UPC, EAN; валидация через контрольную сумму; `O(n)`

### **2. Распознавание паттернов**
* **Word patterns:** биекция строк ↔ числа; `O(m)` через map
* **Language detection:** N-gram frequency comparison; стоп-слова
* **Bioinformatics:** DNA/protein sequence analysis; кодоны, аминокислоты, сайты рестрикций

### **3. Регулярные выражения**
* **Движок:** реализация через NFA/DFA; Thompson's construction; backtracking vs автомат
* **Конечные автоматы:** DFA для паттернов; детерминированный поиск `O(n)`

## **I. ФОНЕТИЧЕСКИЕ И ИГРОВЫЕ АЛГОРИТМЫ**
> `i/i.md` · `i/i.cpp` · `struct PhoneticAlgorithms`

### **1. Фонетические алгоритмы**
* **Soundex:** кодирование по звучанию `O(n)`; сравнение через хеш; применяется в генеалогии
* **Metaphone / Double Metaphone:** улучшенный Soundex; точнее для английских слов
* **NYSIIS (New York State Identification and Intelligence System):** улучшенный Soundex

### **2. Игры со строками**
* **Pig Latin:** языковая игра; простые трансформации строк
* **Word Ladder:** BFS на графе слов; расстояние Хэмминга = 1; `O(n·m·Σ)`
* **Boggle:** поиск слов в матрице через DFS `O(n·m·4^l)` где `l` — макс. длина слова
* **Scrabble word validation:** проверка слова по словарю

## **J. БИТОВЫЕ И НИЗКОУРОВНЕВЫЕ ОПЕРАЦИИ**
> `j/j.md` · `j/j.cpp` · `struct BitStringOperations`

### **1. Битовые манипуляции**
* **Bitmask для строк:** множества символов через биты; `O(1)` на проверку вхождения символа; `O(Σ)` на построение
* **Bit-parallel string matching:** Shift-Or/Shift-And; поиск `k` паттернов `O(n·⌈m/w⌉)` где `w` — размер машинного слова; для небольших алфавитов

### **2. Кодировки**
* **ASCII:** `1` байт/символ; `128` символов; прямая проекция `char → int`
* **UTF-8:** `1–4` байта/символ; variable-length; обратно совместим с ASCII
* **UTF-16:** `2–4` байта/символ; surrogate pairs для supplementary characters
* **UTF-32:** фиксированные `4` байта/символ; простой доступ по индексу, но память
* **Unicode normalization:** NFC (составной), NFD (декомпозиция), NFKC/NFKD (совместимость)
* **Byte order mark (BOM):** определение порядка байтов
* **String encoding conversion:** преобразование между кодировками
