**B. ПОИСК ПОДСТРОКИ (STRING MATCHING)**

> **Архитектура:** `StringMatching` (b.cpp) — наследует `StringContainers` (a.cpp). Реализует: наивный поиск, префикс-функцию и KMP, Z-функцию, Rabin-Karp (rolling hash), Boyer-Moore, border array, Манакер. Все алгоритмы параметризованы типом символа `char` и работают с произвольными строками.
>
> **Связи:** `std::string` — основной входной тип — `string/a`; хеш-функции (полиномиальный хеш, двойное хеширование) — `string/d`; приоритетные очереди — `struct.md` (IV); ДП — `dynamic.md` (C — расстояния, D — подстроки); suffix array и suffix automaton — `string/e` (для поиска через структуры данных).

---

# **1. Наивный поиск (Naive)**

* **Алгоритм:** для каждой позиции `i ∈ [0, n−m]` проверяем `s[i..i+m) == pat`
* **Сложность:** `O(n·m)` худший (например, `s = "aaa...a"`, `pat = "aa...ab"`); `O(n)` средний при случайных строках
* **Применение:** короткие паттерны; baseline для сравнения; когда `m` мало

## **1.5. Bitap Algorithm (Shift-Or)**
* **Идея:** битовое представление состояний; `R[ch]` — битовая маска: бит `j` установлен если `pat[j] == ch`
* **Алгоритм:** `state = (state << 1) | R[text[i]]`; совпадение ⟺ бит `m−1` установлен
* **Сложность:** `O(n · ⌈m/w⌉)` где `w` — размер машинного слова (обычно `64`)
* **Применение:** поиск с нечётким соответствием (до `k` ошибок); для небольших алфавитов и паттернов `m ≤ w`

---

# **2. Префикс-функция и KMP**

## **2.1. Префикс-функция (Prefix Function)**
* **Определение:** `π[i]` = длина наибольшего proper-префикса `s[0..i]`, который является суффиксом `s[0..i]`
* **Вычисление:** `O(n)` — один проход; при несовпадении `s[i] ≠ s[π[i−1]]` — цепочка откатов `π[i] = π[π[i−1]]`
* **Свойство:** `π[i] ≤ π[i−1] + 1` — увеличение не более чем на 1

## **2.2. KMP поиск**
* **Построение:** `π` для строки `pat + '#' + text` (символ `#` гарантирует, что префиксы паттерна не выходят за его границы)
* **Алгоритм:** при `π[i] == m` — вхождение найдено; при несовпадении — переход на `π[i−1]`
* **Сложность:** `O(n + m)` — построение `π` `O(m)` + поиск `O(n)`
* **Применение:** множественный поиск, поиск в потоке, поиск всех вхождений

## **2.3. Свойство периода**
* Строка `s` длины `n` имеет период `p = n − π[n−1]` если `n mod p == 0`
* Минимальный период строки: `p = n − π[n−1]` если `n mod (n − π[n−1]) == 0`, иначе `n`

---

# **3. Z-функция (Z-algorithm)**

* **Определение:** `z[i]` = длина наибольшего префикса `s[i..n)`, совпадающего с `s[0..)`
* **Вычисление:** `O(n)` — алгоритм с «окном» `[L, R]`:
    * При `i ∈ [L, R]`: `z[i] = min(R − i + 1, z[i − L])` (переиспользование)
    * При `i > R` или `z[i − L] ≥ R − i + 1`: расширение окна
* **Свойство:** `z[0]` не определён (или `= n`); окно `[L, R]` — самый дальнийReachable префикс
* **Применение:**
    * Поиск паттерна: `z` для `pat + '#' + text` — при `z[i] == |pat|` → вхождение `O(n + m)`
    * Периодичность: строка имеет период `p` если `z[i] == n − i` для некоторых `i`
    * Longest common prefix любых двух суффиксов

---

# **4. Rabin-Karp (rolling hash)**

* **Идея:** хеш паттерна `h(pat)` vs хеш окна `h(text[i..i+m−1])`; совпадение хешей → проверка символов
* **Rolling hash:** `h(s[i+1..i+m]) = (h(s[i..i+m−1]) − s[i]·p^{m−1})·p + s[i+m]` `O(1)` на шаг
* **Сложность:** `O(n + m)` ожидаемо (при хорошем хеше), `O(n·m)` худший (коллизии)
* **Двойное хеширование:** два модуля `(m₁, m₂)` → вероятность коллизии `O(1/(m₁·m₂))`
* **Применение:** поиск множества паттернов, поиск в потоке, проверка палиндромов

---

# **5. Бойер-Мур (Boyer-Moore)**

* **Bad character rule:** при несовпадении `s[i] ≠ pat[j]` — сдвинуть паттерн так, чтобы `pat[k] == s[i]` для максимально правого `k`
* **Good suffix rule:** после совпадения суффикса `pat[j+1..m)` — сдвинуть на основе уже совпавшей части
* **Сложность:** `O(n·m)` худший, `O(n/m)` лучший (для большого алфавита); на практике один из самых быстрых

---

# **6. Border array и обобщения**

* **Border array:** `ba[i]` = длина наибольшего border `s[0..i]`; обобщение префикс-функции
* **Связь с Z-функцией:** `z[i]` и `π[i]` связаны через border array; можно вычислить один через другой `O(n)`
* **Применение:** определение периодов строки, поиск повторяющихся подстрок

# **7. Специализированные алгоритмы**

## **7.1. Алгоритм Манакера**
* **Задача:** найти все палиндромы в строке за `O(n)`
* **Идея:** расширение от центров с использованием уже вычисленной симметрии (аналог Z-окна)
* **Результат:** массив `d1[i]` — радиус нечётных палиндромов, `d2[i]` — чётных
* **Применение:** longest palindromic substring, число палиндромных подстрок

## **7.2. Two-way (Крочемор-Перрин)**
* Гарантированно `O(n + m)` без риска деградации; разбиение паттерна на две части
* Применяется в некоторых реализациях `strstr`

## **7.3. Apostolico-Giancarlo**
* Оптимизация KMP с пропуском уже проверенных позиций; на практике быстрее классического KMP

## **7.4. Commentz-Walter**
* Множество паттернов через trie + скользящее окно; `O(n·log m + k)` где `k` — число вхождений

# **8. Поиск с шаблонами**

## **8.1. Wildcard Pattern Matching**
* Символы `*` (любая последовательность) и `?` (любой символ)
* **ДП:** `dp[i][j]` — совпадает ли `s[0..i)` с `pat[0..j)`; `O(n·m)` время, `O(m)` память

## **8.2. Regular Expression Matching**
* **Движок:** NFA/DFA построение (Thompson's construction); regex с обратными ссылками
* **ДП:** `dp[i][j]` — совпадает ли `s[0..i)` с `pat[0..j)` для `.` и `*`; `O(n·m)`
