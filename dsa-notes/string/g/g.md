**G. СЖАТИЕ СТРОК**

> **Архитектура:** `StringCompression` (g.cpp) — наследует `StringAnalysis` (f.cpp). Реализует: RLE, Huffman, LZ77, BWT, Move-to-Front. Все алгоритмы параметризованы размером входных данных `n` и размером алфавита `Σ`.
>
> **Связи:** суффиксный массив — `string/e` (3) (для BWT `O(n log n)`); priority queue — `struct.md` (IV) (для Хаффмана `O(n log n)`); хеш-функции — `string/d` (для словарей LZ); префиксные суммы — `struct.md` (V.A); ДП — `dynamic.md` (G — оптимальное кодирование).

# **1. Безпотерные алгоритмы**

## **1.1. RLE (Run-Length Encoding)**
* **Идея:** замена серий повторяющихся символов на `(символ, количество)`
* **Кодирование:** `aaabbc → 3a2b1c` или `aaabbc → 3a2bc` (оптимизация для единичных)
* **Декодирование:** обратное преобразование `O(n)`
* **Сложность:** `O(n)` кодирование, `O(m)` декодирование где `m` — размер сжатых данных
* **Эффективность:** хорошо при длинных сериях (`σ` small); плохо при случайных данных

## **1.2. Хаффман (Huffman Coding)**
* **Идея:** префиксные коды с переменной длиной; частые символы — короткие коды
* **Построение:** дерево через priority queue `O(n log n)` ( `n` — число различных символов)
* **Кодирование:** замена символов на битовые коды из дерева; `O(n)` после построения дерева
* **Декодирование:** обход дерева по битам; `O(m)` где `m` — длина закодированной строки
* **Оптимальность:** среди префиксных кодов — оптимальное по средней длине; `H ≤ L_avg ≤ H + 1` где `H` — энтропия
* **Canonical Huffman:** упрощённое представление; коды задаются длиной

## **1.3. LZ77**
* **Идея:** словарь = скользящее окно `(offset, length, next_char)`
* **Кодирование:** замена повторяющихся подстрок на ссылки на уже встречавшиеся; `O(n)` время
* **Декодирование:** копирование по ссылкам; `O(n)` время
* **Применение:** gzip/Deflate (LZ77 + Huffman)

## **1.4. LZ78**
* **Идея:** растущий словарь; каждое новое слово = `(index, next_char)` где `index` — существующий префикс
* **Сложность:** `O(n)` время; словарь растёт до `n` записей

## **1.5. LZW (Lempel-Ziv-Welch)**
* **Идея:** как LZ78, но словарь строится симметрично (кодер и декодер одинаковы)
* **Применение:** GIF, UNIX compress

# **2. Преобразования для сжатия**

## **2.1. BWT (Burrows-Wheeler Transform)**
* **Идея:** циклические сдвиги → сортировка → последний столбец; повышает локальность
* **Построение:** `O(n log n)` через суффиксный массив; `O(n)` через SA-IS
* **Обратное преобразование:** `O(n)` через first-column/last-column mapping
* **Применение:** bzip2 (BWT + Move-to-Front + Huffman)

## **2.2. Move-to-Front (MTF)**
* **Идея:** каждый символ заменяется его индексом в текущем «алфавите»; при использовании символ перемещается в начало
* **Сложность:** `O(n · Σ)` в худшем, `O(n)` амортизированно
* **Применение:** предобработка перед Huffman в bzip2
