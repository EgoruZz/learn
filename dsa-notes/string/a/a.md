**A. СТРОКОВЫЕ КОНТЕЙНЕРЫ И ПРЕДСТАВЛЕНИЯ**

> **Архитектура:** `StringContainers` (a.cpp) — базовый класс всей ветки string. Вводит стандартные контейнеры (`std::string`, `string_view`), продвинутые структуры (Rope, Gap Buffer, Piece Table) и оптимизации памяти (SSO, interning). Все последующие разделы (B–J) строятся на этих примитивах.
>
> **Связи:** `std::string` — основа для всех строковых алгоритмов (B–J); SSO и COW — тема `analysis.md` (амортизация); Rope/Gap/Piece — связаны с `struct.md` (II — деревья поиска, V — дерево отрезков); stringstream — применяется в парсинге (`struct.md` IX); C-строки — мост к низкоуровневым операциям (J).

# **1. Стандартные контейнеры**

## **1.1. std::string**
* **Устройство:** динамический массив символов (`char` по умолчанию); хранит `size`, `capacity`, указатель на данные
* **SSO (Small String Optimization):** если `size ≤ k` (обычно `k = 15–22` в зависимости от реализации), данные хранятся прямо в объекте (внутренний буфер); heap-аллокация не происходит
* **Амортизация `push_back`:** `O(1)` — при `size == capacity` выделяется новый буфер размера `capacity · f` ( `f = 2` или `1.5`); копирование `O(capacity)` происходит амортизированно `O(1)` раз на `f−1` вставок
* **Ключевые операции:**
    * `append(s)` — добавление строки `O(m)` где `m = |s|`
    * `substr(pos, len)` — выделение подстроки `O(len)` (копирование)
    * `find(pat)` — поиск подстроки `O(n·m)` худший; `std::string::npos` если не найдено
    * `replace(pos, len, s)` — замена подстроки `O(n)` (сдвиг хвоста)
    * `insert(pos, s)` — вставка `O(n)`
    * `erase(pos, len)` — удаление `O(n)` (сдвиг хвоста)
    * `compare(s)` — лексикографическое сравнение `O(min(n,m))`
* **Память:** `sizeof(std::string)` обычно `32` байта (libc++) или `24` байта (libstdc++)

## **1.2. std::string_view (C++17)**
* **Устройство:** легковесная read-only view — указатель + длина; `O(1)` копирование
* **Не владеет данными:** lifetime привязан к источнику; UB при обращении после уничтожения источника
* **Преимущество:** избегание копирования при передаче в функции; `O(1)` создание
* **Ключевые операции:** `substr` `O(1)`, `find` `O(n·m)`, `remove_prefix`, `remove_suffix`
* **Ограничение:** нет модификаций; нельзя использовать как параметр для `std::string` без конвертации

## **1.3. Unicode-контейнеры**
* **`std::wstring`:** `wchar_t` символы; размер `sizeof(wchar_t) = 2` (Windows) или `4` (Linux/macOS)
* **`std::u16string, std::u32string`:** UTF-16, UTF-32; фиксированный размер символа
* **`std::basic_string<T>`:** шаблонная версия для произвольных типов символов

## **1.4. C-строки**
* **Представление:** `char[]` с нулевым терминатором `\0`; `strlen` `O(n)` — проход до `\0`
* **Безопасные функции:** `strncpy`, `snprintf`, `strlcpy` — ограничение длины; `strcmp` — сравнение `O(min(n,m))`
* **Применение:** совместимость с C-API; стековые строки; максимальная производительность (без аллокаций)

## **1.5. Потоки**
* **`std::stringstream`:** чтение + запись; форматирование через `<<` и `>>`
* **`std::ostringstream`:** запись в строку; построение строк через `<<`
* **`std::istringstream`:** чтение из строки; парсинг через `>>`
* **Применение:** преобразование типов (`to_string`, `stoi`), парсинг CSV/JSON, построение строк

# **2. Продвинутые структуры**

## **2.1. Rope (канатная структура)**
* **Идея:** сбалансированное бинарное дерево, где листья — подстроки; внутренние узлы — объединение
* **Операции:**
    * `insert(pos, s)` — `O(log n + m)` — разрезание дерева + вставка нового узла
    * `erase(pos, len)` — `O(log n + len)` — удаление поддерева
    * `substr(pos, len)` — `O(log n + len)` — навигация + сбор
    * `concat(other)` — `O(log n + log m)` — слияние корней
* **Память:** `O(n)` —每个 символ хранится ровно один раз в листьях
* **Применение:** текстовые редакторы с большими документами (`> 10⁶` символов); операции в середине документа `O(log n)` вместо `O(n)` у `std::string`

## **2.2. Gap Buffer**
* **Идея:** массив с «разрывом» (gap) в позиции курсора; вставка в gap `O(1)`, удаление из gap `O(1)`
* **Операции:**
    * `insert(ch)` — вставка в текущую позицию `O(1)` (если gap не пуст) иначе `O(gap_size)` на перемещение
    * `erase()` — удаление перед курсором `O(1)`
    * `move_to(pos)` — перемещение gap `O(|pos − current|)`
* **Параметр:** размер gap `g`; амортизация `O(1)` при `g = O(1)` от числа операций
* **Применение:** Emacs; быстрые операции в позиции курсора

## **2.3. Piece Table**
* **Идея:** два буфера — `original` (начальный текст) и `modified` (изменения); таблица кусков (start, length, buffer_id)
* **Операции:**
    * `insert(pos, s)` — добавление в `modified` + обновление таблицы `O(log k)` где `k` — число кусков
    * `erase(pos, len)` — пометка кусков как удалённых `O(log k)`
* **Память:** `O(n + k)` где `n` — размер текста, `k` — число модификаций
* **Применение:** VS Code; эффективные модификации без копирования всего текста

# **3. Память и оптимизации**

## **3.1. SSO (Small String Optimization)**
* **Принцип:** если строка короткая (`≤ k` символов), данные хранятся прямо в объекте; heap-аллокация не происходит
* **Параметр `k`:** зависит от `sizeof(std::string)` и выравнивания; типично `15–22` символа
* **Выигрыш:** избегание `malloc/free` для коротких строк; улучшение кэш-локальности

## **3.2. String Interning**
* **Идея:** пул уникальных строк; при создании строки — проверка, существует ли уже; если да — вернуть указатель на существующую
* **Сравнение:** `O(1)` через указатель (вместо `O(n)` побайтового сравнения)
* **Память:** экономия при дублировании; overhead — хеш-таблица
* **Применение:** компиляторы (таблица символов), интерпретаторы, JVM

## **3.3. Copy-on-Write (COW)**
* **Идея:** при копировании строки — не копировать данные, а разделить указатель; при модификации — сначала скопировать (copy)
* **Исторически:** применялся в `std::string` (GCC/libstdc++ до C++11); запрещён в C++11+ из-за проблем с потокобезопасностью
* **Применение:** сейчас редко; концептуально важно для понимания семантики копирования
