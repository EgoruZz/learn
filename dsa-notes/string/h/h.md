**H. ВАЛИДАЦИЯ И ПАТТЕРНЫ**

> **Архитектура:** `StringValidation` (h.cpp) — наследует `StringCompression` (g.cpp). Реализует: валидацию данных (email, телефоны, ID, кредитные карты, ISBN), распознавание паттернов (word patterns, language detection), простой regex engine (NFA/DFA). Все алгоритмы параметризованы форматом ввода и работают за `O(n)`.
>
> **Связи:** DFA/NFA — `math/discrete-and-logic` (автоматы); KMP/Z-функция — `string/b` (2,3) (поиск паттернов);(suffix array) — `string/e` (3) (поиск подстрок); регулярные выражения — связь с `struct.md` (IX — парсеры); frequency analysis — `string/f` (1) (для language detection); ДП — `dynamic.md` (C — wildcard/regex matching).

# **1. Валидация данных**

## **1.1. Email**
* Базовая проверка: `local@domain.tld`; `local` — буквы/цифры/точки/плюсы; `domain` — буквы/цифры/точки/дефисы; `tld` ≥ 2 символа
* **Сложность:** `O(n)`

## **1.2. Телефоны**
* E.164 формат: `+{country_code}{number}`; `O(n)` проверка
* Национальные форматы: через regex или DFA

## **1.3. Кредитные карты (Luhn Algorithm)**
* Чётные по позиции снизу × 2 (если > 9 → сумма цифр); сумма + контрольная цифра ≡ 0 mod 10
* **Сложность:** `O(n)`

## **1.4. ISBN**
* ISBN-10: 10 цифр, `Σ dᵢ·(10−i) ≡ 0 mod 11`
* ISBN-13: 13 цифр, `Σ dᵢ·wᵢ ≡ 0 mod 10` где `wᵢ = {1,3}` попеременно
* **Сложность:** `O(n)`

## **1.5. Штрихкоды (UPC, EAN)**
* UPC-A: 12 цифр, `Σ dᵢ·wᵢ ≡ 0 mod 10` где `wᵢ = {3,1}` попеременно
* **Сложность:** `O(n)`

# **2. Распознавание паттернов**

## **2.1. Word Patterns**
* Биекция строк ↔ числа: `["a","b","a"]` → `[0,1,0]`
* Проверка: `O(m)` через map

## **2.2. Language Detection**
* N-gram frequency comparison; стоп-слова
* **Сложность:** `O(n + k·Σ)` где `k` — число N-грамм

## **2.3. Bioinformatics**
* DNA: проверка допустимых символов `{A,C,G,T}`
* Аминокислоты: проверка по таблице кодонов
* **Сложность:** `O(n)`

# **3. Регулярные выражения (упрощённый движок)**

## **3.1. Поддерживаемые операции**
* `.` — любой символ
* `*` — ноль и более повторений предыдущего
* `+` — одно и более повторений
* `?` — ноль или одно вхождение
* `[abc]` — набор символов
* `[^abc]` — отрицание набора

## **3.2. Движок**
* **DFA approach:** построение автомата за `O(m)` ( `m` — длина regex); поиск за `O(n)`
* **Backtracking approach:** рекурсивный перебор; `O(2^m)` худший, но простой в реализации
* **Сложность:** DFA `O(n + m)`, backtracking `O(2^m · n)` худший
