# **A. МОДЕЛИ ПАМЯТИ**

## **1. Иерархия памяти**

### **1.1. Уровни**
* **Регистры:** ~1 ns, ~1 KB;最快的 память, доступна напрямую в инструкциях
* **L1 кэш:** ~4 цикла, ~32-64 KB; раздельный (instruction/data)
* **L2 кэш:** ~10 циклов, ~256 KB-1 MB; общий для ядра
* **L3 кэш:** ~40 циклов, ~2-8 MB; общий для всех ядер
* **RAM:** ~200 циклов, ~8-64 GB; основная память
* **SSD:** ~10⁴ циклов; твердотельный накопитель
* **HDD:** ~10⁶ циклов; жёсткий диск

### **1.2. Влияние на алгоритмы**
* **Кэш-промах:** обращение к RAM вместо L1 → замедление в 50-100 раз
* **Локальность данных:** обработка смежных данных → меньше промахов
* **Предвыборка:** `__builtin_prefetch` для данных, которые понадобятся через итерацию

## **2. Кэш-линия**

### **2.1. Определение**
* Минимальная единица передачи данных между кэшем и RAM
* **Размер:** обычно 64 байта (x86-64)
* **Последствия:** обращение к одному элементу массива загружает 16 int (4 байта) или 8 long long (8 байт)

### **2.2. Оптимизация**
* Выравнивание данных по границе кэш-линии (64 байта)
* Обход массива последовательно (а не random access)
* Блочные алгоритмы: обработка по блокам размера кэша

## **3. Word-RAM модель**

### **3.1. Определение**
* Слово = `w = Θ(log n)` бит; одна операция над словом = O(1)
* Массив `n` элементов занимает `n` слов = `O(n)` памяти

# **B. АНАЛИЗ ИСПОЛЬЗОВАНИЯ ПАМЯТИ**

## **1. Статическая память**

### **1.1. Определение**
* Компиляторно-распределяемая память: массивы фиксированного размера
* **Пример:** `int a[1000]` → O(1) доп. памяти (размер известен при компиляции)

## **2. Динамическая память**

### **2.1. Определение**
* Куча: `new/delete`, `malloc/free`, `vector`
* **Сложность:** O(1) на операцию (амортизированно для вектора)
* **Утечки:** забытый `delete` → рост потребления памяти

## **3. Рекурсивная память**

### **3.1. Определение**
* Стек вызовов: каждый рекурсивный вызов хранит локальные переменные, адрес возврата
* **Сложность:** O(depth) — глубина рекурсии
* **Пример:** Merge Sort: O(log n) стек; Fibonacci: O(n) стек

## **4. In-place алгоритмы**

### **4.1. Определение**
* O(1) дополнительной памяти (не считая входных данных)
* **Примеры:** Bubble Sort, Selection Sort, Quick Sort (in-place partition)
* **Не in-place:** Merge Sort O(n), Counting Sort O(k)

# **C. CACHE-OBLIVIOUS АЛГОРИТМЫ**

## **1. Принцип**

### **1.1. Определение**
* Алгоритм, оптимизированный для **всех** размеров кэша (M) и блоков (B)
* Не требует знания M и B — «забывает» о параметрах кэша

### **1.2. Преимущество**
* Работает оптимально на любой архитектуре
* Не нужно перенастраивать при сменеhardware

## **2. Примеры**

### **2.1. Cache-oblivious сортировка**
* Funnel Sort: рекурсивное слияние с блоками
* Фаза: сортировка блоков по размеру кэша → слияние
* Сложность: O((n/B) log_{M/B}(n/B)) I/O

### **2.2. Matrix multiplication**
*:Tiled умножение матриц: блоки размера √M × √M
* Cache complexity: O(n³ / (B·√M))

## **3. Влияние на практику**

### **3.1. Ускорение**
* Кэш-оптимизированные алгоритмы: 2-10x быстрее
* Пример: matrix multiplication — tiled vs naive → 3-5x ускорение

### **3.2. I/O модель**
* `N` — размер данных, `B` — размер блока, `M` — размер кэша
* I/O complexity: число блочных операций чтения/записи
