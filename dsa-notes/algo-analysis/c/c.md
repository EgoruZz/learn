# **A. АНАЛИЗ ПО СЛУЧАЯМ**

## **1. Худший случай (worst case)**

### **1.1. Определение**
* `T_worst(n) = max_{|вход|=n} T(вход)` — максимальное время среди всех входов размера `n`
* **Значение:** гарантированная верхняя граница; алгоритм **никогда** не работает медленнее

### **1.2. Примеры**
* QuickSort: O(n²) — когда опорный всегда min/max
* Merge Sort: O(n log n) — **всегда** (не зависит от входа)
* Linear Search: O(n) — когда элемент последний или отсутствует

## **2. Лучший случай (best case)**

### **2.1. Определение**
* `T_best(n) = min_{|вход|=n} T(вход)` — минимальное время среди всех входов
* **Значение:** нижняя граница для конкретного алгоритма (не для класса задач)

### **2.2. Примеры**
* QuickSort: O(n) — когда опорный всегда медиана
* Insertion Sort: O(n) — когда массив уже отсортирован
* Binary Search: O(1) — когда элемент в середине

## **3. Средний случай (average case)**

### **3.1. Определение**
* `T_avg(n) = E[T(вход)]` — математическое ожидание времени по всем входам размера `n`
* **Предположение:** входы распределены равномерно (или по другой модели)

### **3.2. Примеры**
* QuickSort: O(n log n) — средний при равномерном распределении
* Hash Table: O(1) — средний при хорошей хеш-функции
* Randomized QuickSort: O(n log n) — ожидаемое время (garanteed)

## **4. Смешанный случай**

### **4.1. Определение**
* Algo­ritm работает за O(f(n)) в худшем, но O(g(n)) при «typical» входах
* **Пример:** QuickSelect (nth element) — O(n²) худший, O(n) средний;nth_element в STL

# **B. АНАЛИЗ ИТЕРАТИВНЫХ АЛГОРИТМОВ**

## **1. Суммирование рядов**

### **1.1. Арифметический ряд**
* `Σᵢ₌₁ⁿ i = n(n+1)/2 = Θ(n²)`

### **1.2. Геометрический ряд**
* `Σᵢ₌₀ⁿ rⁱ = (rⁿ⁺¹ − 1)/(r − 1)` при `r ≠ 1`
* При `|r| < 1`: `Σᵢ₌₀^∞ rⁱ = 1/(1 − r)` — сходится

### **1.3. Гармонический ряд**
* `Σᵢ₌₁ⁿ 1/i = ln(n) + γ + O(1/n)` ≈ ln(n) + 0.5772
* `ln(n)` растёт **очень медленно** (при n = 10⁶: ln(n) ≈ 13.8)

## **2. Произведения**

### **2.1. Формула**
* `Πᵢ₌₁ⁿ aᵢ = exp(Σᵢ₌₁ⁿ ln(aᵢ))` — сводится к сумме логарифмов
* **Пример:** `n! = Πᵢ₌₁ⁿ i = exp(Σ ln i) ≈ exp(n ln n − n) = nⁿ · e⁻ⁿ` (стёрлинг)

## **3. Анализ вложенных циклов**

### **3.1. Принцип**
* Каждый цикл contributes множитель к сложности
* `for(i=0; i<n; i++) for(j=0; j<n; j++) O(1)` → O(n²)
* `for(i=0; i<n; i++) for(j=0; j<i; j++) O(1)` → O(n(n−1)/2) = O(n²)

### **3.2. Типичные паттерны**
* `for(i=0; i<n; i++) for(j=0; j<n; j++)` → O(n²)
* `for(i=0; i<n; i++) for(j=0; j<i; j++)` → O(n²)
* `for(i=0; i<n; i++) for(j=i; j<n; j++)` → O(n²)
* `for(i=0; i<n; i++) for(j=0; j<log n; j++)` → O(n log n)

## **4. Метод замены переменной**

### **4.1. Замена суммы на интеграл**
* `Σᵢ₌₁ⁿ f(i) ≈ ∫₁ⁿ f(x)dx` при монотонном `f`
* **Пример:** `Σᵢ₌₁ⁿ 1/i ≈ ∫₁ⁿ dx/x = ln(n)`

# **C. МЕТОД ПОДСЧЁТА ОПЕРАЦИЙ**

## **1. Подсчёт сравнений**

### **1.1. Сортировки**
* **Bubble Sort:** в худшем `n(n−1)/2` сравнений
* **Insertion Sort:** в худшем `n(n−1)/2`, в лучшем `n−1`
* **Merge Sort:** `n log n − n + 1` сравнений (точно)
* **Quick Sort:** среднее `~1.39 n log n` (2n ln n)

### **1.2. Нижняя граница**
* **Теорема:** любая сортировка сравнениями требует `Ω(n log n)` сравнений
* **Доказательство:** дерево решений имеет `n!` листьев; высота дерева `≥ log₂(n!) = Θ(n log n)`

## **2. Подсчёт обменов**

### **2.1. Сортировки**
* **Bubble Sort:** в худшем `n(n−1)/2` обменов (каждое сравнение → обмен)
* **Insertion Sort:** в худшем `n(n−1)/2` обменов (сдвиги)
* **Selection Sort:** ровно `n−1` обменов (фиксировано)
* **Merge Sort:** O(n) дополнительных копирований (не обменов)

## **3. IO-сложность (внешняя сортировка)**

### **3.1. Модель**
* `M` — размер оперативной памяти (в записях)
* `N` — размер данных на диске
* `B` — размер блока (размер страницы диска)
* **IO-операция:** чтение/запись одного блока

### **3.2. Внешняя сортировка (merge sort с k-way merge)**
* Фаза 1: разделить данные на блоки по M, отсортировать каждый в памяти → O(N/B · log(M/B)) IO
* Фаза 2: k-way merge → O((N/B) · log_{M/B}(N/M)) IO
* **Общая сложность:** O((N/B) · log_{N/M}(N/M)) = O((N/B) · log(N/M))
