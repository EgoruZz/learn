# **A. ЭМПИРИЧЕСКИЙ АНАЛИЗ**

## **1. Профилирование**

### **1.1. Инструменты**
* **gprof:** статический профилировщик GNU; компиляция с `-pg`; профилирует частоту вызовов функций и время в них
* **perf:** динамический профилировщик Linux; опрос PMU (Performance Monitoring Unit); cache-misses, branch-misses, cycles
* **Valgrind/Callgrind:** эмуляция кэша; точный подсчёт инструкций, промахов, предсказания ветвлений; замедление ~10-50x
* **Intel VTune:** аппаратное профилирование; NUMA, кэш, векторизация (SIMD)
* **google-perf:** профилирование времени в строках кода

### **1.2. Методика**
* Изолировать процесс (отключить фоновые задачи)
* Зафиксировать частоту CPU (отключить turbo boost)
* Прогреть кэш (запустить k₁ итераций перед измерением)

## **2. Бенчмаркинг**

### **2.1. Генерация данных**
* Случайные: `rand()` для uniform распределения
* Отсортированные: `sorted(data)`
* Обратно-отсортировные: `reverse(sorted(data))`
* Частично отсортированные: sorted с k обменами

### **2.2. Многократные прогоны**
* Минимум 10-20 запусков на каждый размер
* Медиана устойчивее среднего к выбросам
* Стандартное отклонение: `σ = sqrt(Σ(Tᵢ − T̄)²/(n−1))`

### **2.3. Логарифмический масштаб**
* `log T(n)` vs `log n` → наклон = степень полинома
* Наклон 1 → O(n), наклон 2 → O(n²), наклон ~1 → O(n log n)

## **3. Кросс-алгоритмический анализ**

### **3.1. Определение**
* Построение `T₁(n)/T₂(n)` для разных `n`
* **Crossover point:** `n*` где `T₁(n*) = T₂(n*)`
* Ниже `n*`: алгоритм 1 быстрее; выше `n*`: алгоритм 2

### **3.2. Пример**
* QuickSort vs Insertion Sort: crossover ≈ 20-30 (QuickSort быстрее для n > 30)
* MergeSort vs QuickSort: crossover ≈ 100-1000 (зависит от реализации)

# **B. СТАТИСТИЧЕСКИЕ МЕТОДЫ АНАЛИЗА**

## **1. Регрессионный анализ**

### **1.1. Модель**
* `T(n) = a · nᵇ + c` — параметры a, b, c определяются из данных
* **Логарифмирование:** `log T(n) = log a + b · log n` → линейная регрессия `Y = A + B·X`

### **1.2. МНК (метод наименьших квадратов)**
* Минимизация `Σᵢ(Tᵢ − model(nᵢ))²`
* **Наклон B** = степень полинома (≈ 1 для O(n), ≈ 2 для O(n²))

### **1.3. Коэффициент детерминации R²**
* `R² = 1 − SS_res / SS_tot`
* `R² ≈ 1` → модель хорошо описывает данные
* Сравнение моделей: R², AIC, BIC

## **2. Доверительные интервалы**

### **2.1. Формула**
* 95% CI: `T̄ ± 1.96 · σ / √N` (при нормальности)
* **Bootstrap:** повторная выборка для оценки распределения статистики

## **3. Устранение шума**

### **3.1. Изоляция**
* Отключение фоновых процессов
* Фиксация частоты CPU
* Фиксация environment variables

### **3.2. Прогрев**
* k₁ «прогревочных» итераций перед измерением
* Прогревает кэш, TLB, branch predictor

### **3.3. Нормализация**
* Деление на время базовой операции (clock cycle normalization)
* Относительные измерения: `T(n)/T(n₀)`
