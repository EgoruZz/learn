# **A. ДВА УКАЗАТЕЛЯ**

## **1. Встречные указатели (Converging Two Pointers)**
* **Определение:** два указателя с концов массива, движущиеся навстречу друг другу; на каждом шаге проверяем условие и сдвигаем один из указателей
* **Почему работает:** на каждом шаге один из указателей гарантированно продвигается; если массив отсортирован, движение определяется монотонностью
* **Обобщение:** произвольный предикат `pred(left_val, right_val)` для решения; произвольная функция移动 `advance_left(val)` / `advance_right(val)`
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `two_pointers_converging` — обобщённая с предикатом и функциями移动
* **Применения:** Two Sum (отсортированный массив), Container With Most Water, Trapping Rain Water

## **2. Параллельные указатели (Fast/Slow Pointers)**
* **Определение:** два указателя, движущиеся с разной скоростью по одной структуре; медленный — на 1, быстрый — на k шагов
* **Почему работает:** если цикл существует, быстрый «догонит» медленный; расстояние между ними кратно длине цикла
* **Обобщение:** скорость быстрого указателя как параметр (typically 2 или 3)
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `fast_slow_cycle_detect` — обнаружение цикла (Floyd), `find_cycle_start` — вход в цикл
* **Применения:** обнаружение цикла в linked list, поиск среднего элемента, проверка палиндрома в linked list

## **3. Разделяющие указатели (Partitioning Pointers)**
* **Определение:** три указателя (lt, i, gt), разделяющие массив на три части относительно pivot
* **Почему работает:** инвариант: `a[lo..lt-1] < pivot`, `a[lt..i-1] == pivot`, `a[gt+1..hi-1] > pivot`
* **Обобщение:** произвольный компаратор `cmp(a, b)` для определения отношений; произвольный pivot
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `dutch_flag_three_pointers` — переиспользует логику из Quick Sort (I.B.6) и `struct` I.A.11
* **Применения:** Dutch National Flag, 3-way partition Quick Sort, сортировка массива из 0/1/2

## **4. Три указателя: 3Sum**
* **Определение:** найти все уникальные тройки `(a[i], a[j], a[k])` such that `a[i] + a[j] + a[k] = target`
* **Алгоритм:** фиксируем `i`,Two Sum для `target - a[i]` встречными указателями; пропускаем дубликаты
* **Обобщение:** произвольная целевая сумма `target`, произвольное число слагаемых (KSum через рекурсию)
* **Сложность:** O(n²) время, O(1) память (не считая вывод)
* **Реализация:`three_sum` — с пропуском дубликатов и рекурсивным k_sum

## **5. K указателей (KPointers)**
* **Определение:** обобщение двух указателей на K массивов: один указатель на каждый массив, движение с наименьшим значением
* **Почему работает:** при сортировке массивов движение наименьшего указателя гарантирует рассмотрение всех комбинаций по порядку
* **Обобщение:** K отсортированных массивов, произвольная функция.merge
* **Сложность:** O(n · K) где n — суммарный размер, O(K) память
* **Реализация:** `k_way_merge_pointers` — через min-heap (переиспользует `priority_queue` из struct IV)
* **Применения:** слияние K отсортированных массивов, K-th smallest in sorted matrices

## **6. Two Pointers + Sorting (олимпиадный паттерн)**
* **Паттерн:** сортировка массива + два указателя вместо вложенного цикла
* **Применения:** Two Sum, 3Sum, Container With Most Water — избегает O(n²) на неупорядоченных данных
* **Реализация:** переиспользует `two_pointers_converging` (A.1)

# **B. СКОЛЬЗЯЩЕЕ ОКНО**

## **6. Фиксированное окно (Fixed Window)**
* **Определение:** окно фиксированного размера `k`; на каждом шаге: добавляем элемент справа, убираем слева; поддерживаем агрегат (сумма, минимум и т.д.)
* **Почему O(n):** каждый элемент добавляется и удаляется ровно один раз
* **Обобщение:** размер окна `k` как параметр; произвольная функция `add(val)` для добавления и `remove(val)` для удаления из окна
* **Сложность:** O(n) время, O(k) память
* **Реализация:** `fixed_window_sum` — окно с поддержкой суммы; `fixed_window_max` — окно с поддержкой максимума (переиспользует deque из раздела 8)

## **7. Динамическое окно (Dynamic Window)**
* **Определение:** окно переменного размера; расширяем правый указатель, пока условие выполнено; сжимаем левый, пока условие нарушено
* **Паттерн:** `while (right < n) { добавить a[right]; while (condition нарушено) { удалить a[left]; left++; } right++; }`
* **Обобщение:** произвольный предикат `condition(val)` для расширения и сжатия
* **Сложность:** O(n) время (каждый элемент добавляется и удаляется не более одного раза), O(1) память
* **Реализация:** `dynamic_window_longest_no_repeat` — максимальная подстрока без повторяющихся символов; `dynamic_window_min_window` — минимальное окно, содержащее все символы шаблона
* **Применения:** longest substring without repeating characters, minimum window substring, longest subarray with at most K distinct

## **8. Монотонное окно (Monotonic Deque)**
* **Определение:** deque поддерживает монотонную последовательность индексов; элементы в deque отсортированы по значению (для максимума — убывающе, для минимума — возрастающе)
* **Почему O(n):** каждый элемент входит и выходит из deque не более одного раза
* **Алгоритм:** при добавлении `i`: удаляем сзади все `j` such that `a[j]` не лучше `a[i]`; при удалении с frente проверяем `front == left`
* **Обобщение:** произвольная функция `is_better(new_val, old_val)` для сравнения; произвольная операция (максимум/минимум)
* **Сложность:** O(n) время, O(n) память (размер deque ≤ n)
* **Реализация:** `monotonic_deque_max_slide` — максимум в каждом окне размера k; `monotonic_deque_min_slide` — минимум; `monotonic_deque_sliding_max`
* **Связь:** переиспользует `std::deque` (`struct.md`); связь с задачами на гистограммах и прямоугольниках

## **9. Frequency Map окно (Hash Map Window)**
* **Определение:** окно с поддержкой частот через `unordered_map`; позволяет работать с подстроками произвольного характера
* **Почему O(n):** каждое обновление частоты — O(1) амортизированно
* **Обобщение:** произвольный предикат на частоты (максимум K уникальных, все символы шаблона и т.д.)
* **Сложность:** O(n) время, O(σ) память где σ — размер алфавита
* **Реализация:** `freq_map_window_k_distinct` — longest substring с ≤ K уникальными символами; `freq_map_window_anagram` — все анаграммы шаблона в строке
* **Применения:** find all anagrams, longest substring with at most K distinct characters, permutation in string

## **10. Sliding Window + Hash Map (олимпиадный паттерн)**
* **Паттерн:** окно + частотная карта для задач на подстроки
* **Применения:** longest substring without repeating, minimum window substring, all anagrams
* **Реализация:** переиспользует `dynamic_window_longest_no_repeat`, `dynamic_window_min_window`

# **C. СКАНИРУЮЩАЯ ПРЯМАЯ (SWEEP LINE)**

## **10. Сортировка событий (Event Sort)**
* **Определение:** преобразование отрезков/интервалов в события (start, +1; end, -1); сортировка событий → проход с поддержанием активного множества
* **Почему O(n log n):** сортировка 2n событий → O(n log n), проход → O(n)
* **Обобщение:** произвольные типы событий `(position, type, data)`; произвольная функция `process_event(event)`
* **Сложность:** O(n log n) время, O(n) память
* **Реализация:** `sweep_line_max_overlap` — максимальное количество пересекающихся отрезков; `sweep_line_union_intervals` — объединение интервалов

## **11. Активные множества (Active Set)**
* **Определение:** множество «активных» (currently overlapping) элементов; при встрече start-события — добавляем, end-события — удаляем
* **Почему работает:** сортировка гарантирует, что при обработке события все связанные отрезки уже в active set
* **Обобщение:** произвольная структура для active set (multiset, map, Fenwick tree)
* **Сложность:** O(n log n) время (вставка/удаление в структуре), O(n) память
* **Реализация:** `active_set_segments` —维护活性集 для задачи на пересечения

## **12. Пересечение отрезков**
* **Определение:** найти все точки, принадлежащие максимальному числу отрезков
* **Алгоритм:** события (координата, +1/-1) → сортировка → сканирование с поддержанием текущего count
* **Обобщение:** взвешенные отрезки (вес добавляется при start, вычитается при end)
* **Сложность:** O(n log n) время, O(n) память
* **Реализация:** `sweep_line_point_max_cover` — точка с максимальным покрытием

## **13. Объединение интервалов (Merge Intervals)**
* **Определение:** дан набор отрезков, объединить все пересекающиеся
* **Алгоритм:** сортировка по началу → проход: если текущий пересекается с предыдущим — объединяем, иначе — начинаем новый
* **Обобщение:** произвольный предикат `overlaps(a, b)` для определения пересечения
* **Сложность:** O(n log n) время, O(n) память
* **Реализация:** `merge_intervals` — с предикатом пересечения

## **14. Sweep Line + Segment Tree / BIT (олимпиадный паттерн)**
* **Паттерн:** сканирующая прямая + дерево отрезков для запросов «сколько активных точек в диапазоне»
* **Применения:** задачи на пересечения с весами, динамические покрытия
* **Связь:** `struct.md` V (дерево отрезков, Fenwick tree)

# **D. АЛГОРИТМЫ МАКСИМАЛЬНЫХ СУММ**

## **14. Kadane's Algorithm (1D)**
* **Определение:** найти максимальную сумму непрерывного подмассива
* **Рекуррентность:** `dp[i] = max(a[i], dp[i-1] + a[i])` → ответ = max(dp[i])
* **Почему O(n):** один проход, каждый элемент обрабатывается один раз
* **Обобщение:** произвольная функция `combine(current, new_val)` вместо сложения; произвольный предикат `valid(subarray)`
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `kadane_1d` — обобщённый; `kadane_1d_indices` — возвращает начало и конец подмассива

## **15. Kadane's 2D (Maximum Sum Rectangle)**
* **Определение:** найти прямоугольник максимальной суммы в матрице
* **Алгоритм:** фиксируем верхнюю и нижнюю строки → схлопываем столбцы в 1D массив → Kadane 1D
* **Обобщение:** произвольные размеры матрицы `rows × cols`, произвольная функция склейки столбцов
* **Сложность:** O(rows² · cols) время, O(cols) память
* **Реализация:** `kadane_2d` — с определением координат прямоугольника

## **16. Циклический Kadane (Circular Maximum Subarray)**
* **Определение:** массив циклический; найти максимальную сумму подмассива (может «перетекать» через конец)
* **Идея:** max(circular) = total_sum - min(non_empty_subarray); ответ = max(kadane_1d, circular)
* **Обобщение:** произвольная функция агрегации; проверка на полный отрицательный массив
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `kadane_circular`

## **17. Kadane с ограничениями на длину**
* **Определение:** максимальная сумма подмассива длины от `min_len` до `max_len`
* **Алгоритм:**.prefix sums +deque (монотонное окно) для поддержки минимума/максимума префиксных сумм в окне
* **Обобщение:** произвольные `min_len` и `max_len`, произвольная функция веса
* **Сложность:** O(n) время, O(n) память (префиксные суммы)
* **Реализация:** `kadane_bounded_length`

## **18. K-Maximum Subarrays (K-Sum)**
* **Определение:** найти K подмаксимальных подмассивов (или сумму K наибольших)
* **Алгоритм:** через heap (K largest subarray sums) или через D&C с partition
* **Обобщение:** произвольное K, произвольная функция веса подмассива
* **Сложность:** O(n log n + K log n) через heap
* **Реализация:** `k_max_subarray_sums` — через min-heap

## **19. Kadane + Prefix Sums (олимпиадный паттерн)**
* **Паттерн:** Kadane как DP + префиксные суммы для задач с ограничениями на длину
* **Применения:** maximum sum with length constraints, circular arrays, 2D rectangles
* **Реализация:** переиспользует `kadane_1d`, `kadane_circular`, `kadane_bounded_length`

# **E. ЛИНЕЙНОЕ ПРОГРАММИРОВАНИЕ (СИМПЛЕКС)**

## **19. Каноническая форма задачи ЛП**
* **Определение:** минимизация `c^T x` при ограничениях `Ax = b, x ≥ 0` (каноническая) или `Ax ≤ b, x ≥ 0` (стандартная)
* **Приведение:** стандартная → каноническая через slack-переменные; равенства → неравенства через `x = x⁺ - x⁻`
* **Обобщение:** произвольные размеры `m` ограничений и `n` переменных, произвольная матрица `A` и вектор `c`
* **Связь:** двойственная задача (F.21), симплекс-таблица (F.20)

## **20. Симплекс-таблица (Simplex Tableau)**
* **Определение:** матричная форма: строка целевой функции + m строк ограничений; базис — m переменных
* **Алгоритм:** 1) найти входящую переменную (столбец с наименьшим `c_j < 0`); 2) найти исходящую (минимальное отношение `b_i / a_{ik}`); 3) pivot; повторять пока есть `c_j < 0`
* **Почему O(2^m) худший:** число базисов C(n, m) экспоненциально; на практике O(m) итераций
* **Обобщение:** произвольный выбор входящей (most negative, Bland's rule дляAnti-Cycling), произвольный выбор исходящие (минимальное отношение)
* **Сложность:** O(m · n · pivot_operations) время, O(m · n) память
* **Реализация:** `simplex` — полная симплекс-таблица

## **21. Двойственная симплекс-метода (Dual Simplex)**
* **Определение:** начальное решение Dual-допустимо (c ≥ 0), но не primal-допустимо (b может содержать отрицательные); находим исходящую (отрицательное b_i), затем входящую через ratio test
* **Преимущество:** полезен при добавлении ограничений в existing оптимальное решение (re-optimization)
* **Обобщение:** произвольная стратегия выбора входящей переменной
* **Сложность:** аналогична primal simplex

## **22. Revised Simplex**
* **Определение:** хранит обратную матрицу базиса B⁻¹ вместо всей таблицы; пересчёт B⁻¹ при каждом pivot
* **Преимущество:** O(m²) на итерацию вместо O(m·n); лучше для разреженных задач
* **Обобщение:** произвольная стратегия выбора pivot
* **Сложность:** O(m² · pivot_operations) время, O(m² + m·n) память

## **23. Network Simplex**
* **Определение:** симплекс для задач на транспортных графах (min cost flow); базис — дерево; pivot — замена ребра в дереве (cycle canceling)
* **Преимущество:** O(m · n · log n) при good pivot стратегии; специализированный для сетевых задач
* **Обобщение:** произвольный граф, произвольные пропускные способности и стоимости
* **Связь:** min cost flow (`graph.md`), транспортная задача

## **24. Метод внутренней точки (Karmarkar)**
* **Определение:** итеративный метод: начальная допустимая точка → проекция на центрированный целевой функционал → продолжение
* **Преимущество:** полиномиальная сложность O(n^3.5 · L) где L — размер входа; на практике быстрее симплекса для больших задач
* **Обобщение:**
* **Сложность:** O(n^3.5 · L) время, O(n²) память

## **25. LP relaxation для целочисленных задач (олимпиадный паттерн)**
* **Паттерн:** решить LP relaxation → округлить → доказать оптимальность через dual
* **Применения:** Vertex Cover (2-approximation), Set Cover, assignment problems

# **F. ВЕНГЕРСКИЙ АЛГОРИТМ**

## **25. Задача о назначениях (Assignment Problem)**
* **Определение:** дана матрица стоимостей `C[n][n]`; найти биекцию `π: [n] → [n]` минимизирующую `Σ C[i][π(i)]`
* **Почему O(n³):** n итераций, каждая — O(n²) (поиск min в матрице + обновление potentials)
* **Обобщение:** произвольная матрица `C[n][m]` (rectangular assignment, n ≤ m), произвольная функция стоимости

## **26. Классический Венгерский алгоритм**
* **Алгоритм:** 1) вычесть минимум по строкам; 2) вычесть минимум по столбцам; 3) покрыть все нули минимумом линий; 4) если линий < n → добавить min uncovered, повторить; 5) найти максимальное паросочетание в нулях
* **Сложность:** O(n⁴) классический, O(n³) через улучшения
* **Реализация:** `hungarian_basic` — классический O(n³)

## **27. Венгерский алгоритм O(n³)**
* **Алгоритм (Kuhn-Munkres через potentials):** 1) potential u[i] = min(C[i][j]), v[j] = 0; 2) для каждого i: находим augmenting path через slack; 3) обновляем potentials
* **Почему O(n³):** n итераций × O(n²) на each (поиск через slack + обновление)
* **Обобщение:** матрица `C[n][m]` (n ≤ m), произвольная функция стоимости
* **Сложность:** O(n³) время, O(n²) память
* **Реализация:** `hungarian` — полная O(n³) реализация

## **28. Jonker-Volgenant (ускоренная версия)**
* **Определение:** эвристический вариант Венгерского для длинных/узких матриц (n << m или n >> m)
* **Преимущество:** на практике в 2-3 раза быстрее классического для sparse/unbalanced задач
* **Обобщение:** произвольная матрица `C[n][m]`, произвольная функция стоимости
* **Сложность:** O(n² · m) в худшем, O(n · m) в среднем
* **Реализация:** `hungarian_jv` — Jonker-Volgenant variant
