# **VII. ПЛАНИРОВАНИЕ**

> **Архитектура:** `Scheduling` (g.cpp) — класс ветки technique, наследует `GameTheory` (f.cpp). Реализует классические задачи распределения ресурсов и диспетчеризации: от жадных алгоритмов (Interval Scheduling, Fractional Knapsack) до ДП (Weighted Interval Scheduling) и имитации планировщиков ОС. Все методы параметризуются предикатами, функциями веса и квантами времени. Класс интегрирует материал предыдущих разделов: сортировки (I) — для предобработки интервалов; бинарный поиск (II) — для поиска по ответу; жадные алгоритмы (V) — как основа для earliest-finish стратегии; ДП (`dynamic.md`) — для взвешенного планирования; очереди и кучи (`struct.md` IV) — для симуляции планировщиков.
>
> **Связи:** Interval Scheduling связан с Activity Selection (V.B); Weighted Interval Scheduling — классическая задача ДП (`dynamic.md` — оптимальная подструктура); Bin Packing — NP-трудная, поэтому жадные приближения (V.D — Set Cover); Load Balancing связан с задачами на графах (`graph.md` — назначения); планировщики ОС — приложение сортировок и очередей (I, `struct.md`); Multilevel Feedback Queue — иерархические структуры (`struct.md` — очереди).
>
> **Олимпиадные паттерны:**
> * **Сортировка как предобработка:** перед жадными/ДП алгоритмами — сортировка по релевантному ключу (endTime для Interval Scheduling, density для Fractional Knapsack, processing time для SJF).
> * **Восстановление решения:** после ДП (Weighted Interval Scheduling) — обратный проход по таблице для извлечения оптимального подмножества.
> * **Двоичный поиск + проверка:** задачи с параметром (minimize makespan, maximize profit) → бинарный поиск по параметру → проверка через жадный или ДП.
> * **Диспетчеризация и имитация:** моделирование планировщика через очередь (FIFO, priority queue) + счётчики времени; метрики: turnaround time, waiting time, response time, throughput.
> * **NP-трудные задачи и приближения:** Bin Packing, Job Scheduling с произвольными длительностями — NP-трудные; используем приближённые алгоритмы с гарантиями.

# **A. ЗАДАЧИ РАСПИСАНИЙ**

## **1. Interval Scheduling (Жадный: Earliest Finish)**
* **Определение:** дан набор интервалов [start_i, end_i], найти максимальное подмножество непересекающихся интервалов
* **Жадная стратегия:** сортировка по end_i →贪心 выбор интервала с ранним завершением → отбрасывание пересекающихся
* **Почему оптимален:** свойство greedy choice property — выбор раннего finish оставляет максимальное пространство для оставшихся интервалов
* **Обобщение:** произвольный компаратор для сортировки; возврат индексов выбранных интервалов
* **Сложность:** O(n log n) время (сортировка), O(n) память
* **Реализация:** `interval_scheduling` — жадный по endTime, возврат индексов
* **Связь:** Activity Selection (V.B) — частный случай;贪心 оптимален благодаря matroid structure

## **2. Weighted Interval Scheduling (ДП)**
* **Определение:** каждый интервал имеет вес w_i; найти подмножество непересекающихся интервалов с максимальной суммарной стоимостью
* **Рекуррентность:** DP[i] = max(DP[i-1], w_i + DP[p(i)]), где p(i) — последний интервал, не пересекающийся с i-м (ищется через бинарный поиск)
* **Почему ДП:** оптимальная подструктура — оптимальное решение содержит оптимальное подрешение для префикса
* **Обобщение:** произвольная функция веса; предикат пересечения; возврат оптимального подмножества через восстановление
* **Сложность:** O(n log n) время (сортировка + бинарный поиск), O(n) память
* **Реализация:** `weighted_interval_scheduling` — ДП, возврат оптимального подмножества
* **Связь:** `dynamic.md` — классическая задача ДП; Longest Increasing Subsequence (I.D.15, Patience Sort)

## **3. Job Scheduling with Deadlines (Minimize Penalties)**
* **Определение:** n задач, каждая занимает единое время, имеет deadline d_i и штраф p_i; найти порядок выполнения, минимизирующий суммарный штраф за просроченные задачи
* **Жадная стратегия:** сортировка по убыванию штрафа → каждую задачу размещаем на последнее свободное время ≤ deadline (Disjoint Set Union для эффективности)
* **Почему работает:** если задача A имеет больший штраф, чем B, и обе могут быть выполнены до deadline — лучше выполнить A раньше
* **Обобщение:** произвольные длительности задач; штраф как функция от задержки; возврат порядка и множества выполненных задач
* **Сложность:** O(n log n) время (сортировка + DSU операции), O(n) память
* **Реализация:** `job_scheduling_deadlines` — minimize penalties
* **Связь:** DSU (`struct.md` III) для эффективного поиска свободного слота;贪心 + DSU — классический паттерн

## **4. Task Scheduling on Multiple Machines**
* **Определение:** n независимых задач с временем выполнения t_i; m одинаковых параллельных машин; найти расписание, минимизирующее makespan (время завершения последней задачи)
* **Жадная стратегия (LPT):** сортировка по убыванию времени → каждая задача назначается на наименее загруженную машину
* **Почему оптимален приближённо:** LPT даёт makespan ≤ (4/3 − 1/(3m))·OPT; для m=2 это 7/6·OPT
* **Обобщение:** произвольное число машин; предикат назначения; возврат распределения и makespan
* **Сложность:** O(n log n + n log m) время (сортировка + min-heap), O(n + m) память
* **Реализация:** `task_scheduling_multiple_machines` — LPT через min-heap текущих загрузок
* **Связь:** Load Balancing (B.6) — тот же алгоритм, другая постановка; двоичный поиск по ответу (II.B) для проверки可行性 при фиксированном makespan; задачи на графах (`graph.md` — назначения)

## **5. Highest Response Ratio Next (HRRN)**
* **Определение:** некоммутативный планировщик; на каждом шаге выбирается задача с наибольшим Response Ratio: R = (w + s) / s, где w — время ожидания, s — время обслуживания
* **Почему работает:** балансирует SJF (малые s) и FCFS (большое w); избегает starvation за счёт роста R с увеличением w
* **Обобщение:** произвольная функция response ratio; предикат tie-breaking; возврат полной шкалы выполнения
* **Сложность:** O(n²) время (наивный пересчёт R на каждом шаге), O(n) память
* **Реализация:** `hrrn_scheduling` — симуляция с пересчётом Response Ratio
* **Связь:** SJF (C.9) — частный случай при w=0; Priority Scheduling (C.11) — динамический приоритет

## **6. Job Sequence With Deadline (максимизация числа задач)**
* **Определение:** n задач, каждая занимает единое время; deadline d_i; выбрать максимум задач, которые можно выполнить до дедлайнов
* **Жадная стратегия:** сортировка по убыванию d_i → greedily размещаем каждую задачу на последний свободный слот ≤ deadline
* **Почему оптимален:** свойство matroid — множество выполнимых расписаний образует matroid
* **Обобщение:** произвольные длительности задач; возврат числа выполненных задач и порядка
* **Сложность:** O(n log n) время (сортировка), O(n) память
* **Реализация:** `job_sequence_with_deadline` — максимизация числа выполненных задач
* **Связь:** Job Scheduling with Deadlines (A.3) — тот же подход, другой критерий оптимизации

## **7. Job Sequencing With Deadline (максимизация прибыли)**
* **Определение:** n задач, длительность = 1, deadline d_i, прибыль p_i; выбрать подмножество задач для максимизации суммарной прибыли с учётом дедлайнов
* **Жадная стратегия:** сортировка по убыванию прибыли → размещение на последний свободный слот ≤ deadline (DSU для эффективности)
* **Почему работает:** задача с большей прибылью приоритетнее; DSU позволяет за O(α(n)) найти свободный слот
* **Обобщение:** произвольные длительности; штраф как функция от задержки; возврат оптимального подмножества
* **Сложность:** O(n log n) время (сортировка + DSU), O(n) память
* **Реализация:** `job_scheduling_deadlines` (A.3) — общий случай; `job_sequence_with_deadline` — частный случай (все p_i = 1)
* **Связи:** DSU (`struct.md` III) для эффективного поиска свободного слота; Fractional Knapsack (B.5) — аналогичный жадный подход к заполнению

# **B. РАСПРЕДЕЛЕНИЕ РЕСУРСОВ**

## **5. Fractional Knapsack (Жадный)**
* **Определение:** предметы с весами w_i и стоимостями v_i; рюкзак вместимости W; можно брать доли предметов; максимизировать стоимость
* **Жадная стратегия:** сортировка по плотности стоимости (v_i / w_i) → заполняем рюкзак от наиболее плотных предметов
* **Почему оптимален:** для дробного рюкзака жадный выбор оптимален (отличие от 0/1 Knapsack — ДП)
* **Обобщение:** произвольная функция плотности; параметризация предметов через предикат; возврат состава (взятые предметы + доли)
* **Сложность:** O(n log n) время (сортировка), O(n) память
* **Реализация:** `fractional_knapsack` — параметризация предметов
* **Связь:** 0/1 Knapsack (`dynamic.md`) — NP-полная версия;贪да оптимальность для дробного варианта

## **6. Bin Packing**
* **Определение:** предметы размеров s_i; бины ёмкости C; упаковать все предметы в минимальное число бинов
* **Приближённые алгоритмы:**
  * **First Fit:** каждый предмет в первый подходящий бин — O(n log n) (через set) или O(n²) наивно; худший: ≤ 1.7·OPT бинов
  * **Best Fit:** каждый предмет в бин с минимальным оставшимся пространством — O(n log n); худший: ≤ 1.7·OPT
  * **First Fit Decreasing:** сортировка по убыванию размера + First Fit — O(n log n); худший: ≤ 11/9·OPT + 1
* **NP-трудность:** точное решение — NP-трудное (связь `dynamic.md` — полный перебор с отсечениями)
* **Обобщение:** параметр функции выбора бина; произвольная ёмкость бина; возврат распределения предметов по бинам
* **Сложность:** O(n log n) для всех вариантов, O(n) дополнительной памяти
* **Реализация:** `bin_packing_first_fit`, `bin_packing_best_fit`, `bin_packing_first_fit_decreasing`
* **Связь:** Set Cover (V.D) — аналогичная NP-трудная задача с приближениями; First Fit Decreasing — один из лучших приближённых алгоритмов

## **7. Load Balancing (Minimize Makespan)**
* **Определение:** n задач с временем выполнения t_i; m одинаковых машин; распределить задачи для минимизации времени завершения последней задачи (makespan)
* **Жадная стратегия (Longest Processing Time):** сортировка по убыванию времени → каждая следующая задача назначается на наименее загруженную машину
* **Почему LPT:** балансирует нагрузку, минимизируя «голодание» коротких задач на загруженных машинах
* **Обобщение:** произвольное число машин; предикат назначения; функция оценки загрузки; возврат распределения и makespan
* **Сложность:** O(n log n) время (сортировка + куча для m машин), O(m + n) память
* **Реализация:** `load_balancing_makespan` — через min-heap текущих загрузок
* **Связь:** задачи на графах (`graph.md` — назначения); двоичный поиск по ответу (II.B) для проверки可行性 при фиксированном makespan

# **C. ДИСПЕТЧЕРИЗАЦИЯ (ПЛАНИРОВЩИКИ ОС)**

## **8. FCFS (First Come First Served)**
* **Определение:** задачи выполняются в порядке поступления (очередь FIFO)
* **Почему прост:** не требует предварительной сортировки; минимум накладных расходов
* **Проблема:** «convoy effect» — длинная задача блокирует короткие; высокое среднее время ожидания
* **Обобщение:** параметр функции порядка поступления; возврат времени ожидания и turnaround для каждой задачи
* **Сложность:** O(n) время, O(n) память
* **Реализация:** `process_scheduling_sim` с параметром FCFS
* **Связь:** `struct.md` II — очередь FIFO как базовая структура

## **9. SJF (Shortest Job First)**
* **Определение:** задача с наименьшим временем выполнения выполняется первой
* **Варианты:**
  * **Non-preemptive (SJF):** после начала выполнения задача не прерывается
  * **Preemptive (SRTF — Shortest Remaining Time First):** при поступлении новой задачи с меньшим оставшимся временем — прерывание текущей
* **Оптимальность:** SJF оптимален по среднему времени ожидания (доказательство через обмен аргументов)
* **Обобщение:** предикат сравнения задач; параметр preemptive/non-preemptive; возврат полной шкалы выполнения (gantt chart)
* **Сложность:** O(n log n) время (сортировка), O(n) память
* **Реализация:** `process_scheduling_sim` с параметром SJF
* **Связь:**贪да оптимальность — тот же подход, что Interval Scheduling (A.1); SRTF связан с диспетчеризацией Round Robin

## **10. Round Robin**
* **Определение:** каждая задача получает квант времени quantum; по истечении кванта — перемещение в конец очереди
* **Параметры:** размер кванта quantum — ключевой параметр:
  * Малый квант → высокий накладные расходы на переключение, но хорошая отзывчивость
  * Большой квант → деградация к FCFS
* **Почему справедлив:** каждая задача гарантированно получает процессорное время
* **Обобщение:** параметр кванта; предикат приоритета; возврат времени ответа и turnaround для каждой задачи
* **Сложность:** O(n) время (с использованием очереди), O(n) память
* **Реализация:** `process_scheduling_sim` с параметром Round Robin
* **Связь:** `struct.md` II — циклическая очередь; Multilevel Feedback Queue (C.11) — обобщение

## **11. Priority Scheduling**
* **Определение:** каждая задача имеет приоритет; выполняется задача с наивысшим приоритетом
* **Варианты:**
  * **Non-preemptive:** после начала выполнения — до конца
  * **Preemptive:** при поступлении задачи с более высоким приоритетом — прерывание
* **Проблема:** starvation (голодание) задач с низким приоритетом → решение: aging (постепенное повышение приоритета)
* **Обобщение:** произвольная функция приоритета; предикат preemptive/non-preemptive; механизм aging; возврат полной шкалы выполнения
* **Сложность:** O(n log n) время (сортировка или priority queue), O(n) память
* **Реализация:** `process_scheduling_sim` с параметром Priority
* **Связь:** `struct.md` IV — priority queue (куча); Multilevel Feedback Queue (C.11) — многоуровневый приоритет

## **12. Multilevel Feedback Queue**
* **Определение:** несколько очередей с разными квантами и приоритетами; задачи «просачиваются» вниз при превышении лимита
* **Структура:**
  * Очередь уровня i: квант quantum_i, приоритет priority_i
  * Задача, не завершившаяся за quantum_i, перемещается в очередь уровня i+1
  * Новые задачи поступают в очередь уровня 0
  * Задачи в последней очереди — Round Robin
* **Почему эффективен:** автоматическое разделение CPU-bound и I/O-bound задач
* **Обобщение:** параметры количества уровней, квантов, пороговых значений; предикат миграции задач; возврат полной шкалы выполнения
* **Сложность:** O(n · k) время (k — число уровней), O(n + k) память
* **Реализация:** `multilevel_feedback_queue` — симуляция
* **Связь:** Priority Scheduling (C.10) + Round Robin (C.9) — гибрид; `struct.md` — несколько очередей FIFO
