# **A. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ**

## **1. Энтропия Шеннона**
* **Определение:** мера неопределённости случайной величины X с вероятностями p(x):
  `H(X) = −Σ p(x) · log₂ p(x)` (биты на символ)
* **Свойства:**
  * H(X) ≥ 0; H(X) = 0 ⟺ ∃!x: p(x) = 1 (нет неопределённости)
  * H(X) ≤ log₂ |アルファ벳| (равенство при равномерном распределении)
  * Субаддитивность: H(X, Y) ≤ H(X) + H(Y) (равенство ⟺ X, Y независимы)
* **Условная энтропия:** H(X|Y) = H(X, Y) − H(Y) — неопределённость X при известном Y
* **Взаимная информация:** I(X; Y) = H(X) − H(X|Y) = H(Y) − H(Y|X)
* **Почему важно для сжатия:** энтропия — нижняя граница средней длины кода; невозможно сжать данные до < H(X) бит на символ (первая теорема Шеннона)

## **2. Пределы сжатия**
* **Первая теорема Шеннона (source coding theorem):** существует префиксный код с длиной кода L(x) такой, что H(X) ≤ L̄ < H(X) + 1
* **Вторая теорема Шеннона:** при блочном кодировании блоков длины n средняя длина на символ стремится к H(X) при n → ∞
* **Размер сжатого файла:** ≥ N · H(X) бит, где N — число символов; реальные алгоритмыachievable: O(N · H(X) + overhead)
* **Коэффициент сжатия:** CR = (размер_оригинал) / (размер_сжатый); CR ≤ 8 / H(X) для байтовых данных

### **2a. Метрики эффективности сжатия**
* **PSNR (Peak Signal to Noise Ratio):** метрика качества для сжатия с потерями
  * `PSNR = 10 · log₁₀(MAX² / MSE)`, где MAX — макс. значение пикселя (255 для 8-bit), MSE = (1/N)·Σ(xᵢ − x̂ᵢ)²
  * Типичные значения: >40 dB — отличное качество, 30–40 dB — хорошее, <30 dB — заметные артефакты
  * Используется для JPEG, MP4, WebP; не完美 коррелирует с субъективным качеством (SSIM лучше)
* **bpp (bits per pixel):** среднее число бит на пиксель в сжатом изображении
  * `bpp = (размер_файла_в_битах) / (ширина × высота)`
  * Связь с PSNR: R(D) theory → bpp ↑ = PSNR ↑ (при фиксированном методе)
  * Примеры: JPEG高质量 ~1.0–2.0 bpp; WebP lossy ~0.5–1.5 bpp; lossless PNG ~4–8 bpp

## **3. Rate-Distortion Theory**
* **Определение:** компромисс между bitrate R и distortion D при сжатии с потерями
* **Функция rate-distortion:** R(D) = min_{Q: E[d(X,X̂)] ≤ D} I(X; X̂) — минимальный битрейт при допустимом искажении
* **Квадратичное искажение:** d(x, x̂) = (x − x̂)² — основа для JPEG, MP3
* **Битрейт-распределение:** выделение бит «важным» компонентам (коэффициентам DCT, частотам)
* **Применение:** JPEG — R(D) для DCT-коэффициентов; MP3 — R(D) для心理声ических моделей

## **4. Энтропийные модели**
* **Статическая модель:** вероятности p(x) известны заранее (или оценены по корпусу) → фиксированный код
* **Адаптивная модель:** вероятности обновляются по мере чтения данных → переменный код, лучше для нестационарных данных
* **Контекстная модель:** p(x | контекст) — вероятность зависит от предыдущих символов → LZMA, ZPAQ
* **Связь:** адаптивный Хаффман (Vitter), арифметическое кодирование с моделью

# **B. СЖАТИЕ БЕЗ ПОТЕРЬ**

## **5. RLE (Run-Length Encoding)**
* **Определение:** замена повторяющихся последовательностей (runs) на пары (символ, длина)
* **Формат:** (символ₁, длина₁), (символ₂, длина₂), ...
* **Когда эффективно:** данные с длинными runs (растровые изображения, факс, DNA-последовательности)
* **Когда неэффективно:** данные без повторов → расширение (каждый символ → пара)
* **Варианты:**
  * **RLE0:** подсчёт нулей (сжатие разреженных данных)
  * **RLE с escape-символом:** для обработки runs длины 1
* **Сложность:** O(n) время, O(n) худшее памяти (при отсутствии повторов)

## **6. Хаффман (Huffman Coding)**
* **Определение:** префиксный код с оптимальной средней длиной для известных вероятностей
* **Алгоритм построения:**
  1. Создать листья для каждого символа с весом p(x)
  2. Итеративно: объединить два узла с минимальными весами в новый (вес = сумма)
  3. Ребра: левое — 0, правое — 1; код символа — путь от корня к листу
* **Оптимальность:** L̄ = Σ p(x) · L(x) минимален среди всех префиксных кодов
* **Свойства:**
  * Длины кодов: L(x) = ⌈−log₂ p(x)⌉ (приблизительно)
  * H(X) ≤ L̄ < H(X) + 1
  * Не более одного узла с нечётным весом (при нечётном числе символов)
* **Адаптивный Хаффман:** обновление дерева при каждом символе (алгоритм Виттера / Кнута)
  * Без предварительного прохода: дерево строится динамически при кодировании/декодировании
  * Нумерация узлов по схеме sibling property: каждый узел пронумерован, номера возрастают от корня к листьям
  * При новом символе: создаётся новый лист + новый внутренний узел; дерево перестраивается swaps
  * Преимущество: один проход, не нужен буфер частот; адаптируется к локальным статистикам
  * Сложность: O(n) амортизировано на символ (O(1) на шаг + O(log n) на swap)
* **Коды Голомба и Райса:**
  * Оптимальны для геометрического распределения P(X=k) = (1−p)^k · p (обрезанное экспоненциальное)
  * **Голомб:** число q = ⌊x/m⌋ кодируется unary (q единиц + 0), остаток r = x mod m — бинарно (log₂m бит или ⌈log₂m⌉)
  * Параметр m подбирается: m ≈ −1/ln(p) для геометрического распределения с параметром p
  * **Райс (специальный случай):** m = 2^k — остаток кодируется ровно k битами (быстрее)
  * Применение: FLAC (аудио), JPEG lossless, медицинские изображения
  * Средняя длина: H(X) + O(1) при оптимальном m
* **Сложность:** O(n log n) построение (через min-heap), O(n) декодирование

## **7. Арифметическое кодирование**
* **Определение:** кодирование целого сообщения в одно дробное число из [0, 1)
* **Идея:** каждому сообщению соответствует интервал длиной ∏ p(xᵢ); чем длиннее сообщение, тем меньше интервал → больше бит
* **Алгоритм:**
  1. Интервал [low, high) = [0, 1)
  2. Для каждого символа: сузить интервал пропорционально p(x)
  3. Выход: любое число из финального интервала
* **Преимущество перед Хаффманом:** нет ограничения целочисленными длинами кодов → эффективнее на 5–15%
* **Реализация:** целочисленная арифметика (128-bit или 64-bit аккумулятор)
* **Связь:** основа для LZMA, ZPAQ, modern image codecs

## **8. LZ77 (Lempel-Ziv 1977)**
* **Определение:** словарь — скользящее окно; кодирование: (смещение, длина, следующий символ)
* **Формат:** тройки (offset, length, next_char)
  * offset: расстояние до начала совпадения в окне
  * length: длина совпадения
  * next_char: символ после совпадения (для случаев без совпадения)
* **Параметры:**
  * Размер окна W: определяет максимальный offset
  * Размер буфера lookahead L: максимальная длина совпадения
* **Оптимизация:**贪心 — ищем максимально длинное совпадение в окне
* **Сложность:** O(n·W) наивный, O(n·log W) с суффиксным массивом, O(n) с хешированием

## **9. LZ78 / LZSS / LZW**
* **LZ78:** словарь — дерево фраз; кодирование: (индекс в дереве, новый символ)
  * Словарь: корень = пустая фраза; каждый узел — (родительский_индекс, символ)
  * Алгоритм: ищем longest match в дереве → выводим (parent_index, next_char) → добавляем новую фразу
  * Преимущество: не нужен размер окна; недостаток: дерево может вырасти → нужен сброс при переполнении
  * Сложность: O(n·√n) наивный поиск, O(n·log n) с хешированием
* **LZSS (Lempel-Ziv-Storer-Szymanski):** улучшение LZ77
  * Отличие от LZ77: нет next_char — только (offset, length); битовый флаг: 1 = совпадение, 0 =_literal
  * Формат: [flag][offset|literal][length|literal]... — компактнее LZ77
  * Используется в: PNG (как часть DEFLATE), ARJ, LHA
  * Эффективность: ~5–10% лучше LZ77 за счёт отсутствия next_char
* **LZW (Lempel-Ziv-Welch):** улучшенный LZ78 с фиксированной шириной кода
  * Словарь инициализируется всеми символами алфавита (0..255)
  * Алгоритм: ищем максимальное совпадение → выводим индекс → добавляем новую фразу (match + next_char)
  * Коды: фиксированной ширины (9–12 бит) → легко декодировать; для адаптации — сброс словаря
  * Используется в: GIF, TIFF, PDF
  * Сложность: O(n) время, O(2^K) память (K — макс. ширина кода в битах)

## **10. BWT (Burrows-Wheeler Transform)**
* **Определение:** перестановка, группирующая похожие символы (улучшает сжимаемость RLE/MTF)
* **Алгоритм:**
  1. Построить все циклические сдвиги строки
  2. Отсортировать их лексикографически
  3. BWT-строка = последний столбец отсортированной матрицы
  4. Выход: (BWT-строка, индекс первоначальной строки в матрице)
* **Обратное преобразование:** использует first-to-last mapping (LF-mapping)
  1. Построить первый столбец (сортировка BWT)
  2. Итеративно: next = T[last[i]] → восстановление строки
* **Свойства:** не изменяет энтропию; группирует повторяющиеся символы → RLE/MTF работают лучше
* **Связь:** суффиксные массивы (`string.md`) — основа эффективного BWT

## **11. MTF (Move-to-Front Transform)**
* **Определение:** замена каждого символа его индексом в текущем списке символов
* **Алгоритм:**
  1. Инициализировать список L = [0, 1, 2, ..., alphabet_size − 1]
  2. Для каждого символа x: вывести позицию pos(x) в L → переместить x в начало L
* **Эффект:** после BWT повторяющиеся символы → нули и малые числа → хорошо сжимается Хаффманом/арифметикой
* **Обратное преобразование:** зная индекс pos → символ = L[pos] → переместить символ в начало

## **12. Delta Encoding**
* **Определение:** кодирование разностей между последовательными элементами
* **Формула:** δ[i] = x[i] − x[i−1] (для отсортированных данных)
* **Применение:** временные ряды, географические координаты, версии файлов
* **Варианты:**
  * **Delta of sorted:** для возрастающих последовательностей → малые положительные числа
  * **Delta-encoding с RLE:** для gần грубо равномерных данных
* **Связь:** Coordinate Compression (D.15), BWT+MTF (B.10–B.11)

## **12. Сжатие как инструмент в задачах (олимпиадный паттерн)**
* **Паттерн:** если данные имеют структуру повторов/паттернов → RLE-encoding перед обработкой
* **Пример:** задачи на строках — сжатие runs → линейная обработка → декодирование
* **Координатное сжатие (D.15):** Fenwick/Segment tree требуют индексы в [0, N); координаты до 10⁹ → сжать

## **13. Битовые операции в кодировании (олимпиадный паттерн)**
* **Паттерн:** выделение бит из потока, запись бит в поток — основа для всех энтропийных кодеров
* **Реализация:** буфер-аккумулятор (обычно 32/64 бита) + сдвиги
* **Связь:** BitWriter/BitReader в d/cpp

# **C. СЖАТИЕ С ПОТЕРЯМИ**

## **13. JPEG (DCT-сжатие)**
* **Этапы:**
  1. Цветовое пространство YCbCr (отделяем яркость от цветности)
  2. Разбиение на блоки 8×8
  3. DCT-II (Discrete Cosine Transform): перевод в частотную область
  4. Квантование: деление на матрицу квантования Q (теряются высокие частоты)
  5. Зигзаг-сканирование → RLE + Хаффман
* **Параметры качества:** масштаб матрицы Q; качество 1–100
* **Сжатие яркости vs цветности:** человек хуже различает цвет →Cb/Cr квантование грубее (4:2:0)
* **Сложность:** O(n) по пикселям, O(1) на блок 8×8

## **14. JPEG 2000 (Wavelet)**
* **Отличие от JPEG:** вместо DCT — вейвлет-преобразование (DWT,typically CDF 5/3 или 9/7)
* **Преимущества:**
  * Нет артефактов 8×8 блоков
  * Масштабируемость (progressive decode)
  * РOI (Region of Interest) — сжатие области с лучшим качеством
* **Квантование:** эмбеддед量化 + arithmetic coding (EBCOT)
* **Применение:** цифровое кино (DCI),医学ская визуализация, спутниковые снимки

## **15. WebP**
* **Формат:** VP8 (видео) + предсказание блоков + Хаффман/арифметика
* **Режимы:**
  * Lossy: предсказание блоков 4×4 + DCT + квантование (аналогично H.264 intra)
  * Lossless: вейвлет-преобразование +的空间预测 + энтропийное кодирование
* **Эффективность:** на 25–35% меньше JPEG при comparable качестве

## **16. MP3/AAC/Opus (аудио)**
* **Общая схема:**
  1. Разложение на фреймы (окна)
  2. Преобразование в частотную область (MDCT для MP3/AAC, MDCT+STFT для Opus)
  3. Психоакустическая модель: маскировка → удаление «не слышимых» компонент
  4. Квантование + энтропийное кодирование (Huffman in MP3/AAC, arithmetic in Opus)
* **MP3:** MDCT 36/12 полос, Huffman, CBR/VBR
* **AAC:** MDCT 1024 полосы, более совершенная psychoacoustic model, TNS, PNS
* **Opus:** гибрид SILK (нижние частоты) + CELT (высокие), adaptive bitrate, lowest latency

## **17. H.264/H.265/AV1 (видео)**
* **Общая архитектура:**
  * Intra-кадры: предсказание блоков (空间prediction)
  * Inter-кадры: движение компенсация (motion estimation + residual)
  * Остаток → DCT/integer transform → квантование → энтропийное кодирование
* **H.264 (AVC):** блоки до 16×16, 9 режимов intra-prediction, CABAC/CAVLC
* **H.265 (HEVC):** блоки до 64×64 (CTU), 35 intra-режимов, 更好的 motion vectors
* **AV1:** блоки до 128×128, 56 intra-режимов, без лицензионных отчислений (Royalty-Free)
* **Сжатие:** H.265/AV1 в ~50% битрейта от H.264 при comparable качестве

# **D. СПЕЦИАЛИЗИРОВАННЫЕ МЕТОДЫ**

## **18. Coordinate Compression**
* **Определение:** замена координат на их ранги (порядковые номера в отсортированном списке)
* **Алгоритм:**
  1. Собрать все координаты → отсортировать → уникальные
  2. Заменить каждую координату на её индекс (0-based) в уникальном отсортированном списке
* **Зачем:** координаты до ~10⁹, но после сжатия — до ~10⁵ → помещаются в массив
* **Применение:**
  * Fenwick tree / segment tree (`struct.md` V): индексы должны быть в [0, n)
  * Геометрические задачи: sweep line с отрезками
  * Задачи на строках: замена символов на ранги
* **Связь:** Counting Sort (I.C.7), Fenwick tree (`struct.md` V)

## **19. Сжатие графов (теория)**
* **WebGraph:** графы веб-страниц ( billions рёбер):
  * references[] — массив out-degree-списков
  * BWT + MTF + Gamma-кодирование ссылок
  * Эффективность: ~3–4 бит на ребро
* **K²-деревья:**
  * Представление разреженных бинарных матриц (adjacency matrix)
  * Рекурсивное разбиение на блоки 2×2 → дерево
  * Запросы: existence(u,v), out-neighbors(u) за O(degree)
* **Compressed Sparse Row (CSR):**
  * values[] + row_ptr[] + col_ind[] — стандартное сжатие разреженных матриц
  * Эффективность: O(nnz) памяти (nnz — число ненулевых)
* **ELIAS-FANO кодирование:**
  * Сжатие возрастающих последовательностей (row_ptr в CSR)
  * Верхние биты → unary, нижние биты → binary
  * Память: 2 + o(1) бит на элемент + min(max_value, n·log₂(n/max_value))

## **19a. Дискретизация данных**
* **Равномерная дискретизация:**
  * Диапазон значений [min, max] разбивается на K равных интервалов (бинов)
  * Каждое значение заменяется на номер бина: `bin = ⌊(x − min) / (max − min) · K⌋`
  * Квантованные значения кодируются целыми числами (log₂K бит на значение)
  * Используется в: гистограммы, кластеризация, предобработка для сжатия
* **Квантование по значимости:**
  * Значимость определяется вкладом в общую дисперсию (или энтропию)
  * Важные значения → мелкое квантование (высокая точность); малозначимые → грубое
  * Пример:JPEG — квантование DCT-коэффициентов; низкочастотные коэффициенты важнее → Q[0][0] < Q[7][7]
  * Rate-distortion: распределение бит пропорционально вкладу компонента в R(D)
* **Адаптивная дискретизация:**
  * Количество бинов адаптируется к локальной статистике данных
  * В участках с высокой энтропией → больше бинов (точнее); в однородных → меньше
  * Пример: ADPCM (audio) — размер шага квантования зависит от предыдущих значений
  * Преимущество: лучше R(D) при фиксированном bitrate, чем равномерная

## **19b. Сжатие баз данных**
* **Dictionary compression:**
  * Замена повторяющихся значений (столбцов, строк) на ID из словаря (integer references)
  * Словарь: уникальные значения → целочисленные ID (0, 1, 2, ...)
  * Эффективность: O(n) хранение вместо O(n·L) (L — длина строки); декодирование — lookup по ID
  * Применение: column stores (ClickHouse, Vertica), строковые столбцы в реляционных БД
* **Bit-packing:**
  * Упаковка целых чисел в биты без выравнивания: если max(value) = 15, то 4 бита на число (вместо 32)
  * Формула: размер = n · ⌈log₂(max_value + 1)⌉ бит
  * Преимущество: экономия памяти в 2–8× для малых целых; простая реализация (битовые сдвиги)
  * Недостаток: случайный доступ требует деления; не SIMD-дружелюбен
* **Frame Of Reference (FOR):**
  * Блок данных разбивается на фреймы (страницы); в каждом фрейме — свой базовый адрес (min)
  * Значения хранятся как смещения от базы: `offset = value − base` → малые числа → bit-packing
  * Формула: размер_фрейма = base (полный тип) + n · ⌈log₂(max_offset + 1)⌉ бит
  * Преимущество:很好 для возрастающих данных (incremental); FOR + delta encoding → very compact
  * Используется в: ColumnIO (Google), Parquet,orc

# **E. ГИБРИДНЫЕ МЕТОДЫ**

## **20. DEFLATE = LZ77 + Хаффман**
* **Используется в:** gzip, zip, PNG
* **Этапы:**
  1. LZ77: поиск совпадений в окне 32K → тройки (offset, length)
  2. Разбиение: literals + lengths + offsets → три отдельных потока
  3. Хаффман: динамический (пересылается в заголовке) или статический
* **Блоки:** каждое сообщение → серия блоков; блок может быть uncompressed, static или dynamic
* **Эффективность:** ~2–3× сжатие для текста; ~1.5× для смешанных данных

## **21. BZip2 = BWT + MTF + RLE + Хаффман**
* **Этапы:**
  1. BWT: группировка похожих символов
  2. MTF: замена на индексы в списке → малые числа, много нулей
  3. RLE0 (run-length encoding нулей): группы нулей → (длина, бит)
  4. Хаффман: энтропийное кодирование
* **Блок:** 100–900K символов; BWT оптимален для блоков ~600K
* **Эффективность:** ~20–30% лучше gzip для текста; медленнее (BWT — O(n log n))

## **22. LZMA = LZ77 + арифметическое**
* **Используется в:** 7z, xz
* **Отличия от DEFLATE:**
  * Словарь LZ77: до 4 GiB (vs 32K в DEFLATE)
  * Арифметическое кодирование вместо Хаффмана → ~5–15% лучше
  * Контекстная модель: вероятности зависят от контекста (предыдущих байтов)
  * LZMA2: параллелизация, улучшенная модель
* **Этапы:**
  1. LZ77: длинные совпадения в большом словаре
  2. Literal/Length/Distance → три контекстных модели
  3. Арифметическое кодирование с range coder
* **Эффективность:** ~50–70% лучше gzip для текста; ~30–40% лучше DEFLATE

## **22a. Адаптивные методы**
* **PPM (Prediction by Partial Matching):**
  * Контекстная модель: P(x | контекст) оценивается по вхождениям контекста в корпусе
  * Алгоритм: для каждого символа ищем longest match контекста → эскейп на более короткий контекст → uniform
  * Кодирование: арифметическое (с моделью PPM) или Хаффман
  * PPM variants: PPMd (discrete), PPMz (adaptive escape), PPMII (оба)
  * Эффективность: ~2.0–2.5 бит/символ для текста (лучше LZMA); используется в: zpaq, бенчмарки сжатия
* **PAQ (Prediction by Arithmetical coding with Quantization):**
  * ансамбль нейросетевых предикторов: каждый предиктор — простая модель (.context tree, neural net)
  * Взвешенное голосование: P(x) = Σ wᵢ · Pᵢ(x); веса обновляются online (logistic regression)
  * PAQ8/PAQ9/PAQ10: до 80+ предикторов; лучшее сжатие, но O(n²) в худшем случае
  * Используется в: zpaq (open source), бенчмарки (silesia, calgary corpus)
* **Dynamic Markov Compression (DMC):**
  * Строит.context tree по мере чтения: каждый узел — статистика 0/1 после данного контекста
  * Алгоритм: текущий контекст → вероятность следующего бита → арифметическое кодирование
  * Преимущество:在线 адаптация, хорош для бинарных данных
  * Сложность: O(n · state_size) время; state_size растёт ( clipping нужен)

## **22b. Преобразования и анализ**
* **Wavelet transforms (DWT):**
  * Разложение сигнала на вейвлет-компоненты:低频 (аппроксимация) + высокочастотные детали
  * Фильтры: Haar (простой), Daubechies (гладкие), CDF 5/3 (lossless), CDF 9/7 (lossy)
  * Иерархия: аппроксимация → детали → детали деталей... (multi-resolution analysis)
  * Преимущество: локализация во времени и частоте (в отличие от Fourier)
  * Используется в: JPEG 2000, Denoising, фрактальное сжатие
* **Fourier transforms (DFT/FFT):**
  * Разложение на гармоники: X[k] = Σ x[n] · e^(−2πi·kn/N)
  * FFT: быстрое вычисление O(N log N) вместо O(N²)
  * Применение: анализ спектра, фильтрация, сжатие (丢弃 высокочастотных компонент)
  * Недостаток: глобальное разложение (нет локализации во времени) → windowed FFT (STFT)
* **Karhunen-Loève transform (KLT / PCA):**
  * Оптимальное линейное преобразование для минимизации среднеквадратичной ошибки
  * Матрица преобразования: собственные векторы ковариационной матрицы данных
  * После KLT: компоненты некоррелированные; первые K компонент → основная часть энергии
  * Применение: image compression (аналог DCT, но data-dependent), face recognition (Eigenfaces)
  * Недостаток: требует знания ковариационной матрицы (статический) →不适合在线 сжатие

# **F. Практические применения и форматы**

## **26. Архиваторы**
* **ZIP (DEFLATE):**
  * Формат: серия блоков; блок = header + compressed data + checksum
  * DEFLATE = LZ77 (окно 32K) + dynamic/static Huffman; уровни 1–9 (скорость vs сжатие)
  * Опции: шифрование (AES-256 в ZIP 2.0), спанNING (тома), UTF-8 filenames
  * Скорость: быстрое (100–500 MB/s); сжатие: ~2.5–3× для текста
* **7-Zip (LZMA/LZMA2):**
  * LZMA: словарь до 4 GiB, арифметическое кодирование, контекстная модель
  * LZMA2: параллелизация (до 8 потоков), улучшенная модель, без ограничения dictionary size
  * Формат: 7z (сжатие) или xz (только сжатие); опции: шифрование (AES-256), солид-архив
  * Сжатие: ~30–50% лучше DEFLATE для текста; медленнее (50–200 MB/s)
* **RAR:**
  * Проприетарный формат; лучшее сжатие чем ZIP, но не open source (только чтение)
  * Методы: RAR3 (LZ + Huffman + арифметика), RAR4+ ( LZ + оптимизированный Huff)
  * Функции: Recovery records,olid volumes, AES-256
* **tar.gz (tar + gzip):**
  * tar: объединение файлов в один поток (без сжатия); gzip: DEFLATE поверх tar-потока
  * Преимущество: простота, совместимость; tar.gz — стандарт Linux-дистрибутивов
  * Недостаток: нет солид-сжатия (каждый файл отдельно), нет шифрования

## **27. Форматы файлов**
* **PNG (Portable Network Graphics):**
  * Lossless: фильтры (Sub, Up, Average, Paeth) → DEFLATE (LZ77 + Huffman)
  * Фильтры: предсказание пикселей → остатки лучше сжимаются DEFLATE
  * Interlace: Adam7 — progressive отображение; ANC: анимация + альфа-канал
  * Сжатие: ~1.5–3× для фоторо, ~5–10× для графики с плоскими областями
* **GIF (Graphics Interchange Format):**
  * LZW: индексированная палитра (до 256 цветов) → LZW-сжатие индексов
  * Анимация: серия кадров с задержкой; disposal methods (что делать с предыдущим кадром)
  * Ограничения: 8 бит/пиксель; не適合 для фотографий (качество низкое)
* **PDF (Portable Document Format):**
  * Содержимое: векторная графика (команды рисования), текст (шрифты), изображения (JPEG/PNG/CCITT)
  * Сжатие: FlateDecode (DEFLATE), LZWDecode, DCTDecode (JPEG), JPXDecode (JPEG 2000)
  * Структура: объекты (obj → stream); перекрёстные ссылки (xref); файл может быть Incremental
* **MP4 (MPEG-4 Part 14):**
  * Контейнер: H.264/H.265 (видео) + AAC/Opus (аудио) + субтитры
  * Структура: atoms (boxes) → trak (видео/аудио дорожки) + moov (метаданные)
  * Сжатие:depends на codecs; H.264 ~100–500 MB/час (1080p), H.265 ~50–250 MB/час
  * Применение: стриминг (HLS/DASH), хранение, запись видео

## **28. Системы хранения**
* **Deduplication:**
  * Обнаружение и удаление дубликатов блоков данных; замена на указатель (reference)
  * Фиксированные блоки: простые, но border problem; переменные (content-defined): Rabin hash → fingerprint
  * Формула: ratio = (original size) / (unique blocks + references)
  * Применение: backup systems (Veeam, NetApp), storage arrays, cloud storage
* **Compressed file systems:**
  *透明ное сжатие на уровне ФС:透明ное сжатие на уровне ФС:Transparent Compression: ZFS (LZ4/ZSTD), Btrfs (zstd/LZO), NTFS (compact)
  * Блок-уровень: сжимаются отдельные блоки (4K–128K); random access сохраняется
  * Преимущество: экономия места без изменения приложений; недостаток: CPU overhead
* **Database compression:**
  * Табличные: словари для строк (Dictionary), bit-packing для целых, FOR для возрастающих
  * Колоночные: column-group compression, run-length + dictionary combo (ClickHouse)
  * Page-level: сжатие страниц (InnoDB: key-value compression; RocksDB: zstd на block cache)
  * Trade-off: CPU на сжатие/декодирование vs экономия I/O и памяти

# **G. Алгоритмические оптимизации**

## **29. Хеширование и суффиксы**
* **Rolling hash:**
  * Хеш окна [i..i+W-1] вычисляется из хеша [i-1..i+W-2] за O(1): `h = (h − a[i]·p^(W-1))·p + a[i+W]`
  * Используется в: Rabin-Karp (поиск подстроки), content-defined chunking (deduplication)
  * Параметры: p (простое число), mod (большое простое) — для минимизации коллизий
* **Suffix arrays (суффиксные массивы):**
  * Отсортированный массив всех суффиксов строки; SA[i] — начало i-го суффикса
  * Построение: O(n log²n) наивный, O(n log n) с doubling, O(n) — SA-IS (Nanakoe)
  * LCP-массив: длина наибольшего общего префикса соседних суффиксов → O(n) для поиска подстрок
  * Применение: BWT (сортировка циклических сдвигов), поиск подстрок, сжатие (bzip2)
* **Hash chains:**
  * Цепочки хешей: h₀ = seed; hₖ = f(hₖ₋₁, dataₖ) — для построения цепочек совпадений
  * Используется в: hash chains (спич-чекер), password cracking (rainbow tables)
  * В сжатии: построение цепочек совпадений для LZ77 (замена полного перебора)

## **30. Структуры данных для сжатия**
* **Circular buffers:**
  * Кольцевой буфер: фиксированный размер W; запись по модулю W → старые данные перезаписываются
  * Используется в: LZ77 sliding window, streaming compression (zlib)
  * Преимущество: O(1) на запись, O(1) на доступ по offset; память = O(W)
* **Priority queues:**
  * Мин-куча: O(log n) на вставку/извлечение минимума → основа для Хаффмана (build tree)
  * Fibonacci heap: O(1) amortized decrease-key → лучше для алгоритмов с частыми decrease (Дейкстра)
  * Pairing heap: проще, быстрее на практике; используется в std::priority_queue (C++)
* **Tries ( префиксные деревья):**
  * Бинарное дерево: каждый узел — 0/1ветвь; строка — путь от корня к листу
  * Compact tries (Patricia/Radix): сжатие цепочек с единственным ребёнком → O(n) память
  * Применение: LZ78 словарь, поиск подстрок, словари сжатия (dictionary compression)

## **31. Аппаратные оптимизации**
* **SIMD оптимизации:**
  * Несколько данных за одну инструкцию: SSE (128-bit), AVX (256-bit), AVX-512 (512-bit)
  * Применение в сжатии: LZ4 (поиск совпадений), Zstd (контекстные модели), Brotli (hash chains)
  * Пример: SIMD для поиска совпадений — 16 байтов за инструкцию (SSE2: _mm_cmpeq_epi8)
  * Недостаток: сложная отладка; разные SIMD-инструкции на разных CPU (portability issues)
* **Многопоточное сжатие:**
  * Parallel DEFLATE: разбиение на независимые блоки → параллельное сжатие → multithread inflate
  * LZ77: разделение окна между потоками (threaded LZ77); sync между потоками → overhead
  * BWT: multikey quicksort параллельно; suffix array construction O(n/p) с p потоками
  * Frame-level: каждый frame/superblock сжимается отдельно (Brotli, Zstd, ZPAQ)
* **GPU ускорение:**
  * Параллельное сжатие: каждый поток GPU обрабатывает один блок → massive parallelism
  * Применение: gzip на GPU (cuZlib), LZ4 на GPU, Huffman на CUDA
  * Ограничения: передача данных CPU↔GPU (PCIe overhead);不适合 для маленьких файлов
  * Перспектива: dedicated compression chips (FPGA/ASIC) для storage systems

# **H. Теоретические границы и сложность**

## **32. Теорема Шеннона и пределы**
* **Первая теорема Шеннона (source coding):**
  * Существует префиксный код с средней длиной L̄: H(X) ≤ L̄ < H(X) + 1
  * Это граница: невозможно средней длины < H(X) (для стационарного источника)
  * Для блочного кодирования: L̄_n → H(X) при n → ∞ (вторая теорема)
* **Rate-distortion theory:**
  * R(D) = min_{Q: E[d(X,X̂)] ≤ D} I(X; X̂) — минимальный битрейт при допустимом искажении D
  * Для квадратичного искажения: R(D) = ½ · log₂(σ²/D) — теоретический предел для Gaussian sources
  * Применение: JPEG/MP3/MP4 — оптимальное распределение бит между компонентами
  * В сжатии с потерями: баланс между размером файла и качеством (PSNR/bpp)
* **Энтропийные модели и пределы:**
  * Для нестационарных источников: локальная энтропия Hₙ(x) = −(1/n)·log P(x₁..xₙ)
  * SLLN: Hₙ → H (асимптотическая энтропия) при n → ∞ для эргодических источников
  * Практический предел: современные алгоритмы (PPM, ZPAQ) достижимы в 1.0–1.5× от H(X)

## **33. Сложность алгоритмов сжатия**
* **Хаффман:**
  * Построение: O(n log n) через min-heap (priority queue); n — число символов
  * Кодирование: O(n) (символы → биты); декодирование: O(L) (L — длина закодированной строки)
  * Адаптивный Хаффман (Vitter): O(n) амортизировано на символ
* **LZ77:**
  * Наивный: O(n·W) (перебор в окне); с хешем: O(n·L) (L — lookahead); с suffix array: O(n·log W)
  * DEFLATE: O(n·W) → практике 100–500 MB/s
* **BWT:**
  * Построение: O(n log n) (сортировка суффиксов/циклических сдвигов)
  * Суффиксные массивы: O(n log n) (double), O(n) (SA-IS) → BWT за O(n)
  * Обратное преобразование: O(n) (LF-mapping)
* **Арифметическое кодирование:**
  * O(n) на символ (один проход); точность: 64-bit аккумулятор → O(1) на символ
* **PPM/PAQ:**
  * PPMd: O(n · K) (K — макс. длина контекста); PAQ: O(n · P) (P — число предикторов)
  * В худшем случае: PAQ ~O(n²) (при растущей модели); практике: O(n·log n)

# **I. Современные тенденции**

## **34. Нейросетевые методы**
* **Autoencoders:**
  * Encoder: вход → компактное представление (latent space); Decoder: latent → реконструкция
  * Variational Autoencoders (VAE): latent space — распределение (μ, σ) → генерация + сжатие
  * Применение: image compression (0.15–0.5 bpp при PSNR 30–36 dB), video (H.266/VVC vs learned)
  * Недостаток: медленные (inference через нейросеть),不适合 для real-time; плохо для lossless
* **Generative models:**
  * GAN-based compression: генератор → сжатое представление; дискриминатор → оценка качества
  * Diffusion models: итеративная денойзинг-процедура → сжатие через latent diffusion
  * Преимущество: perceptual quality лучше PSNR (SSIM/LPIPS); адаптация к стилю данных
  * Перспектива: real-time learned codecs (NVIDIA, Google Research)
* **Differentiable compression:**
  * Энд-обучаемые пайплайны: кодирование → квантование → энтропийное кодирование — всё differentiable
  * Пример: Entropy Bottleneck (Balle) — обучение энтропийной модели совместно с encoder/decoder
  * Результаты: соревнование с VVC/H.266 наบาง benchmarks; Lossless: конкурентоспособны

## **35. Специализированные методы**
* **Genomic data compression:**
  * Геномные последовательности: ACGT (4 символа); высокая энтропия ~2 бит/символ
  * Методы:reference-based (CRAM: разница от референсного генома), dictionary (GenCompress)
  * Специфика: длинные повторы ( tandem repeats), структуры (inversions, translocations)
  * Форматы: CRAM (ref-based), gZ (general purpose), DELIMINATE (reference-free)
* **Time series compression:**
  * Временные ряды: корреляция между последовательными значениями → delta encoding + RLE
  * Методы: Gorilla (Facebook): XOR + leading zeros + trailing zeros → bit-packing
  * Compressed Time Series: delta-of-delta, exponential encoding, dictionary для меток
  * Применение: мониторинг (Prometheus), IoT, financial data; сжатие ~10–20×
* **3D model compression:**
  * Меш: вершины + треугольники; сжатие: quantization + entropy coding (Draco, Open3DGC)
  * Point clouds: octree + quantization; compression ~100–1000× (vs raw XYZ)
  * Нейросетевые: NeRF (neural radiance fields) → сжатие 3D-сцен через нейросеть (~100× vs point cloud)
  * Применение: VR/AR, autonomous vehicles, digital twins

## **36. Аппаратные средства**
* **Dedicated compression chips:**
  * ASIC для сжатия: высокопроизводительные (10+ GB/s) с низким энергопотреблением
  * Примеры: Intel QAT (QuickAssist Technology), Broadcom Stingray, Marvell LiquidIO
  * Поддерживают: LZ4, ZSTD, DEFLATE, GZIP, IPsec (ciphertext compression)
* **FPGA:**
  * Программируемая логика: конфигурируемый пайплайн сжатия; низкая задержка (μs)
  * Применение: HFT (high-frequency trading), network compression (TCP/IP), storage acceleration
  * Преимущество: энергоэффективность (vs GPU/CPU); гибкость (обновление прошивки)
* **Hardware video encoders:**
  * Видео-кодеки в silicon: NVENC (NVIDIA), Quick Sync (Intel), VCE (AMD), Apple VideoToolbox
  * Встраиваемые: H.264/H.265 encoding на уровне GPU → offload CPU; скорость 100+ fps
  * Ограничения: качество ~5–10% хуже программных (x264/x265); но скорость в 10–100× выше
  * Направление: AV1 hardware encoding (NVIDIA Ada, Intel Arc, AMD RDNA3)
