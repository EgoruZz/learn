# **VI. ТЕОРИЯ ИГР**

> **Архитектура:** `GameTheory` (f.cpp) — класс ветки technique, наследует `GreedyAlgorithms` (e.cpp). Переиспользует: сортировки из I (для предобработки позиций); двоичный поиск из II (для бинарного поиска по ответу в играх); жадные алгоритмы из V (для оценки ветвления); ДП из `dynamic.md` (стоимость позиций, MDP); графы из `graph.md` (игры на графах, циклы). Класс закладывает фундамент для комбинаторной теории игр (Ним, Гранди), деревьев принятия решений (Minimax, Alpha-Beta), и вероятностных игр (Expectiminimax, Q-learning). Собственной арифметики не имеет — использует XOR для nim-sum, std::function для параметризации переходов и оценок.
>
> **Связи:** функция Гранди связана с ДП (`dynamic.md` — рекуррентность на DAG); Minimax и Alpha-Beta связаны с поиском на графах (`graph.md`); A*/IDA* переиспользуются из II.F (метаэвристики); MCTS использует вероятностный анализ (`probability.md`); Пятнашки (15-puzzle) связаны с эвристиками расстояния (`graph.md`); Wythoff's game — комбинаторная задача с вещественным анализом (黄金比例 φ).
>
> **Олимпиадные паттерны:**
> * **XOR-стратегия:** задача сводится к Nim → вычислить XOR → проверить ≠ 0 (задачи с кучами, игры с ограничениями на ход, мосты и острова).
> * **Гранди для составных игр:** игра разбивается на независимые компоненты → каждая оценивается через G → общий результат — XOR (игра на нескольких досках, комбинация Nim с другими играми).
> * **Minimax + Alpha-Beta для досочных игр:** дерево игры → Alpha-Beta с эвристической оценкой → выбор лучшего хода (шахматы, го, реверси).
> * **IDA* для комбинаторных задач:** задача на перестановки/конфигурации → эвристика → IDA* экономит память (15-puzzle, 8-puzzle, TSP).
> * **Вероятностные модели для циклических игр:** граф с циклами → Markov chain / MDP → решение через итерации (игры с костями, случайные среды, RL).

# **A. ОСНОВЫ КОМБИНАТОРНЫХ ИГР**

## **0. Формальное определение игры**
* **Множество игроков:** N = {1, 2, ..., n} — конечное множество участников
* **Множество состояний:** S — множество всех возможных конфигураций игры
* **Начальное состояние:** s₀ ∈ S — стартовая позиция
* **Множество действий:** A(s) — допустимые ходы в состоянии s
* **Функция переходов:** T(s, a) → s' —Deterministic: детерминированные переходы; T(s, a) → D(S): стохастические — распределение по следующим состояниям
* **Функция выигрыша/полезности:** u_i(s) — полезность состояния s для игрока i (в терминальных состояниях)
* **Терминальные состояния:** Z ⊆ S — позиции, где игра заканчивается; функция выигрыша определена только в Z
* **Поле определения:** Γ(s) = A(s) для s ∉ Z; Γ(s) = ∅ для s ∈ Z

## **1. Классификация игр**
* **По количеству игроков:**
  * **Антагонистические (двухplayerные):** максимизация одного игрока = минимизация другого (шахматы, го)
  * **Кооперативные:** все игроки стремятся к общему выигрышу (кооперативные МДП)
  * **n-игроки:** произвольное число игроков с собственными выигрышами (покер,экономические игры)
* **По сумме выигрышей:**
  * **Нулевая сумма:** Σ u_i(s) = 0 для всех s (классические двоичные игры)
  * **Ненулевая сумма:** общая «пирог» не фиксирован (кооперативные игры, торговые модели)
* **По информации:**
  * **Полная информация:** все игроки видят все состояние (шахматы, го, Ним)
  * **Неполная информация:** скрытые данные (покер — закрытые карты; бридж — рука партнёра)
* **По ходам:**
  * **Последовательные (alternating):** игроки ходят по очереди (большинство настольных игр)
  * **Одновременные:** все игроки выбирают действия одновременно (камень-ножницы-бумага)
* **По детерминированности:**
  * **Детерминированные:** нет случайности (шахматы, го, Ним)
  * **Стохастические:** случайные элементы (кости, колода карт, монета)

## **2. P-позиции и N-позиции**
* **Определение:** в бесконтактных играх (normal play) каждая позиция является либо P-позицией (prevailing, выигрышная для предыдущего игрока — того, кто только что ходил), либо N-позицией (next, выигрышная для следующего игрока — того, кто ходит сейчас)
* **Базис:**终端 позиции (где нет доступных ходов) — P-позиции (игрок, которому нужно ходить, проигрывает)
* **Рекурсия:** позиция — P-позиция, если все доступные ходы ведут в N-позиции; позиция — N-позиция, если существует хотя бы один ход в P-позицию
* **Связь с ДП:** классификация P/N — это ДП на графе состояний (`dynamic.md` G); для acyclic игр — полный перебор; для cyclic — решение системы уравнений
* **Применение:** определяет, выиграет ли первый игрок при оптимальной игре обеих сторон

## **2. Функция Гранди (Шпрага-Гранди)**
* **Определение:** для каждой позиции x в бесконтактной игре: G(x) = mex{G(y) : y — достижима из x}, где mex (minimum excludant) — наименьшее неотрицательное целое, не принадлежащее множеству
* **Свойства:** G(x) = 0 ↔ x — P-позиция; G(x) ≠ 0 ↔ x — N-позиция; значение G(x) — «nim-value» позиции
* **Почему mex:** гарантирует, что для любого значения k < G(x) существует ход в позицию с G = k; для G(x) = k нет хода в позицию с G = k
* **Вычисление:** ДП на DAG: для терминальных позиций G = 0; для остальных — рекурсивно из достижимых позиций
* **Обобщение:** параметризация: функция переходов `moves(pos) → vector<pos>`; функция terminal `is_terminal(pos) → bool`
* **Сложность:** O(V + E) для acyclic игр (V — число позиций, E — число рёбер переходов); O(V³) для cyclic (через систему уравнений)
* **Реализация:** `grundy_value` — вычисление G(x) для заданной позиции

## **3. Сумма игр: G(A + B) = G(A) ⊕ G(B)**
* **Определение:** если игра состоит из нескольких независимых подигр, общая функция Гранди — XOR (побитовое «исключающее ИЛИ») функций Гранди подигр
* **Почему XOR:** свойство nim-sum: для любого k < G(A) ⊕ G(B) существует ход, изменяющий одну подигру так, чтобы суммарный G = k; для k = G(A) ⊕ G(B) нет такого хода
* **Применение:** сложные игры разбиваются на независимые компоненты; каждая компонента оценивается отдельно; общий результат — XOR
* **Связь с Ним:** классический Ним — частный случай: каждая куча — подигра с G(стек) = размер стека; nim-sum = XOR размеров куч
* **Обобщение:** параметризация числа подигр; произвольные функции Гранди для компонент
* **Реализация:** `nim_sum` — вычисление XOR кучек

# **B. ИГРЫ С ПОЛНОЙ ИНФОРМАЦИЕЙ**

## **4. Minimax**
* **Определение:** алгоритм выбора оптимального хода в двоичных играх (max vs min): max-игрок максимизирует оценку, min-игрок минимизирует; рекурсия до терминальных узлов или глубины limit
* **Рекурсия:** `value(state) = max{value(child)}` для max-хода; `value(state) = min{value(child)}` для min-хода; база: terminal state → evaluation(state)
* **Свойства:** при оптимальной игре обеих сторон даёт гарантированный результат; полный перебор дерева
* **Обобщение:** параметризация: функция `children(state) → vector<state>`; функция `eval(state) → double` для терминальных/ограниченных узлов; флаг `is_max_turn`
* **Сложность:** O(b^d) где b — ветвление (число ходов), d — глубина дерева
* **Реализация:** `minimax` — рекурсивный на деревье игры

## **5. Alpha-Beta Pruning**
* **Определение:** оптимизация Minimax: отсечение ветвей, не влияющих на итоговое решение через α (лучшее значение max) и β (лучшее значение min)
* **Идея:** если min-игрок уже гарантировано получит ≤ α, а max-игрок уже имеет ≥ β, дальнейший перебор бесполезен
* **Почему работает:** инвариант: α ≤ value(state) ≤ β; нарушение инварианта → отсечение
* **Оптимальность:** при идеальном порядке ходов отсекает O(b^{d/2}) узлов вместо O(b^d) — удвоение эффективной глубины
* **Обобщение:** параметризация: те же функции, что в Minimax; 추가лены α, β как параметры состояния
* **Сложность:** O(b^{d/2}) лучший, O(b^d) худший; O(d) памяти (стек рекурсии)
* **Реализация:** `alpha_beta` — с отсечениями

## **6. A* и IDA* для игр**
* **Определение:** A* — информированный поиск: f(n) = g(n) + h(n), где g — стоимость от start, h — эвристика; IDA* — итеративное углубление с порогом f(n) ≤ limit
* **Применение в играх:** A* для поиска кратчайшего пути к выигрышной позиции; IDA* для 15-puzzle и других задач с ограничением памяти
* **Эвристики:** admissible (не завышает) → A* оптимален; consistent (monotone) → оптимален и efficient
* **Связь с II.F:** A* и IDA* реализованы в `SearchAlgorithms` (b.cpp); для игр используются те же алгоритмы с игровыми эвристиками
* **Реализация:** `a_star_search`, `ida_star_search` — переиспользуются из b.cpp; для 15-puzzle — `fifteen_puzzle_solve` с эвристикой Манхэттена

## **7. MCTS (Monte Carlo Tree Search)**
* **Определение:** вероятностный поиск: симуляция случайных игр → оценка позиций → выбор лучших ходов через UCB1
* **Этапы:** Selection (UCB1) → Expansion (добавление узла) → Simulation (случайная игра до конца) → Backpropagation (обновление оценок)
* **UCB1:** value(child) + C · sqrt(ln(parent.visits) / child.visits) — баланс исследования и использования
* **Почему эффективен:** не требует эвристики; работает с любым деревом; при бесконечном времени — оптимален
* **Обобщение:** параметризация: функция `simulate(state) → outcome`; константа C в UCB1; стратегия выбора (UCT — UCB1 for Trees)
* **Сложность:** O(n) за итерацию; число итераций — параметр
* **Реализация:** `mcts` — с UCB1 и параметризуемой функцией симуляции

## **8. Эвристики и оценочные функции**
* **Killer Heuristic:**
  * **Идея:** запоминать ходы, которые вызвали отсечение (beta-cutoff) на фиксированной глубине; проверять их первыми при переборе на такой же глубине
  * **Почему работает:** отсекающие ходы часто повторяются в сёблингах (sibling nodes); проверка лучших кандидатов раньше → больше отсечений
  * **Реализация:** массив killer_moves[depth][2] — два лучших хода на каждую глубину; при переборе проверять их первыми
* **History Heuristic:**
  * **Идея:** накапливать статистику: какой ход из какого состояния вызывал отсечение за всё время поиска
  * **Отличие от Killer:** Killer — локальный (только для текущей глубины); History — глобальный (для всей игры)
  * **Реализация:** таблица history[s][a] (или hash-based): увеличивать счётчик при отсечении; сортировать ходы по history score
* **Quiescence Search:**
  * **Проблема:** на « зависших » позициях (pending captures, check) оценка нестабильна — horizon effect
  * **Решение:** продолжать поиск直到 позиция «тихая » (нет pending captures/checks) или достигнут лимит глубины
  * **Применение:** шахматы — продолжать после взятий; покер — после шоудауна; любые игры с резкими изменениями оценки
  * **Параметризация:** функция `is_quiescent(state) → bool`; max_quiescence_depth

# **C. КОМБИНАТОРНАЯ ТЕОРИЯ ИГР**

## **8. Ним (Nim)**
* **Определение:** n куч; ход — удаление любого числа элементов из одной кучи; проигравший — тот, кто не может ходить (normal play) или последний ходивший (misère play)
* **Теорема Шпрага-Гранди:** позиция выигрышна ↔ nim-sum (XOR размеров куч) ≠ 0
* **Стратегия:** при nim-sum ≠ 0 — сделать ход, чтобы nim-sum стал 0; при nim-sum = 0 — любой ход对手 выигрывает
* **Варианты:**
  * **Misère Nim:** проигрывает тот, кто делает последний ход; стратегия отличается, когда все кучи ≤ 1
  * **Ограниченные ходы:** каждый ход ≤ m элементов из одной кучи → модифицированный Nim
  * **Multiple-pile Nim:** несколько куч, каждый ход — из одной кучи
* **Обобщение:** параметризация: число куч; ограничение на ход; misère/normal play
* **Реализация:** `nim_sum`, `is_nim_winning`

## **9. Misère Nim**
* **Определение:** как Nim, но проигрывает тот, кто делает последний ход (берёт последний элемент)
* **Стратегия:** если все кучи ≤ 1 — parity (чётность); иначе — как normal, но с поправкой: когда все кучи ≤ 1, XOR = 0 → проигрыш (вместо выигрыша в normal)
* **Почему:** в misère последний ход — проигрыш; поэтому при всех кучах ≤ 1 нужно оставить нечётное число ходов对手
* **Реализация:** параметризация через флаг misère

## **10. Ограниченный Nim (Bounded Nim)**
* **Определение:** каждый ход — удаление от 1 до m элементов из одной кучи (m — фиксировано)
* **Решение:** G(k) = k mod (m + 1); выигрыш ↔ XOR(k_i mod (m + 1)) ≠ 0
* **Почему:**周期性的: после m + 1 элементов цикл повторяется
* **Обобщение:** параметр m (максимальный ход)

## **11. Игры на графах**
* **Определение:** позиция — вершина графа; ход — перемещение по ребру; терминальные вершины (листьья) — P-позиции
* **Acyclic графы:** G(v) = mex{G(u) : (v, u) — ребро}; вычисляется через топологическую сортировку (I.D.22)
* **Cyclic графы:** G(v) не определена напрямую; используются вероятностные модели (Markov chains) или решение системы уравнений
* **Применение:** «Игра в графах» (Geography) — каждый ход перемещается фишку; проигрывает тот, кому нечего ходить
* **Обобщение:** произвольный граф; взвешенные рёбра (стоимость ходов)
* **Связь:** `graph.md` — топологическая сортировка для acyclic; циклы → ДП на циклических графах

## **12. Wythoff's Game**
* **Определение:** два стека; ход — взять любойמספר элементов из одного стека или одинаковое число из обоих; проигрывает тот, кто берёт последний элемент
* **Решение:** позиция (a, b) (a ≤ b) — P-позиция ↔ a = ⌊k · φ⌋, b = ⌊k · φ²⌋ = a + k для некоторого k ≥ 0, где φ = (1 + √5)/2 — золотое сечение
* **Почему φ:** оптимальная стратегия связана с бессеребряным числом Фибоначчи; φ — предельное отношение
* **Реализация:** `wythoff_nim` — проверка, является ли позиция P-позицией

# **D. ИГРЫ НА ГРАФАХ**

## **11. Ациклические игровые графы (DAG)**
* **Определение:** граф без циклов; каждая вершина — позиция; каждое ребро — переход; терминальные вершины (листьья) — P-позиции (G = 0)
* **Ретроспективный анализ:** вычисление G(v) от терминальных позиций к начальной; для DAG — в обратном топологическом порядке
* **Алгоритм:**
  1. Топологическая сортировка DAG (O(M))
  2. Обход в обратном топологическом порядке
  3. Для каждой вершины v: G(v) = mex{G(u) : (v, u) — ребро}
  4. P-позиция ⟺ G(v) = 0; N-позиция ⟺ G(v) ≠ 0
* **Сложность:** O(V + E) — полный об графа
* **Применение:** игра в графах (Geography), Nim на DAG, составные игры на деревьях
* **Реализация:** `acyclic_game_solve` — ретроспективный анализ за O(M)

## **12. Циклические игровые графы**
* **Проблема циклов:** в графах с циклами топологическая сортировка невозможна; G(v) не определена рекурсивно
* **Ничьи (draws):** циклы приводят к «бесконечным» играм; позиции в циклах — ничьи при optimal play
* **Алгоритмы:**
  * **Система уравнений:** для каждой вершины v: G(v) = mex{G(u) : (v, u) — ребро}; решается через итерации (Gauss-Seidel) или метод Якоби
  * **Марковские цепи:** вероятностные переходы → стационарное распределение → вероятность выигрыша
  * **Разрешение циклов:** итеративное удаление «бесполезных» вершин (как в Karp's algorithm); вершины в циклах → draw (0.5)
* **Параметризация:** граф G(V, E); начальное состояние s₀; функция выигрыша для терминальных вершин
* **Сложность:** O(V³) для системы уравнений; O(V + E) для итеративного удаления
* **Реализация:** `cyclic_game_solve` — итеративное разрешение

# **E. ВЕРОЯТНОСТНЫЕ ИГРЫ**

## **13. Expectiminimax**
* **Определение:** обобщение Minimax для игр со случайными элементами: после хода max/min игрока может быть chance-узел (случайный исход с вероятностями)
* **Рекурсия:** `value(state) = max{value(child)}` для max; `value(state) = min{value(child)}` для min; `value(state) = Σ P(child) · value(child)` для chance
* **Применение:** игры с костями (Backgammon, Monopoly); покер; шахматы с несовершенной информацией
* **Обобщение:** параметризация: функция `chance_children(state) → vector<(child, prob)>`; вероятностное распределение
* **Сложность:** O(b^d · c^d) где c — ветвление chance-узлов; экспоненциальная

## **14. MDP (Markov Decision Process)**
* **Определение:** модель решений в случайной среде: состояния S, действия A, вероятности переходов P(s'|s,a), награды R(s,a,s'), дисконтирование γ
* **Уравнение Беллмана:** V(s) = max_a Σ_{s'} P(s'|s,a) · (R(s,a,s') + γ · V(s'))
* **Итерационное решение:** Value Iteration: V_{k+1}(s) = max_a Σ_{s'} P(s'|s,a) · (R(s,a,s') + γ · V_k(s')); Policy Iteration: оценка политики → улучшение политики
* **Связь с ДП:** MDP — ДП на случайных переходах; V(s) — стоимость состояния (`dynamic.md` G)
* **Обобщение:** параметризация: пространство состояний S; пространство действий A; функция переходов; функция награды; дисконт γ
* **Реализация:** `value_iteration`, `policy_iteration` — итеративные методы

## **15. Q-Learning**
* **Определение:** model-free RL: обучение ценности действий без модели переходов; Q(s,a) — ожидаемая награда при действии a в состоянии s
* **Обновление:** Q(s,a) ← Q(s,a) + α · (r + γ · max_{a'} Q(s', a') − Q(s,a))
* **Параметры:** α (learning rate), γ (discount), ε (exploration rate для ε-greedy)
* **Сходимость:** при充分ном числе探索 и уменьшающемся α → оптимальная Q-функция
* **Обобщение:** произвольное пространство состояний/действий; функция вознаграждения; стратегия исследования
* **Реализация:** `q_learning` — с ε-greedy стратегией

## **16. Policy Iteration**
* **Определение:** итеративный метод: 1) Policy Evaluation: вычислить V^π(s) для фиксированной политики π; 2) Policy Improvement: обновить π(s) = argmax_a Σ_{s'} P(s'|s,a) · (R(s,a,s') + γ · V^π(s'))
* **Гарантия сходимости:** за конечное число итераций ( политика монотонно улучшается)
* **Преимущество перед Value Iteration:** часто сходится быстрее, особенно для детерминированных политик
* **Обобщение:** параметризация: пространство состояний/действий; функция переходов; дисконт γ
* **Реализация:** `policy_iteration` — через оценку политики и улучшение

## **20. Стоимость позиций через ДП**

# **G. СОВЕРШЕННАЯ ИГРА И РАВНОВЕСИЕ НЭША**

## **26. Совершенная игра (Perfect Information Games)**
* **Определение:** игра, в которой каждый игрок в любой момент времени знает все действия, совершённые до текущего момента, и текущее состояние игры
* **Существование оптимальных стратегий:** в конечных двоичных совершенных играх всегда существует оптимальная стратегия (теорема Цермело)
* **Цена игры (value of the game):** результат при оптимальной игре обеих сторон; V = max_σ min_τ u(σ, τ) = min_τ max_σ u(σ, τ)
* **Алгоритмы:** Minimax, Alpha-Beta Pruning, IDA*, MCTS — все для совершенных игр
* **Связь:** теорема Цермело гарантирует, что для любой позиции: либо первый игрок может выиграть, либо второй может заставить ничью/второй выиграет
* **Примеры:** шахматы, го, Ним, пente, реверси

## **27. Равновесие Нэша (Nash Equilibrium)**
* **Определение:** стратегический профиль (σ₁*, σ₂*, ..., σₙ*), где ни один игрок не может улучшить свой выигрыш, односторонне изменив свою стратегию
* **Чистые стратегии:** каждый игрок выбирает одно действие детерминированно; равновесие в чистых стратегиях может не существовать (камень-ножницы-бумага)
* **Смешанные стратегии:** каждый игрок назначает вероятности действиям (σ_i ∈ Δ(A_i)); существование гарантировано (теорема Нэша, 1950)
* **Вычисление:** для двухplayerных игр — через систему linear complementarity; для n-player — итеративные методы (Lemke-Howson, support enumeration)
* **Связь с теорией игр:** равновесие Нэша — обобщение минимакса; в нулевых суммах минимакс = Нэш
* **Применение:** экономика (рыночные равновесия), криптография (mixed strategies), AI (многопользовательские игры)

# **H. СТОХАСТИЧЕСКИЕ ИГРЫ**

## **28. Марковские процессы принятия решений (MDP)**
* **Определение:** (S, A, P, R, γ) — состояния S, действия A, переходы P(s'|s,a), награды R(s,a,s'), дисконт γ ∈ [0,1)
* **Уравнение Беллмана:** V*(s) = max_a Σ_{s'} P(s'|s,a) · (R(s,a,s') + γ · V*(s'))
* **Value Iteration:** итеративное приближение V_k → V*; сходимость гарантирована при γ < 1
* **Policy Iteration:** итеративное улучшение политики π; за конечное число шагов (политика конечна)
* **Q-Learning:** model-free: Q(s,a) ← Q(s,a) + α(r + γ·max_a' Q(s',a') - Q(s,a)); без модели P
* **Применение:** игры с вероятностными переходами (Backgammon, Monopoly), RL, робототехника

## **29. Reinforcement Learning**
* **Q-Learning:** обновление Q-таблицы через опыт; ε-greedy для исследования; сходимость при полном опыте
* **Deep Q-Networks (DQN):** Q(s,a) ≈ Q_θ(s,a) через нейросеть; experience replay + target network для стабильности
* **Policy Gradients:** параметризация политики π_θ(a|s); градиент ∇_θ J(θ) = E[∇_θ log π_θ(a|s) · R]; REINFORCE, A2C, PPO
* **Actor-Critic:** комбинация policy gradient (actor) + value function (critic); A2C, A3C, SAC
* **Применение:** Atari, Go (AlphaGo), Dota 2, autonomous driving

# **I. ИГРЫ С НЕПОЛНОЙ ИНФОРМАЦИЕЙ**

## **30. Байесовские игры (Bayesian Games)**
* **Определение:** игра, где каждый игрок имеет тип θ_i ∈ Θ_i (скрытый от других); стратегии зависят от типа
* **Типы игроков:** Θ_i — множество возможных «ролей» или «состояний» игрока i
* **Априорные распределения:** μ_i(θ_i) — вероятность того, что игрок i имеет тип θ_i; common priors или individual beliefs
* **Байесовское равновесие:** каждый тип θ_i оптимизирует свою стратегию, зная своё распределение beliefs о типах других
* **Связь с Нэш:** байесовское равновесие — обобщение равновесия Нэша для игр с неполной информацией
* **Вычисление:** сводится к обычному равновесию Нэша в «расширенной» игре (Harsanyi transformation)
* **Применение:** аукционы, торги, сигнализирование (signaling games)

## **31. Игры с несовершенной информацией (Imperfect Information Games)**
* **Информационные множества:** множество позиций, которые игрок не может различить (considered equivalent); стратегия определена на информационных множествах
* **Стратегии:** каждое информационное множество → одно действие; игрок не знает точную позицию, но знает «класс эквивалентности»
* **Формальное определение:** I = {I₁, I₂, ...} — разбиение позиций; для каждого I_k: одинаковые доступные действия
* **Болтомбеки (Beliefs):** вероятностное распределение по позициям внутри информационного множества
* **Связь с MCTS:** imperfect information MCTS (Information Set MCTS, IS-MCTS) — симуляции из информационных множеств
* **Применение:** покер (закрытые карты), бридж (рука партнёра), Kriegspiel (скрытые фигуры)

# **J. УСИЛЕНИЕ ОБУЧЕНИЯ В ИГРАХ** (дополнение к E.15)

## **32. MCTS с UCB1 (детально)**
* **UCB1 формула:** UCB1(child) = Q(child)/N(child) + C · sqrt(ln(N(parent)) / N(child))
  * Q(child) — суммарная награда; N(child) — число посещений; C — константа исследования (√2 теоретически)
* **Selection:** от корня до листа: на каждом узле выбрать ребёнка с максимальным UCB1
* **Expansion:** добавить нового ребёнка к листу (пока не все ходы исследованы)
* **Simulation (Rollout):** случайная игра до конца; результат — награда (win/loss/draw)
* **Backpropagation:** обновить N и Q для всех узлов на пути от листа до корня
* **Расширения:** RAVE (Rapid Action Value Estimation), Progressive Widening, PUCT (AlphaGo)

## **33. Q-Learning и Deep RL для игр**
* **Q-Learning:** Q(s,a) ← Q(s,a) + α(r + γ·max_a' Q(s',a') - Q(s,a)); без модели; сходимость при полном опыте
* **Deep Q-Networks (DQN):** Q(s,a) ≈ Q_θ(s,a) через CNN; experience replay (устраняет корреляцию); target network (стабильность)
* **Policy Gradients:** π_θ(a|s) = softmax(f_θ(s)); ∇_θ J(θ) = E[∇_θ log π_θ(a|s) · R]; REINFORCE с baseline
* **Actor-Critic (A2C/A3C):** actor = политика π_θ; critic = функция ценности V_φ(s); advantage = R - V_φ(s); параллельные эпизоды
* **Применение:** AlphaGo (MCTS + Policy/Value Networks), OpenAI Five (Dota 2), AlphaStar (StarCraft)

# **K. КЛАССИЧЕСКИЕ ИГРЫ И ИХ АНАЛИЗ**

## **34. Шахматы**
* **Сложность:** ~10^120 позиций (Shannon number); ~10^47LEGAL позиций; среднее ветвление ~35 ходов; средняя глубина ~80 полуходов
* **Основные алгоритмы:**
  * Minimax + Alpha-Beta (классика)
  * Iterative Deepening (поиск с увеличением глубины)
  * Transposition Tables (запоминание уже рассмотренных позиций)
  * Move Ordering (сортировка ходов для лучшего отсечения)
  * Opening Books (дебютная база данных)
  * Endgame Tablebases (этюдные базы до 7-8 фигур)
* **Современные движки:** Stockfish (Alpha-Beta + NNUE), Leela Chess Zero (MCTS + нейросети)
* **Эвристики:** Material, Piece-Square Tables, Pawn Structure, King Safety, Mobility

## **35. Го (Go)**
* **Сложность:** ~10^170 позиций (намного больше шахмат); ветвление ~250; доска 19×19
* **Почему сложнее шахмат:** больше доска → больше позиций; нет простой эвристики материала; территориальная природа
* **Алгоритмы:**
  * **MCTS + нейросети** (AlphaGo, AlphaGo Zero, KataGo): policy network (предсказание ходов) + value network (оценка позиции)
  * **Минимакс непригоден:** слишком глубокое дерево; MCTS работает лучше
* **AlphaGo Zero:** сама играет (self-play) + MCTS + deep residual networks; без человеческих знаний
* **Территориальная оценка:** control territory, influence, moyo; трудно формализовать

## **36. Покер**
* **Тип:** игра с неполной информацией (закрытые карты); Texas Hold'em — стандартный вариант
* **Сложность:** ~10^180 состояний (с учётом распределений); information sets — огромны
* **Алгоритмы:**
  * **Counterfactual Regret Minimization (CFR):** итеративное минимизация regret для каждого информационного множества
  * **Monte Carlo CFR (MCCFR):** аппроксимация через симуляции
  * **Deep CFR:** нейросети для аппроксимации regret и стратегий
* **Лимитный vs Безлимитный:** лимитный (Fixed-Limit) решён (Cepheus); безлимитный (No-Limit) — приближённо (Pluribus, Libratus)
* **Pluribus:** 6-игрок No-Limit Hold'em; CFR + симметрия; играет на уровне профессионалов

# **L. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ**

## **37. Теорема Цермело (Zermelo's Theorem)**
* **Формулировка:** в любой конечной двоичной детерминированной игре с полной информацией (шахматы, го) первый игрок либо может выиграть, либо может заставить ничью
* **Следствие:** существует оптимальная стратегия для каждого игрока; цена игры определена
* **Доказательство:** по индукции от терминальных позиций; Minimax на полном дереве
* **Теорема Цермело-фон Неймана:** обобщение на стохастические игры: в конечной игре с полной информацией и вероятностными переходами существует оптимальная смешанная стратегия
* **Ограничения:** теорема не даёт способа вычислить стратегию; только гарантирует существование

## **38. Сложность вычислительных игр**
* **EXPTIME-complete:** шахматы с произвольным размером доски; го с произвольным размером; checkers (последовательные ходы, полная информация)
* **PSPACE-complete:** QBF (Quantified Boolean Formula); параллельные шахматы (parallel chess);some coordination игры
* **NP-complete:** finding winning move in generalizedHex; Mahjong Solitaire;some card games
* **Экспоненциальная сложность:** для большинства интересных игр; полный перебор невозможен → эвристики, MCTS, RL
* **Параметризованная сложность:** FPT для игр на узких графах (bounded treewidth); W[1]-hard для произвольных графов

# **M. АЛГОРИТМИЧЕСКИЕ ТЕХНИКИ ДЛЯ ИГР**

## **39. Bitboard-представления**
* **Определение:** битовая доска: каждая клетка = 1 бит в 64-битном целом; белые/чёрные фигуры — отдельные bitboard
* **Преимущества:** popcount (число единиц) за O(1); побитовые операции для атак/защит; кэш-эффективность
* **Применение:** шахматы: occupancy, pawn structure, attacks; го: territory; реверси: flips
* **Примеры:** _pext_u64, _tzcnt_u64, __builtin_popcountll — аппаратные инструкции
* **Реализация:** std::bitset<64> или uint64_t; магические числа для sliding attacks

## **40. Pattern Databases**
* **Определение:** база данных эвристических оценок для подмножества фигур; precomputed: для каждой конфигурации подмножества → оптимальное расстояние до цели
* **Применение:** 15-puzzle: pattern database для 4-5 плиток; шахматы: endgame tablebases (Syzygy, Lomonosov)
* **Алгоритм построения:** обратный BFS от целевых позиций; заполнение таблицы расстояний
* **Использование:** h(state) = max(h_db(subset)) для каждого подмножества; admissible, поэтому A*/IDA* оптимален
* **Размер:** 2^k состояний для k фигур; компрессия через pattern reflection symmetry

## **41. Null-Move Pruning и Late Move Reductions**
* **Null-Move Pruning:**
  * **Идея:** «пропустить ход» (дать противнику два хода подряд); если результат ≤ α, текущая позиция, вероятно, плоха → отсечение
  * **Формула:** null_val = -alpha_beta(state, depth - R - 1, !is_max, -β, -β+1); если null_val ≥ β → отсечение
  * **Параметр R:** глубина reductions (typically 2-3 для шахмат)
  * **Ограничение:** не работает в endgame (zugzwang); не использовать при глубине < R
* **Late Move Reductions (LMR):**
  * **Идея:** ходы, отсортированные не на первых местах, вероятно, плохи → проверять их на меньшей глубине
  * **Правило:** если move_index > LMR_threshold && depth >= LMR_min_depth → search(depth - 1 - reduction) вместо (depth - 1)
  * **Thresholds:** LMR_threshold ≈ 3-4; reduction ≈ 1-2; зависит от depth и move_index
  * **Результат:** ускорение Alpha-Beta в 2-5 раз; приблизительное дерево поиска
