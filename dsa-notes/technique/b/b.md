# **A. ЛИНЕЙНЫЙ И ПОСЛЕДОВАТЕЛЬНЫЙ ПОИСК**

## **1. Sequential Search (Linear Search)**
* **Определение:** проход по всем элементам; O(n) сравнений
* **Почему для олимпиад:** единственная альтернатива для неотсортированных данных; база для Sentinel и Double-ended вариантов
* **Обобщение:** предикат `pred(x)` вместо равенства; возврат индекса или значения
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `linear_search` — с предикатом, возвращает индекс или -1

## **2. Особые случаи линейного поиска**
* **Search in unsorted array:** базовый линейный поиск — единственная альтернатива для неотсортированных данных (без построения хеш-таблицы)
* **Search with early exit:** прерывание при первом совпадении; если известно, что элемент единственный — O(1) лучший случай
* **Search for multiple occurrences:** найти все вхождения — добавляем результат в вектор; подсчёт количества — инкремент счётчика
* **Сложность:** O(n) время, O(k) память (k — число вхождений) для all; O(1) память для count
* **Реализация:** `linear_search_all` (все индексы), `linear_search_count` (количество)

## **3. Sentinel Search**
* **Определение:** искомый элемент помещается в конец массива — убирается проверка границ `i < n` в цикле
* **Почему работает:** sentinel гарантирует, что поиск остановится на искомом элементе (или на нём самом)
* **Сложность:** O(n) время, O(1) память; на 1–2 сравнения меньше обычного линейного
* **Реализация:** `sentinel_search`

## **4. Double-ended Search**
* **Определение:** поиск с двух концов одновременно; каждый указатель ищет свою «половину»
* **Сложность:** O(n/2) шагов в худшем случае, но O(n) по-прежнему
* **Реализация:** `double_ended_search`

# **B. ДВОИЧНЫЙ ПОИСК (BINARY SEARCH)**

## **1. Классический двоичный поиск**
* **Определение:** поиск в отсортированном массиве: деление диапазона пополам
* **Инвариант:** `a[lo] ≤ target ≤ a[hi]` (для lower_bound); ответ всегда в `[lo, hi]`
* **Реализации:**
  * **Итеративная:** `while (lo < hi)` с mid = lo + (hi - lo) / 2 (защита от переполнения)
  * **Рекурсивная:** divide & conquer с базой `lo == hi`
* **Варианты:**
  * **Lower Bound:** первый элемент `≥ target` — `lo = mid + 1` при `a[mid] < target`
  * **Upper Bound:** первый элемент `> target` — `lo = mid + 1` при `a[mid] ≤ target`
  * **Equal Range:** `[lower_bound, upper_bound)`
* **Обобщение:** произвольный компаратор `cmp(a, b)` и предикат; STL-эквиваленты: `std::lower_bound`, `std::upper_bound`, `std::equal_range`
* **Сложность:** O(log n) время, O(1) память
* **Реализация:** `binary_search_lb` (lower_bound), `binary_search_ub` (upper_bound), `binary_search_eq` (equal range), `binary_search_cmp` (произвольный компаратор)
* **Связь:** бинарный поиск в дереве (`struct.md` II) — тот же принцип, но по указателям

## **2. Рекурсивный двоичный поиск**
* **Определение:** рекурсивная версия бинарного поиска: divide & conquer с базой `lo == hi`
* **Паттерн:** `f(lo, hi)` → вычислить mid → рекурсия в левой или правой половине
* **Сравнение с итеративным:** итеративный экономит стек (O(1) память), рекурсивный — нагляднее
* **Сложность:** O(log n) время, O(log n) память (стек вызовов)
* **Реализация:** `binary_search_recursive`

## **3. Бинарный поиск в бесконечном массиве**
* **Определение:** массив неизвестного/бесконечного размера; невозможно задать hi = n
* **Алгоритм:** Exponential Search для нахождения границы [1, 2, 4, 8, ...] + Binary Search в найденном диапазоне
* **Почему O(log pos):** экспоненциальный поиск находит границу за O(log pos), бинарный — за O(log pos)
* **Применения:** поиск в потоке данных, файловых системах, бесконечных генераторах
* **Реализация:** комбинация `exponential_search` + `binary_search_lb`

## **4. Бинарный поиск по ответу (Binary Search on Answer)**
* **Идея:** если предикат `P(x)` монотонен (∀x≤y: P(x)⟹P(y) или обратно), найти границу `x*` где P(x) меняет значение
* **Паттерн:**
  ```
  lo = min_possible, hi = max_possible
  while (lo < hi):
      mid = lo + (hi - lo) / 2
      if P(mid): hi = mid    (для поиска минимума x с P(x))
      else: lo = mid + 1
  ```
* **Применения:** минимизация максимума, максимизация минимума, задачи с монотонными предикатами
* **Обобщение:** предикат `P(x)` как параметр; бинарный поиск по вещественной области (B.6)
* **Сложность:** O(log(max − min)) итераций × O(check) время проверки
* **Реализация:** `binary_search_answer` — шаблон с предикатом; `check` передаётся как параметр
* **Связь:** связь с convex hull trick (`dynamic.md`), параметрический поиск (B.10)

## **5. Вещественный бинарный поиск**
* **Определение:** поиск корня f(x) = 0 или экстремума на вещественном отрезке
* **Критерий остановки:**
  * Фиксированное число итераций (100–200) — гарантированная точность 2^{-100}
  * `while (hi - lo > eps)` — точность до eps
* **Обобщение:** произвольная непрерывная монотонная функция `f(x)`; корень на отрезке `[lo, hi]` с `f(lo)·f(hi) < 0`
* **Сложность:** O(log((hi − lo)/eps)) итераций
* **Реализация:** `binary_search_real` — с eps и максимальным числом итераций
* **Связь:** Newton's method (`math/analysis.md`) — быстрее (квадратичная сходимость), но требует производную

## **6. Бинарный поиск в rotated/sorted массиве**
* **Определение:** массив повёрнут на k позиций; найти элемент за O(log n)
* **Идея:** в каждом подмассиве одна половина гарантированно отсортирована; определяем, в какой половине лежит target
* **Обобщение:** произвольный поворот k; повторяющиеся элементы (осторожно)
* **Сложность:** O(log n)
* **Реализация:** `binary_search_rotated`

## **7. Бинарный поиск в 2D матрице**
* **Определение:** матрица отсортирована по строкам и столбцам; поиск за O(m + n) или O(log m + log n)
* **Подходы:**
  * От правого верхнего угла: влево — уменьшение, вниз — увеличение → staircase search O(m + n)
  * Бинарный поиск по строкам + бинарный поиск по столбцам → O(m log n)
* **Реализация:** `search_matrix_sorted` (staircase), `search_matrix_bs`

## **8. Бинарный поиск + Greedy/DP check**
* **Паттерн:** задача «найди минимум X такой, что condition(X)» → бинарный поиск по X, проверка через greedy или DP
* **Пример:** задача «минимальный makespan для m машин» → бинарный поиск по makespan, проверка: можно ли распределить задачи за это время?
* **Обобщение:** монотонный предикат `check(X)`; параметризация проверки

## **9. Two pointers вместо бинарного поиска**
* **Иногда:** два указателя на отсортированном массиве работают за O(n) вместо O(n log n)
* **Когда:** задача не требует random access к произвольному элементу; достаточно двух проходов

## **10. Бинарный поиск по индексу**
* **Паттерн:** ответ — индекс в массиве; бинарный поиск по индексу, проверка через предикат
* **Пример:** найти первый индекс `i` такой, что `pred(i) == true`

# **C. ПРОМЕЖУТОЧНЫЕ АЛГОРИТМЫ ПОИСКА**

## **1. Jump Search**
* **Определение:** прыжки фиксированного размера `step = √n`, затем линейный поиск в блоке
* **Почему √n:** оптимальный баланс между числом прыжков (√n) и числом сравнений в блоке (√n) → O(√n)
* **Обобщение:** размер прыжка как параметр (оптимум: √n при равномерном распределении)
* **Сложность:** O(√n) время, O(1) память
* **Реализация:** `jump_search`

## **2. Interpolation Search**
* **Определение:** предсказание позиции через интерполяцию: `pos = lo + (target - a[lo]) * (hi - lo) / (a[hi] - a[lo])`
* **Почему O(log log n):** при равномерном распределении каждый шаг сужает диапазон экспоненциально
* **Худший случай:** O(n) (экспоненциальное распределение)
* **Обобщение:** функция распределения как параметр
* **Сложность:** O(log log n) среднее, O(n) худшее
* **Реализация:** `interpolation_search`

## **3. Fibonacci Search**
* **Определение:** деление через числа Фибоначчи: F(k) ≥ n, сравнение с `a[F(k-2)]`
* **Почему полезен:** только сложение/вычитание (деление дорого на некоторых архитектурах)
* **Сложность:** O(log n), O(1) память
* **Реализация:** `fibonacci_search`

## **4. Exponential Search**
* **Определение:** для бесконечных/неизвестного размера массивов: экспоненциальный поиск границы + бинарный поиск
* **Алгоритм:** i = 1; пока a[i] < target: i *= 2; бинарный поиск в [i/2, min(i, n−1)]
* **Применения:** поиск в потоке, бесконечных массивах
* **Сложность:** O(log pos) где pos — позиция элемента
* **Реализация:** `exponential_search`

# **D. ТРОИЧНЫЙ ПОИСК (TERNARY SEARCH)**

## **1. Классический троичный поиск**
* **Определение:** для унимодальных функций: деление на 3 части, отбрасывание трети
* **Унимодальная функция:** строго возрастающая, затем строго убывающая (или наоборот)
* **Обобщение:** минимум/максимум; произвольная унимодальная функция
* **Сложность:** O(log₃ n) итераций
* **Реализация:** `ternary_search_int`, `ternary_search_real`

## **2. Применения троичного поиска**
* **Нахождение максимума/минимума унимодальной функции:** классическая задача — найти x* = argmax f(x) на [lo, hi]
* **Задачи на параболы и квадратичные функции:** f(x) = ax² + bx + c — унимодальна на [-∞, vertex] или [vertex, +∞]
* **Геометрические задачи:** минимизация расстояний, оптимальное размещение, площади — сводятся к унимодальным функциям
* **Оптимизация в machine learning:** линия поиска (line search) в градиентном спуске — finding step size α that minimizes f(θ − α∇f)
* **Сложность:** O(log₃ n) или O(log_{φ} n) итераций; каждая итерация — O(1) вычислений функции

## **3. Golden Section Search**
* **Определение:** оптимальное деление интервала с соотношением φ = (1+√5)/2
* **Преимущество:** одна новая оценка функции на итерацию (вторая переиспользуется)
* **Сложность:** O(log_{φ}((hi−lo)/eps)) итераций
* **Реализация:** `golden_section_search`

# **E. ВЫБОР МЕДИАНЫ И k-Й СТАТИСТИКИ**

## **1. QuickSelect (Randomized)**
* **Определение:** найти k-й порядковый элемент за O(n) ожидаемо
* **Идея:** partition (как в Quick Sort), но рекурсия только в одной половине
* **Обобщение:** k как параметр; медиана — частный случай k = n/2
* **Сложность:** O(n) ожидаемо, O(n²) худший
* **Реализация:** `quickselect` — через partition из Quick Sort (I.B.6, переиспользуется, не переписывается)
* **Связь:** Median of Medians (E.16) даёт детерминированный O(n)

## **2. Median of Medians (BFPRT)**
* **Определение:** детерминированный выбор pivot: группы по 5 → медиана каждой → медиана медиан → partition
* **Гарантия:** O(n) в худшем случае (Blum, Floyd, Pratt, Rivest, Tarjan)
* **Почему 5:** оптимальная константа; группы по 3 дают O(n log n)
* **Сложность:** O(n) гарантированно, ~3n сравнений
* **Реализация:** `median_of_medians`

## **3. IntroSelect**
* **Определение:** QuickSelect с переключением на Median of Medians при глубине > c·log n
* **Гарантия:** O(n) в худшем случае
* **Реализация:** `intro_select`

## **4. HeapSelect**
* **Определение:** k-й элемент через min-heap размера k
* **Сложность:** O(n log k) время, O(k) память
* **Реализация:** `heap_select` — через `std::priority_queue`

## **5. Медиана в потоке данных**
* **Два кучи:** max-heap для меньшей половины, min-heap для большей; балансировка размеров
* **Сложность:** O(log n) на добавление, O(1) на запрос медианы
* **Реализация:** `running_median`

## **6. Counting Select (для ограниченного диапазона)**
* **Определение:** выбор k-го элемента, когда значения ∈ [0, range−1]; O(n + range) время
* **Идея:** подсчёт частот → кумулятивная сумма → определение k-го элемента за один проход
* **Преимущество над QuickSelect:** детерминированный O(n + range), нет рекурсии
* **Применение:** сортировка подсчётом (I), порядковые статистики для малых диапазонов
* **Сложность:** O(n + range) время, O(range) память
* **Реализация:** `counting_select`

## **7. Медиана двух отсортированных массивов**
* **Определение:** два отсортированных массива размеров m и n; найти медиану за O(log min(m, n))
* **Идея:** бинарный поиск по разбиению меньшего массива; проверка корректности через max/min соседей
* **Ключевой инвариант:** max(left_A) ≤ min(right_B) и max(left_B) ≤ min(right_A)
* **Сложность:** O(log min(m, n)) время, O(1) память
* **Реализация:** `median_two_sorted`
* **Два кучи:** max-heap для меньшей половины, min-heap для большей; балансировка размеров
* **Сложность:** O(log n) на добавление, O(1) на запрос медианы
* **Реализация:** `running_median`

# **F. МЕТАЭВРИСТИКИ И ЛОКАЛЬНЫЙ ПОИСК**

## **1. Backtracking**
* **Определение:** систематический перебор с отсечениями: строим решение по шагам, при нарушении约束 — откат
* **Паттерн:** рекурсия + проверка约束 + откат (restore state)
* **Применения:** N-Queens, Sudoku Solver (`struct` I.A.16), Graph Coloring, перестановки
* **Сложность:** экспоненциальная; качество зависит от剪枝
* **Реализация:** `backtracking` — обобщённый шаблон (solution, is_valid, next_candidates)
* **Forward checking:** после назначения переменной — немедленная проверка Domains оставшихся переменных; удаление невозможных значений
* **Constraint propagation:** полное устранение противоречий: AC-3 (arc consistency), FC (forward checking), MAC (maintaining arc consistency); сужает domains до непротиворечивых

## **2. Hill Climbing**
* **Определение:** локальный поиск: начальное решение → moves в окрестности → лучший邻居 → повтор
* **Варианты:**
  * Simple: первый улучшающий ход
  * Steepest-Ascent: лучший из всех邻居
  * Stochastic: случайный из улучшающих
* **Проблемы:** локальные максимумы, плато
* **Реализация:** `hill_climbing` — с функцией邻居 и оценки

## **3. Simulated Annealing**
* **Определение:** имитация отжига: принятие «плохих» ходов с вероятностью `e^{ΔE/T}`; T убывает
* **Параметры:** начальная T, функция охлаждения `T_new = α·T`, критерий остановки
* **Гарантия:** при бесконечном времени — глобальный оптимум
* **Реализация:** `simulated_annealing`

## **4. Tabu Search**
* **Определение:** локальный поиск с памятью (tabu list): запрещённые недавние ходы
* **Компоненты:** tabu list (круговой буфер), aspiration criteria (игнорировать tabu при улучшении)
* **Реализация:** `tabu_search`

## **5. Genetic Algorithms**
* **Определение:** эволюционный подход: популяция → selection → crossover → mutation → повтор
* **Операторы:** fitness function, selection (tournament/roulette), crossover (one-point/two-point/uniform), mutation
* **Реализация:** `genetic_algorithm`

## **6. A* Search**
* **Определение:** информированный поиск: f(n) = g(n) + h(n), где g — стоимость от start, h — эвристика до goal
* **Корректность:** если h — admissible (не завышает), A* находит оптимальное решение
* **Обобщение:** произвольная эвристика `h(n)`; для графов — `graph.md`
* **Сложность:** O(b^d) худший (b — ветвление, d — глубина), но с хорошей эвристикой экспоненциально быстрее
* **Реализация:** `a_star_search` — на графе (adjacency list), с эвристикой

## **7. IDA* (Iterative Deepening A*)**
* **Определение:** итеративное углубление с порогом f(n) ≤ limit; экономит память (O(depth))
* **Преимущество:** O(最优 решение) по памяти, полнота
* **Реализация:** `ida_star_search`

## **8. Beam Search**
* **Определение:** ограниченный BFS: сохранять только k лучших узлов на каждом уровне
* **Обобщение:** ширина луча k как параметр; эвристика для оценки
* **Реализация:** `beam_search`

# **G. СТРИМИНГОВЫЙ И ОНЛАЙН ПОИСК**

## **1. Reservoir Sampling**
* **Определение:** выбор k случайных элементов из потока неизвестного размера за один проход
* **Идея:** i-й элемент (i ≥ k) заменяет случайный из k с вероятностью k/i
* **Сложность:** O(n) время, O(k) память
* **Реализация:** `reservoir_sampling`

## **2. Heavy Hitters**
* **Определение:** элементы, встречающиеся > n/k раз
* **Алгоритм Misra-Gries:** k−1 счётчиков; при новом элементе: если есть счётчик — инкремент, иначе все −1, удалить нулевые
* **Сложность:** O(n) время, O(k) память
* **Реализация:** `misra_gries`

## **3. Quantiles в потоке**
* **Greenwald-Khanna:** приближённые квантили с гарантированной ошибкой ε
* **Сложность:** O(1/ε · log(εn)) памяти
* **Реализация:** `greenwald_khanna` (упрощённая версия)

# **H. ПАРАМЕТРИЧЕСКИЙ И МНОГОКРИТЕРИАЛЬНЫЙ ПОИСК**

## **1. Parametric Search**
* **Определение:** преобразование задачи оптимизации в задачу принятия решения через бинарный поиск
* **Паттерн:** бинарный поиск по значению → check(feasibility) за O(T(n))
* **Связь:** бинарный поиск по ответу (B.5)

## **2. Pareto-optimal Search**
* **Определение:** множество недоминированных решений (ни одно не строго лучше другого по всем критериям)
* **Алгоритм:** сортировка по одному критерию → сканирование с поддержанием максимума по другому
* **Реализация:** `pareto_front`

# **I. ПАРАЛЛЕЛЬНЫЙ И РАСПРЕДЕЛЁННЫЙ ПОИСК**

## **1. Параллельные алгоритмы**
* **Parallel Binary Search (для multiple queries):** offline processing — все запросы обрабатываются параллельно; бинарный поиск по ответу для каждого запроса, но на каждом шаге — пакетная обработка (batch processing) всех запросов
* **Идея:** вместо последовательного бинарного поиска для каждого запроса — один проход по данным для всех запросов одновременно; O((n + q) log C) вместо O(q log C)
* **Parallel Search in arrays (SIMD):** векторные инструкции для параллельного сравнения 4/8/16 элементов одновременно; AVX2/AVX-512
* **OpenMP:** автоматический распараллеливание циклов; `#pragma omp parallel for reduction`
* **MPI:** распределённый поиск по процессам; each process ищет в своей части данных
* **Сложность:** O(n/p + log n) для p процессов (при идеальном распараллеливании)

## **2. Распределённый поиск**
* **Distributed Hash Tables (DHT):**
  * **Chord:** кольцевая топология; finger table для O(log n) маршрутизации; successor/predecessor pointers
  * **Kademlia:** XOR-метрика для расстояния; k-buckets для маршрутизации; iterative lookup
  * **Pastry:** prefix-based routing; leaf set и routing table; O(log n) hops
* **MapReduce для поиска:**
  * **Inverted index construction:** Map: (doc, word) → (word, doc); Reduce: word → [doc1, doc2, ...]
  * **Распределённый полнотекстовый поиск:** shard'ы индекса + роутинг запросов + агрегация результатов
* **Сложность:** O(log n) маршрутизация (DHT), O(n/p) обработка (MapReduce)

# **J. КВАНТОВЫЙ И ПРОБАБИЛИСТИЧЕСКИЙ ПОИСК**

## **1. Квантовые алгоритмы**
* **Grover's Algorithm:** поиск по неструктурированной базе за O(√N) — квадратичное ускорение
* **Идея:** оракул помечает искомый элемент; амплификация амплитуды через diffusion operator
* **Схема:** инициализация суперпозиция → O(√N) итераций (oracle + diffusion) → измерение
* **Применение:** криптография ( AES-128 за 2^64 вместо 2^128), оптимизация, SAT
* **Quantum Walk Search:** квантовое блуждание на графе; квадратичное ускорение для поиска в графах
* **Сложность:** O(√N) для Grover, O(√N) для quantum walk на полном графе

## **2. Вероятностный поиск**
* **Randomized Search:**
  * **Monte Carlo:** быстрый, но может ошибаться (вероятность ошибки < ε); повтор для уменьшения ошибки
  * **Las Vegas:** всегда правильный, но случайное время выполнения; O(n) ожидаемо
* **Probabilistic Data Structures:**
  * **Bloom filter:** множество с вероятностными false positive; O(k) на вставку/запрос, O(m) память
  * **Count-Min Sketch:** приближённые частоты элементов; O(log W) память, O(1) запрос
  * **HyperLogLog:** приближённый подсчёт уникальных элементов (cardinality); O(log log n) память
* **Применение:**.big data, stream processing, распределённые системы (membership queries)

# **K. СПЕЦИАЛИЗИРОВАННЫЕ АЛГОРИТМЫ ПОИСКА**

## **1. Поиск в сжатых данных**
* **Elias-Fano encoding:** компактное представление возрастающей последовательности; O(1) access, O(log n) search
* **Succinct data structures:** деревья, графы, суффиксные массивы с размером, близким к информационной энтропии
* **Wavelet tree:** поиск в сжатом массиве; rank/select за O(log σ), где σ — алфавит
* **Применение:** полнотекстовый поиск, суффиксные структуры, геномика

## **2. Поиск с учётом контекста**
* **Semantic search:** поиск по значению, а не по ключевым словам; word embeddings, transformers
* **Federated Search:** агрегация результатов из нескольких источников; ранжирование через learning-to-rank
* **Применение:** поисковые системы, рекомендации,问答系统 (QA)
