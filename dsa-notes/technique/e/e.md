# **A. ТЕОРЕТИЧЕСКИЕ ОСНОВЫ**

## **1. Матроиды (жадная оптимальность)**
* **Определение:** матроид — пара (E, I), где E — конечное множество, I — система независимых подмножеств, удовлетворяющая: (1) ∅ ∈ I; (2) A ∈ I, B ⊆ A ⟹ B ∈ I (гередитарность); (3) A, B ∈ I, |A| < |B| ⟹ ∃x ∈ B \ A: A ∪ {x} ∈ I (свойство обмена)
* **Теорема (Rado-Edmonds):** если w: E → ℝ₊ — функция веса, то жадный алгоритм (наращиваем максимальное независимое множество, всегда добавляя элемент максимального веса) находит maximum-weight independent set
* **Примеры матроидов:**
  * **Graphic matroid:** E = рёбра графа, I = системы без циклов (леса). Жадный → Maximum Spanning Tree (Kruskal)
  * **Transversal matroid:** E = элементы, I = системы, на которые есть инъекция в другое множество
  * **Linear matroid:** E = векторы, I = линейно независимые подмножества
* **Почему важно для олимпиад:** если задача сводится к матроиду — жадный гарантированно оптимален; если нет — нужен ДП или приближения

## **2. Свойство оптимальной подструктуры**
* **Определение:** оптимальное решение задачи содержит оптимальные решения для подзадач (связь `dynamic.md`)
* **Жадное свойство (greedy-choice property):** локально оптимальный выбор на первом шаге не ухудшает глобальное решение — существует оптимум, содержащий этот выбор
* **Когда жадный работает:** оптимальная подструктура + greedy-choice property → жадный алгоритм корректен
* **Когда НЕ работает:** отсутствие greedy-choice property → нужен ДП (например, 0/1 Knapsack vs Fractional Knapsack)
* **Связь с матроидами:** в матроиде оба свойства гарантированы для задачи о максимальном независимом множестве

## **3. Когда жадный НЕ работает (олимпиадный паттерн)**
* **0/1 Knapsack:** предметы нельзя дробить → нужен ДП (`dynamic.md` E)
* **Set Cover (точный):** NP-трудная задача; жадный — приближение O(ln n)
* **Travelling Salesman:** жадный (nearest neighbour) — плохое приближение
* **General Coin Change:** произвольные номиналы → ДП

## **4. Доказательства корректности жадных (олимпиадный паттерн)**
* **Обмен (exchange argument):** предположить оптимум, показать, что замена на жадный выбор не ухудшает
* **Индукция:** база — пустое множество; шаг — жадный выбор + индуктивное предположение
* **Матроид:** если задача — поиск максимального независимого множества в матроиде, жадный оптимален (теорема Радо-Эдмондса)

# **B. ЗАДАЧИ РАСПИСАНИЙ**

## **3. Activity Selection Problem**
* **Задача:** даны n активностей с началом start и концом end; выбрать максимальное число непересекающихся
* **Жадная стратегия:** сортировка по endTime →贪心 выбор активностей с наименьшим endTime, не пересекающихся с выбранными
* **Корректность:** доказательство через обмен: замена любой активности на активность с меньшим endTime не ухудшает решение
* **Сложность:** O(n log n) из-за сортировки, O(n) после сортировки
* **Реализация:** `activity_selection` — сортировка по endTime, проход с выбором

## **4. Minimum Waiting Time**
* **Задача:** n задач с временем выполнения dur[i]; минимизировать суммарное время ожидания (каждая задача ждёт время выполнения всех предыдущих)
* **Жадная стратегия:** сортировка по времени выполнения ( Shortest Job First )
* **Формула:** время ожидания i-й задачи = Σ_{j<i} dur[p[j]], где p — перестановка
* **Оптимальность:** доказательство через обмен соседних элементов (связь с VII.C — планировщики ОС)
* **Сложность:** O(n log n)

## **5. Optimal Merge Pattern**
* **Задача:** n отсортированных файлов размеров sizes[i]; слияние двух файлов стоит сумму их размеров; найти порядок слияния с минимальной стоимостью
* **Жадная стратегия:** всегда сливать два наименьших файла ( min-heap ). Это то же, что построение дерева Хаффмана (IV.B)
* **Связь:** дерево Хаффмана — бинарное дерево, где листья — файлы, внутренние узлы — слияния; стоимость дерева = суммарная стоимость слияний
* **Сложность:** O(n log n) через priority_queue
* **Реализация:** `optimal_merge_pattern` — через min-heap (переиспользуем priority_queue из `struct.md` IV)

## **6. Smallest Range Covering Elements from K Lists**
* **Задача:** k отсортированных списков; найти минимальный диапазон [a, b], содержащий по крайнему мере один элемент из каждого списка
* **Жадная стратегия:** min-heap с k указателями (по одному на список); текущий диапазон = [min, max] в heap; сдвигаем указатель минимального элемента → обновляем max
* **Сложность:** O(N log k), где N — суммарное число элементов
* **Реализация:** `smallest_range` — через min-heap

## **7. Задача Джонсона с одним станком**
* **Задача:** n заданий с временем выполнения dur[i]; минимизировать суммарное время ожидания (каждое задание ждёт время выполнения всех предыдущих)
* **Решение:** сортировка по убыванию dur (Shortest Job First) — оптимально для минимизации суммарного времени ожидания (аналог Minimum Waiting Time)
* **Формула:** время ожидания i-й задачи = Σ_{j<i} dur[p[j]], где p — перестановка
* **Сложность:** O(n log n)
* **Реализация:** `johnson_one_machine`

## **8. Задача Джонсона с двумя станками**
* **Задача:** n заданий, каждое проходит через станцию A (время a[i]) затем станцию B (время b[i]); найти порядок минимизации общего Makespan
* **Жадная стратегия (правило Джонсона):** разделить задания на две группы: G1 = {i : a[i] ≤ b[i]}, G2 = {i : a[i] > b[i]}; отсортировать G1 по возрастанию a[i], G2 по убыванию b[i]; финальный порядок = G1 + G2
* **Корректность:** доказательство через обмен邻接ных элементов — если нарушено правило Джонсона, swap уменьшает Makespan
* **Сложность:** O(n log n)
* **Реализация:** `johnson_two_machines`

## **9. Оптимальный выбор заданий при известных временах завершения и длительностях**
* **Задача:** n заданий с длительностью dur[i] и дедлайном deadline[i]; выбрать максимум заданий, каждое завершается не позже дедлайна
* **Жадная стратегия:** сортировка по deadline по возрастанию; проход с приоритетной очередью (max-heap по длительности); если текущее задание не помещается — заменяем самое длительное из выбранных
* **Альтернатива:** сортировка по deadline +贪心 выбор (если все dur[i] = 1 — сводится к Activity Selection)
* **Сложность:** O(n log n)
* **Реализация:** через приоритетную очередь

## **10. Паттерн: сортировка + жадный выбор (олимпиадный)**
* **Схема:** отсортировать по критерию (endTime, плотность, размер) → линейный проход с выбором
* **Применения:** Activity Selection (B.3), Fractional Knapsack (D.14), Minimum Waiting Time (B.4), Johnson one machine (B.7)

## **11. Паттерн: priority_queue + жадный выбор (олимпиадный)**
* **Схема:** min-heap для извлечения минимума на каждом шаге
* **Применения:** Optimal Merge (B.5), Smallest Range (B.6), внешняя сортировка (I.D.24)

# **C. РАЗМЕН МОНЕТ И ПОКУПКИ**

## **10. Minimum Coin Change (жадный)**
* **Задача:** номиналы coins[] и сумма target; минимизировать число монет
* **Жадная стратегия:** брать максимальный номинал ≤ остаток; повторять
* **Когда корректен:** только для систем номиналов, где каждый номинал делится на предыдущий (канонические системы, например [1, 5, 10, 25])
* **Когда НЕ корректен:** произвольные номиналы → нужен ДП (`dynamic.md`). Пример: coins = [1, 3, 4], target = 6; жадный даст [4, 1, 1] (3 монеты), оптимум [3, 3] (2 монеты)
* **Сложность:** O(n) после сортировки, где n — число номиналов
* **Реализация:** `minimum_coin_change_greedy`

## **11. Best Time to Buy and Sell Stock**
* **Задача:** prices[i] — цена акции в день i; найти максимальную прибыль от одной покупки и одного продажи (купить до продажи)
* **Жадная стратегия:** один проход: минимум на текущий момент ( min_so_far ) и максимальная прибыль ( max_profit = max(max_profit, price - min_so_far))
* **Обобщение:** параметр max_transactions (k транзакций) → ДП (`dynamic.md`); без ограничений на транзакции → сумма всех положительных разностей
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `best_time_buy_sell_stock`

## **12. Best Time to Buy and Sell Stock II (множественные сделки)**
* **Задача:** prices[i] — цена акции в день i; можно совершать неограниченное число сделок (купить-продать); максимизировать прибыль
* **Жадная стратегия:** суммировать все положительные разности consecutive上涨: profit = Σ max(0, prices[i] − prices[i−1])
* **Корректность:** если цена растёт от дня d₁ до дня d₂, любая промежуточная сделка не ухудшает результат; если цена падает — не берём
* **Сложность:** O(n) время, O(1) память
* **Реализация:** `best_time_buy_sell_stock_ii`

## **13. Gas Station**
* **Задача:** circle[] — количество газа в каждой станции, cost[] — стоимость проезда до следующей; найти начальную станцию, с которой можно объехать весь круг
* **Жадная стратегия:** если суммарный газ ≥ суммарных затрат — решение существует; начальная станция = индекс, с которого накопленный баланс не падает ниже нуля ( total_tank и current_tank )
* **Корректность:** инвариант: если доехали от start до i с дефицитом, то ни одна станция между start и i не может быть начальной
* **Сложность:** O(n)
* **Реализация:** `gas_station`

# **D. РЮКЗАК И ПОКРЫТИЕ**

## **14. Fractional Knapsack**
* **Задача:** n предметов с весом w[i] и стоимостью v[i]; рюкзак вместимостью W; можно брать дробную часть предмета
* **Жадная стратегия:** сортировка по убыванию стоимости на единицу веса ( v[i]/w[i] );贪心 заполнять
* **Корректность:** доказательство: замена любой доли предмета с меньшей плотностью на предмет с большей плотностью увеличивает стоимость
* **Сравнение:** в отличие от 0/1 Knapsack (ДП, `dynamic.md`), дробный рюкзак допускает жадное решение
* **Сложность:** O(n log n) из-за сортировки
* **Реализация:** `fractional_knapsack` — параметризованная функция плотности

## **15. Greedy Set Cover**
* **Задача:** множество X и семейство подмножеств S; найти минимальное подмножество S', покрывающее X
* **Жадная стратегия:** на каждом шаге выбирать множество, покрывающее наибольшее число ещё не покрытых элементов
* **Аппроксимация:** O(ln n) — оптимально для P ≠ NP (Raz-Safra, Lund-Mosseri-Raz)
* **Почему ln n:** жадный может выбрать log n «половинок» вместо одной полной; это худший случай
* **Сложность:** O(|X| · |S|) в простейшей реализации; с приоритетной очередью O(|S| log |X|)
* **Реализация:** `greedy_set_cover`

## **16. Recursive Approach Knapsack (рекурсивный вариант)**
* **Задача:** 0/1 Knapsack через рекурсию с мемоизацией (как альтернатива жадному Fractional Knapsack)
* **Рекуррентность:** knap(i, W) = max(knap(i−1, W), v[i] + knap(i−1, W−w[i])) если w[i] ≤ W
* **Связь с ДП:** то же, что и bottom-up ДП (`dynamic.md`), но в рекурсивной форме; мемоизация — таблица dp[i][W]
* **Сложность:** O(nW) время и память (с мемоизацией)
* **Реализация:** через рекурсию + unordered_map или vector<vector>

## **17. Fractional Knapsack 2 (альтернативная реализация)**
* **Задача:** то же, что D.14, но с явным отслеживанием долей каждого предмета
* **Отличие от D.14:** возвращает не только общую стоимость, но и вектор<pair<int, double>> — (индекс предмета, доля)
* **Жадная стратегия:** та же — сортировка по плотности; заполняем до W
* **Сложность:** O(n log n)
* **Реализация:** `fractional_knapsack_with_shares`

## **18. Fractional Cover Problem (дробная задача покрытия)**
* **Задача:** множество X, семейство подмножеств S с весами w[i]; выбрать дробные доли подмножеств (x[i] ∈ [0,1]) так, чтобы каждый элемент был покрыт суммарной долей ≥ 1, при минимизации Σ w[i]·x[i]
* **Решение:** это линейная задача оптимальности (LP); жадная эвристика — жадный Set Cover с дробными долями
* **Связь:** обобщение Set Cover (D.15); LP-релаксация → приближение O(ln n)
* **Сложность:** O(|X| · |S| · log |X|) для LP-релаксации
* **Реализация:** `fractional_cover`

## **19. Поиск подотрезка с максимальной/минимальной суммой за O(N)**
* **Задача:** дан массив a[]; найти подотрезок [l, r] с максимальной (или минимальной) суммой
* **Алгоритм Кадана (максимум):** один проход: current_sum = max(a[i], current_sum + a[i]); best_sum = max(best_sum, current_sum)
* **Алгоритм Кадана (минимум):** аналогично, заменяем max на min
* **Сложность:** O(N) время, O(1) память
* **Реализация:** `kadane_max_sum`, `kadane_min_sum`
