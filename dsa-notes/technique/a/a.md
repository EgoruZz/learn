# **I. СОРТИРОВКИ**

> **Архитектура:** `Sortings` (a.cpp) — базовый класс всей ветки technique. Собственной арифметики не имеет. Закладывает фундамент: сортировка — база для бинарного поиска (II), жадных алгоритмов (V), планирования (VII), а также для ряда структур данных (`struct.md` — BST, heap, treap). Все квадратичные сортировки — on-place, стабильные или нестабильные; O(n log n) — divide & conquer или кучи; линейные — ограничения на ключи. Все методы параметризуются компаратором `cmp` и диапазоном `[lo, hi)`.
>
> **Связи:** быстрая сортировка (partition) — та же операция, что Dutch National Flag (`struct` I.A.11) и QuickSelect (II.E); слияние (merge) — база для Merge Sort и для слияния списков (`struct` I.B.7); пирамидальная сортировка использует бинарную кучу (`struct` IV); Topological Sort — `graph.md`; Counting/Radix — ограничения на ключи (мост в IV — сжатие); стабильность сортировки — ключевое свойство для парных данных и radix-сортировки.
>
> **Олимпиадные паттерны:**
> * **Сортировка с нестандартным ключом (decorate-sort-undecorate):** вместо сортировки по значению — сортировка по `key(x)`: создаётся вектор пар `(key(x), x)`, сортируется, затем извлекаются только значения. Произвольная функция ключа `key: T → K`, где K — упорядоченный тип.
> * **Стабильность сортировки:** равные элементы сохраняют исходный порядок. Стабильные: Bubble, Insertion, Merge, Counting, Radix, Tim. Нестабильные: Selection, Quick, Heap, Shell. Важно при сортировке по нескольким ключам (radix sort, сортировка таблиц).
> * **Сортировка как инструмент:** предобработка — сортировка + два указателя (II), сортировка + бинарный поиск (II.B); координатное сжатие — сортировка уникальных значений → замена на индексы (связь `struct` V.C, IV.D); группировка — сортировка → проход с подсчётом равных подряд.

# **A. КВАДРАТИЧНЫЕ СОРТИРОВКИ O(n²)**

## **1. Bubble Sort**
* **Определение:** проходы по массиву, обмен соседних элементов при нарушении порядка; за каждый проход «всплывает» минимум/максимум на своё место
* **Почему O(n²):** n−1 проходов, каждый до n−1 сравнений (в худшем случае)
* **Обобщение:** параметр компаратора `cmp(a, b)` — произвольный строгий порядок; ранний выход при отсутствии обменов (оптимизация «флаг»)
* **Сложность:** O(n²) худший/средний, O(n) лучший (с флагом, отсортированный массив), O(1) памяти, стабильная
* **Реализация:** `bubble_sort` — обобщённая с флагом раннего выхода и параметром диапазона `[lo, hi)`
* **Связь:** наивная база; Patience Sort использует бинарный поиск вместо обменов

## **2. Selection Sort**
* **Определение:** на каждом шаге найти минимум в `[i, n)` и поменять с `a[i]`
* **Почему O(n²):** n−1 поиск минимума (суммарно n(n−1)/2 сравнений), но минимум обменов: O(n)
* **Обобщение:** параметр компаратора; вариант с нахождением и минимума, и максимума за один проход (оптимизация: 2n/3 сравнений вместо n)
* **Сложность:** O(n²) всегда, O(n) обменов, O(1) памяти, нестабильная
* **Реализация:** `selection_sort` — с нахождением min и max за проход (оптимизация Two-Phase)
* **Связь:** нестабильность — важный контраст с Bubble/Insertion

## **3. Insertion Sort**
* **Определение:** каждый элемент вставляется в отсортированный префикс (сдвиги вправо)
* **Почему важна:** лучшая для почти отсортированных массивов (O(n + d), где d — число инверсий); база для Tim Sort и Shell Sort
* **Варианты:**
  * **Binary Insertion Sort:** вставка через бинарный поиск (O(n²) сравнений, но O(n log n) перемещений) — мост в II
  * **Recursive Insertion Sort:** рекурсивная формулировка (база для анализа)
* **Обобщение:** компаратор, порог переключения на другую сортировку (гибрид)
* **Сложность:** O(n²) худший, O(n + d) почти отсортированный, O(1) памяти, стабильная
* **Реализация:** `insertion_sort`, `binary_insertion_sort`, `recursive_insertion_sort`
* **Связь:** Tim Sort (D.16) использует Insertion Sort для коротких блоков

# **B. ЭФФЕКТИВНЫЕ СОРТИРОВКИ O(n log n)**

## **4. Merge Sort**
* **Определение:** divide & conquer: массив делится пополам, каждая половина сортируется рекурсивно, затем две половины сливаются
* **Рекуррентность:** T(n) = 2T(n/2) + O(n) → O(n log n) (мастер-теорема, `analysis.md`)
* **Почему O(n) на слиянии:** два указателя, каждый элемент проходится один раз
* **Почему стабильна:** при равных элементах левый берётся раньше правого
* **Варианты:**
  * **Iterative Merge Sort:** bottom-up, слияние блоков 1→2→4→…→n (без рекурсии)
  * **Merge Insertion Sort (Ford-Johnson):** для малых n использует Insertion Sort, минимизирует число сравнений
* **Обобщение:** компаратор; буфер для слияния (O(n) доп. памяти или in-place с O(1) доп. — сложнее)
* **Сложность:** O(n log n) всегда, O(n) дополнительной памяти, стабильная
* **Реализация:** `merge_sort` (рекурсивный), `merge_sort_iter` (итеративный), `merge` (слияние двух отсортированных частей)
* **Связь:** слияние списков — `struct` I.B.7; сортировка слиянием — база для External Sort (D.10)

## **5. Heap Sort**
* **Определение:** построить max-heap из массива, затем n раз извлекать максимум (помещая в конец)
* **Этапы:** 1) build heap за O(n) (снизу вверх); 2) n extract-max за O(log n) каждый → O(n log n)
* **Почему O(n) на построение:** суммарная стоимость sift-down по уровням — геометрическая прогрессия
* **Обобщение:** параметр компаратора (max-heap / min-heap); индексная арифметика `parent(i) = (i−1)/2`, `left(i) = 2i+1`, `right(i) = 2i+2` — переиспользуется из `struct` IV
* **Сложность:** O(n log n) всегда, O(1) памяти, нестабильная
* **Реализация:** `heap_sort` (с `sift_down` и `build_heap`)
* **Связь:** бинарная куча — `struct` IV; приоритетная очередь — `std::priority_queue`

## **6. Quick Sort**
* **Определение:** choose pivot → partition (<L, =L, >L) → рекурсия на части
* **Рекуррентность (средний):** T(n) = T(n/2) + T(n/2) + O(n) → O(n log n); худший (отсортированный): T(n) = T(n−1) + O(n) → O(n²)
* **Оптимизации:**
  * **Median-of-three:** pivot = median(a[lo], a[mid], a[hi]) — отсечение худшего случая
  * **Randomized:** pivot выбирается случайно — ожидаемое O(n log n)
  * **3-way partition (Dutch National Flag):** обработка дубликатов за O(n) — переиспользует `struct` I.A.11
  * **Intro Sort:** переключение на Heap Sort при глубине > c·log n — гарантия O(n log n)
* **Обобщение:** компаратор; порог для Insertion Sort (малые подмассивы)
* **Сложность:** O(n log n) ожидаемо, O(n²) худший (с оптимизациями — O(n log n) гарантированно), O(log n) стека (хвостовая рекурсия)
* **Реализация:** `quick_sort`, `quick_sort_3way`, `partition` (Lomuto / Hoare)
* **Связь:** partition — та же операция, что Dutch Flag; QuickSelect (II.E) — partial quicksort

# **C. ЛИНЕЙНЫЕ СОРТИРОВКИ O(n + k)**

## **7. Counting Sort**
* **Определение:** для целых ключей из диапазона [min_key, max_key]: подсчёт частот → префиксные суммы → расстановка
* **Почему O(n + k):** k = max_key − min_key + 1; два прохода по k (подсчёт +.prefix) и один по n (расстановка)
* **Стабильность:** при записи в обратном порядке (от конца) — стабильная
* **Обобщение:** диапазон [lo_key, hi_key] как параметр (не обязательно от 0); компаратор не нужен — сортировка по значению ключа
* **Сложность:** O(n + k) времени, O(n + k) памяти, стабильная
* **Реализация:** `counting_sort` — с автоматическим определением диапазона по массиву
* **Связь:** база для Radix Sort; Dutch National Flag — частный случай для k=3

## **8. Radix Sort**
* **Определение:** сортировка по разрядам: от младшего (LSD) или старшего (MSD) к младшему, используя стабильную сортировку (Counting Sort) как подпрограмму
* **LSD (Least Significant Digit):** фиксированное число разрядов `d`; проход от разряда 0 до d−1; O(d·(n + b)), b — основание
* **MSD (Most Significant Digit):** рекурсивный: сначала по старшему разряду, затем рекурсия внутри каждого бакета; полезен для строк
* **Почему O(d·(n + b)):** d проходов Counting Sort; при фиксированном b и d = O(log_b(max_key)) — линейная
* **Обобщение:** основание `b` (radix) как параметр (typical: 256 для байтов); число разрядов `d` — из данных; ключ — произвольная функция `get_key(element, digit)`
* **Сложность:** O(d·(n + b)) времени, O(n + b) памяти, стабильная
* **Реализация:** `radix_sort_lsd`, `radix_sort_msd`
* **Связь:** суффиксные массивы (`string.md`) строятся через radix sort

## **9. Bucket Sort**
* **Определение:** для данных с известным распределением: разбиение на `n` бакетов → сортировка внутри каждого (Insertion Sort) → слияние
* **Почему O(n) в среднем:** при равномерном распределении каждый бакет содержит O(1) элементов
* **Обобщение:** функция распределения `bucket_fn(key) → [0, n)` как параметр; порог для переключения сортировки внутри бакета
* **Сложность:** O(n) среднее (равномерное распределение), O(n²) худшее (все в одном бакете), O(n) памяти
* **Реализация:** `bucket_sort`
* **Связь:** Pigeonhole Sort — частный случай (бакеты размера 1)

# **D. ДОПОЛНИТЕЛЬНЫЕ СОРТИРОВКИ**

## **10. Shell Sort**
* **Определение:** Insertion Sort с убывающими шагами gap: gap = n/2, n/4, ..., 1; на каждом шаге — Insertion Sort по подмассивам с шагом gap
* **Почему эффективен:** элементы быстро перемещаются на большие расстояния при большом gap; финальная Insertion Sort (gap=1) работает почти на отсортированных
* **Обобщение:** последовательность gap (Shell: n/2, Knuth: (3^k−1)/2, Ciura: эмпирическая)
* **Сложность:** O(n^{1+ε}) в зависимости от последовательности gap; O(n^{3/2}) для经典的 Shell; O(1) памяти
* **Реализация:** `shell_sort`
* **Связь:** обобщение Insertion Sort (A.3)

## **11. Cocktail Shaker Sort**
* **Определение:** Bidirectional Bubble Sort: проходы чередуются (слева направо, справа налево)
* **Преимущество:** корректно обрабатывает «черепахи» (маленькие элементы в конце)
* **Сложность:** O(n²), O(1) памяти, стабильная
* **Реализация:** `cocktail_shaker_sort`

## **12. Comb Sort**
* **Определение:** Bubble Sort с убывающим gap (начиная с n/1.3); gap уменьшается до 1
* **Почему лучше Bubble:** устраняет «черепахи» быстрее
* **Сложность:** O(n²) худший, O(n log n) средний, O(1) памяти
* **Реализация:** `comb_sort`

## **13. Cycle Sort**
* **Определение:** на основе циклов перестановки: каждый элемент перемещается напрямую в позицию назначения
* **Почему оптимален по записям:** минимум записей в память (n−c записей, c — число циклов)
* **Сложность:** O(n²), O(1) памяти, нестабильная; оптимальна по числу записей
* **Реализация:** `cycle_sort`

## **14. Strand Sort**
* **Определение:** последовательно вытягивает отсортированные подпоследовательности (strands) и сливает их
* **Почему интересен:** адаптивная, стабильная, on-place (но O(n) доп. памяти для слияний)
* **Сложность:** O(n²) худший, O(n log n) средний
* **Реализация:** `strand_sort`

## **15. Patience Sort**
* **Определение:** раскладывает элементы по «стопкам» (стекам): каждый элемент идёт на левую стопку, вершина которой ≥ элемента (поиск через бинарный поиск); затем n-ways merge стопок
* **Почему O(n log n):** число стопок ≤ √n (для отсортированных), но в худшем O(n); merge через k-ary heap
* **Обобщение:** параметр структуры для поиска стопки (binsearch → O(n log n))
* **Сложность:** O(n log n) время, O(n) памяти
* **Реализация:** `patience_sort`
* **Связь:** длина LIS = число стопок (на strict increasing); Longest Increasing Subsequence — связь `dynamic.md`

## **16. Tim Sort**
* **Определение:** гибрид Merge Sort + Insertion Sort: массив разбивается на «runs» (возрастающие/убывающие подмассивы), runs сортируются Insertion Sort, затем сливаются
* **Почему на практике лучшая:** адаптивна к частично отсортированным данным; O(n) на уже отсортированных
* **Обобщение:** порог `MIN_RUN` (typically 32–64); min-heap для merge k runs
* **Сложность:** O(n log n) худший, O(n) лучший, стабильная
* **Реализация:** `tim_sort`
* **Связь:** использует Insertion Sort (A.3) и Merge Sort (B.4)

## **17. Intro Sort**
* **Определение:** Quick Sort с переключением на Heap Sort при глубине > c·log n; Insertion Sort для малых подмассивов
* **Почему O(n log n) гарантированно:** Heap Sort отсекает худший случай Quick Sort
* **Реализация:** `intro_sort`
* **Связь:** гибрид Quick + Heap + Insertion

## **18. Gnome Sort**
* **Определение:** Insertion Sort, но сдвиги делаются обменами соседних элементов (как гном移动)
* **Сложность:** O(n²), O(1) памяти, стабильная
* **Реализация:** `gnome_sort`

## **19. Odd-Even Sort (Brick Sort)**
* **Определение:** параллельная сортировка: чередующиеся фазы (odd: сравнение пар (1,2), (3,4),...; even: (0,1), (2,3),...)
* **Почему для параллелизма:** все сравнения в фазе независимы
* **Сложность:** O(n²), O(1) памяти
* **Реализация:** `odd_even_sort`

## **20. Bitonic Sort**
* **Определение:** сортировка сети: битонная последовательность (сначала возрастает, затем убывает) сортируется через сеть comparator'ов
* **Почему для GPU/FPGA:** фиксированная структура сравнений (параллелизм)
* **Сложность:** O(n log²n) comparisons, O(log²n) глубина сети
* **Реализация:** `bitonic_sort`
* **Связь:** сеть Бэтчера (Batcher's odd-even merge sort)

## **21. Topological Sort**
* **Определение:** линейная упорядоченность вершин DAG: для каждого ребра u→v, u идёт раньше v
* **Алгоритмы:**
  * **Kahn (BFS):** удаление вершин с in-degree = 0
  * **DFS:** reverse postorder
* **Сложность:** O(V + E)
* **Реализация:** `topological_sort_kahn`, `topological_sort_dfs`
* **Связь:** `graph.md` — полный разбор; планирование задач (VII)

## **22. Dutch National Flag Sort**
* **Определение:** для массива с 3 значениями (0, 1, 2) — one-pass сортировка через три указателя
* **Реализация:** переиспользует `dutch_flag` из `struct` I.A.11 (не переписывается)
* **Связь:** 3-way partition Quick Sort

## **23. Bead Sort (Gravity Sort)**
* **Определение:** имитация гравитации: каждый элемент — столбик бусин; бусины «падают» вниз
* **Сложность:** O(n · max_val) время, O(n · max_val) памяти; для целых неотрицательных
* **Реализация:** `bead_sort`

## **24. Bogo Sort**
* **Определение:** случайная перестановка + проверка отсортированности; повтор до победы
* **Сложность:** O((n+1)!) ожидаемо — наихудшая из всех сортировок
* **Реализация:** `bogo_sort`

## **25. Circle Sort**
* **Определение:** рекурсивное сравнение и обмен крайних элементов по кругу
* **Сложность:** O(n log n) средний, O(n²) худший
* **Реализация:** `circle_sort`

## **26. Cyclic Sort**
* **Определение:** для массива [1..n]: каждый элемент ставится на позицию a[i]−1 циклом
* **Сложность:** O(n) время, O(1) памяти — оптимально для перестановок [1..n]
* **Реализация:** `cyclic_sort`

## **27. Double Sort**
* **Определение:** сортировка двух массивов одновременно по ключу первого
* **Сложность:** O(n²) (наивно) или O(n log n) через пары
* **Реализация:** `double_sort`

## **28. Exchange Sort**
* **Определение:** обмен каждого элемента с каждым следующим при нарушении порядка
* **Сложность:** O(n²), O(1) памяти, нестабильная
* **Реализация:** `exchange_sort`

## **29. Natural Sort**
* **Определение:** Merge Sort, который находит уже отсортированные runs и сливает их
* **Сложность:** O(n log n) худший, O(n) лучший (отсортированный)
* **Реализация:** `natural_sort`

## **30. Pancake Sort**
* **Определение:** только операция reverse(a[0..k]) — «переворот сковороды»; минимум переворотов
* **Сложность:** O(n²) время, O(1) память
* **Реализация:** `pancake_sort`

## **31. Pigeonhole Sort**
* **Определение:** частный случай Counting Sort: число бакетов = число элементов (k = n)
* **Сложность:** O(n + range), O(n + range) памяти
* **Реализация:** `pigeonhole_sort`

## **32. Shrink Shell Sort**
* **Определение:** Shell Sort с последовательностью шагей Shrink: gap = gap * 2/3 + 1
* **Сложность:** O(n^{4/3}) — лучше классического Shell
* **Реализация:** `shrink_shell_sort`

## **33. Slowsort**
* **Определение:** divide & conquer: сортируем обе половины, затем сравниваем и сдвигаем — намеренно медленная
* **Сложность:** O(n^{log n}) — изначально шуточная, но доказуемо медленная
* **Реализация:** `slowsort`

## **34. Stooge Sort**
* **Определение:** если a[hi−1] < a[lo], меняем; затем рекурсия на 2/3 начала, 2/3 конца, снова 2/3 начала
* **Сложность:** O(n^{log 3 / log 1.5}) ≈ O(n^{2.709})
* **Реализация:** `stooge_sort`

## **35. Tree Sort**
* **Определение:** вставка всех элементов в BST, затем inorder-обход
* **Сложность:** O(n log n) средний, O(n²) худший (деградация BST)
* **Реализация:** `tree_sort`

## **36. Wiggle Sort**
* **Определение:** a[0] ≤ a[1] ≥ a[2] ≤ a[3] ≥ ... — «зубчатый» порядок
* **Сложность:** O(n log n) через сортировку + обмен чётных/нечётных, или O(n) через swap
* **Реализация:** `wiggle_sort`

## **37. Внешняя сортировка (External Sort)**
* **Определение:** сортировка данных, не помещающихся в память: разбиение на блоки → сортировка каждого в памяти → k-ways merge через min-heap
* **Сложность:** O(n log n log_{M/B} (n/B)) I/O операций (M — память, B — размер блока)
* **Реализация:** `external_merge_sort`
