# **A. SKIP LIST**

## **1. Определение**
* **Skip List:** многоуровневый упорядоченный список; каждый элемент может появиться на нескольких «уровнях» с вероятностью `p = 1/2`
* **Структура:** головной узел с максимальным уровнем; каждый уровень — отсортированный связный список
* **Свойство:** ожидаемая высота `O(log n)`, ожидаемое время поиска/вставки/удаления `O(log n)`

## **2. Операции**

### **2.1. Поиск**
* Начинаем с верхнего уровня, двигаемся вправо пока следующий элемент < ключа
* Спускаемся на уровень ниже, повторяем
* Сложность: `O(log n)` в среднем

### **2.2. Вставка**
* Находим позицию для вставки (как в поиске)
* Генерируем случайный уровень: `level = 1` с вероятностью `1/2`, `level = 2` с `1/4`, и т.д.
* Вставляем элемент на все уровни до выбранного

### **2.3. Удаление**
* Находим элемент на всех его уровнях, удаляем из каждого

## **3. Параметры**
* **Вероятность `p`:** обычно `1/2`; меньше `p` → выше дерево, больше памяти, быстрее поиск
* **Максимальная высота:** `log_{1/p}(n)` — гарантирует, что все элементы покрыты

# **B. ФИЛЬТР БЛУМА И ЕГО ВАРИАНТЫ**

## **1. Базовый Bloom Filter**

### **1.1. Определение**
* Структура данных для приближённой проверки принадлежности элемента множеству
* **Ответы:** «точно нет» (false negative невозможен) / «возможно есть» (false positive возможен)
* **Структура:** битовый вектор `m` бит + `k` независимых хеш-функций

### **1.2. Операции**
* **Добавление:** для каждого `hᵢ(x)` устанавливаем бит `m[hᵢ(x)] = 1`
* **Проверка:** если все `m[hᵢ(x)] == 1` → «возможно есть»; иначе → «точно нет»

### **1.3. Вероятность false positive**
* `P(fp) = (1 − e^{−kn/m})^k`
* **Оптимальное k:** `k = (m/n) · ln 2 ≈ 0.693 · m/n`
* При оптимальном `k`: `P(fp) ≈ (0.6185)^{m/n}`

### **1.4. Память**
* `m` бит на `n` элементов при заданной `P(fp)`
* **Формула:** `m = −n · ln(P(fp)) / (ln 2)²`

## **2. Counting Bloom Filter**

### **2.1. Идея**
* Вместо битов — счётчики (обычно 4 бита)
* **Удаление:** декремент счётчика для каждого `hᵢ(x)`
* **Проблема:** обнуление счётчиков может привести к ложным «точно нет»

## **3. Scalable Bloom Filter**

### **3.1. Идея**
* Динамическое добавление новых слоёв Bloom filter при росте числа элементов
* Каждый слоёв имеет свою `m` и `k`; при переполнении — новый слой с увеличенной `m`

## **4. Bloomier Filter**

### **4.1. Идея**
* Ассоциативный фильтр: каждому ключу сопоставляется значение (а не просто «есть/нет»)
* Применение: компактные таблицы с приближёнными значениями

# **C. SKETCH-СТРУКТУРЫ**

## **1. Count-Min Sketch**

### **1.1. Определение**
* Оценка частоты элементов в потоке (frequency estimation)
* **Структура:** матрица счётчиков `d × w`, `d` хеш-функций

### **1.2. Параметры**
* `w = ⌈e/ε⌉` — ширина (где `ε` — допустимая ошибка)
* `d = ⌈ln(1/δ)⌉` — число строк (где `1−δ` — вероятность гарантии)
* **Память:** `O((1/ε) · ln(1/δ))` на `n` элементов

### **1.3. Гарантия**
* Оценка `f̂(x) ≥ f(x)` (всегда завышает)
* `P(f̂(x) > f(x) + εn) ≤ δ`

### **1.4. Применения**
* Heavy hitters (top-k элементов)
* Оценка квантилей и моментов
* Мониторинг сетевого трафика

## **2. Count-Sketch**

### **2.1. Отличие от Count-Min**
* Использует знаковые хеш-функции: `+1` или `−1`
* **Свойство:** несмещённая оценка `E[f̂(x)] = f(x)` (в отличие от Count-Min, который всегда завышает)

## **3. HyperLogLog**

### **3.1. Определение**
* Оценка кардинальности (числа уникаль элементов) в потоке
* **Идея:** `m` корзин; для каждого элемента определяем корзину и считаем максимальное число ведущих нулей в хеш-коде

### **3.2. Формула**
* `Estimate = α · m² / Σ 2^{−M[j]}`, где `M[j]` — максимум ведущих нулей в корзине `j`
* `α` — поправочный коэффициент (зависит от `m`)

### **3.3. Точность**
* `误差 ≈ 1.04 / √m` (стандартное отклонение)
* При `m = 2^14 = 16384`: ошибка ~0.81%

## **4. AMS Sketch**

### **4.1. Определение**
* Оценка второго момента распределения: `F₂ = Σ fᵢ²`
* Применение: определение числа потоковых соединений, обнаружение аномалий

# **D. RESERVOIR SAMPLING**

## **1. Алгоритм**

### **1.1. Задача**
* Равномерная выборка размера `k` из потока неизвестной длины (one-pass)

### **1.2. Алгоритм Виттера (Algorithm R)**
* Первые `k` элементов → в выборку
* Для `i = k+1, k+2, ...`: заменяем случайный элемент выборки на `i`-й с вероятностью `k/i`
* **Корректность:** каждый элемент с вероятностью `k/n` оказывается в выборке

## **2. Обобщения**

### **2.1. Взвешенная выборка**
* Каждый элемент имеет вес `wᵢ`; вероятность выборки `∝ wᵢ`
* Алгоритм: замена с вероятностью `wᵢ · k / Σ_{выбранные} wⱼ`

# **E. ПРОДВИНУТЫЕ СТРУКТУРЫ**

## **1. Quotient Filter**

### **1.1. Идея**
* Эффективное использование памяти (лучше стандартного Bloom filter)
* Хранит целые хеши (а не биты), используя кластеризацию

## **2. Cuckoo Filter**

### **2.1. Преимущество перед Bloom Filter**
* Лучшая производительность при низком fp
* Поддержка удаления (в отличие от базового Bloom filter)
* Меньше памяти при малых fp
