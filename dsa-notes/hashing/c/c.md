# **A. СТРУКТУРА ХЭШ-ТАБЛИЦЫ**

## **1. Базовые понятия**

### **1.1. Определение**
* **Хэш-таблица:** структура данных, реализующая отображение `key → value` за `O(1)` в среднем
* **Принцип:** `key → h(key) → индекс массива → bucket → value`
* **Компоненты:** массив бакетов `buckets[m]`, хеш-функция `h: K → {0,...,m−1}`, стратегия разрешения коллизий

### **1.2. Фактор загрузки (load factor)**
* `α = n/m` — отношение числа элементов к числу бакетов
* **Оптимальные значения:**
    * Цепочки: `α ≤ 1` (хорошо), `α > 1` (допустимо, но медленнее)
    * Открытая адресация: `α < 0.7` (обязательно), `α ≈ 0.5` (оптимально)
* **Автоматическое рехеширование:** при `α > threshold` — увеличение размера в 2 раза + перехеширование

### **1.3. Сложность операций**
* **Средний случай:** `O(1)` — при хорошей хеш-функции и `α ≤ const`
* **Худший случай:** `O(n)` — все ключи в одном бакете (при плохой хеш-функции)
* **Амортизированная:** `O(1)` — при динамическом рехешировании

## **2. Динамическое масштабирование**

### **2.1. Рехеширование**
* При `α > threshold`: создаём новый массив в 2 раза, перехешируем все элементы
* **Стоимость:** `O(n)` — амортизированно `O(1)` на операцию (амортизированный анализ)

### **2.2. Выбор размера**
* **Простые числа:** уменьшает вероятность коллизий (при хеше `h(k) = k mod m`)
* **Степени двойки:** быстрый модуль через битовую маску `k & (m−1)`, но хуже распределение

# **B. МЕТОДЫ РАЗРЕШЕНИЯ КОЛЛИЗИЙ**

## **1. Separate Chaining (Цепочки)**

### **1.1. Идея**
* Каждый бакет — связный список (или другой контейнер) всех элементов с одинаковым хешем
* **Вставка:** `O(1)` — добавление в голову списка
* **Поиск:** `O(1 + α)` — перебор цепочки
* **Удаление:** `O(1 + α)` — поиск + удаление из списка

### **1.2. Оптимизации**
* **Упорядочивание цепочки:** поддержка отсортированного порядка (для range-запросов)
* **Объединение списков:** при большом `α` — переключение на дерево (как в Java 8 HashMap)

## **2. Open Addressing (Открытая адресация)**

### **2.1. Общая идея**
* Все элементы хранятся в самом массиве (без ссылок)
* При коллизии: ищем следующую свободную ячейку по some пробной последовательности

### **2.2. Linear Probing (Линейное пробирование)**
* `h(k, i) = (h(k) + i) mod m` — последовательный поиск
* **Проблема:** primary clustering (скопления занятых ячеек)
* **Средняя длина поиска:** `≈ (1 + 1/(1−α))/2`

### **2.3. Quadratic Probing (Квадратичное пробирование)**
* `h(k, i) = (h(k) + c₁·i + c₂·i²) mod m`
* **Преимущество:** уменьшение кластеризации
* **Ограничение:** при `m` — степень двойки и `c₂ = 0`: проверяются только чётные/нечётные позиции

### **2.4. Double Hashing (Двойное хеширование)**
* `h(k, i) = (h₁(k) + i·h₂(k)) mod m`
* **Преимущество:** хорошее распределение (каждый ключ имеет свою пробную последовательность)
* **Вторая хеш-функция:** `h₂(k) = 1 + (k mod (m−1))` (гарантирует полный перебор)

### **2.5. Cuckoo Hashing (Хэширование кукушки)**
* Две хеш-функции `h₁`, `h₂`; каждый ключ может быть в одном из двух бакетов
* **Вставка:** если оба бакета заняты — «выселяем» текущий жильца (он ищет свой второй бакет)
* **Гарантия:** `O(1)` worst-case поиск (максимум 2 проверки)
* **Проблема:** циклы при выселении → перехеширование с новыми `h₁`, `h₂`

# **C. ПРОДВИНУТЫЕ РЕАЛИЗАЦИИ**

## **1. Perfect Hashing**

### **1.1. Идея**
* Хеш-таблица без коллизий для **фиксированного** набора ключей
* **Двухуровневая схема:** внешний массив + внутренние таблицы для каждого бакета
* **Сложность:** `O(1)` worst-case поиск, `O(n)` память

## **2. Universal Hashing**

### **2.1. Семейство хеш-функций**
* `H = {h_{a,b}(x) = ((ax + b) mod p) mod m}` — случайный выбор `a ∈ {1,...,p−1}`, `b ∈ {0,...,p−1}`
* **Свойство:** для `x ≠ y`: `P(h(x) = h(y)) ≤ 1/m` — равномерное распределение коллизий

### **2.2. Применение**
* Защита от враждебных входов (adversarial attacks)
* Гарантия средней сложности `O(1)` для любого распределения ключей

## **3. Robin Hood Hashing**

### **3.1. Идея**
* При вставке: если новый элемент «беднее» (дальше от своего хеша), чем текущий жилец — меняем их местами
* **Результат:** уменьшение дисперсии длины поиска (все элементы примерно на одинаковом расстоянии от своего хеша)

## **4. Hopscotch Hashing**

### **4.1. Идея**
* Каждая ячейка имеет «окно» из `H` соседних позиций
* При коллизии: ищем свободную ячейку в окне; если нет — «прыгаем» (hop) соседние элементы
* **Преимущество:** хорошая кэш-локальность (элементы рядом)

# **D. ТЕСТИРОВАНИЕ И БЕНЧМАРКИНГ**

## **1. Метрики производительности**
* **Throughput:** операций в секунду (insert/get/delete)
* **Latency:** время одной операции (p50, p99, p999)
* **Memory overhead:** память на элемент (байт/элемент)

## **2. Сравнение стратегий**
* При `α < 0.5`: все методы примерно одинаковы
* При `α > 0.7`: цепочки лучше открытой адресации
* При `α → 1`: открытая адресация деградирует экспоненциально
