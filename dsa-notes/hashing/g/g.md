# **A. АЛГОРИТМИЧЕСКИЕ ОПТИМИЗАЦИИ**

## **1. Lookup Tables**

### **1.1. Идея**
* Предвычисление результатов для всех возможных входов
* **Таблицы:** для 8-битных значений — 256 элементов; для S-блоков — 16/256 элементов
* **Торговля:** память vs скорость (L1 cache ~32KB, L2 ~256KB)

### **1.2. Применение**
* CRC32: таблица из 256 полиномов
* Base64: таблица преобразования символов
* S-блоки SHA/AES: предвычисленные таблицы

## **2. Loop Unrolling**

### **2.1. Идея**
* Развертывание циклов: вместо `for(i=0;i<4;i++)` → 4 явных тела
* **Преимущество:** уменьшение накладных расходов на управление циклом
* **Недостаток:** увеличение размера кода (icache pressure)

## **3. Branchless Programming**

### **3.1. Идея**
* Устранение условных переходов через арифметику/битовые операции
* **Пример:** `result = (condition) ? a : b` → `result = b ^ ((a ^ b) & (-condition))`
* **Преимущество:** нет промахов предсказания ветвления (branch misprediction ~15-20 циклов)

# **B. АППАРАТНЫЕ ОПТИМИЗАЦИИ**

## **1. SIMD (AVX2/AVX-512)**

### **1.1. Идея**
* Векторизация: обработка 4/8/16 значений за инструкцию
* **AVX2:** 256-битные регистры (8 × float32 или 4 × int64)
* **AVX-512:** 512-битные регистры

### **1.2. Применение в хешировании**
* Параллельное вычисление хешей для нескольких ключей
* Ускорение lookup-table через gather-инструкции

## **2. Аппаратные ускорения**

### **2.1. AES-NI**
* Нативные инструкции для AES: `AESENC`, `AESDEC`, `AESKEYGENASSIST`
* Ускорение: ~10x по сравнению с программной реализацией

### **2.2. SHA-NI**
* Нативные инструкции для SHA-256: `SHA256RNDS2`, `SHA256MSG1/2`
* Ускорение: ~3-5x для SHA-256

### **2.3. CRC32**
* Нативная инструкция `CRC32` для вычисления CRC32
* Ускорение: ~10x по сравнению с таблицей

## **3. Кэш-оптимизация**

### **3.1. Принципы**
* **Локальность данных:** обработка смежных данных (кэш-линии 64 байта)
* **Предвыборка:** `__builtin_prefetch` для данных, которые понадобятся через итерацию
* **Выравнивание:** данные выровнены по границе кэш-линии (64 байта)

### **3.2. Применение**
* Хеш-таблицы: бакеты выровнены по кэш-линии
* Bulk-хеширование: обработка блоками по размеру кэша

# **C. РАСПРЕДЕЛЁННЫЕ И ПАРАЛЛЕЛЬНЫЕ РЕАЛИЗАЦИИ**

## **1. Многопоточные хеш-функции**

### **1.1. Lock-free хеш-таблицы**
* Атомарные операции: `compare_exchange_strong`, `fetch_add`
* **Проблемы:** ABA-проблема, memory ordering

### **1.2. Sharding**
* Разбиение ключей по `n` шардам: `shard = h(key) % n`
* Каждый шард — независимая хеш-таблица

## **2. GPU ускорение**

### **2.1. Массовый параллелизм**
* CUDA/OpenCL: тысячи потоков одновременно
* **Применение:** перебор паролей, майнинг, брутфорс

## **3. Распределённое хеширование**

### **3.1. Консистентное хеширование**
* Ключи и серверы на кольце `[0, 2^m)`
* При добавлении/удалении сервера перехешируется только `1/n` ключей
* **Виртуальные узлы:** каждый сервер → несколько позиций на кольце

### **3.2. DHT (Distributed Hash Tables)**
* **Chord:** кольцо с finger table для быстрого поиска `O(log n)`
* **Kademlia:** XOR-метрика, `k`-ближайших соседей, α-параллельных запросов
