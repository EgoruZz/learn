# **A. ХЕШИРОВАНИЕ СЛОЖНЫХ СТРУКТУР ДАННЫХ**

## **1. Графы и сети**

### **1.1. Каноническая форма**
* Представление графа в уникальной форме для сравнения
* **Лексикографически минимальная строка:** все изоморфные графы → одна строка

### **1.2. Инварианты изоморфизма**
* **Степень вершин:** сортировка степеней — грубый инвариант
* **Хеш-сумма степеней:** `h(G) = Σ h(deg(v))` — не чувствителен к порядку
* **Хеш рёбер:** `h(G) = Σ_{(u,v)} h(min(u,v), max(u,v))` — для невзвешенных графов

## **2. Геометрические объекты**

### **2.1. Точки**
* **Хеш точки:** `h(x, y) = h(x) ⊕ (h(y) << 32)` или полиномиальный `h(x·p + y)`
* **Инвариант:** расстояние до начала координат `d = x² + y²`

### **2.2. Многоугольники**
* **Порядко-независимый хеш:** `h(P) = Σ h(edge)` для всех рёбер (порядок не важен)
* **Зависимый от порядка:** `h(P) = h(v₁, v₂) ⊕ h(v₂, v₃) ⊕ ... ⊕ h(vₙ, v₁)` (ориентация)

## **3. Множества и последовательности**

### **3.1. Порядко-независимые хеши**
* XOR-хеш: `h(S) = Σ_{x∈S} h(x)` — коммутативный, но `h(x) ⊕ h(x) = 0`
* Добавочная свёртка: `h(S) = Σ h(x) mod p` — без проблемы самоколлизий

### **3.2. Порядковые хеши**
* Полиномиальный: `h(s) = Σ s[i] · pⁱ mod m` — чувствителен к порядку

# **B. БАЗЫ ДАННЫХ И СИСТЕМЫ ХРАНЕНИЯ**

## **1. Индексирование**

### **1.1. Хеш-индексы**
* Ключ → хеш → страница/строка
* **Преимущество:** O(1) поиск
* **Ограничение:** нет range-запросов (только equality)

## **2. Дедупликация**

### **2.1. Обнаружение дубликатов**
* Content-addressable storage: хеш содержимого → адрес
* **两级 индекс:** быстрый хеш (xxhash) → точный хеш (SHA-256)

## **3. Версионность**

### **3.1. Хеши для отслеживания изменений**
* Git: каждый коммит — хеш его содержимого + родителей
* **Merkle tree:** корневой хеш изменяется при любом изменении листа

# **C. СЕТЕВЫЕ ПРОТОКОЛЫ**

## **1. DHT (Distributed Hash Tables)**

### **1.1. Chord**
* Кольцо `[0, 2^m)`: ключи и серверы на кольце
* **Finger table:** для каждого сервера `i` — указатель на `i + 2^j mod 2^m`
* Поиск: `O(log n)` — за каждый шаг的距离 уменьшается вдвое

### **1.2. Kademlia**
* XOR-метрика: `d(x, y) = x ⊕ y` (не метрика, но полуметрика)
* **k-ближайших соседей:** для каждого ключа храним `k` серверов
* α-параллельные запросы для ускорения

## **2. Верифицируемые вычисления**

### **2.1. Меркловы деревья**
* Бинарное дерево: листья — данные, внутренние узлы — `h(left ‖ right)`
* **Корневой хеш:** уникальный для всего набора данных
* **Доказательство включения:** путь от листа к корню — O(log n) хешей

### **2.2. Применения**
* Блокчейн: каждый блок содержит Merkle tree транзакций
* IPFS: content-addressable storage через Merkle DAG
* Certificate Transparency: дерево сертификатов
