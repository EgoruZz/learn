# **A. КРИПТОАНАЛИЗ ХЕШ-ФУНКЦИЙ**

## **1. Дифференциальный криптоанализ**

### **1.1. Принцип**
* Анализ **разностей** между парами входов: `Δx = x₁ ⊕ x₂`
* Для каждого раунда: `P(F(x) ⊕ F(x ⊕ Δx) = Δy)` — дифференциальная вероятность
* **Цель:** найти цепочку раундов с высокой累积ной вероятностью

### **1.2. Дифференциальные пути**
* Последовательность разностей `(Δ₀, Δ₁, ..., Δₙ)` через раунды
* **Активные S-блоки:** S-блоки, на которые влияет входная разность (не все биты маскируются)
* **Стоимость атаки:** `~2^{n−k}` где `n` — размер блока, `k` — число активных S-блоков

## **2. Линейный криптоанализ**

### **2.1. Принцип**
* Аппроксимация S-блоков **линейными**布尔евыми функциями
* **P(f(x) = L(x)) = 1/2 + ε` — чем больше `|ε|`, тем лучше линейное приближение

### **2.2. Piling-up Lemma**
* `P(x₁ ⊕ x₂ ⊕ ... ⊕ xₙ = 0) = 1/2 + 2^{n−1} · ∏ᵢ εᵢ`
* Связь линейных аппроксимаций через XOR

## **3. Алгебраические атаки**

### **3.1. Системы уравнений**
* Каждый раунд хеш-функции — система уравнений над GF(2)
* **Базис Грёбнера:** приведение системы к простой форме для решения

### **3.2. Интегральное представление**
* Запись хеш-функции как интеграла на торе (для непрерывных аппроксимаций)

# **B. СОВРЕМЕННЫЕ КРИПТОГРАФИЧЕСКИЕ ХЕШИ**

## **1. SHA-2 семейство**

### **1.1. SHA-256**
* Блочный шифр: 64 раунда, 512-битный блок, 256-битный выход
* **Константы:** 64 32-битных константы `K[i]`, инициализация `H₀ = {0x6a09e667, ...}`
* **Раунд:** `Σ₀(a) + Maj(a,b,c) + e + K[i] + W[i]` → обновление регистров

### **1.2. SHA-512**
* Аналог SHA-256, но 80 раундов, 1024-битный блок, 512-битный выход

## **2. SHA-3 (Keccak)**

### **2.1. Sponge Construction**
* `r = 1152` бит (rate), `c = 512` бит (capacity), `b = r + c = 1600` бит
* **Фаза Absorbing:** каждый блок данных XORится с внутренним состоянием
* **Фаза Squeezing:** из состояния извлекается хеш-код

### **2.2. Преобразования раунда**
* **θ (theta):** diffusion через XOR соседних столбцов
* **ρ (rho):** вращение每一位
* **π (pi):** перестановка позиций
* **χ (chi):** нелинейное преобразование (аналог S-блока)
* **ι (iota):** добавление константы раунда

## **3. BLAKE3**

### **3.1. Конструкция**
* Базируется на BLAKE2 (릎а Merkle-Damgård + ChaCha)
* **Дерево Меркла:** параллельное хеширование блоков → `O(log n)` глубина
* **Производительность:** ~1 GB/s на одном ядре

# **C. СПЕЦИАЛИЗИРОВАННЫЕ ПРИМИТИВЫ**

## **1. Argon2**

### **1.1. Назначение**
* Memory-hard функция для хеширования паролей (Password Hashing Competition, 2015)
* **Цель:** затруднить атаки ASIC/GPU через высокое потребление памяти

### **1.2. Параметры**
* `m` — память (MB), `t` — время (итерации), `p` — параллелизм
* **Argon2i:** идентичные итерации (защита от side-channel)
* **Argon2d:** данные-зависимые итерации (защита от GPU)

## **2. HMAC (Hash-based Message Authentication Code)**

### **2.1. Формула**
* `HMAC(K, m) = H((K' ⊕ opad) ‖ H((K' ⊕ ipad) ‖ m))`
* `K' = H(K)` если `|K| > blockSize`, иначе `K' = K ‖ 0...0`
* `ipad = 0x3636...36`, `opad = 0x5c5c...5c`

### **2.2. Безопасность**
* Свойство: `HMAC(K, ·)` — PRF если `H` — хорошая хеш-функция
* Применение: проверка целостности + аутентификация

## **3. HKDF (HMAC-based Key Derivation Function)**

### **3.1. Фазы**
* **Extract:** `PRK = HMAC-Hash(salt, IKM)` — извлечение ключа из входного материала
* **Expand:** `OKM = T(1) ‖ T(2) ‖ ...` где `T(i) = HMAC(PRK, T(i−1) ‖ info ‖ i)`
* Применение: генерация ключей из мастер-ключа
