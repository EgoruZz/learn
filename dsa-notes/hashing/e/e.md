# **A. УНИВЕРСАЛЬНЫЕ СЕМЕЙСТВА ХЕШ-ФУНКЦИЙ**

## **1. Теорема Картера-Вегмана**

### **1.1. Формулировка**
* Пусть `H` — семейство хеш-функций из `D` в `{0,...,m−1}`
* `H` называется ** universally hash**, если для любых `x ≠ y`:
    * `P_{h∈H}(h(x) = h(y)) ≤ 1/m`

### **1.2. Конструкция**
* `h_{a,b}(x) = ((ax + b) mod p) mod m`, где `p` — простое > |D|, `a ∈ {1,...,p−1}`, `b ∈ {0,...,p−1}`
* **Свойство:** `P(h(x) = h(y)) ≤ 1/m` — равномерное распределение коллизий

## **2. Полиномиальное хеширование**

### **2.1. Формула**
* `h(s) = (s[0]·p^{n−1} + s[1]·p^{n−2} + ... + s[n−1]) mod m`
* Или: `h = (((s[0]·p + s[1])·p + s[2])·p + ...) mod m` (метод Хорнера)

### **2.2. Свойства**
* **Простые `p`, `m`:** хорошее распределение для случайных строк
* **Обратный элемент:** для подстрочного хеша: `h(l..r) = (h(0..r) − h(0..l−1)·p^{r−l+1}) mod m`
* **Столкновения:** полиномы степени `n−1` совпадают в `n` точках → максимум `n` столкновений

## **3. Tabulation Hashing**

### **3.1. Идея**
* Каждый байт ключа — индекс в таблице; хеш — XOR значений из таблиц
* `h(x) = T₁[x₁] ⊕ T₂[x₂] ⊕ ... ⊕ Tₖ[xₖ]`
* **Свойство:** 3-wise независимость (для трёх различных ключей)

# **B. КРИПТОГРАФИЧЕСКИЕ КОНСТРУКЦИИ**

## **1. Merkle-Damgård**

### **1.1. Схема**
* Последовательное сжатие: `hᵢ = f(hᵢ₋₁, mᵢ)`
* `H₀` — фиксированный вектор; `Hₙ` — финальный хеш

### **1.2. Уязвимости**
* **Length extension attack:** по `H(m)` и `|m|` можно вычислить `H(m ‖ padding ‖ x)`
* **Решение:** HMAC, Sponge (SHA-3)

## **2. Sponge Construction**

### **2.1. Фазы**
* **Absorbing:** данные «поглощаются» в внутреннее состояние
* **Squeezing:** из внутреннего состояния «выжимается» хеш-код
* **Емкость `c`:** `r + c = b` (размер блока); безопасность ≈ `c/2` бит

## **3. Криптографические хеш-функции**

### **3.1. MD5**
* 128-битный хеш; 64 раунда
* **Уязвим:** коллизии находятся за `2^{21}` вычислений ( prakticheski)
* **Применение:** хеш-суммы файлов (не для безопасности!)

### **3.2. SHA-1**
* 160-битный хеш; 80 раундов
* **Сломан:** Google нашёл коллизию (SHAttered, 2017)

### **3.3. SHA-256 (SHA-2)**
* 256-битный хеш; 64 раунда
* **Безопасен:** наилучшая атака — `2^{128}` операций
* Применение: Bitcoin, TLS, кодовые подписи

# **C. НЕКРИПТОГРАФИЧЕСКИЕ ХЕШ-ФУНКЦИИ**

## **1. Djb2 (Дэниел Бернштейн)**
* `h = h * 33 + c` для каждого символа `c`
* Быстрый, хорошее распределение для строк

## **2. Sdbm**
* `h = c + (h << 6) + (h << 16) − h` для каждого символа `c`
* Используется в SDBM database

## **3. Elf**
* `h = ((h << 4) + h) + c` для каждого символа `c`
* Используется в ELF формате (Linux)

## **4. Adler32**
* `s₁ = (1 + Σ cᵢ) mod 65521`, `s₂ = (s₁ + Σ(s₁ − i)·cᵢ) mod 65521`
* Используется в zlib, gzip

## **5. Fletcher16**
* `sum₁ = (sum₁ + cᵢ) mod 255`, `sum₂ = (sum₂ + sum₁) mod 255`
* Простая контрольная сумма

# **D. СПЕЦИАЛИЗИРОВАННЫЕ АЛГОРИТМЫ**

## **1. Rolling Hash**

### **1.1. Полиномиальный rolling hash**
* `h(s[l..r]) = h(s[l..r−1]) · p + s[r] − s[l] · p^{r−l+1}`
* Сложность добавления/удаления символа: `O(1)`

### **1.2. Rabin-Karp**
* Поиск подстроки длины `m` в строке длины `n`: `O(n + m)` средний
* Сравнение хешей вместо попарного сравнения символов

## **2. Locality-Sensitive Hashing (LSH)**

### **2.1. MinHash (Jaccard)**
* `J(A, B) = |A ∩ B| / |A ∪ B|` — коэффициент Жаккара
* Подпись: вектор из `r` минимумов хешей
* `P(min(h(A)) = min(h(B))) = J(A, B)` — несмещённая оценка

### **2.2. SimHash (косинус)**
* Бинарное хеширование векторов: `h(x) = sign(W · x)`, где `W` — случайная матрица
* `P(h(x) = h(y)) ∝ cos(x, y)` — вероятность совпадения пропорциональна косинусному сходству

## **3. Perceptual Hashing (pHash)**
* Устойчивость к масштабированию, повороту, сжатию
* Применение: поиск похожих изображений

## **4. Luhn Algorithm**
* Проверка checksum номеров (кредитные карты, IMEI)
* `сумма + checksum ≡ 0 (mod 10)`

## **5. Hamming Code**
* Код для обнаружения и исправления одной ошибки
* Добавление контрольных битов: `k` контрольных битов для `2^k − k − 1` данных битов
