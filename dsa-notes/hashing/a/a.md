# **A. ВВЕДЕНИЕ В ХЕШИРОВАНИЕ**

## **1. Что такое хеш-функция**

### **1.1. Определение**
* **Хеш-функция:** отображение `h: {0,1}* → {0,1}^m` (или `h: D → {0,1}^m`), где `D` — произвольное пространство данных, `m` — фиксированный размер выхода (хеш-код, хеш-сумма, дайджест)
* **Свойства хорошей хеш-функции:**
    * **Детерминированность:** одинаковый вход → одинаковый выход (всегда)
    * **Быстрота:** вычисление `h(x)` за `O(|x|)` или лучше
    * **Равномерность:** выходные значения распределены равномерно по пространству `{0,1}^m`
    * **Стойкость к коллизиям:** сложно найти `x ≠ y` такие, что `h(x) = h(y)`

### **1.2. Типы коллизий**
* **Коллизия:** два различных входа `x ≠ y` дают одинаковый хеш: `h(x) = h(y)`
* **Устойчивость к найти-первому (first-preimage resistance):** по заданному `y` сложно найти `x` такое, что `h(x) = y`
* **Устойчивость к найти-второму (second-preimage resistance):** по заданному `x` сложно найти `x' ≠ x` такое, что `h(x) = h(x')`
* **Устойчивость к коллизиям (collision resistance):** сложно найти любую пару `x ≠ y` с `h(x) = h(y)`

## **2. Основные применения**

### **2.1. Хеш-таблицы**
* Быстрый поиск, вставка, удаление: `O(1)` в среднем
* Ключ → хеш → индекс массива → доступ к значению
* Коллизии разрешаются: цепочками, открытой адресацией и т.д.

### **2.2. Проверка целостности данных**
* Контрольные суммы (CRC32, Adler32)
* Хеш-функции для файлов: SHA-256 для проверки загрузки
* Деревья Меркла: иерархическая проверка целостности

### **2.3. Криптография**
* Доказательства знания (zero-knowledge proofs)
* Цифровые подписи (RSA, ECDSA)
* Блокчейн (Proof of Work — нахождение хеша с ограничением)

### **2.4. Индексирование и поиск**
* Инвертированные индексы
* Дедупликация данных
* Кэширование (LRU через хэш-таблицы)

# **B. ПРИНЦИПЫ РАБОТЫ ХЕШ-ФУНКЦИЙ**

## **1. Процесс хеширования**

### **1.1. Общая схема**
* **Инициализация:** фиксированный вектор состояния `H₀`
* **Цикл обработки блоков:** для каждого блока входных данных `Mᵢ`:
    * `Hᵢ = compress(Hᵢ₋₁, Mᵢ)` — функция сжатия
* **Финализация:** дополнение, обработка остатка, выдача хеш-кода

### **1.2. Merkle-Damgård конструкция**
* Последовательное сжатие блоков: `hᵢ = f(hᵢ₋₁, mᵢ)`
* Проблема: уязвимость к атакам расширения (length extension attack)
* Решение: HMAC, Sponge (SHA-3)

## **2. Математические основы**

### **2.1. Модульная арифметика**
* `h(x) = (ax + b) mod p` — полиномиальное хеширование
* Выбор простого `p` > размера алфавита → хорошее распределение

### **2.2. Битовые операции**
* XOR, AND, OR, сдвиги — основа большинства хеш-функций
* Мешающие функции (mixing functions): перемешивание битов для равномерности

### **2.3. Теория вероятностей**
* Парадокс дней рождения: при `n` элементах и `2^m` возможных хешах
    * Вероятность коллизии `P(коллизия) ≈ 1 − e^{−n²/(2^{m+1})}`
    * Для `P > 0.5` достаточно `n ≈ 2^{m/2}` элементов

## **3. Метрики качества**

### **3.1. Равномерность распределения**
* Avalanche effect: изменение 1 бита входа → изменение ~50% битов выхода
* Independence:每一位 выхода зависит от всех битов входа

### **3.2. Скорость вычисления**
* Внутренние хеш-функции (для таблиц): ~10-100 нс на вызов
* Криптографические: ~1-100 мкс (в 1000-10000 раз медленнее)

### **3.3. Стойкость к коллизиям**
* Для `m`-битного хеша нужно `2^{m/2}` вычислений для нахождения коллизии (атака дня рождения)
* Криптографические:安全保障 = `2^{m/2}` операций (для `m=256`: `2^{128}`)

# **C. ПРАКТИКА В C++**

## **1. Стандартные средства**

### **1.1. std::hash**
* Шаблонная структура: `std::hash<T>` — хеш для типа `T`
* Реализован для: `int`, `long long`, `double`, `string`, `pointer`, `pair`, `tuple`
* Вызов: `std::hash<T>{}(value)` → `size_t`

### **1.2. unordered_map и unordered_set**
* `unordered_map<K, V>` — ассоциативный массив (хэш-таблица)
* `unordered_set<T>` — множество (хэш-таблица без значений)
* Сложность: `O(1)` средний, `O(n)` худший случай
* Параметры: `max_load_factor()`, `bucket_count()`, `rehash(n)`

## **2. Кастомные хеши**

### **2.1. Специализация std::hash**
```cpp
struct Point { int x, y; };
namespace std {
    template<> struct hash<Point> {
        size_t operator()(const Point& p) const {
            return hash<int>{}(p.x) ^ (hash<int>{}(p.y) << 1);
        }
    };
}
```

### **2.2. Комбинирование хешей**
* `h₁ ⊕ (h₂ << 1)` — стандартный паттерн
* boost::hash_combine — более продвинутое комбинирование
* `h = h * seed + component` — полиномиальное комбинирование

## **3. Типичные задачи**

### **3.1. Поиск дубликатов**
* Через unordered_set: O(n) время, O(n) память
* Через сортировку: O(n log n) время, O(1) доп. память

### **3.2. Группировка данных**
* unordered_map<key, vector<value>>: группировка по общему признаку
* Пример: группировка анаграмм, группировка по хешу строки

### **3.3. Кэширование**
* LRU-кэш: unordered_map + двусвязный список
* TTL-кэш: добавление времени жизни записи
