**H. ДИНАМИКА НА ГРАФАХ (DAG И НЕ ТОЛЬКО)**

> **Архитектура:** `GraphDP` (h.cpp) — класс ветки dynamic, наследует `TreeDP` (g.cpp), а через него `ProfileDP`, `SubsetDP`, `SegmentDP`, `MatrixDP`, `LinearDP`, `DPBasics`. Раздел вводит динамику на графах: на DAG состояние — вершина, порядок табуляции — топологический (H.1, H.2, H.14); строковые задачи как сведения к графам/ДП (H.3, H.4); классические алгоритмы как ДП — по промежуточным вершинам (H.5), по числу шагов (H.6, H.7), по слоям через степень матрицы смежности (H.8); специальные семейства — интервальные графы (H.9), двудольные графы (H.10, H.13), циклы (H.11), игры (H.12). Переиспользуются, а не дублируются: House Robber на цикле `max_non_adjacent_sum_circular` (b.md B.3 — H.11), независимое множество по маскам (e.md E.11 — H.10: на двудольном графе полиномиально через паросочетание), LIS (d.md D.14 — H.9: интервалы по правым концам), паросочетание на дереве (g.md G.7 — сверка H.10).
>
> **Связи:** топологический порядок — каркас раздела A (H.1, H.2, H.14); релаксация рёбер как ДП по шагам — H.6, H.7; матричные переходы — b.md (B.9 — каркас H.8); пути в сетке — частный DAG (b.md B.11); игры — P/N-позиции (раздел I, I.19); расширение состояния — a.md (A.3).

### **Основные понятия и принципы**

* **Что это:** состояние — вершина графа; на DAG порядок табуляции — топологический (все предшественники обработаны раньше), на графах с циклами ДП применяется в специальных формах
* **Почему выделяется в отдельный класс:** в общем графе нет естественного порядка вычисления (циклы — «круговая зависимость» состояний), поэтому наивная динамика по вершинам корректна только на DAG; остальное — сведение к ДП-формам: по промежуточным вершинам (Флойд), по числу шагов (Беллман-Форд, степени матрицы смежности), по слоям BFS
* **Ключевые принципы:** декомпозиция по последней вершине/ребру пути; релаксация рёбер как шаг динамики; сведение к двудольным паросочетаниям (теорема Кёнига, покрытие путей, теорема Дилуорса); игры на DAG — P/N-позиции и мемоизированный DFS; строковые задачи сводятся к ДП на DAG (разбиения слова — пути в графе позиций)
* **Как распознать:** «число путей», «кратчайший/длиннейший путь в DAG», «разбиения и покрытия», «кто выиграет в игре без циклов»
* **Границы:** длиннейший путь на общем графе NP-труден; отрицательные циклы ломают оптимумы; игры с циклами — нимберы и теория Гранди (раздел I); кратчайшие пути на больших графах — Дейкстра (`graph`)

# **A. НА НАПРАВЛЕННОМ АЦИКЛИЧЕСКОМ ГРАФЕ (DAG)**

## **H.1. Количество путей**
* **Постановка:** DAG; число путей из s в t; dp[v] — число путей из s в v
* **Рекуррентность:** топологический порядок: dp[v] = Σ_{(u,v)} dp[u] (все предшественники обработаны), база dp[s] = 1; ответ dp[t]
* **Почему корректно:** декомпозиция пути по последней вершине — полна и непересекаема; в топологическом порядке u обработана раньше v (a.md A.1)
* **Пример:** 0→1, 0→2, 1→3, 2→3, 2→4, 3→5, 4→5: путей 0→5: 3 ({0-1-3-5, 0-2-3-5, 0-2-4-5}), 0→3: 2; из 2 в 5: 2 пути
* **Сложность:** O(V + E) времени и памяти
* **Обобщение:** между парой вершин — та же база dp[s] = 1; модификации: веса (H.2), ограничения на путь (H.14), число путей длины ровно k — H.8 (степень матрицы)
* **Реализация:** `count_dag_paths(adj, s)` — возвращает вектор dp (число путей из s во все вершины)
* **Связь:** сетка — частный DAG (b.md B.11); счёт — каркас H.14

## **H.2. Самый длинный/короткий путь**
* **Постановка:** взвешенный DAG; экстремум веса пути s→t; восстановление пути
* **Рекуррентность:** dp[v] = max_{(u,v)} (dp[u] + w(u,v)); prev[v] = u, достигшая максимума; восстановление — обратный проход по prev
* **Почему корректно:** каждый путь оканчивается ребром (u, v); оптимальность префикса (a.md A.1); ацикличность — топологический порядок корректен
* **Пример:** 0→1:4, 0→2:1, 1→3:2, 2→3:4, 2→4:2, 3→5:5, 4→5:1: длиннейший 0→5 = 11 (0-1-3-5); 0-2-3-5 = 10; 0-2-4-5 = 4
* **Сложность:** O(V + E) — против O(V·E) Беллмана-Форда (H.6) и O(V³) Флойда (H.5)
* **Обобщение:** минимум — замена max на min (тот же каркас); на общем графе длиннейший путь NP-труден — в DAG полиномиален
* **Реализация:** `dag_longest_path(adj, s, t)` — пара (длина, путь)
* **Связь:** релаксация — H.6, H.7

## **H.3. Word Break**
* **Постановка:** разбиение строки s на слова словаря: dp[i] — существует ли разбиение префикса s[0..i)
* **Рекуррентность:** dp[i] = ∃j: dp[j] и s[j..i) ∈ dict — последнее слово; база dp[0] = true; ответ dp[n]
* **Почему корректно:** последнее слово фиксирует разбиение хвоста; префикс — независимая подзадача (a.md A.1)
* **Пример:** "leetcode" = "leet" + "code" → true; "catsandog" по {cats, dog, sand, and, cat} → false; "aaaa" по {a, aa} → 5 разбиений
* **Сложность:** O(n·|dict|·len) — O(n²) с хешами подстрок/trie
* **Обобщение:** подсчёт способов — суммы вместо ∃ (как H.1); ограничения на число слов
* **Реализация:** `word_break(s, dict)`, `count_word_breaks(s, dict)`
* **Связь:** «последний элемент» — a.md (A.1, A.3)
* **Взгляд как на DAG (каркас раздела A):** вершины — позиции 0..n, ребро j→i ⇔ s[j..i) ∈ dict — граф ацикличен (длина слова > 0), dp[i] — число путей из 0 в i (H.1); разбиения строки ⇔ пути в этом графе

## **H.4. Word Ladder**
* **Постановка:** преобразование start → end заменой одной буквы за шаг, все промежуточные слова из словаря; минимум числа слов в цепочке (BFS-уровни — ДП по графу переходов)
* **Идея:** BFS от start: соседи слова — слова словаря, отличающиеся одной буквой; dist — уровень (длина цепочки)
* **Почему корректно:** слои BFS — кратчайшие пути в невзвешенном графе: слово — вершина, переход — допустимое редактирование; уровень первого вхождения слова минимален
* **Пример:** hit → cog по {hot, dot, dog, lot, log, cog} → 5 (hit-hot-dot-dog-cog); hot → dog по {hot, dog, dot} → 3; без cog в словаре → −1
* **Сложность:** O(|dict|·L·σ) — σ размер алфавита (для строчных латинских букв σ = 26) — число рёбер графа слов
* **Обобщение:** двунаправленный BFS; взвешенные редактирования — H.6, H.7
* **Реализация:** `word_ladder(start, end, dict)`
* **Связь:** слои как число шагов — H.6, H.7

# **B. АЛГОРИТМЫ НА ГРАФАХ КАК ДП**

## **H.5. Floyd-Warshall**
* **Постановка:** все пары кратчайших путей; ДП по промежуточным вершинам
* **Рекуррентность:** dp[k][i][j] = min(dp[k−1][i][j], dp[k−1][i][k] + dp[k−1][k][j]) — пути через вершины {0..k−1}; сжатие до 2D: d[i][j] = min(d[i][j], d[i][k] + d[k][j])
* **Почему корректно:** путь через {0..k} либо не использует k (вариант dp[k−1][i][j]), либо проходит через k (склейка i→k и k→j); индукция по k
* **Пример:** 4 вершины (0→1:3, 0→3:7, 1→0:8, 1→2:2, 2→0:5, 2→3:1, 3→0:2): dist[0][2] = 5, dist[0][3] = 6 (через 1 и 2), dist[3][2] = 7
* **Сложность:** O(V³) времени, O(V²) памяти
* **Обобщение:** транзитивное замыкание — булев вариант (∨/∧ вместо min/+); отрицательный цикл — d[i][i] < 0
* **Реализация:** `floyd_warshall(w)`, `transitive_closure(adj)`
* **Связь:** минимум по промежуточным — каркас раздела J (оптимизации интервальной ДП)

## **H.6. Bellman-Ford**
* **Постановка:** кратчайшие пути из s; релаксация рёбер как ДП по числу шагов
* **Рекуррентность:** dp[k][v] = min(dp[k−1][v], min_{(u,v)} dp[k−1][u] + w(u,v)) — k-я итерация; после n−1 итераций — ответы (нет отрицательных циклов); n-я итерация находит отрицательный цикл
* **Почему корректно:** простой путь содержит ≤ n−1 ребро; каждая итерация добавляет один переход (индукция по k); отрицательный цикл релаксирует на любой итерации — признак на n-й
* **Пример:** граф H.5: dist из 0 = {0, 3, 5, 6}; 0→1:1, 1→2:−1, 2→0:−1 → отрицательный цикл
* **Сложность:** O(V·E) времени, O(V) памяти
* **Обобщение:** ограничение на число рёбер — H.7; SPFA-улучшение очереди
* **Реализация:** `bellman_ford(n, edges, s)` — пара (dist, признак отрицательного цикла)
* **Связь:** ДП по шагам — H.7; сравнение с H.5

## **H.7. Min Distance Up Bottom**
* **Постановка:** итеративный вариант Беллмана-Форда снизу вверх: dp[k][v] — минимум по путям из ≤ k рёбер
* **Идея:** слои: dp[0][s] = 0, остальное ∞; dp[k][v] = min(dp[k−1][v], min_{(u,v)} dp[k−1][u] + w(u,v)); ndp = dp — «не более k рёбер»
* **Почему корректно:** та же индукция по k (H.6); слой k−1 → k — ровно один дополнительный переход
* **Пример:** 0→1:3, 0→3:7, 1→2:2, 2→3:1: ≤ 1 ребра dist[3] = 7, ≤ 2 рёбер dist[2] = 5 и dist[3] = 7, ≤ 3 рёбер dist[3] = 6
* **Сложность:** O(k·E) времени, O(V) памяти
* **Обобщение:** «число шагов как состояние» — параметрическая ДП (a.md A.3, раздел I)
* **Реализация:** `min_distance_up_bottom(adj, s, maxSteps)`
* **Связь:** релаксация — H.6; слои — H.4

## **H.8. Число путей длины k (степень матрицы смежности)**
* **Постановка:** A^k[i][j] — число маршрутов длины k из i в j; ДП по слоям
* **Рекуррентность:** маршруты длины a+b склеиваются в середине: (A^(a+b))[i][j] = Σ_t A^a[i][t]·A^b[t][j] — матричное умножение; бинарное возведение в степень, A^0 = I
* **Почему корректно:** перебор средней вершины t — декомпозиция маршрута полна и непересекаема (a.md A.1); композиция степеней — индукция по битам k
* **Пример:** цикл C3: A²[0][0] = 2, A²[0][1] = 1, A⁴[0][0] = 6; цепочка 0→1→2→3: A²[0][2] = 1, A³[0][3] = 1, A⁴[0][3] = 0
* **Сложность:** O(V³·log k) времени, O(V²) памяти
* **Обобщение:** взвешенные графы — умножение по (min, +) (задел на раздел J); число путей из s в t — суммирование строки/столбца
* **Реализация:** `count_walks_length_k(adj, k)` — adj — список смежности (как во всех методах раздела), матрица строится внутри
* **Связь:** матричный переход — b.md (B.9); возведение в степень — math

# **C. СПЕЦИАЛЬНЫЕ ЗАДАЧИ**

## **H.9. Maximum Clique в интервальном графе**
* **Постановка:** интервалы на прямой; клика — интервалы, попарно пересекающиеся; максимум клики = максимум одновременно активных интервалов
* **Идея:** sweep line: события (начало +1, конец −1) сортируются по позиции; текущее число активных — максимум и есть ответ; «сортировка по правым концам» — общий каркас интервальных задач (LIS — d.md D.14)
* **Почему корректно:** для интервалов (свойство Хелли) попарное пересечение эквивалентно общей точке; sweep пересматривает все точки переключения
* **Пример:** {(1,4), (2,5), (3,6)} → 3; {(1,4), (2,3), (3,5), (4,7)} → 2
* **Сложность:** O(n·log n) времени, O(n) памяти
* **Обобщение:** взвешенные клики; независимое множество интервалов (непересекающиеся) — жадный по правым концам / LIS-ДП
* **Реализация:** `max_clique_interval_graph(intervals)`
* **Связь:** LIS — d.md (D.14); жадность — math

## **H.10. MIS в двудольном графе (теорема Кёнига)**
* **Постановка:** двудольный граф; MIS = n − размер максимального паросочетания (ДП по рёбрам — увеличивающие пути)
* **Рекуррентность/идея:** алгоритм Куна: для каждой левой вершины DFS ищет увеличивающий путь — цепочка рёбер «свободное, занятое, свободное, ...», переметка занятых рёбер; MIS = n − matching (теорема Кёнига: MVC = matching, MIS = n − MVC)
* **Почему корректно:** критерий Бержа: паросочетание максимально ⇔ нет увеличивающих путей; переметка при неудаче — корректная дедупликация попыток
* **Пример:** левые {0,1,2}, правые {3,4,5}: 0-3, 0-4, 1-3, 2-5: паросочетание 3 → MIS = 3; без ребра 2-5: паросочетание 2 → MIS = 4
* **Сложность:** O(V·E) (Куна); O(E·√V) (Хопкрофт-Карп)
* **Обобщение:** минимальное вершинное покрытие = паросочетание; минимум путей в DAG — H.13; деревья — частный случай (g.md G.7)
* **Реализация:** `max_bipartite_matching(leftAdj, nRight)`, `mis_bipartite(leftAdj, nRight)`
* **Связь:** маски (E.11) — на общих графах; паросочетание на дереве — g.md (G.7)

## **H.11. Динамика на пути/цикле**
* **Постановка:** последовательности на цикле (первый и последний элементы соседние) — два прохода; классика — House Robber II
* **Идея:** два прохода: без последнего элемента и без первого; ответ — максимум (первая вершина зафиксирована / не зафиксирована)
* **Почему корректно:** оптимальное решение либо не берёт первый элемент, либо не берёт последний — два случая покрывают все решения (два прохода — g.md G.2)
* **Пример:** {2, 3, 2} → 3; {1, 2, 3, 1} → 4
* **Сложность:** O(n) времени и памяти
* **Обобщение:** любые задачи на цикле — сведение к двум линейным случаям
* **Реализация:** переиспользуется `max_non_adjacent_sum_circular` (b.md B.3) — отдельного метода не требуется
* **Связь:** House Robber — b.md (B.3); два прохода — g.md (G.2)

## **H.12. Игры на DAG**
* **Постановка:** фишка на вершине DAG; ход — переход по ребру; нет хода — проигрыш; позиция выигрышная (N), если есть ход в проигрышную (P)
* **Рекуррентность:** win(v) = ∃(v,u): ¬win(u); проигрышная — все ходы в выигрышные; мемоизация DFS (по обратному топологическому порядку — реверс рёбер)
* **Почему корректно:** индукция от листьев (терминальных позиций); DAG — рекурсия завершается; определение N/P — взаимная индукция (раздел I, I.19)
* **Пример:** 0→1, 0→2, 1→3, 2→3, 3→4, 4→5 (5 — лист): win(5)=0, win(4)=1, win(3)=0, win(1)=win(2)=1, win(0)=0; с ребром 0→5: win(0)=1; цепочка 0→1→2: win(0)=0
* **Сложность:** O(V + E)
* **Обобщение:** графы с циклами — нимберы (I.18), Шпраг-Гранди (I.21); Ним и его варианты (I.20)
* **Реализация:** `can_win_dag(adj, s)`
* **Связь:** топологический порядок — H.1; игры — раздел I (I.19)

## **H.13. Minimum Path Cover в DAG**
* **Постановка:** минимум вершинно-непересекающихся путей, покрывающих все вершины
* **Идея:** расщепление: вершина v → v_out (левая доля) и v_in (правая); ребро u→v → u_out→v_in; покрытие = n − max паросочетание (Кёниг для DAG)
* **Почему корректно:** каждая пара «конец пути → следующий путь» — ребро паросочетания; непокрытые вершины — начала путей: число путей = n − (число склеек)
* **Пример:** 0→1, 0→2, 1→3, 2→3: покрытие 2 ({0-1-3, 2} или {0-2-3, 1}); цепочка 0→1→2→3: покрытие 1
* **Сложность:** O(V·E) (Куна)
* **Обобщение:** наименьшее число цепей в частичном порядке (теорема Дилуорса)
* **Реализация:** `min_path_cover_dag(adj)`
* **Связь:** паросочетание — H.10

## **H.14. Counting путей с ограничениями**
* **Постановка:** число топологически различных путей s→t с ограничениями на вершины пути (чередование цветов и т.п.)
* **Рекуррентность:** dp[v] = Σ_{(u,v): ограничение выполнено} dp[u] — расширение H.1 условием перехода; дополнительное измерение состояния при необходимости (a.md A.3)
* **Почему корректно:** фильтр по рёбрам сохраняет декомпозицию H.1 по последней вершине; сумма по допустимым предшественникам полна
* **Пример:** 0→1, 0→2, 1→3, 2→3, 3→4 с цветами 0, 1, 1, 0, 1: чередующиеся пути 0→4: {0-1-3-4, 0-2-3-4} → 2
* **Сложность:** O(V + E)
* **Обобщение:** состояние-кортеж (число красных ≤ k, максимум, пары цветов); длина пути — H.8
* **Реализация:** `count_alternating_paths(adj, colors, s, t)`
* **Связь:** счёт путей — H.1; расширение состояния — a.md (A.3)
