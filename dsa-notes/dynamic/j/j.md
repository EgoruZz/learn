**J. СЛОЖНЫЕ ОПТИМИЗАЦИИ ДП**

> **Архитектура:** `OptimizationDP` (j.cpp) — класс ветки dynamic, наследует `SpecialDP` (i.cpp), а через него `GraphDP`, `TreeDP`, `ProfileDP`, `SubsetDP`, `SegmentDP`, `MatrixDP`, `LinearDP`, `DPBasics`. Раздел — техники, ускоряющие уже написанные рекуррентности: оптимизация памяти (A: роллинг, биты, префиксы, in-place — J.1–J.4), оптимизация времени пересчёта (B: монотонность точки оптимума, CHT, Aliens, очереди — J.5–J.13), параллельные и распределённые реализации (C: J.14–J.17). Переиспользуются, а не дублируются: `lcs` (c.md C.12 — уже O(m) памяти), `edit_distance` (c.md C.11), `knapsack_01` (c.md C.19 — уже in-place), `matrix_chain_min` (d.md D.1 — внешний цикл по диагоналям), `merge_stones_min_cost` (d.md D.9 — плотный O(n³) аналог для J.6), `count_subsets_with_sum` (i.md I.27 — in-place), `min_subarray_len_ge_sum` (i.md I.29 — каркас двух указателей для J.12).
>
> **Связи:** монотонность точки оптимума — b.md (B.2); интервальная динамика — d.md (D.1); вогнутость/выпуклость и неравенство четырёхугольника — math/analysis; матроиды и двойственность (λ-штраф) — math/linear-algebra; дерево отрезков — struct (применение к J.9); производящие функции — math/combinatorics.

### **Основные понятия и принципы**

* **Что это:** не новые задачи, а техники ускорения уже построенных рекуррентностей: память (роллинг слоёв, битовые сдвиги, две строки, in-place перезапись) и время (монотонность точки оптимума, Divide & Conquer, Knuth, SMAWK, CHT/Li Chao, Aliens trick, монотонная очередь)
* **Почему выделяется в отдельный класс:** разделение «что считать» и «как быстро считать» — рекуррентность уже известна, но наивная сложность (память O(n²), время O(n³)) неприемлема; ускорение возможно только при наличии структурного свойства задачи, которое и выделяет применимый приём
* **Ключевые принципы:** каждому приёму — свой тип рекуррентности и своё структурное условие (четырёхугольное неравенство — D&C/Knuth; матрица Монжа — SMAWK; линейность по j·x — CHT; окно по j — deque; выпуклость по числу сегментов — Aliens); проверка условия важнее самой техники — карта выбора J.17; комбинирование приёмов (Aliens + CHT, Knuth + роллинг)
* **Как распознать:** монотонный оптимум → D&C/Knuth; линейный переход → CHT; окно → deque; «ровно K сегментов» с выпуклой стоимостью → Aliens; матрица Монжа → SMAWK; слой зависит только от предыдущего → роллинг
* **Границы:** нарушение структурных условий даёт неверные ответы — обязательна эмпирическая проверка на малых n; восстановление пути при роллинге невозможно (полная таблица или Хиршберг); параллельные реализации (GPU, MapReduce) — схемы распараллеливания, а не новые методы

# **A. ОПТИМИЗАЦИЯ ПАМЯТИ (MEMORY OPTIMIZATION)**

## **J.1. Rolling DP: скроллинг слоёв**
* **Постановка:** таблица dp размером n×m, но переходы используют только предыдущий слой: храним dp[2][...] (два слоя) или dp[k][...]; интервальные ДП — проход по диагоналям (d.md D.1: внешний цикл по длине — один слой на диагональ)
* **Рекуррентность:** для сетки: dp[i][j] = cost[i][j] + min(dp[i−1][j], dp[i][j−1]) — нужны только строка i−1 и текущая строка: два массива длины m вместо (n+1)·(m+1)
* **Почему корректно:** после обработки строки i старые значения строки i−1 не читаются никогда (переходы — вниз/вправо); замена слоя = копирование одного массива; восстановление пути по скроллингу невозможно — нужна полная таблица (c.md C.12 `lcs_with_path` — компромисс)
* **Пример:** cost = {{1, 3, 1}, {1, 5, 1}, {4, 2, 1}}: путь 1→3→1→1→1, стоимость 7
* **Сложность:** O(n·m) времени, O(m) памяти — вместо O(n·m)
* **Обобщение:** три и более слоя (переходы назад на k шагов); интервальные — диагональный порядок (D.1); скроллинг совместим с любой оптимизацией времени (B)
* **Реализация:** `min_cost_grid_rolling(cost)` — минимальная стоимость пути в сетке, два слоя
* **Связь:** LCS на двух строках — c.md (C.12); in-place — J.4

## **J.2. Bit DP: сжатие состояния в биты**
* **Постановка:** булево измерение (достижимо/нет) — бит; суммарные переходы dp |= dp << c — «сдвиг-ИЛИ»: разом все суммы, достижимые добавлением предмета
* **Рекуррентность:** bitset B: B = B | (B << cᵢ) по предметам — бит s = 1 ⇔ сумма s достижима; сдвиг-ИЛИ — w сумм за одну операцию над словом (w — разрядность слова)
* **Почему корректно:** бит s−cᵢ = 1 ⇒ после добавления cᵢ бит s = 1 — в точности переход 0/1-рюкзака; порядок предметов не важен (OR — коммутативен); каждая операция над словом обрабатывает w состояний параллельно
* **Пример:** a = {1, 2, 3, 4, 5}: достижимы все суммы 0..15: S = 10 → да, S = 16 → нет
* **Сложность:** O(n·S/w) времени, O(S/w) памяти (w — разрядность слова)
* **Обобщение:** длинные битсеты (большие S); модификации: ровно k предметов — слой битсетов по k; подсчёт вместо достижимости — не битовый (i.md I.27); сдвиг с переносом — произвольная длина слова
* **Реализация:** `subset_sum_bitset(a, S)` — достижимость через битовый сдвиг (vector из слов по w бит, в реализации w = 64); база — c.md (C.22, `subset_sum_reachable`)
* **Связь:** битмаски как состояние — e.md (E.1); счёт — i.md (I.27)

## **J.3. DP на префиксах: O(N) памяти**
* **Постановка:** рекуррентности, где строка i зависит только от строки i−1 (LCS, Edit Distance): две строки вместо таблицы; восстановление пути требует полной таблицы (c.md C.12 — `lcs_with_path`)
* **Рекуррентность:** Edit Distance: fᵢ(j) = min(fᵢ(j−1), fᵢ₋₁(j), fᵢ₋₁(j−1) + (aᵢ ≠ bⱼ)) — две строки f и fᵢ₋₁; длина строки — O(min(n, m))
* **Почему корректно:** окно зависимости размера 2 по i — старшие строки недостижимы; LCS уже реализован роллингом (c.md C.12) — двухстрочный вариант той же рекуррентности для Edit Distance закрывает симметричную пару
* **Пример:** "kitten" → "sitting": 3 операции (замена k→s, замена e→i, вставка g)
* **Сложность:** O(n·m) времени, O(min(n, m)) памяти
* **Обобщение:** восстановление — полная таблица или алгоритм Хиршберга (деление по строкам: два роллинг-прохода + точка разрыва, память O(min(n, m))); три строки — рекуррентности с окном 3; «две строки» + argmin — полная таблица opt (J.5, J.6)
* **Реализация:** `edit_distance_rolling(a, b)` — двухстрочная версия; полная таблица — c.md (C.11)
* **Связь:** роллинг — J.1; интервальные по диагоналям — d.md (D.1)

## **J.4. In-place DP: перезапись с контролем направления**
* **Постановка:** одномерный массив перезаписывается «в себе», направление цикла гарантирует семантику 0/1 или неограниченного выбора
* **Рекуррентность:** 0/1: по j сверху вниз (f[j] = max(f[j], f[j−cᵢ] + vᵢ) — f[j−cᵢ] ещё со старого слоя, предмет не повторяется); неограниченный: по j снизу вверх (f[j−cᵢ] уже обновлён — повторяется)
* **Почему корректно:** направление цикла определяет, читается ли обновлённое значение; нисходящий проход изолирует слои, восходящий — смешивает (это и есть «много использований»); порядок предметов не влияет (сумма/максимум коммутативны)
* **Пример:** классика — 0/1-рюкзак (c.md C.19, `knapsack_01` — уже in-place); подсчёт подмножеств (i.md I.27 — тот же нисходящий проход)
* **Сложность:** O(n·W) времени, O(W) памяти
* **Обобщение:** обратный проход для восстановления — opt-таблица отдельно (c.md C.19 `knapsack_01_path`); рюкзак по ценности (c.md C.20); кратные предметы — двоичное разбиение (c.md C.21)
* **Реализация:** не требуется — переиспользуются `knapsack_01` (c.md C.19) и `count_subsets_with_sum` (i.md I.27)
* **Связь:** скроллинг — J.1; измерение суммы — i.md (I.27)

# **B. ОПТИМИЗАЦИЯ ВРЕМЕНИ ПЕРЕСЧЁТА**

## **J.5. Divide & Conquer Optimization**
* **Постановка:** dp[k][i] = min_{j<i} (dp[k−1][j] + C(j+1, i)) — разбиение на K сегментов со стоимостью сегмента C; если opt[k][i] монотонна (opt[k][i] ≤ opt[k][i+1]) — перебор j сужается до [opt[k][i−1], opt[k][i+1]]
* **Рекуррентность:** рекурсивное вычисление слоя: compute(l, r, optL, optR): середина m, перебор j ∈ [optL, optR], argmin — opt[m]; затем compute(l, m−1, optL, opt[m]) и compute(m+1, r, opt[m], optR)
* **Почему корректно:** монотонность opt (четырёхугольное неравенство на C) — каждая пара (i, j) проверяется O(log n) раз; j-перебор каждого уровня в сумме O(n) (коридоры уровня вложены — общие только границы), уровней O(log n) → O(n log n) на слой, K слоёв
* **Пример:** a = {1, 2, 3, 4}, K = 2, C = (сумма сегмента)²: разбиение {1,2,3}|{4}: 36 + 16 = 52 — минимум
* **Сложность:** O(K·n·log n) времени, O(n) памяти на слой
* **Обобщение:** C с четырёхугольным неравенством — монотонность opt гарантирована (проверка: C(a, c) + C(b, d) ≤ C(a, d) + C(b, c)); без условия — тест монотонности opt на малых n (J.17); минимум/максимум — симметрично
* **Реализация:** `divide_conquer_min(n, K, cost)` — cost(i, j): стоимость сегмента [i, j]; возвращает минимум разбиения на ровно K сегментов
* **Связь:** монотонность точки оптимума — b.md (B.2); Knuth — J.6; SMAWK — J.7

## **J.6. Knuth Optimization**
* **Постановка:** интервальная рекуррентность dp[i][j] = min_{k∈[i,j)} (dp[i][k] + dp[k+1][j] + C[i][j]) с четырёхугольным неравенством и монотонностью на C — opt[i][j] лежит в [opt[i][j−1], opt[i+1][j]]
* **Рекуррентность:** перебор k только по коридору opt[i][j−1]..opt[i+1][j]; opt[i][i] = i; коридор монотонно расширяется с ростом длины
* **Почему корректно:** четырёхугольное неравенство + монотонность по включению на C дают opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j]; суммарная работа по всем (i, j) одной длины — O(n) (коридоры вложены), длин n → O(n²)
* **Пример:** слияние соседних кучек {4, 1, 3, 2}: 20 ((4,1)→5, (3,2)→5, (5,5)→10 — 5+5+10)
* **Сложность:** O(n²) времени (вместо O(n³)), O(n²) памяти
* **Обобщение:** применим к Optimal BST, слиянию камней (K = 2), матричному умножению с QI; K > 2 — другое семейство (d.md D.9); плотный аналог — `merge_stones_min_cost` (d.md D.9, любой K)
* **Реализация:** `merge_stones_min_cost_knuth(a)` — слияние соседних кучек (K = 2) за O(n²); переиспользует рекуррентность d.md (D.9)
* **Связь:** D&C — J.5; четырёхугольное неравенство — J.7, J.17

## **J.7. Monge Array Optimization и SMAWK**
* **Постановка:** матрица w Монжа: w[i][j] + w[i+1][j+1] ≤ w[i][j+1] + w[i+1][j] ⇔ полностью монотонна: минимумы строк не убывают по i; SMAWK находит минимум каждой строки за O(n + m) сравнений
* **Идея:** редукция столбцов (столбец y доминируется x при w[i][x] ≤ w[i][y] для всех строк-кандидатов), рекурсия на прореженных строках (каждая вторая), добор минимумов отброшенных строк линейным проходом по коридору между минимумами соседних опорных строк
* **Почему корректно:** полная монотонность — сравнение двух столбцов в строке i отсекает один из них для всех строк ≥ i; нечётные строки — опорные (минимум чётной строки между минимумами соседних нечётных); рекурсия уменьшает размер вдвое, редукция — линейна
* **Пример:** w[i][j] = (i − j)² (Монжа: 2a² ≤ (a−1)² + (a+1)²): минимумы строк = {0, 1, 2, 3}
* **Сложность:** O(n + m) на полностью монотонную матрицу; память O(n + m)
* **Обобщение:** применение к слою ДП «dp[i] = min_j (dp[j] + C(j, i))» с Монжа-C — минимумы строк слоя за O(n) (J.13); матрицы Монжа — класс задач (LARSCH — обобщение на DP с аргументом); вложенные минимумы — четырехугольное неравенство (J.6)
* **Реализация:** `smawk_row_minima(n, m, get)` — get(i, j): ячейка матрицы (полная монотонность — предусловие); возвращает минимум каждой строки (индекс столбца)
* **Связь:** D&C — J.5; Knuth — J.6; конвейер — J.13

## **J.8. Convex Hull Trick (CHT)**
* **Постановка:** dp[i] = min_j (a[j]·x[i] + b[j]) — минимум линейных функций в точке: линии (наклоны a[j], сдвиги b[j]) — выпуклая оболочка снизу; при монотонных наклонах и запросах — очередь с указателем
* **Рекуррентность:** добавление линии: пока пересечение (prev, new) лежит левее (prev, prevprev) — prev удаляется (выпуклость); запрос: указатель идёт вправо пока следующая линия лучше (монотонность x)
* **Почему корректно:** минимум кусочно-линейной выпуклой функции; в точке x лучшая линия — одна из на оболочке; монотонность наклонов поддерживает оболочку деком (амортизация O(1) на операцию), монотонность запросов — указатель никогда не возвращается
* **Пример:** x = {0, 1, 3, 6}: dp[i] = min_j (dp[j] + (x[i] − x[j])²): линии −2x[j]·X + (x[j]² + dp[j]): dp = {0, 1, 5, 14}
* **Сложность:** O(n) суммарно (добавление и запрос амортизированно O(1)) при монотонных наклонах и запросах
* **Обобщение:** максимум — симметричная оболочка; немонотонные наклоны/запросы — Li Chao (J.9); дробные пересечения — деление без плавающей точки (J.9); восстановление argmin — хранение индекса линии
* **Реализация:** `min_quadratic_transition_dp(x)` — dp[i] = min_j (dp[j] + (x[i] − x[j])²) на монотонном CHT; внутренний класс `MonotoneCHT` — линии (a, b), запросы (x) — переиспользуется в J.10, J.11
* **Связь:** динамическая версия — J.9; задачи — J.10; Aliens — J.11

## **J.9. Реализации CHT: Li Chao Tree**
* **Постановка:** произвольный порядок добавления линий и запросов — динамическая выпуклая оболочка: Li Chao Tree — дерево отрезков по области x, в узле — «лучшая» линия
* **Рекуррентность:** добавление линии L в узел с границами [l, r]: если L лучше текущей в середине — обмен, старая уходит в ту половину, где она лучше; запрос — спуск к точке с минимумом по всем узлам пути
* **Почему корректно:** каждая линия хранится в узле, где она доминирует на подмножестве области (инвариант: в любой точке лучшая линия — на пути от корня к листу); высота O(log C) — вставка не вырождается
* **Пример:** линии y = 2x+1, y = −x+3, y = 3x−10 на x ∈ [0, 5]: в точках {0, 1, 3, 5}: {−10, −7, −1, −2}
* **Сложность:** O(log C) на добавление и запрос (C — диапазон x); память O(m·log C)
* **Обобщение:** целочисленные пересечения без плавающей точки (сравнение a₁x + b₁ и a₂x + b₂ через __int128); максимум — знак сравнения; точки-дроби — координатное сжатие x; дерево отрезков как основа — struct
* **Реализация:** `LiChaoTree` — класс: add_line(a, b), query(x) (минимум); линии с произвольным порядком добавления
* **Связь:** статическая версия — J.8; задачи — J.10; дерево отрезков — struct

## **J.10. Задачи CHT: Land Acquisition**
* **Постановка:** прямоугольники (ширина w, высота h); группа покупается за max(w)·max(h) группы; минимизировать суммарную цену — классическая задача CHT
* **Рекуррентность:** сортировка по w возр. + отбрасывание доминируемых (w' ≥ w, h' ≥ h — бесплатно в группе с w'); после фильтра w возрастает, h убывает: dp[i] = min_{j≤i} (dp[j−1] + h[j]·w[i]) — линии (h[j], dp[j−1]) с убывающими наклонами, запросы w[i] — монотонный CHT
* **Почему корректно:** доминируемый прямоугольник не меняет max(w)·max(h) группы — исключение не теряет оптимума; в группе j..i максимум ширины — w[i] (последний, w возрастают), высоты — h[j] (первый, h убывают); формула перебирает первую позицию последней группы
* **Пример:** (4, 3), (6, 2), (3, 5): одна группа 6·5 = 30; раздельно 12 + 12 + 15 = 39; минимум 30
* **Сложность:** O(n·log n) (сортировка) + O(n) (CHT); память O(n)
* **Обобщение:** «коммандо» (параболы — квадратичные переходы), доставка (сумма расстояний × весов) — те же линии; максимум-варианты — оболочка сверху; сопряжённая задача — Aliens (J.11)
* **Реализация:** `max_profit_land_groups(rects)` — минимум цены групп через `MonotoneCHT` (J.8)
* **Связь:** CHT — J.8, J.9; разделяй и властвуй по слоям — J.5

## **J.11. Aliens Trick (Лагранжева релаксация)**
* **Постановка:** dp с ограничением «ровно K элементов/сегментов»: вводим штраф λ за каждый сегмент, решаем без ограничения, подбираем λ так, чтобы использовалось ровно K сегментов
* **Рекуррентность:** solve(λ): dp[i] = min_j (dp[j] + C(j+1, i)) + λ за сегмент; функция f(λ) = (стоимость − λ·K) выпукла по K — бинарный поиск λ; при равных стоимостях берём максимум числа сегментов (монотонность подсчёта)
* **Почему корректно:** стоимость как функция числа сегментов выпукла (для C с QI); λ — множитель Лагранжа: касательная к выпуклой оболочке точек (k, cost(k)) в точке K; бинарный поиск по λ сходится (целочисленные λ — до смены ответа); восстановление: cost(K) = solve(λ*) − λ*·K
* **Пример:** a = {1, 3, 2}, K = 2, C = (сумма)²: {1,3}|{2}: 16 + 4 = 20
* **Сложность:** O(n·log C) — solve за O(n) на монотонном CHT (J.8), λ — бинарный поиск
* **Обобщение:** «не более K» ⇔ «ровно K» (монотонность: добавить сегменты нулевой стоимости); вещественный λ при дробных C; задачи: K-сегментное разбиение, K-маршруты, выбор K лучших
* **Реализация:** `min_cost_k_segments_alien(a, K)` — C(i, j) = (сумма a[i..j])², solve через `MonotoneCHT`; возвращает минимум на ровно K сегментов
* **Связь:** двойственность — math/linear-algebra; CHT — J.8; выпуклость — math/analysis

## **J.12. Оптимизация через очередь минимумов (deque)**
* **Постановка:** ans = max по подотрезкам длины ≤ k суммы элементов: pref[i] − min_{j∈[i−k, i−1]} pref[j] — минимум префиксов по скользящему окну: монотонная очередь хранит кандидатов-префиксы с возрастающими значениями (голова — минимум окна)
* **Рекуррентность:** при движении i: удалить из головы выпавшие из окна (j < i−k), удалить из хвоста префиксы ≥ pref[i] (новый кандидат не хуже и дольше живёт), добавить i; ответ окна — голова очереди
* **Почему корректно:** кандидат j доминируется j' > j, если pref[j'] ≤ pref[j] (значение не больше и j' позже выпадает из окна); очередь монотонна по значению — голова минимум; амортизация O(1) на операцию
* **Пример:** a = {1, 2, 3, −2, 1, 4, 3}, k = 2: максимум подотрезка длины ≤ 2: {4, 3} → 7
* **Сложность:** O(n) времени, O(k) памяти
* **Обобщение:** минимум суммы — максимум подотрезка; общая форма — значения dp[j] − pref[j] с убывающей очередью (dp[i] = max_{j∈[i−k, i−1]} (dp[j] − pref[j]) + pref[i]); окно по двум условиям — два указателя + очередь (i.md I.29); Sliding Window в статике — отдельный класс задач (J.17); декартово дерево/стек — альтернатива при отсутствии монотонности
* **Реализация:** `max_subarray_sum_limited(a, k)` — максимум суммы подотрезка длины ≤ k (монотонная deque)
* **Связь:** скользящее окно — i.md (I.29); деревья отрезков — struct

## **J.13. SMAWK в ДП на конвейере**
* **Постановка:** слои ДП вида dp[i] = min_j (prev[j] + C(j, i)) с Монжа-C: минимумы строк слоя — минимумы строк матрицы prev[j] + C(j, i) (Монжа — сохраняется сложением строки); один слой за O(n) вместо O(n²) или O(n log n) (J.5)
* **Идея:** слой prev известен — матрица слоя получается сдвигом Монжа-C на константы строк; smawk_row_minima (J.7) находит argmin всех i; K слоёв — K применений
* **Почему корректно:** сложение константы к строке не нарушает полную монотонность (минимум строки не меняется по j); условие Монжа для C проверяется независимо от prev
* **Пример:** конвейерная задача: K стадий, стоимость перехода C(j, i) = (x[i] − x[j])² — матрица Монжа, слои за O(n) каждый
* **Сложность:** O(K·n) времени (сравнений), O(n) памяти на слой
* **Обобщение:** эквивалентность с LARSCH (полностью монотонные матрицы без явного предъявления); при немонотонной C — не применим (J.17); строки-функции вместо явной матрицы — get(i, j) (J.7)
* **Реализация:** не требуется — послойное применение `smawk_row_minima` (J.7) к матрице prev[j] + C(j, i)
* **Связь:** SMAWK — J.7; D&C — J.5; диагностика — J.17

# **C. ПАРАЛЛЕЛЬНЫЕ И РАСПРЕДЕЛЁННЫЕ РЕАЛИЗАЦИИ ДП**

## **J.14. GPU-оптимизации (CUDA/OpenCL)**
* **Постановка:** массивы-слои — массовый параллелизм: каждый поток считает ячейку слоя; узкое место — зависимость по строкам/диагоналям
* **Идея:** диагональный порядок (d.md D.1) — ячейки диагонали независимы (анти-диагонали — тоже); для зависимостей i−1, j−1, i−1, j−1 — волновой фронт по анти-диагоналям; роллинг (J.1) — два буфера в глобальной памяти, каждый слой — kernel
* **Почему корректно:** параллелизм — по независимым ячейкам одного фронта; затраты на синхронизацию — на границах фронтов; память — банки/шаринг (column-major для соседних j)
* **Сложность:** O(n·m/p) при p ядрах — идеал; реально — узкое место в передаче слоёв
* **Обобщение:** битовые слои (J.2) — векторизация по w бит на поток; интервальные ДП — фронты по длинам; вне рамок библиотеки — схемы, не методы
* **Реализация:** не требуется — теоретическая тема
* **Связь:** роллинг — J.1; диагональный порядок — d.md (D.1)

## **J.15. Распределённое ДП (MapReduce)**
* **Постановка:** слои, не зависящие между собой (k-й слой по k-му предмету): map — частичные переходы, reduce — слияние слоёв
* **Идея:** DP по предметам = конкатенация операторов: свертка слоя с предметом; map-фаза — независимые блоки слоя, reduce — максимум/сумма по источникам; перераспределение — только между слоями
* **Почему корректно:** переходы предмета — монотонные операторы на слое (ассоциативность слияния); границы слоёв — точки синхронизации (аналог фронтов J.14)
* **Сложность:** O(n·m/p + коммуникация); коммуникация доминирует при малых m
* **Обобщение:** потоковые версии (J.16) — частный случай с одним проходом; хеш-секционирование по j — уменьшение перекоса
* **Реализация:** не требуется — теоретическая тема
* **Связь:** слои — J.1; конвейер — J.13

## **J.16. Потоковые алгоритмы (one-pass DP)**
* **Постановка:** данные поступают по одному элементу: рекуррентности, читающие только прошлое (B.1 — лестница, B.6 — подпоследовательности, I.29 — окно): O(1) дополнительной памяти
* **Идея:** состояние — «суффиксная статистика» (последний элемент/серия); инкрементальное обновление при добавлении элемента — то же, что шаг по i таблицы, но без хранения истории
* **Почему корректно:** ДП по времени — марковость по состоянию: будущее зависит от прошлого только через состояние; роллинг (J.1) — уже потоковый для одномерных задач
* **Сложность:** O(n) времени, O(1)–O(k) памяти
* **Обобщение:** скользящие окна (J.12) — потоковые с очередью; вычисление на лету без финального массива — редукция по ответу
* **Реализация:** не требуется — теоретическая тема
* **Связь:** роллинг — J.1; окна — J.12; указатели — i.md (I.29)

## **J.17. Общая стратегия выбора оптимизации**
* **Постановка:** диагностика структуры переходов перед выбором приёма: монотонность точки оптимума → J.5/J.6; линейность по запросу → J.8/J.9; окно по j → J.12; выпуклость по ограничению → J.11; Монжа-матрица → J.7/J.13
* **Рекуррентность-карта:** (1) dp[i] = min_{j<i} (prev[j] + C(j+1, i)): C с QI — D&C (J.5), C Монжа — SMAWK (J.13), C линейная в j·x[i] — CHT (J.8); (2) dp[i][j] = min_{k∈[i,j)} (dp[i][k] + dp[k+1][j] + C[i][j]) с QI — Knuth (J.6); (3) dp[i] = max_{j∈[i−k, i−1]} (...): окно — deque (J.12); (4) ограничение «ровно K» при выпуклой стоимости — Aliens (J.11)
* **Почему корректно:** каждый приём требует своего структурного условия — проверка условия важнее самой техники: QI на C (малые n), монотонность opt по таблице, выпуклость f(k) по точкам
* **Пример:** dp[i] = min_j (dp[j] + (x[i] − x[j])²): QI есть, C Монжа, линии в j — все три применимы (J.5, J.13, J.8); выбор — по простоте реализации
* **Сложность:** проверки — O(n²) предварительно (таблицы opt на малых n); сам приём — по карте
* **Обобщение:** комбинации: Knuth + роллинг, D&C + скроллинг, Aliens + CHT (J.11); эмпирическая проверка на случайных данных — контроль монотонности
* **Реализация:** не требуется — теоретическая тема
* **Связь:** QI — math/analysis; весь раздел B — карта приёмов
