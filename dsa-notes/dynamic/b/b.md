**B. ОДНОМЕРНАЯ ДИНАМИКА**

> **Архитектура:** `LinearDP` (b.cpp) — класс ветки dynamic, наследует `DPBasics` (a.cpp): мемоизация, табуляция, восстановление ответа и разминка (факториал, Фибоначчи, Каталана) переиспользуются из базы; биномиальные коэффициенты — `C_iter` из `math/combinatorics` (a/a.md). Раздел вводит одномерную динамику в трёх семействах: классические задачи (лестницы, линейные рекурренты, оптимизации max/min, Иосиф), комбинаторная динамика (подсчёт способов, путей, беспорядки) и дополнительные олимпиадные задачи (декодирование, акции, прыжки, слияние указателями, сжатие значений, серии и ограничения длины). Все B-алгоритмы — методы `LinearDP`.
>
> **Связи:** состояния и функциональное уравнение — a.md (A.1–A.4); рекуррентности и порядок вычисления — a.md (A.5); мемоизация и табуляция — a.md (B.1–B.2); восстановление ответа — a.md (B.4); расширение состояния для задач «с памятью» (серии, cooldown) — a.md (A.3); биномиальные коэффициенты и включения-исключения — `math/combinatorics` (a/a.md); линейные рекурренты через матрицу k×k — раздел C; монотонная очередь — раздел J (задел — B.22).

### **Основные понятия и принципы**

* **Что это:** простейший класс ДП: состояние — одна числовая координата (обычно позиция префикса i), ответ для префикса выражается через ответы меньших префиксов
* **Почему выделяется в отдельный класс:** структура задачи — линейная последовательность решений; «последний шаг» (последняя ступень, последняя монета, последний элемент подпоследовательности) разбивает задачу на подзадачи с меньшим i, откуда возникает естественный порядок вычисления слева направо — без таблиц и обходов
* **Ключевые принципы:** декомпозиция по последнему элементу (a.md A.1); правило суммы для счёта способов и максимум/минимум для оптимумов; линейные рекурренты порядка k как обобщение — зависимость от k предыдущих значений; восстановление ответа — обратный проход по таблице решений
* **Как распознать:** задача на последовательность, где решение в позиции i зависит только от предыдущих позиций и «сжимается» до одного числа (или кортежа константного размера — хвоста рекурренты); классика — лестницы, монеты, подпоследовательности, беспорядки
* **Границы:** две независимые координаты (две строки, предмет + вес) — раздел C; задачи «с памятью» (серии, cooldown) — расширение состояния (a.md A.3); большие n с рекуррентами — матричные переходы (раздел C); окна и очереди — раздел J

# **A. КЛАССИЧЕСКИЕ ЗАДАЧИ**

## **B.1. Climbing Stairs**
* **Постановка:** число способов подняться на ступень n, если каждый шаг имеет длину от 1 до k
* **Рекуррентность:** f(n) = Σ_{i=1..k, i ≤ n} f(n−i), база f(0) = 1 (стоим у подножия); последний шаг длины i различает множества способов для разных i
* **Почему сумма:** способы, оканчивающиеся шагами разной длины, не пересекаются — правило суммы (`math/combinatorics`, a.md B.2)
* **Пример:** k = 2: f(n) = f(n−1) + f(n−2) — числа Фибоначчи (a.md 5.2): f(10) = 89; k = 3: f(10) = 274
* **Сложность:** O(n·k) времени, O(n) памяти; достаточно последних k значений — O(k) памяти
* **Обобщение:** шаги произвольных длин L = {ℓ₁, ..., ℓₖ}: f(n) = Σ_{ℓ ∈ L, ℓ ≤ n} f(n−ℓ) — без фиксированных границ (a.md B.5)
* **Ограничение серий:** не более t шагов длины m подряд — состояние расширяется длиной серии (a.md A.3): f(i, j) — способы на ступени i с серией шагов длины m длиной j; шаг длины m ведёт в j+1 (пока j+1 ≤ t), шаг другой длины — в j = 0; ответ Σⱼ f(n, j)
* **Реализация:** `climbing_stairs`, `climbing_stairs_constrained`
* **Связь:** трибоначчи — частный случай k = 3 (B.2); серии — Paint Fence (B.19)

## **B.2. Fibonacci, Tribonacci**
* **Постановка:** линейная рекуррента порядка k: aₙ = Σ_{i=1..k} cᵢ·aₙ₋ᵢ с заданной базой a₀..aₖ₋₁; классика — трибоначчи T(n) = T(n−1) + T(n−2) + T(n−3), базы T(0) = 0, T(1) = 0, T(2) = 1
* **Порядок вычисления:** a₀ → a₁ → ... → aₙ; каждый член — сумма k предыдущих; при кольцевом хранении размера k значение a[i] лежит в a[i mod k] — O(k) памяти (a.md B.2)
* **Пример:** T(10) = 81; T(25) = 755476; Фибоначчи — a.md 5.2
* **Сложность:** O(n·k) времени, O(k) памяти
* **Обобщение:** матрица перехода k×k и её возведение в степень — O(k³·log n): раздел C (MatrixDP); нелинейные рекуррентности (свёртки, Каталана) — a.md 5.3
* **Реализация:** `linear_recurrence` (общий порядок k; трибоначчи — c = {1, 1, 1}, база {0, 0, 1})
* **Связь:** Climbing Stairs с шагами 1..k — та же рекуррента (B.1); быстрое вычисление Фибоначчи в базе — a.md (B.2)

## **B.3. House Robber / Max Non Adjacent Sum**
* **Постановка:** из массива a выбрать подмножество без соседних элементов с максимальной суммой (значения неотрицательные — классика House Robber)
* **Рекуррентность:** dp[i] = max(dp[i−1], dp[i−2] + a[i]) — пропустить i-й (лучшее до i−1) или взять его (лучшее до i−2 плюс a[i])
* **Почему два варианта:** оптимальное подмножество либо не содержит a[i] (тогда dp[i−1]), либо содержит (тогда a[i−1] недоступен — dp[i−2] + a[i]) — полное разбиение случая
* **Пример:** {2, 7, 9, 3, 1}: 2 + 9 + 1 = 12
* **Сложность:** O(n) времени, O(1) памяти (два последних значения)
* **Кольцевой вариант:** первый и последний элементы соседние — два прохода: по a[0..n−2] (без последнего) и по a[1..n−1] (без первого), ответ — максимум
* **Реализация:** `max_non_adjacent_sum`, `max_non_adjacent_sum_circular`
* **Связь:** Delete and Earn (B.20) сводится к ней сжатием значений; база max-семейства одномерной динамики

## **B.4. Max Subarray Sum — алгоритм Кадане**
* **Постановка:** максимальная сумма непрерывного подотрезка массива
* **Рекуррентность:** best[i] = max(best[i−1] + a[i], a[i]) — лучший подотрезок, оканчивающийся в i: продолжает лучший слева либо начинается заново; ответ — максимум по всем i
* **Обоснование:** оптимальный подотрезок, оканчивающийся в i, либо длины 1, либо продолжает оптимальный подотрезок, оканчивающийся в i−1 (иначе замена улучшила бы — a.md 6)
* **Пример:** {−2, 1, −3, 4, −1, 2, 1, −5, 4}: подотрезок 4, −1, 2, 1 → 6
* **Сложность:** O(n) времени, O(1) памяти
* **Обобщение:** минимальный подотрезок — та же рекуррентность с min; подотрезок с ограничением длины k — префиксные суммы + монотонная очередь: B.22 (задел на J)
* **Реализация:** `max_subarray_sum`, `min_subarray_sum`
* **Связь:** Maximum Sum Submatrix — Кадане по строкам (раздел C); скользящие окна — раздел J

## **B.5. Minimum Steps To One**
* **Постановка:** свести n к 1 операциями из набора; операция — вычитание v с ценой c или деление на p с ценой c; минимизировать суммарную цену
* **Рекуррентность:** f(1) = 0; f(n) = min( min_{вычитание (v,c), v < n} (c + f(n−v)), min_{деление (p,c), p | n} (c + f(n/p)) ) — деление только при делимости, вычитание — пока результат ≥ 1
* **Почему корректно:** последняя операция оптимальной последовательности — одна из допустимых (a.md 6, exchange argument)
* **Пример:** операции «−1 (цена 1)», «÷3 (цена 3)»: f(10) = 6 (путь 10 → 9 → 3 → 2 → 1)
* **Сложность:** O(n·|операции|) времени, O(n) памяти
* **Обобщение (поглощение констант, a.md B.5):** классика «1 + min(f(n−1), f(n/2), f(n/3))» — частный случай единичных цен; вариант с восстановлением пути — a.md B.4 (`min_steps_to_one_path`)
* **Реализация:** `min_ops_to_one`
* **Связь:** единая форма функционального уравнения — a.md A.4; минимум по переходам — семейство B.6

## **B.6. Minimum Coin Change**
* **Постановка:** минимальное число монет набора c₁..cₖ (неограниченный запас), дающих сумму s
* **Рекуррентность:** dp[0] = 0; dp[s] = min_{cᵢ ≤ s} (dp[s − cᵢ]) + 1; недостижимые суммы — ∞ (никакой набор монет не даёт s)
* **Почему корректно:** последняя монета оптимального набора — одна из cᵢ; удалив её, получим оптимальный набор для s − cᵢ
* **Пример:** монеты {1, 3, 4}, s = 6: 3 + 3 → 2 монеты
* **Сложность:** O(s·k) времени, O(s) памяти
* **Восстановление набора:** prev[s] хранит монету оптимального перехода; обратный проход от s до 0 собирает набор (a.md B.4)
* **Реализация:** `coin_change_min`
* **Связь:** количество способов (не минимум) — B.10; произвольные множества чисел — B.18; рюкзак с весами и ценами — раздел C

## **B.7. Minimum Tickets Cost**
* **Постановка:** заданы дни поездок (отсортированные); билет j покрывает dⱼ дней подряд и стоит pⱼ; минимальная стоимость покрытия всех дней поездок
* **Рекуррентность:** dp[d] = dp[d−1] для дней без поездки; для дня с поездкой dp[d] = minⱼ (dp[max(0, d − dⱼ)] + pⱼ) — билет j, купленный в день d − dⱼ + 1, покрывает все дни до d включительно
* **Почему корректно:** билет — интервал; последний по началу билет покрывает последний день поездки, всё до него — та же задача на меньшем числе дней (оптимальная подструктура, a.md A.1)
* **Пример:** дни {1, 4, 6, 7, 8, 20}, билеты 1/7/30 дней по цене 2/7/15: 7-дневный на 1..7 + одиночные на 8 и 20 → 7 + 2 + 2 = 11
* **Сложность:** O(D·|билеты|) времени, O(D) памяти (D — последний день поездки)
* **Обобщение (поглощение констант):** произвольные длительности dⱼ и цены pⱼ; классика «1/7/30 дней» — частный случай
* **Реализация:** `min_tickets_cost`
* **Связь:** та же структура, что у coin change (B.6), но по дням с интервальным покрытием

## **B.8. Задача Иосифа Флавия (Josephus)**
* **Постановка:** n человек в круге; начиная с первого, каждый k-й выбывает; номер последнего оставшегося
* **Рекуррентность (0-индексация):** J(1, k) = 0; J(n, k) = (J(n−1, k) + k) mod n — после первого выбывания круг из n−1 человек, нумерация сдвинута на k
* **Почему корректно:** выбывает человек с индексом k mod n; оставшиеся снова образуют круг размера n−1, а сдвиг их индексов относительно исходных — ровно k
* **Индексация с 1:** J₁(n, k) = J(n, k) + 1
* **Пример:** J(10, 3) = 3 (0-индексация), J₁(10, 3) = 4
* **Сложность:** O(n) времени, O(1) памяти
* **Быстрый вариант (большие n):** прыжки по блокам: пока m < n, t = (m − x)/(k − 1) шагов подряд без «оборота» (x + t·k ≤ m + t); при t = 0 — обычный шаг; O(k·log n) времени — `josephus_fast`
* **Обобщение:** выбывание с m перешагиваний — то же с k = m + 1; последние m выживших: рекуррентность сохраняется для набора — sᵢ = (sᵢ + k) mod sz при росте sz от m до n — `josephus_last_m`
* **Реализация:** `josephus`, `josephus_1based`, `josephus_fast`, `josephus_last_m`
* **Связь:** единственное состояние — размер круга, рекуррентность по n — классика одномерной динамики (задача перенесена сюда из combinatorics)

# **B. КОМБИНАТОРНАЯ ДИНАМИКА**

## **B.9. Combination Sum IV**
* **Постановка:** число последовательностей из монет c₁..cₖ, дающих сумму s — ПОРЯДОК важен (перестановки монет считаются разными)
* **Рекуррентность:** dp[0] = 1; dp[s] = Σ_{cᵢ ≤ s} dp[s − cᵢ] — последний элемент последовательности — одна из монет
* **Почему порядок учтён:** фиксируем последнюю монету — множества последовательностей с разными последними элементами не пересекаются, для каждого префикса берём все его последовательности (правило суммы)
* **Пример:** монеты {1, 2, 3}, s = 4: 7 последовательностей (1111, 112, 121, 211, 22, 13, 31)
* **Сложность:** O(s·k) времени, O(s) памяти
* **Отличие от размена (B.10):** там внешний цикл по монетам — множества без учёта порядка; здесь внешний по суммам — порядок учитывается
* **Реализация:** `combination_sum4`
* **Связь:** «комбинаторное» ДП — opt = сумма (a.md A.4); подсчёты быстро растут — модулярные версии в следующих разделах

## **B.10. Размен монет — количество способов**
* **Постановка:** число НЕупорядоченных наборов монет c₁..cₖ, дающих сумму s (каждая монета — сколько угодно раз)
* **Рекуррентность:** dp[s] += dp[s − cᵢ] с внешним циклом по монетам: dp[s] до обработки монеты cᵢ считает наборы только из уже введённых монет
* **Почему внешний цикл по монетам:** монеты вводятся по одной — набор, содержащий cᵢ, учитывается один раз в момент введения, перестановки не считаются
* **Пример:** монеты {1, 2, 3}, s = 4: 4 набора (1111, 112, 22, 13)
* **Сложность:** O(s·k) времени, O(s) памяти
* **Обобщение:** ограниченный запас монет — добавляется размерность «сколько осталось» (knapsack, раздел C)
* **Реализация:** `coin_change_ways`
* **Связь:** пара «порядок важен/не важен» — B.9; производящие функции для размена — `math/combinatorics` (b/b.md)

## **B.11. Подсчёт путей в сетке**
* **Постановка:** число путей из (0, 0) в (n₁, n₂) шагами вправо и вниз (n₁ шагов вниз, n₂ шагов вправо)
* **Рекуррентность (2D):** f(i, j) = f(i−1, j) + f(i, j−1) — последний шаг либо сверху, либо слева (правило суммы)
* **Одномерная формула:** любой путь — перестановка n₁ + n₂ шагов; выбрать позиции шагов одного типа: f(n₁, n₂) = C(n₁ + n₂, n₁) — бином, `C_iter`
* **Пример:** сетка 10×10: C(18, 9) = 48620; сетка 3×3: C(4, 2) = 6
* **Сложность:** O(1) по формуле (O(n₁) на бином); O(n₁·n₂) табуляцией
* **С запрещёнными клетками:** вычитание путей через препятствия (включения-исключения) — раздел C
* **Реализация:** `grid_paths`
* **Связь:** бином — `math/combinatorics` (a/a.md, `C_iter`); монотонные пути не выше диагонали — Каталана (B.12)

## **B.12. Числа Каталана — интерпретации**
* **Рекуррентность и вычисление:** C₀ = 1, Cₙ = Σ_{i=0}^{n−1} Cᵢ·Cₙ₋₁₋ᵢ — `catalan_dp` из базы (a.md 5.3); биномиальная формула Cₙ = C(2n, n)/(n+1) — `catalan_by_binom`
* **Интерпретации (биекции):**
  * правильные скобочные последовательности из n пар — Cₙ
  * бинарные деревья с n внутренними вершинами — Cₙ
  * триангуляции выпуклого (n+2)-угольника — Cₙ
  * монотонные пути из (0, 0) в (n, n), не поднимающиеся выше диагонали — Cₙ
* **Почему одна формула:** все структуры связаны биекциями — счёт одной даёт все остальные
* **Отражение Андре:** Cₙ = C(2n, n) − C(2n, n+1) — пути, заходящие выше диагонали, биективны путям с отражённым начальным участком (см. B.11)
* **Сверка:** catalan_by_binom(30) = catalan_dp(30) = 3814986502092304 — две независимые формулы дают одно число
* **Сложность:** O(n²) свёрткой; O(n) по формуле (бином C_iter)
* **Реализация:** `catalan_by_binom`
* **Связь:** производящие функции Каталана — `math/combinatorics` (b/b.md); готовые значения по модулю — special-sequences (combinatorics)

## **B.13. Беспорядки (Derangements)**
* **Определение:** перестановки без неподвижных точек (ни один элемент не остаётся на месте)
* **Рекуррентность:** D(1) = 0, D(2) = 1; D(n) = (n−1)·(D(n−1) + D(n−2)) — элемент 1 можно поставить в n−1 позицию; если j, куда пошёл 1, содержит его самого (1 ↔ j) — остальные n−2 беспорядочны (D(n−2)); иначе — беспорядок n−1 (D(n−1))
* **Альтернативная рекуррентность:** D(n) = n·D(n−1) + (−1)ⁿ
* **Через включения-исключения:** D(n) = Σ_{i=0..n} (−1)ⁱ·C(n, i)·(n−i)! = n!·Σ (−1)ⁱ/i! — событие Aᵢ = «i-й элемент на месте», вычитаем пересечения
* **Асимптотика:** D(n) = ⌊n!/e + 1/2⌋ — ближайшее целое к n!/e
* **Пример:** D(10) = 1334961; D(5) = 44
* **Сложность:** O(n) времени, O(1) памяти (рекуррентность)
* **Частичные беспорядки:** ровно k неподвижных точек: C(n, k)·D(n−k) — выбрать позиции неподвижных + беспорядок остальных
* **Реализация:** `derangements`, `derangements_ie` (сверка с рекуррентностью), `derangements_partial`
* **Связь:** включения-исключения — `math/combinatorics` (a.md D); теория беспорядков там же (a.md D.3), рекуррентности перенесены сюда

# **C. ДОПОЛНИТЕЛЬНЫЕ ОЛИМПИАДНЫЕ ЗАДАЧИ**

## **B.14. Decode Ways**
* **Постановка:** цифровая строка кодирует сообщение; коды — числа 1..m (для m = 26 — алфавит): одна цифра или две цифры подряд; число способов декодирования
* **Рекуррентность:** dp[i] = dp[i−1]·[1 ≤ aᵢ ≤ m] + dp[i−2]·[10 ≤ aᵢ₋₁aᵢ ≤ m] — последний символ сообщения — одна буква (одна цифра) или буква с кодом из двух цифр
* **Индикаторы:** [условие] — 1 при истине, 0 при лжи: невалидные коды просто не добавляют способов
* **Пример:** «226» при m = 26: 3 способа (2-2-6, 2-26, 22-6); при m = 20: 1 (22 и 26 — не коды)
* **Сложность:** O(n) времени, O(1) памяти
* **Обобщение (поглощение констант):** алфавит из m кодов вместо фиксированного 26; коды длиной до L цифр — сумма по L вариантам (индикаторы длины L)
* **Реализация:** `decode_ways`
* **Связь:** «серия» последнего блока — серии в B.1, B.19; мемоизация — a.md B.1

## **B.15. Best Time to Buy and Sell Stock (серия)**
* **Постановка:** цены p[0..n−1]; максимизировать прибыль от покупок и продаж; серия задач по числу транзакций
* **Одна транзакция:** profit = max(p[i] − min_{j<i} p[j]) — купить в минимуме до i, продать в i; O(n) за один проход
* **k транзакций:** dp[t][d] = max(dp[t][d−1], p[d] + max_{d'<d} (dp[t−1][d'] − p[d'])) — либо не торгуем в день d, либо продаём в d то, что купили в d'; максимум по d' поддерживается в ходе прохода
* **Почему корректно:** последняя транзакция заканчивается продажей в день d (или её нет — dp[t][d−1]); покупка в d' возможна только после t−1 завершённых транзакций
* **Пример:** k = 2, p = {3, 2, 6, 5, 0, 3}: 7 (купить 2 → продать 6; купить 0 → продать 3)
* **Сложность:** O(k·n) времени, O(n) памяти
* **Обобщение:** комиссия fee за транзакцию — из цены продажи вычитается fee; cooldown (нельзя покупать в день, следующий за продажей) — состояние расширяется (a.md A.3): dp0[d] = max(dp0[d−1], dp1[d−1] + p[d]); dp1[d] = max(dp1[d−1], dp0[d−2] − p[d]) — покупка не раньше, чем через день после продажи
* **Реализация:** `max_profit_one`, `max_profit_k`, `max_profit_k_fee`, `max_profit_cooldown`
* **Связь:** расширение состояния (a.md A.3); двумерная динамика по (t, d) — введение в раздел C

## **B.16. Jump Game**
* **Постановка:** из позиции i можно прыгнуть на любую из i+1..i+a[i]; достижим ли конец (и минимальное число прыжков)
* **Рекуррентность (достижимость):** dp[i] = ∃j < i: dp[j] и j + a[j] ≥ i — позиция достижима, если из какой-то достижимой позиции до неё допрыгивают
* **Однопроходный вариант:** farthest = max(farthest, j + a[j]) — множество достижимых позиций всегда префикс [0..farthest]: позиция i недостижима, если i > farthest
* **Минимальное число прыжков:** жадность слоями: cur — граница текущего слоя, farthest — граница следующего; при i == cur прыжок засчитывается и cur = farthest
* **Пример:** {2, 3, 1, 1, 4} — достижимо, 2 прыжка (1 → 3 → 4); {3, 2, 1, 0, 4} — недостижимо
* **Сложность:** O(n) времени, O(1) памяти
* **Реализация:** `can_reach`, `min_jumps`
* **Связь:** «булево» ДП достижимости; обоснование жадности — обмен аргументов (a.md 6)

## **B.17. Ugly Numbers**
* **Определение:** числа вида p₁^e₁ · ... · pₖ^eₖ (для {2, 3, 5} — классические ugly); n-е по порядку
* **Идея (слияние последовательностей):** каждое следующее число — минимум из «кандидатов»: умножение каждого простого pⱼ на очередное уже найденное число; указатель idx[j] хранит следующее число для умножения на pⱼ
* **Алгоритм:** next = minⱼ (res[idx[j]] · pⱼ); добавить в res; все j, где res[idx[j]]·pⱼ == next, сдвигают указатель — без дубликатов
* **Пример:** {2, 3, 5}: 1, 2, 3, 4, 5, 6, 8, 9, 10, 12 — десятое = 12
* **Сложность:** O(n·k) времени, O(n) памяти
* **Обобщение (поглощение констант):** произвольный набор простых p₁..pₖ вместо {2, 3, 5}; слияние k монотонных последовательностей — общий приём
* **Реализация:** `ugly_numbers`
* **Связь:** указатели в монотонных последовательностях — тот же приём, что слияние в сортировке

## **B.18. Perfect Squares**
* **Постановка:** минимальное число слагаемых-квадратов, дающих n
* **Рекуррентность:** dp[n] = min_{k² ≤ n} dp[n − k²] + 1 — последнее слагаемое — квадрат k²
* **Пример:** 12 = 4 + 4 + 4 → 3 слагаемых
* **Сложность:** O(n·√n) времени (√n квадратов), O(n) памяти
* **Обобщение (поглощение констант):** произвольное множество чисел parts вместо квадратов: dp[n] = min_{p ∈ parts, p ≤ n} dp[n − p] + 1 — та же рекуррентность, что B.6, без восстановления
* **Реализация:** `min_summands`
* **Связь:** полная параллель с B.6; наборы слагаемых и разбиения — `math/combinatorics` (b/b.md)

## **B.19. Paint Fence**
* **Постановка:** покрасить n заборов в k цветов так, чтобы не более t одинаковых цветов шли подряд
* **Рекуррентность (классика t = 2):** same[i] = diff[i−1] (последние два одного цвета — третий обязан отличаться); diff[i] = (same[i−1] + diff[i−1])·(k−1) — последние два разных: k−1 вариант для i-го
* **Обобщение (серия длины t):** состояние — длина текущей серии (a.md A.3): dp[i][1] = (k−1)·total[i−1] (серию не продолжаем), dp[i][j] = dp[i−1][j−1] для j = 2..t (продолжаем); total[i] = Σⱼ dp[i][j]
* **Пример:** n = 3, k = 2, t = 2: 6 (из 8 раскрасок исключены 000 и 111); n = 4, k = 2: 10; t = 3: все 8
* **Сложность:** O(n·t) времени, O(t) памяти
* **Реализация:** `paint_fence`
* **Связь:** серии — приём из B.1 (a.md A.3); total[n] — линейная рекуррента порядка t (B.2)

## **B.20. Delete and Earn**
* **Постановка:** даны числа; взяв значение v, зарабатываем v и «удаляем» все v−1 и v+1; максимизировать сумму
* **Идея (сжатие по значениям):** внутри одного значения выбор тривиален — берём всё: sum[v] = v·count(v); после сжатия конфликтуют только соседние значения — задача House Robber (B.3) на массиве сумм
* **Почему корректно:** конфликт только между соседними значениями, внутри значения конфликтов нет — сумма значений и есть заработок
* **Пример:** {2, 2, 3, 3, 3, 4}: sum[2] = 4, sum[3] = 9, sum[4] = 4 → 9; {3, 4, 2}: 6 (4 + 2)
* **Сложность:** O(max + n) времени (массив сумм по значениям), O(max) памяти
* **Реализация:** `delete_and_earn`
* **Связь:** сведение к B.3 — переиспользование `max_non_adjacent_sum`; сжатие значений — приём при больших разбросах

## **B.21. Maximum Length of Pair Chain / Activity DP**
* **Постановка:** даны пары (aᵢ, bᵢ); цепочка — последовательность с b < a следующей; максимальная длина цепочки
* **Идея:** сортировка по второму элементу + одномерная ДП: dp[i] = 1 + max_{j: bⱼ < aᵢ} dp[j] — лучшая цепочка, оканчивающаяся парой i
* **Почему сортировка по b:** оптимальная цепочка может считаться отсортированной по b (обмен аргументов — a.md 6); упорядочивание делает состояния линейными
* **Пример:** {(1, 2), (2, 3), (3, 4)} → 2; {(1, 2), (7, 8), (4, 5)} → 3
* **Сложность:** O(n²) времени, O(n) памяти; жадность по правому концу (брать пару с наименьшим b) — O(n log n), та же корректность
* **Реализация:** `max_pair_chain`
* **Связь:** сортировка как упорядочивание состояний — общий приём; интервальная динамика — разделы C, D

## **B.22. Подотрезок с ограничением длины k (обобщение B.4)**
* **Постановка:** максимальная сумма подотрезка длины ≤ k (k — параметр)
* **Идея:** префиксные суммы: сумма [l, r] = pref[r] − pref[l−1]; для каждого r нужен минимум pref[l−1] при l−1 ∈ [r−k, r−1] — минимум в скользящем окне
* **Монотонная очередь (deque):** индексы в deque хранятся с возрастающими pref; при добавлении r выбрасываем из конца всё с pref ≥ pref[r−1] (никогда не станут минимумом — есть меньшее и более «свежее»); из начала выбрасываем вышедшие из окна (< r−k); минимум — в голове
* **Почему корректно:** выброшенное значение никогда не станет минимумом окна — перед ним есть меньшее с большим сроком жизни
* **Пример:** {1, 2, 3, −4, 5}, k = 2: подотрезок 2, 3 → 5
* **Сложность:** O(n) времени (каждый индекс входит и выходит один раз), O(k) памяти
* **Статус:** структура «монотонная очередь» разбирается в разделе J — здесь первое применение (задел)
* **Реализация:** `max_subarray_sum_len_k`
* **Связь:** обобщение Кадане (B.4); оптимизации скользящим окном — раздел J
