**E. ДИНАМИКА ПО ПОДМНОЖЕСТВАМ (БИТОВЫЕ МАСКИ)**

> **Архитектура:** `SubsetDP` (e.cpp) — класс ветки dynamic, наследует `SegmentDP` (d.cpp), а через него `MatrixDP`, `LinearDP`, `DPBasics`. Раздел вводит динамику по подмножествам: подмножество множества {0..n−1} кодируется числом (битовая маска), состояние — маска или пара (маска, элемент); ограничение размера — n ≤ 20–25 (память 2ⁿ·n). Переиспользуются, а не дублируются: беспорядки `derangements` (b.md B.13), бином `C_iter` (`math/combinatorics`), ладьи на доске Феррера `ferrers_rook_dp` (c.md C.10 — частный случай задачи о ладьях), достижимость подмножественных сумм `subset_sum_reachable` (c.md C.23, сверка meet-in-the-middle).
>
> **Связи:** состояния и функциональное уравнение — a.md (A.1–A.4); мемоизация и табуляция — a.md (B.1–B.2); восстановление — a.md (B.4); расширение состояния — a.md (A.3); битовые операции и перестановки с запрещёнными позициями — `math/combinatorics` (a.md F.4); беспорядки — b.md (B.13); доска Феррера — c.md (C.10); деревья/циклы — раздел G (Hamiltonian-пути — E.10); венгерский алгоритм O(n³) — альтернатива назначению (E.9); SOS DP (E.15) применяется к задачам разделов G, H; параметрическая динамика — раздел I (E.17 — рюкзачные варианты).

### **Основные понятия и принципы**

* **Что это:** состояние — подмножество базового множества {0..n−1}, закодированное битовой маской; пространство состояний — все 2ⁿ подмножеств, отсюда ограничение n ≤ 20–25
* **Почему выделяется в отдельный класс:** порядок обработки элементов заранее не фиксирован и не важен — полную информацию о «прошлом» даёт само множество уже обработанных/посещённых элементов; классический префиксный порядок невозможен, вместо него — порядок по размеру множества (popcount) или по значению маски
* **Ключевые принципы:** «подмножество + последний элемент» — для задач, где порядок важен (TSP: dp[mask][v] — последняя вершина; назначения: последний рабочий); перебор подмасок за O(3ⁿ); сумма по подмножествам — SOS DP за O(n·2ⁿ); meet-in-the-middle для n ≈ 40; фиксация младшего бита против дублей при счёте
* **Как распознать:** n ≤ 20–25 и задача о выборе подмножества с взаимодействием элементов (клики, покрытия, паросочетания, TSP, назначения, разбиения на равные суммы)
* **Границы:** экспонента по n — при n > 25 нужны другие методы (структура задачи: деревья — раздел G, двудольность — раздел H, жадные/приближённые); задачи на досках с шириной m и длиной n — профильная динамика (раздел F), где экспонента только по ширине

# **A. ОСНОВНЫЕ ТЕХНИКИ**

## **E.1. Bitmask: представление подмножества**
* **Постановка:** подмножество X ⊆ {0..n−1} — число: бит i = 1, если i ∈ X; размеры состояний 2ⁿ, ограничение n ≤ 20–25
* **Операции:** `popcount(mask)` — число битов (размер множества); `test_bit(mask, i)` — проверка i ∈ X; `lowbit(mask)` = mask & (−mask) — младший установленный бит
* **Почему корректно:** побитовые операции над числами — операции над множествами: объединение |, пересечение &, разность &~, проверка подмножества (part & mask) == part
* **Пример:** mask = 11 = 1011₂ — множество {0, 1, 3}; popcount = 3; test_bit(11, 3) = 1, test_bit(11, 2) = 0; lowbit(12) = 4 (100₂)
* **Сложность:** операции O(1), popcount — машинная инструкция
* **Обобщение (поглощение констант):** индексы множества всегда {0..n−1} — редукция входных данных к индексам, константы не участвуют
* **Реализация:** `popcount`, `test_bit`, `lowbit`
* **Связь:** профильные маски — раздел F; маски подмножеств в рекуррентностях — E.4–E.19

## **E.2. Iterating Through Submasks**
* **Постановка:** перечислить все подмаски sub ⊆ mask
* **Рекуррентность (перебор):** for (sub = mask; ; sub = (sub − 1) & mask) — каждая итерация сбрасывает младшие биты: следующая подмаска — уменьшение на 1 с сохранением «разрешающей» маски
* **Почему корректно:** (sub − 1) & mask переходит от sub к наибольшей подмаске mask, меньшей sub (стандартный трюк вычитания); перечисление строго убывающее, заканчивается на 0
* **Сложность:** Σ_mask 2^popcount(mask) = 3ⁿ — суммарный перебор всех подмасок всех масок
* **Пример:** подмаски mask = 11 (1011₂): 11, 10, 9, 8, 3, 2, 1, 0; count_submasks(15) = 16 = 2⁴
* **Обобщение:** пустая подмаска обрабатывается отдельно (последняя итерация); порядок использования — основа E.4 (All Construct)
* **Реализация:** `count_submasks(mask)`, `sum_submasks_counts(n)` (демонстрация O(3ⁿ) = 3ⁿ)
* **Связь:** порождающие подмножества в E.4, E.12, E.14

## **E.3. Subset Generation**
* **Постановка:** перечислить все подмножества, в том числе упорядоченные по размеру; подмножества фиксированного размера
* **Идея:** подмаски собираются в корзины по popcount; внутри корзины — по возрастанию значения маски
* **Почему корректно:** группировка по popcount — ровно перечисление по размеру (биекция размер ↔ popcount)
* **Пример:** подмаски 11 (1011₂): 0; 1, 2, 8; 3, 9, 10; 11 (по размерам 0, 1, 2, 3)
* **Сложность:** O(2ⁿ) времени, O(2ⁿ) памяти
* **Обобщение:** сочетания C(n, k) как подмножества размера k — перечисление по тому же принципу с фильтром (готовые комбинаторные генераторы — `math/combinatorics`)
* **Реализация:** `subsets_sorted_by_size(mask)`
* **Связь:** порядок состояний по размеру — оптимизация E.19 (внешний цикл по popcount)

## **E.4. All Construct**
* **Постановка:** множество частей parts ⊆ {0..n−1}; число способов собрать полное множество из частей (порядок частей важен — последовательность сборки)
* **Рекуррентность:** dp[mask] = Σ dp[mask \ part] по всем part ⊆ mask; база dp[0] = 1 — последняя положенная часть part; остаток собран раньше
* **Почему корректно:** каждая последовательность сборки однозначно задаётся последней частью part и последовательностью сборки остатка (a.md A.1); перебор part полон — полное разбиение по последнему элементу
* **Пример:** n = 3, части {1, 2, 4} (одиночные): 3! = 6 способов; dp[111] = dp[110] + dp[101] + dp[011] = 2 + 2 + 2
* **Сложность:** O(2ⁿ·|parts|) времени, O(2ⁿ) памяти
* **Обобщение:** части одинаковые по содержимому считаются разными способами (позиции частей); неупорядоченный вариант — «0-1 по частям» (E.12 — Set Cover)
* **Реализация:** `count_constructs(n, parts)`
* **Связь:** перебор подмасок — E.2; неупорядоченный счёт — E.12

# **B. КЛАССИЧЕСКИЕ ЗАДАЧИ**

## **E.5. Travelling Salesman: путь**
* **Постановка:** полный ориентированный граф с весами w[u][v]; минимальная стоимость пути, посещающего все вершины ровно по разу, из старта 0 (без возврата)
* **Рекуррентность:** dp[mask][v] = min_{u ∈ mask \ {v}} (dp[mask \ {v}][u] + w[u][v]) — последний шаг u → v; база dp[{0}][0] = 0; ответ min_v dp[full][v]
* **Почему корректно:** состояние (mask, v) — «посещены вершины mask, текущая v»; последняя вершина v приходит из u ∈ mask \ {v} по ребру w[u][v], остаток пути — оптимальный путь по mask \ {v} (a.md A.1)
* **Пример:** w(4 города, классика): путь 0→1→3→2: 10 + 25 + 30 = 65 — минимум
* **Сложность:** O(2ⁿ·n²) времени, O(2ⁿ·n) памяти
* **Обобщение:** восстановление маршрута — E.19; порядок состояний по popcount — E.19; метрический случай — E.7
* **Реализация:** `tsp_path(w)`
* **Связь:** Hamiltonian-путь (существование) — E.10; Bitonic TSP — E.8

## **E.6. TSP с возвратом в старт**
* **Постановка:** замкнутый цикл — вернуться в старт 0
* **Рекуррентность:** те же dp[mask][v]; ответ min_v (dp[full][v] + w[v][0]) — к оптимальному пути добавляется ребро возврата
* **Почему корректно:** замкнутый цикл = путь + ребро из конца в старт; перебор конца v полон
* **Пример:** w(4 города, классика): min_v (dp[full][v] + w[v][0]) = 70 + 10 = 80 (цикл 0→2→3→1→0)
* **Сложность:** O(2ⁿ·n²) времени, O(2ⁿ·n) памяти
* **Обобщение:** произвольный старт — база dp[{s}][s] = 0
* **Реализация:** `tsp_cycle(w)`
* **Связь:** E.5 (та же таблица, другой ответ); Hamiltonian-цикл — E.10

## **E.7. TSP: метрика и эвристики**
* **Постановка:** метрический случай — веса удовлетворяют неравенству треугольника
* **Идея:** без метрики задача не приближаема за полиномиальный множитель (только точное ДП E.5); с метрикой работают жадные и MST-эвристики (2-приближение), но точность гарантируется только динамикой по подмножествам
* **Почему корректно:** неравенство треугольника позволяет «выпрямлять» маршруты без удорожания — отсюда оценки приближения; без него такие операции ломают вес
* **Сложность:** обсуждение — реализация не требуется
* **Обобщение:** геометрический случай (евклидово расстояние) — метрика автоматически; Bitonic TSP (E.8) — полиномиальный частный случай на плоскости
* **Реализация:** отдельного метода нет (точные алгоритмы — E.5/E.6)
* **Связь:** E.5, E.6, E.8

## **E.8. Bitonic TSP**
* **Постановка:** точки на плоскости, отсортированные по x; минимальный цикл — два монотонных (слева направо) пути от самой левой точки до самой правой
* **Рекуррентность:** dp[i][j] (i > j) — суммарная длина двух путей: один оканчивается в i, другой в j, покрыты точки 0..i; переходы: при j < i−1: dp[i][j] = dp[i−1][j] + d(i−1, i) (точка i продолжает путь из i−1); при j = i−1: dp[i][i−1] = min_{k < i−1} (dp[i−1][k] + d(k, i)); база dp[1][0] = d(0,1); ответ min_j (dp[n−1][j] + d(j, n−1))
* **Почему корректно:** точка i присоединяется к одному из двух путей: либо продолжает путь, оканчивающийся в i−1 (единственный кандидат при j < i−1), либо «переключает» — второй путь из k продолжается в i (при j = i−1); перебор полон
* **Пример:** {(0,0), (1,0), (2,0), (3,0)}: ответ 6 (два пути: 0→1→2→3 и 0→3); {(0,0), (1,1), (2,0)}: 2 + 2√2 ≈ 4.8284
* **Сложность:** O(n²) времени, O(n²) памяти
* **Обобщение (поглощение констант):** расстояние — параметр-функция d(i, j) (евклидово — частный случай); сортировка по x — обязательное предварительное условие
* **Реализация:** `bitonic_tsp(points)`
* **Связь:** TSP — E.5 (экспоненциальный общий случай, полиномиальный битонный)

## **E.9. Assignment Problem**
* **Постановка:** n рабочих, n работ; cost[i][j] — стоимость назначения рабочего i на работу j; каждому рабочему — ровно одна работа, каждой работе — ровно один рабочий; минимальная суммарная стоимость
* **Рекуррентность:** dp[mask] = min_{i ∈ mask} (dp[mask \ {i}] + cost[popcount(mask) − 1][i]) — рабочие добавляются по одному: popcount(mask) рабочих уже назначены, последний (рабочий popcount(mask) − 1) берёт работу i
* **Почему корректно:** любое назначение первых r рабочих использует ровно r работ — множество mask; последний назначенный рабочий фиксируется (номер r−1), перебор его работы i полон (a.md A.1)
* **Пример:** cost = {{3,2,7},{5,1,3},{2,3,1}}: минимум 5 (рабочий 0 → работа 0, рабочий 1 → работа 1, рабочий 2 → работа 2)
* **Сложность:** O(2ⁿ·n) времени, O(2ⁿ) памяти
* **Обобщение:** квадратичные матрицы большего размера — венгерский алгоритм O(n³) (альтернатива); минимум/максимум — зеркальные версии
* **Реализация:** `assignment_min(cost)`
* **Связь:** структура «dp[mask] = min по элементам mask» — та же, что E.12 (покрытие)

## **E.10. Hamiltonian Path/Cycle**
* **Постановка:** путь/цикл, посещающий все вершины графа ровно по разу: существование и число путей/циклов
* **Рекуррентность:** dp[mask][v] = Σ_{u ∈ mask \ {v}, edge u→v} dp[mask \ {v}][u]; база dp[{v}][v] = 1; путь: ответ Σ_v dp[full][v]; цикл: фиксируем старт 0, ответ Σ_v dp[full][v] по рёбрам v→0
* **Почему корректно:** последняя вершина v приходит по ребру из u; каждый путь учитывается ровно один раз (единственная последовательность вершин); счёт по правилу суммы
* **Пример:** полный ориентированный граф K4: путей 4! = 24, циклов (n−1)! = 6; цепочка 0→1→2→3: путь 1, цикл 0
* **Сложность:** O(2ⁿ·n²) времени, O(2ⁿ·n) памяти
* **Обобщение:** существование = счёт > 0; неориентированные графы — те же переходы по обеим ориентациям
* **Реализация:** `hamiltonian_path_count`, `hamiltonian_cycle_count`
* **Связь:** TSP — E.5 (вес против существования); «подмножество + последний элемент» — каркас D.14 (LIS), но экспоненциальный

## **E.11. Maximum Clique / Independent Set**
* **Постановка:** максимальная клика (полный подграф) и максимальное независимое множество в графе малого размера
* **Рекуррентность (перебор):** для каждой маски проверяем, что она клика: для всех i ∈ mask: adj[i] ∩ mask = mask \ {i}; максимум popcount по кликам; независимое множество — клика в дополнении графа
* **Почему корректно:** перебор всех подмножеств полон; проверка клики — покомпонентная проверка всех рёбер (все соседи i внутри mask)
* **Пример:** цикл C4: max_clique = 2 (рёбра), max_independent_set = 2 ({0, 2}); полный K4: клика 4
* **Сложность:** O(2ⁿ·n) времени, O(2ⁿ) памяти
* **Обобщение:** дополнение графа для независимых множеств — поглощение констант (n зафиксировано)
* **Реализация:** `max_clique(n, adj)`, `max_independent_set(n, adj)`
* **Связь:** паросочетания — E.18 (парный аналог); большие графы — раздел G (жадные/ветвистые алгоритмы)

## **E.12. Set Cover / Partition**
* **Постановка:** семейство множеств (масок); минимальное число множеств, объединение которых покрывает всё; счёт способов покрытия (неупорядоченных)
* **Рекуррентность (минимум):** dp[mask | s] = min(dp[mask | s], dp[mask] + 1) — добавляем множество s к уже покрытому mask; база dp[0] = 0
* **Рекуррентность (счёт):** 0-1 по множествам: dp[mask | s] += dp[mask] (каждое множество используется не более раза, порядок не важен)
* **Почему корректно:** любой порядок добавления множеств эквивалентен последовательности «добавить s к mask»; минимум не зависит от порядка — проход по mask полон; счёт — каждый набор множеств считается при первом «включении» последнего
* **Пример:** n = 3, множества {3, 6, 7} (= {0,1}, {1,2}, {0,1,2}): минимум 1 ({7}), способов покрыть: 5 ({7}, {3,6}, {3,7}, {6,7}, {3,6,7})
* **Сложность:** O(2ⁿ·|sets|) времени, O(2ⁿ) памяти
* **Обобщение:** разбиение (каждый элемент ровно в одном множестве) — счёт с ограничением дизъюнктности
* **Реализация:** `min_set_cover(n, sets)`, `count_set_covers(n, sets)`
* **Связь:** неупорядоченный счёт — «0-1 по частям» (обратная сторона E.4); минимум — каркас E.9

## **E.13. Перестановки с запрещёнными позициями (ладьи)**
* **Постановка:** число перестановок π из n, для которых π(i) ∉ Sᵢ (запрещённые позиции); классическая задача о ладьях: R_r — число способов расставить r не бьющих ладей на запрещённых клетках
* **Рекуррентность (R_r):** dp[mask] по строкам: для строки i либо пропуск, либо ладья в запрещённой клетке c (c ∈ Sᵢ, c ∉ mask); R_r = Σ_{popcount(mask) = r} dp[mask] после всех строк — O(n·2ⁿ)
* **Рекуррентность (ответ):** включения-исключения: Σ_{r=0}^{n} (−1)^r · R_r · (n−r)! — r перестановок, нарушающих свои запреты, выбираются по R_r, остальные n−r позиций свободны
* **Почему корректно:** не бьющие ладьи = биекция строк на столбцы; каждая перестановка с множеством нарушений T ⊆ {1..n} учитывается в члене r = |T|; включения-исключения дают ровно перестановки без нарушений
* **Пример:** n = 3, Sᵢ = {i} (главная диагональ): R = [1, 3, 3, 1]; ответ 6 − 6 + 3 − 1 = 2 = derangements(3) (B.13); n = 2, S₀ = {0}: ответ 2! − 1·1! = 1
* **Сложность:** O(n·2ⁿ) времени, O(2ⁿ) памяти
* **Обобщение:** ступенчатая доска Феррера — `ferrers_rook_dp` (c.md C.10); слоны и ладьи с запретами — `math/combinatorics` (a.md F.4); частный случай Sᵢ = {i} — беспорядки (b.md B.13)
* **Реализация:** `rook_placement_counts(n, forbidden)`, `permutations_avoiding(n, forbidden)`
* **Связь:** беспорядки — b.md B.13; доска Феррера — c.md C.10; включения-исключения — `math/combinatorics`

# **C. ОПТИМИЗАЦИИ**

## **E.14. Meet-in-the-middle**
* **Постановка:** подмножественные суммы при n ≈ 40: найти максимальную сумму ≤ T (или счёт сумм); полный перебор 2⁴⁰ невозможен
* **Идея:** разбить массив пополам; перечислить все 2^(n/2) сумм каждой половины; отсортировать одну, для каждой суммы второй половины — бинарный поиск дополнения до T
* **Почему корректно:** любое подмножество = левая часть + правая часть; сумма пары = x + y; максимум ≤ T — ровно upper_bound(T − x) в отсортированном списке правой половины
* **Пример:** {1,2,4,8,16,32}, T = 30: 16 + 8 + 4 + 2 = 30; {1,3,5}, T = 7: 6 ({1,5})
* **Сложность:** O(2^(n/2)) памяти и времени (2^(n/2)·log), n ≤ 40–44
* **Обобщение:** счёт пар (x + y ≤ T), «ровно S» (словарь сумм правой половины); сведение TSP-подобных задач к парам состояний
* **Реализация:** `max_subset_sum_mitm(a, T)`
* **Связь:** подмножественные суммы — c.md C.23 (полный перебор 2ⁿ для малых n); сверка в демо

## **E.15. SOS DP (Sum over Subsets)**
* **Постановка:** f[mask] = Σ_{sub ⊆ mask} a[sub] (варианты: сумма, максимум, счёт) за O(n·2ⁿ) вместо O(3ⁿ)
* **Рекуррентность:** по битам: для i = 0..n−1: f[mask] += f[mask ^ (1 << i)] для всех mask с установленным i — итеративно «добавляем» подмножества, различающиеся битом i
* **Почему корректно:** инвариант после обработки битов 0..i: f[mask] = Σ a[sub] по подмножествам, различающимся только битами 0..i (разбиение по старшим битам); индукция по i
* **Обратное (супермножества):** g[mask] = Σ_{sup ⊇ mask} a[sup]: для mask без бита i: g[mask] += g[mask | (1 << i)]
* **Пример:** a = {1..8} (a[mask] = mask + 1): f[7] = 36 (все), f[5] = 14 (подмаски 0,1,4,5); g[1] = 20 (супермножества 1,3,5,7)
* **Сложность:** O(n·2ⁿ) времени, O(2ⁿ) памяти
* **Обобщение:** максимум/минимум/счёт — те же переходы с другой операцией (поглощение констант); применение: подмножественные максимумы в задачах разделов G, H
* **Реализация:** `sos_sum(a)`, `sos_superset_sum(a)`
* **Связь:** перебор подмасок — E.2 (O(3ⁿ) против O(n·2ⁿ))

## **E.16. Number of Ways to Wear Different Hats**
* **Постановка:** n человек, каждый может надеть набор шляп; каждой шляпе — не более одного владельца; число способов раздать всем разные шляпы
* **Рекуррентность:** dp по шляпам h = 1..M: ndp[mask | (1 << i)] += dp[mask] для человека i, умеющего надеть h (маска — множество уже одетых людей); база dp[0] = 1
* **Почему корректно:** состояние — подмножество людей, получивших шляпы; шляпы обрабатываются по одной, каждый человек получает не более одной (бит маски) — полное разбиение по последней шляпе
* **Пример:** люди {1, 2} и {2, 3}: 3 способа ((1,2), (1,3), (2,3))
* **Сложность:** O(M·2ⁿ·n) времени, O(2ⁿ) памяти; оптимизация по меньшей стороне: если людей больше, чем шляп — dp по людям с масками шляп
* **Обобщение:** «ровно k» и варианты — параметрическая динамика (раздел I)
* **Реализация:** `count_hat_assignments(hats)`
* **Связь:** назначение — E.9 (люди ↔ работы с произвольными весами); счёт — E.10

## **E.17. Partition to K Equal Sum Subsets**
* **Постановка:** разбить массив на k подмножеств с равными суммами
* **Рекуррентность:** dp[mask] = сумма текущего (последнего) блока по модулю target (или −1, если маска недостижима); для i ∉ mask с dp[mask] + a[i] ≤ target: dp[mask | (1 << i)] = (dp[mask] + a[i]) % target
* **Почему корректно:** сумма элементов маски определяется однозначно — dp[mask] = Σ(mask) mod target; переход добавляет элемент в текущий блок (иначе начинается новый блок — автоматически при достижении target); ответ dp[full] = 0 — все блоки набраны
* **Пример:** {4,3,2,3,5,2,1}, k = 4 (target 5): да ({5}, {4,1}, {3,2}, {3,2}); {1,2,3,4}, k = 3: нет (сумма 10 не делится на 3)
* **Сложность:** O(2ⁿ·n) времени, O(2ⁿ) памяти; предварительное отсечение max(a) ≤ target
* **Обобщение:** жадная эвристика (сначала большие элементы) ускоряет поиск, но точный ответ — только ДП; рюкзачные варианты — c.md C.22, C.23
* **Реализация:** `can_partition_k_subsets(a, k)`
* **Связь:** равные суммы — c.md C.22 (min partition difference); подсчёт разбиений — раздел I

## **E.18. Matching: совершенное паросочетание**
* **Постановка:** число совершенных паросочетаний (n пар, n чётно) в графе n ≤ 20
* **Рекуррентность:** dp[mask] = Σ_j dp[mask \ {i, j}] по рёбрам (i, j) ⊆ mask, где i — младший бит маски (фиксация i исключает дубли: каждая пара считается один раз)
* **Почему корректно:** в совершенном паросочетании маски элемент i спарен с ровно одним j; фиксация i — канонический первый элемент (без перестановок пар); база dp[0] = 1
* **Пример:** граф с рёбрами (0,1), (1,2), (2,3), (0,3): 2 паросочетания ({0,1}+{2,3}, {0,3}+{1,2})
* **Сложность:** O(2ⁿ·n) времени, O(2ⁿ) памяти
* **Обобщение:** максимальное взвешенное паросочетание — максимум вместо счёта; «фиксация младшего бита» — приём против дублей (E.10, E.16)
* **Реализация:** `count_perfect_matchings(n, adj)`
* **Связь:** Hamiltonian-структуры — E.10 (счёт по маскам); клики — E.11

## **E.19. TSP с восстановлением и порядком состояний**
* **Постановка:** TSP (E.5) плюс восстановление маршрута; оптимизация: внешний цикл по popcount маски
* **Рекуррентность:** те же dp[mask][v]; prev[mask][v] = u — предшественник v в оптимальном пути; восстановление — обратный проход от argmin_v dp[full][v]
* **Почему корректно:** prev фиксирует последний шаг оптимального пути — цепочка по таблице решений (a.md B.4); порядок по popcount гарантирует: все зависимости dp[mask \ {v}] (меньший popcount) обработаны раньше
* **Пример:** w(4 города, классика): маршрут 0→1→3→2, стоимость 65
* **Сложность:** O(2ⁿ·n²) времени, O(2ⁿ·n) памяти
* **Обобщение:** порядок состояний по popcount применим ко всем «mask + последний элемент» задачам (E.10)
* **Реализация:** `tsp_path_with_path(w)`
* **Связь:** E.5 (та же таблица, восстановление), E.3 (порядок по размеру)
