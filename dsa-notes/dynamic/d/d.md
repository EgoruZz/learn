**D. ДИНАМИКА ПО ОТРЕЗКАМ И ПОДСТРОКАМ**

> **Архитектура:** `SegmentDP` (d.cpp) — класс ветки dynamic, наследует `MatrixDP` (c.cpp): двумерная динамика переиспользуется (1D-ядро «подотрезок с суммой ≤ K» — реализовано в C.6, здесь формализуется как D.19; рюкзачные каркасы — C.19–C.28). Раздел вводит динамику по отрезкам и подстрокам в двух семействах: интервальная ДП — оптимизация разбиений (перемножение матриц, разбиение на палиндромы, оптимальное бинарное дерево поиска, разрезание стержня, шары, скрембл-строка, разбиение массива, слияние камней, триангуляция многоугольника) и динамика на подстроках и подпоследовательностях (палиндромные подпоследовательности и подстроки, Manacher, вставки/удаления для палиндрома, LIS, максимальное произведение, повторяющиеся подпоследовательности, подсчёт палиндромных подстрок, различные подпоследовательности, подотрезок с суммой ≤ K, битонные подпоследовательности, подпоследовательности с суммой). Все D-алгоритмы — методы `SegmentDP`.
>
> **Связи:** состояния и функциональное уравнение — a.md (A.1–A.4); порядок табуляции — a.md (B.2); восстановление ответа — a.md (B.4); расширение состояния — a.md (A.3); Кадане — b.md (B.4), обобщение «сумма ≤ K» — c.md (C.6, ядро здесь D.19); Edit Distance с весами — c.md (C.11); LCS — c.md (C.12); неограниченный рюкзак — c.md (C.20) (связь с разрезанием стержня — D.5); Каталана — `math/combinatorics` (a/a.md, `C_iter`) (триангуляции — D.10); Manacher и суффиксные структуры — `string` (задел — D.12); хеширование подстрок для проверки палиндромности — `hashing` (сверка — D.12); Knuth-оптимизация (D.1, D.4), монотонная очередь (D.8, D.9) и Divide & Conquer — раздел J; LIS и его варианты — мост к D.20, D.21 и разделу D (пасьянс); 2D-подсчёт по позиции и сумме — обобщение на раздел I (параметрическая динамика).

### **Основные понятия и принципы**

* **Что это:** состояние — отрезок [l, r] последовательности (или подстрока); ответ для отрезка собирается из ответов его собственных подотрезков, таблица dp[l][r] размера n×n
* **Почему выделяется в отдельный класс:** «последнее действие» оптимального решения происходит ВНУТРИ отрезка и делит его на две независимые части (последнее умножение, последний разрез, последнее слияние, последний палиндромный кусок) — в отличие от префиксной ДП (разделы B, C), где решение приклеивается к концу последовательности
* **Ключевые принципы:** порядок вычисления — по длине отрезка (диагонали таблицы), а не по позиции: все отрезки меньшей длины обязаны быть посчитаны раньше; переход — перебор точки разбиения k ∈ [l, r); восстановление — таблица оптимальных точек разбиения (обратный проход)
* **Как распознать:** операции, склеивающие или разрезающие отрезки/подстроки: перемножение матриц, разбиение на палиндромы, слияние камней, оптимальное BST, триангуляция (Catalan-структуры); задачи на палиндромные подпоследовательности
* **Границы:** наивно O(n³) — при монотонности точки разбиения Knuth-оптимизация даёт O(n²) (раздел J); строковые подзадачи с суффиксными структурами — `string`; если «последний элемент» приклеивается к концу, а не делит отрезок — это префиксная ДП (B, C)

# **A. ОПТИМИЗАЦИЯ РАЗБИЕНИЙ (INTERVAL DP)**

## **D.1. Matrix Chain Multiplication**
* **Постановка:** n матриц A₁..Aₙ с размерами (p₀×p₁), (p₁×p₂), ..., (pₙ₋₁×pₙ); стоимость умножения двух матриц (a×b)·(b×c) = a·b·c; минимальная стоимость перемножения всего произведения (порядок расстановки скобок)
* **Рекуррентность:** dp[i][j] = minₖ (dp[i][k] + dp[k+1][j] + p[i]·p[k+1]·p[j+1]) — последнее умножение делит блок матриц i..j на левый (i..k) и правый (k+1..j); dp[i][i] = 0
* **Почему корректно:** последнее умножение любого оптимального порядка скобок выполняется между двумя соседними блоками; левый и правый блоки обязаны вычисляться оптимально (a.md A.1) — иначе замена улучшила бы всё произведение; перебор k полон
* **Пример:** p = {40, 20, 30, 10, 30} (4 матрицы): минимум 26000 ((A₁·(A₂·A₃))·A₄); p = {10, 20, 30, 40}: 18000 ((A₁·A₂)·A₃ против A₁·(A₂·A₃) = 32000)
* **Сложность:** O(n³) времени (n² состояний × n переходов), O(n²) памяти
* **Обобщение (поглощение констант):** стоимость последнего умножения — произведение размеров, в общем случае — произвольная функция слияния двух блоков (параметризуется в D.2); Knuth-оптимизация: при выполнении четырёхугольного неравенства точка разбиения монотонна opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j] — O(n²) (раздел J, J.6)
* **Реализация:** `matrix_chain_min`
* **Связь:** восстановление скобок — D.2; Knuth-оптимизация — J.6; бинарные деревья разбиений (обобщение Catalan-структур) — D.10, `math/combinatorics`

## **D.2. Matrix Chain Order: восстановление скобок**
* **Постановка:** то же перемножение, но нужно выдать порядок: таблица точек разбиения opt[i][j] (индекс k, дающий минимум) и расстановка скобок
* **Рекуррентность:** при пересчёте dp[i][j] запоминаем k₀ = argmin; восстановление — рекурсивный обход: блок i..j = «(блок i..k₀)(блок k₀+1..j)», одиночная матрица — «Aᵢ»
* **Почему корректно:** точка разбиения k₀ фиксирует последнее умножение оптимальной расстановки; подблоки восстанавливаются рекурсивно тем же способом (a.md B.4 — обратный проход по таблице решений)
* **Пример:** p = {40, 20, 30, 10, 30} → «((A₁(A₂A₃))A₄)», стоимость 26000
* **Сложность:** O(n³) времени (тот же пересчёт), O(n²) памяти; восстановление — O(n)
* **Обобщение:** вариант с разными ценами скобок — стоимость последнего умножения задаётся параметром-функцией merge(pᵢ, pₖ₊₁, pⱼ₊₁) вместо произведения (`matrix_chain_general`): поглощение констант — произведение это частный случай
* **Реализация:** `matrix_chain_order`, `matrix_chain_general`
* **Связь:** оптимальные деревья поиска — D.4 (та же схема minₖ с монотонной точкой); Knuth — J.6

## **D.3. Palindrome Partitioning**
* **Постановка:** строка s; разбить на минимальное число палиндромных частей (или выдать минимальное число разрезов = части − 1)
* **Рекуррентность:** dp[i] = 1 + min{dp[j] : s[j..i) — палиндром} — последняя часть s[j..i); dp[0] = 0; палиндромность предподсчитана: pal[i][j] = (s[i] = s[j]) ∧ pal[i+1][j−1]
* **Почему корректно:** любое разбиение префикса s[0..i) оканчивается палиндромной частью, начинающейся в некотором j; остаток s[0..j) разбит оптимально (a.md A.1); pal[i][j] — индукция по длине
* **Пример:** «aab» → 2 части («aa», «b»), 1 разрез; «abba» → 1 часть
* **Сложность:** O(n²) времени (предподсчёт pal + рюкзак по j), O(n²) памяти (pal); палиндромность по строкам — O(n) через Manacher (D.12)
* **Обобщение:** вариант «все разбиения» — перебор с мемоизацией списков (декартово произведение ответов подзадач); число разбиений — счёт по той же рекуррентности; палиндромность за O(1) — хеши (`hashing`)
* **Реализация:** `min_palindrome_partitions`
* **Связь:** интервальная структура pal — D.11, D.12; «1 + min по предыдущим» — каркас одномерной ДП b.md B.1/B.6

## **D.4. Optimal Binary Search Tree**
* **Постановка:** ключи k₁..kₙ с частотами поиска p₁..pₙ; построить бинарное дерево поиска с минимальной суммарной взвешенной глубиной Σ pᵢ·depth(kᵢ) (глубина корня — 1)
* **Рекуррентность:** dp[i][j] = minₖ (dp[i][k−1] + dp[k+1][j]) + Σ_{t=i..j} pₜ — корень k поднимает все ключи блока на уровень вниз: к стоимости поддеревьев добавляется сумма частот блока; префиксные суммы для Σ pₜ за O(1)
* **Почему корректно:** любой корень k разбивает блок на левое (i..k−1) и правое (k+1..j) поддеревья; поддеревья оптимальны (a.md A.1), добавка Σ pₜ не зависит от выбора k — выносится за min
* **Пример:** частоты {4, 2, 6, 3}: минимум 26 (корень — третий ключ, стоимость 4·2 + 2·3 + 6·1 + 3·2 = 26)
* **Сложность:** O(n³) времени, O(n²) памяти; Knuth-оптимизация (частоты — сумма монотонна, четырёхугольное неравенство выполнено): opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j] — O(n²) (J.6)
* **Обобщение:** произвольные веса ключей и «промахов» (фиктивные ключи между ключами) — добавка Σ(веса ключей + веса промахов) к блоку; общая схема minₖ с монотонной точкой — Knuth-класс (J.6)
* **Реализация:** `optimal_bst_cost`
* **Связь:** та же схема, что D.1 — последнее решение делит блок; префиксные суммы — `math/number-theory`

## **D.5. Rod Cutting**
* **Постановка:** стержень длины n; цена куска длины i — pᵢ; разрезать на куски так, чтобы суммарная цена была максимальной
* **Рекуррентность:** dp[len] = max_{i ≤ len} (dp[len − i] + pᵢ) — первый кусок длины i; dp[0] = 0
* **Почему корректно:** оптимальный набор кусков для длины len содержит первый кусок длины i; остаток длины len − i нарезан оптимально (a.md A.1)
* **Пример:** цены {1, 5, 8, 9, 10, 17, 17, 20}, n = 8: 22 (куски 2 + 6: 5 + 17)
* **Сложность:** O(n²) времени (n состояний × n переходов), O(n) памяти
* **Связь с неограниченным рюкзаком:** куски — «предметы» (длина = вес, цена = ценность), запас неограниченный, вместимость n — это C.20 с ценностью-функцией от длины; направление циклов — по длине снизу вверх
* **Обобщение:** цены не зависят от общей длины — параметр; восстановление набора кусков — обратный проход (a.md B.4)
* **Реализация:** `rod_cutting`
* **Связь:** C.20 (`knapsack_unbounded`); восстановление — a.md B.4

## **D.6. Burst Balloons**
* **Постановка:** ряд шаров со значениями a₁..aₙ; лопаем по одному; при лопании шара k получаем a[i−1]·a[k]·a[j+1], где i, j — ближайшие нелопнутые соседи; максимальная суммарная выручка
* **Рекуррентность (заполнение снаружи внутрь):** dp[i][j] = maxₖ (dp[i][k−1] + dp[k+1][j] + a[i−1]·a[k]·a[j+1]) — k — ПОСЛЕДНИЙ лопнувший шар отрезка (i, j): к моменту его лопания соседи — фиксированные i−1 и j+1, левый и правый отрезки уже опустошены
* **Почему корректно (убирание последнего):** выбор последнего шара фиксирует его соседей — они не зависят от порядка лопания внутри отрезков; подотрезки независимы и оптимальны (a.md A.1); «последний элемент» вместо «первого» — приём, снимающий зависимость от окружения
* **Пример:** {3, 1, 5, 8} → 167 (порядок: 1 → 3 → 5 → 8: 3·1·5 + 3·3·8 + 3·8·8 + 1·8·1...; итоговая сверка демо)
* **Сложность:** O(n³) времени, O(n²) памяти; переходы по длинам отрезка (a.md B.2 — длина внешний цикл)
* **Обобщение:** фиктивные единицы по краям — поглощение констант (a⁰ = aₙ₊₁ = 1); минимум вместо максимума — тот же код
* **Реализация:** `max_burst_balloons`
* **Связь:** канонический пример «интервальная ДП с убиранием последнего» — D.1, D.10 (та же структура minₖ/maxₖ по отрезку)

## **D.7. Scramble String**
* **Постановка:** строка «скремблируется»: делим на две части, рекурсивно скремблируем части, перестановка половинок возможна на любом уровне; можно ли получить b из a
* **Рекуррентность:** dp[i][j][len] = ⋁ₖ ( dp[i][j][k] ∧ dp[i+k][j+k][len−k] ) ∨ ( dp[i][j+len−k][k] ∧ dp[i+k][j][len−k] ) — без обмена: подстроки a[i..i+k) ↔ b[j..j+k) и остатки; с обменом: a[i..i+k) ↔ b[j+len−k..j+len) и наоборот; база dp[i][j][1] = (a[i] = b[j])
* **Почему корректно:** первый же разрез строки a делит её на части длин k и len−k; части b соответствующих длин сопоставляются либо в том же порядке, либо с обменом — два непересекающихся случая, перебор k полон
* **Пример:** «great» → «rgeat»: да (разрез g|reat, обмен: reat → r|eat ↔ ...); «abcde» → «caebd»: нет
* **Сложность:** O(n⁴) времени (n³ состояний × n переходов), O(n³) памяти; мемоизированный вариант с отсечением по мультимножеству символов
* **Обобщение:** алфавит произвольный; отсечение: разные мультимножества символов → false сразу
* **Реализация:** `is_scramble`
* **Связь:** состояние (позиция, позиция, длина) — расширение состояния a.md A.3; сравнение подстрок — C.12, C.13

## **D.8. Partition Array for Maximum Sum**
* **Постановка:** массив a; разбить на подряд идущие куски длины ≤ k; значение куска = длина × максимум куска; максимальная сумма значений
* **Рекуррентность:** dp[i] = max_{l=1..min(k, i)} (dp[i − l] + l·max(a[i−l..i))) — последний кусок длины l; максимум последних l элементов пересчитывается по l
* **Почему корректно:** последний кусок любого разбиения префикса s[0..i) имеет длину l ≤ k; его значение определяется максимумом куска, остаток оптимален (a.md A.1); перебор l полон
* **Пример:** {1, 15, 7, 9, 2, 5, 10}, k = 3: 84 ([15]|[15]|[7,9,2]|[5,10]: 15 + 15 + 27 + 20... сверка демо)
* **Сложность:** O(n·k) времени, O(n) памяти
* **Обобщение:** куски по стоимости = максимум в окне — монотонная очередь за O(n) (раздел J, J.12); значение куска произвольной функции от окна
* **Реализация:** `partition_array_max_sum`
* **Связь:** «1 + min/max по последнему куску» — каркас одномерной ДП; окна — b.md B.22

## **D.9. Minimum Cost to Merge Stones**
* **Постановка:** n кучек камней a₁..aₙ; за ход сливаем ровно K соседних кучек в одну с ценой, равной сумме их камней; минимальная суммарная цена сведения к одной кучке (или −1, если невозможно)
* **Рекуррентность:** dp[i][j] = minₖ (dp[i][k] + dp[k+1][j]) по k = i, i+K−1, i+2(K−1), ...; слагаемое Σ_{t=i..j} aₜ (префиксные суммы) добавляется, только если (j − i) кратно (K − 1) — тогда отрезок можно свести к одной кучке
* **Почему корректно:** сведение отрезка к одной кучке — последнее слияние K кучек, получаемых из K подотрезков; соседство подотрезков фиксирует точки разбиения; шаг k = K−1: только такие точки разбиения оставляют обе части сводимыми; добавка — сумма всего отрезка ровно за последний ход
* **Почему −1:** за каждый ход число кучек уменьшается на K − 1; из n кучек к одной можно свести только при (n − 1) % (K − 1) == 0
* **Пример:** {3, 2, 4, 1}, K = 2: 20 (сливаем попарно: 5, 5, затем 10: 5 + 5 + 10); тот же массив, K = 3: −1
* **Сложность:** O(n³/K) времени, O(n²) памяти
* **Обобщение:** произвольная цена слияния (сумма — частный случай); K = 2 — классические «камни в ряд» (слияние соседей); оптимизация по монотонности — раздел J (J.6, J.12)
* **Реализация:** `merge_stones_min_cost`
* **Связь:** структура отрезка — D.1, D.4; префиксные суммы — `math/number-theory`

## **D.10. Minimum Score Triangulation**
* **Постановка:** выпуклый многоугольник с весами вершин a₁..aₙ; триангуляция — разбиение диагоналями на треугольники; цена треугольника = произведение весов вершин; минимальная суммарная цена
* **Рекуррентность:** dp[i][j] = minₖ (dp[i][k] + dp[k][j] + a[i]·a[k]·a[j]) по i < k < j — треугольник (i, k, j) с фиксированными рёбрами (i, j) и (i, k), (k, j) делит многоугольник на два; dp[i][i+1] = 0 (вырожденный отрезок)
* **Почему корректно:** сторона (i, j) любого треугольника триангуляции с вершиной k; подмногоугольники i..k и k..j триангулированы оптимально (a.md A.1); перебор k полон — любая триангуляция единственна задаётся выбором треугольников по рёбрам
* **Пример:** {1, 2, 3} (треугольник): 6; {3, 7, 4, 5}: 144 (сверка демо)
* **Сложность:** O(n³) времени, O(n²) памяти
* **Обобщение (обобщение Catalan-структур):** число триангуляций n-угольника = Каталана Cₙ₋₂ (`C_iter` — `math/combinatorics`); цена — произвольная функция тройки вершин; мин-версия — зеркальный максимум
* **Реализация:** `min_score_triangulation`
* **Связь:** числа Каталана — `math/combinatorics` (a/a.md), b.md B.12; схема dp[i][k] + dp[k][j] — вариант D.1 без «внешних» размеров

# **B. ДИНАМИКА НА ПОДСТРОКАХ**

## **D.11. Longest Palindromic Subsequence (LPS)**
* **Постановка:** длина наибольшей палиндромной ПОДПОСЛЕДОВАТЕЛЬНОСТИ строки s (не обязательно подряд)
* **Рекуррентность:** при s[i] = s[j]: dp[i][j] = dp[i+1][j−1] + 2 (крайние символы входят в палиндром), иначе dp[i][j] = max(dp[i+1][j], dp[i][j−1]) — один из крайних символов не используется
* **Почему корректно:** любой палиндром подстроки s[i..j] либо использует оба крайних символа (тогда внутренность — палиндром s[i+1..j−1]), либо не использует хотя бы один из них — полное разбиение случая
* **Пример:** «bbbab» → 4 («bbbb»); «cbbd» → 2 («bb»)
* **Сложность:** O(n²) времени (интервальный порядок — длина внешний цикл, a.md B.2), O(n²) памяти (два слоя — O(n))
* **Счёт палиндромных подпоследовательностей (по позициям):** при s[i] ≠ s[j]: dp[i][j] = dp[i+1][j] + dp[i][j−1] − dp[i+1][j−1] (пересечение вычитается); при s[i] = s[j]: dp[i][j] = dp[i+1][j] + dp[i][j−1] + 1 (новая пара s[i], s[j] вокруг каждой внутренней подпоследовательности даёт одну новую — плюс сама пара); база dp[i][i] = 1
* **Реализация:** `lps`, `count_palindromic_subsequences`
* **Связь:** вставки для палиндрома — D.13; LPS-сведение через LCS(s, reverse(s)) — та же длина (C.12)

## **D.12. Longest Palindromic Substring**
* **Постановка:** наибольшая палиндромная ПОДСТРОКА (непрерывная)
* **Идея (расширение от центров):** у каждой подстроки есть центр — символ (нечётные) или промежуток (чётные); расширяем от центра, пока символы равны; O(n²) центров × O(n) расширение
* **Почему корректно:** любой палиндром однозначно задан центром и радиусом; для каждого центра максимальный радиус найден исчерпывающим расширением
* **Пример:** «babad» → «bab» (или «aba», длина 3); «cbbd» → «bb»
* **Сложность:** O(n²) времени, O(1) памяти (без учёта ответа)
* **Manacher O(n):** d1[i] — радиус нечётных палиндромов с центром i, d2[i] — чётных; зеркальный радиус по палиндрому (l, r) ускоряет инициализацию: k = min(d1[l + r − i], r − i + 1); границы (l, r) — правейший найденный палиндром; суммарное расширение O(n), т.к. r только растёт
* **Подсчёт палиндромных подстрок:** сумма радиусов d1[i] + d2[i] — каждый радиус = число палиндромов с данным центром; то же через расширение от центров (D.17)
* **Реализация:** `longest_palindromic_substring` (от центров), `manacher` (d1, d2), `longest_palindromic_substring_manacher` (O(n))
* **Связь:** проверка палиндромности за O(1) хешами — `hashing` (сверка с Manacher); суффиксные структуры — `string` (задел)

## **D.13. Minimum Insertions to Make Palindrome**
* **Постановка:** минимальное число вставок символов, превращающих s в палиндром
* **Рекуррентность (сведение к LPS):** ответ = n − LPS(s) — уже палиндромные символы образуют LPS, остальные дублируются вставкой
* **Почему корректно:** любой способ превратить s в палиндром p вставками даёт в s подпоследовательность p (символы палиндрома слева и справа от вставленных); максимальная такая подпоследовательность — LPS, вставок ровно n − |LPS|
* **Пример:** «mbadm» → 2 («mb adb m»... вставки b и d: «mbdadbm»); n = 5, LPS = 3 → 2
* **Обобщение (путь между строками):** удаления (цена del) и замены (цена rep) с весами: dp[i][j] = min( dp[i+1][j] + del, dp[i][j−1] + del, dp[i+1][j−1] + (s[i] = s[j] ? 0 : rep) ) — обобщение Edit Distance (C.11) на цель-палиндром: вместо правой строки — реверс левой с запретом вставок
* **Реализация:** `min_insertions_palindrome`, `min_palindrome_edit`
* **Связь:** Edit Distance — c.md C.11; LPS — D.11

## **D.14. Longest Increasing Subsequence (LIS)**
* **Постановка:** длина наибольшей строго/нестрого возрастающей подпоследовательности
* **Рекуррентность (O(n²)):** dp[i] = 1 + max{dp[j] : j < i, a[j] < a[i]} — последний элемент подпоследовательности a[i]
* **Почему корректно:** любая возрастающая подпоследовательность, оканчивающаяся a[i], получается добавлением a[i] к возрастающей подпоследовательности, оканчивающейся меньшим a[j] (a.md A.1)
* **Пасьянс O(n log n):** d[l] — минимальный хвост возрастающей подпоследовательности длины l+1 (d монотонно возрастает); для a[i]: lower_bound(d, a[i]) — первое место, куда a[i] улучшает хвост (строгий вариант), upper_bound — нестрогий; длина = |d|
* **Почему пасьянс корректен:** минимальные хвосты монотонны; замена хвоста на меньший не уменьшает достижимых длин — инвариант «минимальный возможный хвост каждой длины»
* **Восстановление:** prev[i] — предшественник в LIS, оканчивающейся a[i] (индекс tails[pos−1] в момент вставки); цепочка от tails.back() по prev (cp-алгоритм)
* **Счёт числа LIS:** O(n²) с cnt: cnt[i] = Σ cnt[j] для j с dp[j] = dp[i] − 1; ответ — Σ cnt[i] для максимального dp
* **Пример:** {10, 9, 2, 5, 3, 7, 101, 18} → 4; {1, 3, 5, 4, 7} → 4, число LIS = 2; {2, 2, 2, 2}: строго 1, нестрого 4
* **Сложность:** O(n log n) (пасьянс), O(n²) (наивная и счёт); память O(n)
* **Реализация:** `lis_naive`, `lis_length` (параметр strict), `lis_with_path` (strict), `lis_count`
* **Связь:** LCS перестановок — c.md C.12 (`lcs_perm` — пасьянс по pos); битонные и суммы — D.20, D.21; «хвостовая» ДП — каркас C.25 (делимое подмножество)

## **D.15. Max Product Subarray**
* **Постановка:** подотрезок с максимальным произведением (значения произвольных знаков)
* **Рекуррентность (пара минимум/максимум):** mx = max(a, mx·a, mn·a), mn = min(a, mx_old·a, mn_old·a) — отрицательные a меняют местами роль минимума и максимума; ответ — максимум mx
* **Почему корректно:** знак произведения определяется числом отрицательных множителей; лучший подотрезок, оканчивающийся в i, либо начинается в i (aᵢ), либо продолжает лучший максимум или лучший минимум предыдущего (перемножение на aᵢ сохраняет экстремум при фиксированном знаке aᵢ)
* **Пример:** {2, 3, −2, 4} → 6 (2·3); {−2, 0, −1} → 0
* **Сложность:** O(n) времени, O(1) памяти
* **Обобщение:** нули естественно обнуляют подотрезки; поглощение констант — старт mx = mn = 1 с обработкой a как элемента
* **Реализация:** `max_product_subarray`
* **Связь:** Кадане — b.md B.4 (мин-макс пара — расширение состояния a.md A.3)

## **D.16. Longest Repeating Subsequence**
* **Постановка:** наибольшая подпоследовательность, встречающаяся в s дважды на непересекающихся позициях (одна и та же позиция не может входить в оба вхождения)
* **Рекуррентность:** LCS(s, s) с запретом совпадения по той же позиции: при s[i−1] = s[j−1] и i ≠ j: dp[i][j] = dp[i−1][j−1] + 1, иначе dp[i][j] = max(dp[i−1][j], dp[i][j−1])
* **Почему корректно:** два вхождения — две подпоследовательности на непересекающихся позициях; сравнение строки с собой (C.12) с индикатором i ≠ j запрещает использование позиции дважды
* **Пример:** «aabebcdd» → 3 («abd»: a@0/a@1, b@2/b@4, d@6/d@7)
* **Сложность:** O(n²) времени, O(n²) памяти (два слоя — O(n))
* **Обобщение:** кратность ≥ 2 — k параллельных копий с попарным запретом позиций (расширение состояния a.md A.3)
* **Реализация:** `longest_repeating_subsequence`
* **Связь:** LCS — c.md C.12; запрет позиции — индикатор-техника C.2

## **D.17. Count Palindromic Substrings**
* **Постановка:** число палиндромных подстрок (по позициям, все длины)
* **Рекуррентность (расширение от центров с подсчётом):** для каждого центра (n нечётных + n−1 чётных) расширяем, пока символы равны; каждый шаг расширения — новая палиндромная подстрока; всего Σ (d1[i] + d2[i])
* **Почему корректно:** каждая палиндромная подстрока имеет единственный центр и учитывается ровно при расширении своего центра; длина расширения — число палиндромов с данным центром
* **Пример:** «aaa» → 6 («a»×3, «aa»×2, «aaa»); «abc» → 3
* **Сложность:** O(n²) времени (худший случай — все символы равны), O(1) памяти; Manacher (D.12) даёт O(n)
* **Обобщение:** подстроки с ограничениями по длине — обрезка расширения; счёт по модулю — большой ответ
* **Реализация:** `count_palindromic_substrings`
* **Связь:** Manacher — D.12 (те же радиусы, O(n) счёт); палиндромность — D.11 (подпоследовательности против подстрок)

## **D.18. Count Distinct Subsequences**
* **Постановка:** число РАЗЛИЧНЫХ подпоследовательностей строки s (включая пустую), различающихся по значению
* **Рекуррентность:** dp[i] = 2·dp[i−1] − dp[last[s[i−1]] − 1] — все подпоследовательности префикса s[0..i) = (все от s[0..i−1)) + (те же с добавленным s[i−1] в конец); дубли — ровно те, что уже заканчивались s[i−1]: их число — подпоследовательности префикса s[0..last−1)
* **Почему корректно:** добавление символа c удваивает число подпоследовательностей (взять/не взять c); подпоследовательность, оканчивающаяся c, встречается в двух экземплярах, если c уже встречался — вычитаем количество «хвостов» от последнего вхождения (единственная точка дублирования по построению «не взяли последний c, взяли предыдущий»)
* **Пример:** «abc» → 8 (2³); «aaa» → 4 (ε, a, aa, aaa); «aba» → 7
* **Сложность:** O(n) времени, O(n) памяти (dp + last); по модулю M — олимпиадный стандарт
* **Обобщение (алфавит произвольного размера):** last — массив размера алфавита или map (в коде — unordered_map); счёт «без пустой» — минус 1
* **Реализация:** `count_distinct_subsequences`
* **Связь:** «вычитание дублей по последнему вхождению» — приём, обобщаемый на счёт подстрок (суффиксные структуры — `string`)

## **D.19. Подотрезок с суммой ≤ K (1D-ядро C.6)**
* **Постановка:** подотрезок с максимальной суммой, не превосходящей K
* **Идея (префиксные суммы + множество):** подотрезок (l, r] имеет сумму pref[r] − pref[l]; для каждого pref[r] нужен наибольший pref[l] ≥ pref[r] − K — lower_bound(pref[r] − K) во множестве уже встреченных префиксов
* **Почему корректно:** любая пара (l, r) задаёт подотрезок и наоборот; условие суммы ≤ K эквивалентно pref[l] ≥ pref[r] − K; максимум суммы = минимум pref[l] при условии — упорядоченное множество даёт его за O(log n)
* **Пример:** {1, 2, 3, −4, 5}, K = 5: 5 ([2, 3]); {1, 0, 1}, K = 2: 2 ([1, 0, 1])
* **Сложность:** O(n·log n) времени, O(n) памяти
* **Связь с C.6:** это ядро техники «максимальная подматрица с суммой ≤ K» — реализовано в c.cpp как `max_subarray_sum_no_more_than_k` (ядро C.6) и переиспользуется здесь (правило «переиспользовать, не переписывать»)
* **Реализация:** переиспользуем `max_subarray_sum_no_more_than_k` (c.cpp, C.6)
* **Связь:** Кадане — b.md B.4 (без ограничения); C.6 — применение в 2D; ordered set — `struct`

## **D.20. Longest Bitonic Subsequence**
* **Постановка:** наибольшая подпоследовательность, сначала строго возрастающая, затем строго убывающая (битонная; допустим монотонный вариант без одной фазы)
* **Рекуррентность:** d1[i] — LIS, оканчивающийся в i; d2[i] — LDS, начинающийся в i (LIS по реверсу); ответ = maxᵢ (d1[i] + d2[i] − 1)
* **Почему корректно:** вершина битонной подпоследовательности — максимум; слева от неё — возрастающая подпоследовательность, справа — убывающая; объединение с общей вершиной даёт битонную (a.md A.1); перебор вершины полон
* **Пример:** {1, 11, 2, 10, 4, 5, 2, 1} → 6 ({1, 2, 10, 4, 2, 1})
* **Сложность:** O(n²) времени (два LIS-прохода), O(n) памяти; O(n log n) — пасьянс (D.14)
* **Обобщение:** число «горных» максимумов — счёт по той же схеме; нестрогие фазы — параметр строгости (D.14)
* **Реализация:** `longest_bitonic_subsequence`
* **Связь:** LIS — D.14; «слева + справа» — приём двух проходов (D.21, C.10 — два массива длин)

## **D.21. Maximum Sum Increasing Subsequence**
* **Постановка:** возрастающая подпоследовательность с максимальной суммой элементов
* **Рекуррентность:** dp[i] = a[i] + max{dp[j] : j < i, a[j] < a[i]} — сумма вместо длины в LIS; dp[i] инициализируется a[i]
* **Почему корректно:** та же аргументация, что в D.14, с заменой «+1» на «+a[i]» (a.md A.1 — оптимальность хвоста по сумме)
* **Пример:** {1, 101, 2, 3, 100, 4, 5} → 106 (1 + 2 + 3 + 100)
* **Сложность:** O(n²) времени, O(n) памяти; дерево отрезков по значениям — O(n log n) (раздел J, `struct`)
* **Обобщение:** веса элементов произвольные (сумма — частный случай); восстановление — prev (a.md B.4)
* **Реализация:** `max_sum_increasing_subsequence`
* **Связь:** LIS — D.14 (длина против суммы); C.25 (делимое подмножество — тот же каркас с условием делимости)

## **D.22. Count Subsequences with Sum S**
* **Постановка:** число ПОДПОСЛЕДОВАТЕЛЬНОСТЕЙ последовательности a₁..aₙ (по позициям) с суммой ровно S
* **Рекуррентность (двумерный вариант по позиции и сумме):** f[i][s] = f[i−1][s] + f[i−1][s − aᵢ] (не брать / взять элемент i); f[0][0] = 1
* **Почему корректно:** последний элемент i либо не входит (все подпоследовательности первых i−1), либо входит — остаток выбирается из первых i−1 с суммой s − aᵢ (правило суммы); позиция в состоянии исключает перестановки и дубли
* **Пример:** {1, 2, 3, 4}, S = 5 → 2 ({1, 4}, {2, 3}) — сверка с `subset_sum_count` (C.23)
* **Сложность:** O(n·S) времени, O(n·S) памяти (два слоя — O(S))
* **Обобщение:** «ровно k элементов» — второе измерение f[i][s][k] (раздел I, I.26); счёт по модулю — редукция; без модуля — быстрый рост ответа
* **Реализация:** `count_subsequences_sum`
* **Связь:** C.23 (`subset_sum_count` — одномерная 0-1-версия той же рекуррентности); параметрическая динамика — раздел I (I.26)
