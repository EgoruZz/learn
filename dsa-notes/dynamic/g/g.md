**G. ДИНАМИКА НА ДЕРЕВЬЯХ**

> **Архитектура:** `TreeDP` (g.cpp) — класс ветки dynamic, наследует `ProfileDP` (f.cpp), а через него `SubsetDP`, `SegmentDP`, `MatrixDP`, `LinearDP`, `DPBasics`. Раздел вводит динамику на деревьях: состояние — вершина v и её поддерево, значение считается от листьев к корню (post-order, G.1); переподвешивание (rerooting) — ответ для каждого корня за O(n) суммарно (G.2, G.15, G.18); типовые состояния «включена/не включена» (G.3–G.7); рюкзак на дереве — слияние детей за O(n²) суммарно (G.17, G.14, G.20); центроидное разложение — «все пути через центроид» (G.19). Переиспользуются, а не дублируются: независимое множество по маскам (e.md E.11 — G.4: на дереве полиномиально), 0/1-рюкзак (c.md C.20 — G.17 слияние поддеревьев), рекурсия «разделяй и властвуй» (F.7 «игра с дыркой» — G.19), битовые операции (e.md E.1 — G.16).
>
> **Связи:** независимое множество/клика — e.md (E.11); рюкзак и подмножественные суммы — c.md (C.20, C.23); числа Фибоначчи как каркас линейных рекуррент — b.md (B.9); «последний элемент» и расширение состояния — a.md (A.1, A.3); профиль как граница обработанного — f.md (F.1).

### **Основные понятия и принципы**

* **Что это:** состояние — вершина v (и её поддерево); значение dp[v] вычисляется от листьев к корню (post-order), ответ — dp[корень]; порядок вычисления задаёт обход DFS, а не таблица
* **Почему выделяется в отдельный класс:** дерево ациклично и имеет единственную естественную декомпозицию на непересекающиеся поддеревья — дети независимы после фиксации решения в вершине; благодаря этому многие NP-трудные на общих графах задачи (MIS, MVC, паросочетание) на дереве решаются полиномиально
* **Ключевые принципы:** бинарные флаги состояния («вершина взята/не взята», три состояния доминирования — G.6); слияние детей рюкзаком — суммарно O(n²) по всем вершинам; переподвешивание (два прохода down/up) — ответ для всех корней за O(n); центроидное разложение — агрегаты по всем путям за O(n·log n); «последний элемент» — «верхняя вершина» пути (G.8, G.13)
* **Как распознать:** задача на дереве с выбором на вершинах/рёбрах и условиями на соседство; «ответ для каждого корня», «все пути», «поддеревья размера k», «предки и LCA»
* **Границы:** циклы — раздел H (графы) или маски (E); большой рюкзак на дереве — O(n·cap); слияние детей без ограничений на размер — комбинаторный взрыв; общие графы — NP-трудные аналоги

# **A. КЛАССИФИКАЦИЯ ЗАДАЧ**

## **G.1. Динамика на корневом дереве**
* **Постановка:** дерево с фиксированным корнем; состояние — вершина v, подзадача — её поддерево; `dp[v]` вычисляется от листьев к корню (post-order), ответ — `dp[root]`
* **Идея:** обход DFS: сначала рекурсивно обрабатываются дети, затем вершина объединяет результаты детей (рюкзак, max/min, сумма)
* **Почему корректно:** поддеревья детей не пересекаются и независимы после фиксации решения в v — декомпозиция задачи по детям полна и непересекаема (a.md A.1)
* **Сложность:** O(n) (или O(n·K) при рюкзаке по размерам — G.14, G.17)
* **Обобщение:** выбор корня произволен (G.2); состояния с флагами (G.3–G.7)
* **Реализация:** post-order обход — каркас всех методов раздела; отдельного метода не требуется
* **Связь:** состояния — G.3; переподвешивание — G.2

## **G.2. Динамика на произвольном дереве (переподвешивание)**
* **Постановка:** ответ нужен для каждого возможного корня (каждая вершина как корень); наивно — G.1 для каждого корня, O(n²)
* **Идея:** rerooting: первый проход — значения в поддеревьях (`down`), второй проход сверху вниз — значения «вне поддерева» (`up`); перенос через ребро за O(1): `ans[to] = ans[v] + n − 2·sz[to]` (G.15)
* **Почему корректно:** для каждого ребра v—to множество вершин разбивается на поддерево to и остальное; обе части считаются независимо (первый и второй проходы покрывают оба разбиения)
* **Сложность:** O(n) суммарно (два прохода DFS)
* **Обобщение:** перенос любого функционала через ребро (G.15, G.18)
* **Реализация:** `sum_distances_all_vertices` (G.15) — образец переноса через ребро
* **Связь:** схема down/up — G.18

# **B. ТИПОВЫЕ СОСТОЯНИЯ**

## **G.3. dp[v][0/1] — вершина не включена/включена**
* **Постановка:** бинарный флаг состояния v: включена в структуру или нет; сумма/максимум по детям с независимыми вариантами
* **Идея:** dp[v][0] и dp[v][1] — значения для поддерева v при флаге; переходы — правила комбинирования с детьми (запрет/разрешение соседства)
* **Почему корректно:** флаг фиксирует решение в v, после чего дети решаются независимо (G.1)
* **Сложность:** O(n) на состояние
* **Обобщение:** три состояния (G.6); размеры компонент (G.14, G.20)
* **Реализация:** конкретные пары состояний — G.4, G.5, G.7
* **Связь:** максимум/счёт/восстановление — G.4

## **G.4. Максимум независимого множества (MIS)**
* **Постановка:** максимальное множество вершин без смежных пар; счёт числа способов; восстановление одного множества
* **Рекуррентность:** dp[v][1] = 1 + Σ dp[c][0] (v взята — дети запрещены); dp[v][0] = Σ max(dp[c][0], dp[c][1]) (v свободна — дети решаются независимо); ответ max(dp[root][0], dp[root][1])
* **Почему корректно:** если v в множестве — ни один ребёнок не может быть; если нет — каждый ребёнок решается оптимально (a.md A.1); перебор флагов детей полон
* **Пример:** цепочка 0–1–2–3: dp[0][1] = 2, dp[0][0] = 2 → размер 2, способы: {0,2}, {0,3}, {1,3} — 3 способа
* **Сложность:** O(n) времени и памяти
* **Обобщение:** счёт способов — перемножение по детям (равенство dp0 = dp1 даёт сумму); восстановление — жадный спуск по dp; на произвольном графе задача NP-трудна (e.md E.11 — маски 2ⁿ), на дереве — полином
* **Реализация:** `max_independent_set_tree(adj)` (размер, способы, одно множество)
* **Связь:** покрытие — G.5 (дополнение)

## **G.5. Минимальное вершинное покрытие (MVC)**
* **Постановка:** минимальное множество вершин, покрывающее все рёбра (в каждом ребре хотя бы один конец)
* **Рекуррентность:** dp[v][1] = 1 + Σ min(dp[c][0], dp[c][1]) (v взята — рёбра v—c покрыты); dp[v][0] = Σ dp[c][1] (v не взята — все дети обязаны); ответ min(dp[root][0], dp[root][1])
* **Почему корректно:** ребро v—c покрыто, только если взята v или c; флаг v фиксирует требования к детям (G.3)
* **Связь (теорема Кёнига для деревьев):** покрытие — дополнение независимого множества: |MVC| = n − |MIS| — вершина, не покрывающая никакое ребро, свободна в независимом множестве; биекция «взята ⇔ не взята» (G.4)
* **Пример:** дерево 6 вершин (0–1, 1–2, 1–3, 2–4, 2–5): MIS = 4 → MVC = 2 (вершины 1, 2)
* **Сложность:** O(n)
* **Обобщение:** взвешенное покрытие — min по флагам с весами; счёт способов — как в G.4
* **Реализация:** `min_vertex_cover_tree(adj)` (сверка: n − MIS)
* **Связь:** независимое множество — G.4

## **G.6. Минимальное доминирующее множество (DMS)**
* **Постановка:** минимальное множество вершин, при котором каждая вершина либо в множестве, либо смежна с вершиной из множества — три состояния
* **Рекуррентность:** dp[v][0] = 1 + Σ min(dp[c][0], dp[c][1], dp[c][2]) (v выбрана — дети в любом состоянии); dp[v][1] = Σ min(dp[c][0], dp[c][1]) + min_c (dp[c][0] − min(dp[c][0], dp[c][1])) (v не выбрана, но доминируется ребёнком — хотя бы один ребёнок выбран); dp[v][2] = Σ dp[c][1] (v не выбрана и ждёт доминирования от родителя — дети не выбраны); лист: dp = (1, ∞, 0); ответ min(dp[root][0], dp[root][1])
* **Почему корректно:** состояния 0/1/2 полно описывают отношения с родителем (выбрана / покрыта изнутри / ждёт родителя); поправка min_c гарантирует «хотя бы один выбранный ребёнок» (G.3); состояние 2 недопустимо для корня (родителя нет)
* **Пример:** путь из 4 вершин → 2 (например {1, 3}); дерево 6 вершин (0–1, 1–2, 1–3, 2–4, 2–5) → 2 (вершины 1, 2)
* **Сложность:** O(n)
* **Обобщение:** взвешенный вариант; доминирование по расстоянию > 1 — расширение состояний (a.md A.3)
* **Реализация:** `min_dominating_set_tree(adj)`
* **Связь:** покрытие рёбер — G.5; доминирование вершин — G.4 (соседство)

## **G.7. Максимальное паросочетание (Maximum Matching)**
* **Постановка:** максимальное множество рёбер без общих вершин
* **Рекуррентность:** dp[v][0] = Σ max(dp[c][0], dp[c][1]) + max(0, max_c (dp[c][1] + 1 − max(dp[c][0], dp[c][1]))) (ребро к родителю не использовано — v может соединиться с лучшим ребёнком); dp[v][1] = Σ max(dp[c][0], dp[c][1]) (ребро к родителю использовано — v занята); ответ dp[root][0]
* **Почему корректно:** флаг «ребро к родителю использовано» фиксирует занятость v; внутри поддерева дети независимы, выбор «соединить v с ребёнком» — максимум из поправок (G.3)
* **Пример:** дерево 6 вершин (0–1, 1–2, 1–3, 2–4, 2–5) → 2 (например {0–1, 2–4})
* **Сложность:** O(n)
* **Обобщение:** взвешенные рёбра — максимум поправок с весами; восстановление паросочетания — жадный спуск (как G.4)
* **Реализация:** `max_matching_tree(adj)`
* **Связь:** покрытие/независимое множество — G.4, G.5

## **G.8. Binary Tree Path Sum**
* **Постановка:** (а) сумма значений на всех путях от корня к листьям; (б) максимальная сумма значений на пути между любыми двумя вершинами (диаметр-обобщение: max(left) + max(right))
* **Рекуррентность (а):** dfs(v, cur): cur += val[v]; лист — total += cur; (б): down[v] = val[v] + max(0, down[лучший ребёнок]); ответ — max по v (val[v] + лучший + второй лучший down ребёнка)
* **Почему корректно:** путь между двумя вершинами имеет единственную «верхнюю» вершину v; его ветви вниз от v — два независимых нисходящих пути; перебор верхней вершины полон (G.1)
* **Пример:** дерево 6 (0–1, 1–2, 1–3, 2–4, 2–5) со значениями 1,2,3,4,5,6: суммы путей корень–лист: 1+2+3+5 = 11, 1+2+3+6 = 12, 1+2+4 = 7 → 30; максимальный путь: 5–2–1–3 = 15
* **Сложность:** O(n) времени, O(высота) памяти
* **Обобщение:** взвешенные рёбра — down с весами; диаметр — G.13 (сверка при единичных значениях: max_path_sum = диаметр + 1)
* **Реализация:** `sum_root_to_leaf_paths(values, children)`, `max_path_sum_any_two(values, children)`
* **Связь:** диаметр — G.13; максимальный подотрезок (каркас «лучший + второй лучший») — b.md (B.1)

## **G.9. Maximum Sum BST (наибольшее по сумме BST-поддерево)**
* **Постановка:** бинарное дерево (массивы left/right); найти поддерево, являющееся валидным BST, с максимальной суммой значений (пустое поддерево — сумма 0)
* **Рекуррентность:** снизу вверх для v: (min, max, sum, valid): если оба ребёнка валидны и val[v] > max(left) и val[v] < min(right): valid, sum = val[v] + sum(left) + sum(right), min/max склеиваются; иначе valid = false (сумма не учитывается — невалидный узел «ломает» все поддеревья выше)
* **Почему корректно:** валидность BST поддерева полностью описывается (min, max) его значений; узел невалиден ⇒ любое содержащее его поддерево невалидно (включение-исключение по структуре); индукция по высоте (a.md A.1)
* **Пример:** [10, 5, 15, 2, 8, 12, 20] (левые: 1,3,5; правые: 2,4,6) — всё дерево валидно: 72; если у 5 левый ребёнок 9 (9 > 5) — левое поддерево невалидно, ответ 47 (15 + 12 + 20)
* **Сложность:** O(n) времени и памяти
* **Обобщение:** наибольшее по числу вершин — счёт вершин вместо суммы; поиск по ключу (минимум/максимум) — структуры данных
* **Реализация:** `max_sum_bst_subtree(values, left, right)`
* **Связь:** снизу вверх по дереву — G.1; бинарный поиск — math

## **G.13. Tree Diameter**
* **Постановка:** максимальное расстояние между двумя вершинами (число рёбер); взвешенный вариант
* **Метод (а):** два прохода DFS/BFS от произвольной вершины: самая дальняя f, затем от f — самая дальняя g; расстояние (f, g) — диаметр
* **Метод (б, однопроходный):** корневое дерево: down[v] — глубина самой глубокой вершины в поддереве v; ответ — max по v (лучший + второй лучший down ребёнка)
* **Почему корректно (а):** для дерева самая дальняя от произвольной вершины x вершина — конец диаметра; (б): путь между двумя вершинами имеет верхнюю вершину v, где он склеивается из двух нисходящих ветвей (G.8)
* **Пример:** дерево 6 (0–1, 1–2, 1–3, 2–4, 2–5): диаметр 3 (4–2–1–3); сверка: max_path_sum с единичными значениями = 4 = диаметр + 1; взвешенный: цепочка 0–1–2–3 с весами 5, 7, 2 → 14
* **Сложность:** O(n)
* **Обобщение:** сверка двух методов; диаметр в метрике сумм — G.8
* **Реализация:** `tree_diameter(adj)`, `tree_diameter_weighted(adj)`
* **Связь:** максимальный путь — G.8; два прохода — G.2 (переподвешивание)

## **G.14. Подсчёт поддеревьев с заданным размером**
* **Постановка:** число связных подмножеств вершин (поддеревьев в широком смысле) размера ровно k
* **Рекуррентность:** dp[v][s] — связные подмножества размера s в поддереве v, содержащие v; база dp[v][1] = 1; слияние ребёнка c — рюкзак: new[s + t] += dp[v][s] · dp[c][t]; ответ: Σ_v dp[v][k] (каждое подмножество имеет единственную верхнюю вершину — ближайшую к корню)
* **Почему корректно:** выбор «взять/не взять» подмножество ребёнка c независим (связность сохраняется через v); верхняя вершина уникальна — деления на орбиты нет; слияние детей — 0/1-рюкзак (c.md C.20)
* **Пример:** цепочка из 4: размеры 1, 2, 3: ответы 4, 3, 2 (отрезки цепочки)
* **Сложность:** O(n²) суммарно (рюкзак по размерам поддеревьев: Σ_v Σ_c sz[v]·sz[c] = O(n²))
* **Обобщение:** другие свойства (диаметр ≤ k, число листьев) — расширение состояния кортежем (a.md A.3); разбиения на компоненты — G.20
* **Реализация:** `count_subtrees_of_size(adj, k)`
* **Связь:** рюкзак на дереве — G.17; слияние детей — G.1

## **G.15. Сумма расстояний до всех вершин**
* **Постановка:** для каждой вершины — сумма расстояний до всех остальных; наивно — BFS из каждой, O(n²)
* **Рекуррентность (rerooting):** первый проход: sz[v], sumDown[v] (сумма расстояний внутри поддерева); перенос через ребро v—to: ans[to] = ans[v] + n − 2·sz[to] (вершины поддерева to приближаются на 1, остальные отдаляются на 1)
* **Почему корректно:** пересечение ребра v—to меняет расстояние ровно на ±1 для каждой из двух частей (G.2); формула переноса пересчитывает все n расстояний за O(1)
* **Пример:** цепочка 0–1–2–3: ans = {6, 4, 4, 6}; дерево 6 (0–1, 1–2, 1–3, 2–4, 2–5): ans = {11, 7, 7, 11, 11, 11}; сверка: Σ ans = 2·Σ парных расстояний
* **Сложность:** O(n) времени и памяти
* **Обобщение:** взвешенные рёбра — перенос с весом ребра; «сумма расстояний в компоненте» — G.20
* **Реализация:** `sum_distances_all_vertices(adj)` (возвращает вектор ответов)
* **Связь:** общая схема down/up — G.18; перенос через ребро — G.2

## **G.16. Kth Ancestor / бинарный подъём**
* **Постановка:** k-й предок вершины v; наивно — подъём по одному, O(k); бинарный подъём — задел для ДП на деревьях (не ДП сам по себе)
* **Идея:** up[j][v] — 2^j-й предок; up[j][v] = up[j−1][up[j−1][v]]; запрос: биты k — прыжки по таблице
* **Почему корректно:** любой k раскладывается в сумму степеней двойки; композиция прыжков — ровно 2^j-й предок (индукция по j)
* **Пример:** цепочка 0–1–2–3–4: kth(4, 2) = 2; kth(4, 10) = −1 (за пределами корня)
* **Сложность:** предподсчёт O(n·log n), запрос O(log n)
* **Обобщение:** LCA через подъём (глубины + подъём); взвешенные пути — минимумы/суммы по прыжкам
* **Реализация:** `kth_ancestor(adj, v, k)`
* **Связь:** битовые операции — e.md (E.1); логарифмическая декомпозиция — G.19

## **G.17. Tree Knapsack (рюкзак на дереве)**
* **Постановка:** предметы на вершинах (вес w[v], ценность val[v]); чтобы взять предмет из поддерева ребёнка, нужно взять сам v (предпосылки); максимум ценности при суммарном весе ≤ cap
* **Рекуррентность:** dp[v][s] — максимальная ценность выборки веса s из поддерева v, содержащей v (s ≥ w[v]); база dp[v][0] = 0 (пустая), dp[v][w[v]] = val[v]; слияние ребёнка: new[s + t] = max(new[s + t], dp[v][s] + dp[c][t]) — 0/1-рюкзак (c.md C.20); ответ: max_s dp[root][s] по s ≤ cap
* **Почему корректно:** «взять/не взять поддерево ребёнка» — независимый выбор (0/1-рюкзак); требование v при выборе ребёнка — препосылки; слияние по одному ребёнку — стандартная дедупликация (каждое подмножество собрано единственным порядком)
* **Пример:** курсы: 0 → {1, 2}, 1 → {3}, 2 → {4}; веса 1, ценности {5, 4, 3, 2, 1}: cap 3 → 12 (0, 1, 2); cap 4 → 14; cap 5 → 15
* **Сложность:** O(n·cap) суммарно по дереву (рюкзак по размерам: Σ_v Σ_c sz[v]·sz[c] ≤ O(n²))
* **Обобщение:** ограничения на размер компонент — G.14, G.20; счёт способов — перемножение (как G.4)
* **Реализация:** `tree_knapsack(children, weights, values, cap)`
* **Связь:** 0/1-рюкзак — c.md (C.20); поддеревья по размерам — G.14

# **D. СПЕЦИАЛЬНЫЕ ТЕХНИКИ**

## **G.18. Rerooting DP (переподвешивание корня)**
* **Постановка:** общая схема G.2: down[v] — ответ в поддереве v, up[v] — ответ «вне поддерева» (для родителя); второй проход сверху вниз переносит up через ребро
* **Идея:** down считаются post-order (G.1); up[to] выражается через up[v] и down соседей v (кроме to); ответ для корня to — комбинация down[to] и up[to]
* **Почему корректно:** разбиение «поддерево to / остальное» покрывает все вершины; up[to] использует только значения, посчитанные до спуска (инвариант сверху вниз)
* **Сложность:** O(n) суммарно (перенос за O(deg) на вершину)
* **Обобщение:** перенос любых агрегатов (суммы G.15, размеры, эксцентриситеты)
* **Реализация:** образец — `sum_distances_all_vertices` (G.15)
* **Связь:** классификация — G.2; перенос через ребро — G.15

## **G.19. DP на центроидном разложении**
* **Постановка:** центроид компоненты — вершина, после удаления которой все компоненты ≤ n/2; рекурсивное разложение — центроидное дерево (высота O(log n)); применение: задачи «все пути через центроид»
* **Метод:** decompose(v): найти центроид c компоненты; посчитать ответы для путей, проходящих через c (расстояния до всех вершин компоненты: пары с dist(u) + dist(v) ≤ k); вычесть пары внутри одного подкомпонента (пересчёт с поправкой на ребро); удалить c, рекурсивно decompose для подкомпонент
* **Почему корректно:** любой путь имеет единственный первый центроид разложения, через который он проходит; пары в одном подкомпоненте посчитаны на этом уровне с завышенным расстоянием и вычитаются — учёт ровно один раз (включения-исключения по уровням)
* **Пример:** цепочка 0–1–2–3: число пар с расстоянием ≤ 1 → 3 (рёбра); ≤ 2 → 5; ≤ 3 → 6
* **Сложность:** O(n·log n) (каждая вершина участвует в O(log n) уровнях; подсчёт пар — сортировка + два указателя)
* **Обобщение:** «все пути через центроид» — любые агрегаты по путям (длины, суммы, деревья решений); высота разложения — логарифмический задел как бинарный подъём (G.16)
* **Реализация:** `count_paths_length_at_most(adj, k)`
* **Связь:** разделяй и властвуй — f.md (F.7 «игра с дыркой»); пары с суммой ≤ k — c.md (C.23, meet-in-the-middle e.md E.14)

## **G.20. Ограничения на размер компонент**
* **Постановка:** разрезания рёбер дерева: число способов получить компоненты размера ≤ k (все компоненты, включая корневую); обобщение — размеры кратны k
* **Рекуррентность:** dp[v][s] — число разрезаний поддерева v (компоненты ≤ k), где компонента v имеет размер s (s ≤ k); база dp[v][1] = 1; ребёнок c: либо ребро режется (множитель Σ_t dp[c][t]), либо нет (рюкзак: new[s + t] += dp[v][s] · dp[c][t]); ответ: Σ_s dp[root][s]
* **Почему корректно:** каждое разрезание — независимый выбор по рёбрам; компонента размера > k отбрасывается (состояния s ≤ k полны); корневая компонента ограничена в ответе (s ≤ k)
* **Пример:** цепочка из 3: k = 1 → 1 (все рёбра режутся), k = 2 → 3, k = 3 → 4 (2^(число рёбер) = 4)
* **Сложность:** O(n²) суммарно (рюкзак по размерам, G.17)
* **Обобщение:** «кратные k» — фильтр s % k == 0 в финале; суммы расстояний в компонентах — G.15
* **Реализация:** `count_partitions_max_size(adj, k)`
* **Связь:** рюкзак на дереве — G.17; поддеревья по размерам — G.14
