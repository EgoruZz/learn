**F. ДИНАМИКА ПО ПРОФИЛЮ**

> **Архитектура:** `ProfileDP` (f.cpp) — класс ветки dynamic, наследует `SubsetDP` (e.cpp), а через него `SegmentDP`, `MatrixDP`, `LinearDP`, `DPBasics`. Раздел вводит динамику по профилю: состояние — граница между обработанной и необработанной частями доски, кодируемая битовой маской длины m (число строк) или маской с метками компонент; переходы — перебор совместимых профилей или «клетка за клеткой» (Plug DP). Профильная динамика применяется к замощениям (домино, тримино, полимино, «мосты»-пары), к гамильтоновым циклам с компонентным профилем и к раскраскам. Переиспользуются, а не дублируются: битовые операции `popcount`, `test_bit` (e.md E.1), числа Фибоначчи как каркас замощений 2×N.
>
> **Связи:** маски и подмаски — e.md (E.1–E.3); перебор масок по размеру — e.md (E.3, E.19); гамильтоновы пути по маскам — e.md (E.10, «клетка за клеткой» — E.18); включения-исключения и доска Феррера — `math/combinatorics`, c.md (C.10); числа Фибоначчи — b.md (B.9); «замощение с запретами» обобщается на произвольные дырки (F.6); Burnside для классов эквивалентности — `math/combinatorics` (счёт орбит); монотонные пути и Каталана — b.md (B.12).

### **Основные понятия и принципы**

* **Что это:** состояние — граница между обработанной и необработанной частью двумерной доски: битовая маска длины m (занятость границы) либо маска с метками (номера компонент, цвета); таблица — слои строк (или клеток) с переходами между профилями
* **Почему выделяется в отдельный класс:** асимметрия сложности — экспонента только по ширине m, полином по длине n: доска обрабатывается строками, и будущее зависит от прошлого лишь через линию разлома — «локальность перехода»; это частный случай динамики по подмножествам, где структура доски урезает пространство состояний до 2ᵐ (а не 2^(n·m))
* **Ключевые принципы:** совместимость профилей соседних строк (переход — перебор совместимых пар); подход «клетка за клеткой» (Plug DP) с рёбрами линии разлома: вход сверху/слева, выход вниз/вправо; метки компонент для связности (гамильтоновы циклы) и для раскрасок
* **Как распознать:** замощения (домино, тримино, полимино), гамильтоновы циклы, раскраски с локальными запретами на досках с малой шириной m ≤ 20
* **Границы:** при больших обеих размерностях экспонента неустранима; связность требует меток — состояний больше, чем с битами; счёт классов с точностью до симметрий — группа преобразований (Burnside, `math/combinatorics`)

# **A. ОСНОВНЫЕ ПОНЯТИЯ**

## **F.1. Профиль: состояние границы**
* **Постановка:** обрабатываем доску строка за строкой; профиль — битовая маска длины m (m — число строк/столбцов границы): бит = «клетка границы занята» (например, вертикальным домино из предыдущей строки)
* **Идея:** состояние — (номер строки, маска): маска описывает, какие клетки текущей строки уже заняты; переходы — заполнение строки фигурами
* **Почему корректно:** клетки строки заполняются независимо от ранее обработанных строк, кроме занятости сверху — ровно она и кодируется маской (a.md A.3 — расширение состояния)
* **Сложность:** O(n·2ᵐ·|переходы|) — экспонента по ширине m, полином по длине n
* **Обобщение:** профиль с метками (номера компонент) — F.11, F.13; профиль с цветами — F.14
* **Реализация:** базовые битовые операции — E.1; отдельного метода не требуется
* **Связь:** маски — e.md E.1; совместимость профилей — F.2

## **F.2. Переходы между профилями**
* **Постановка:** совместимость профилей соседних строк: dp[row][mask] = Σ dp[row−1][prev] по совместимым prev
* **Рекуррентность (заполнение строки домино):** для prev-маски перечисляем все next: клетка c: если занята (бит prev) — пропуск; иначе горизонтальное домино (c, c+1) или вертикальное (бит c в next)
* **Почему корректно:** каждая строка заполняется слева направо; выбор фигуры в клетке c не зависит от будущего — полный перебор DFS; биекция «замощение доски» ↔ «последовательность совместимых профилей»
* **Пример:** m = 2: trans[0] = {0, 3} (обе горизонтальные или обе вертикальные), trans[1] = {2}, trans[2] = {1}, trans[3] = {0} — из prev с одной занятой клеткой единственная свободная закрывается вертикалью (бит next)
* **Сложность:** предподсчёт O(3ᵐ) (перебор по клеткам), ДП O(n·2ᵐ·|trans|)
* **Обобщение (поглощение констант):** другие фигуры — те же DFS с другими шаблонами (F.7, F.8); запреты — F.6
* **Реализация:** `row_transitions(m)`
* **Связь:** замощение домино — F.5; перебор подмасок — e.md E.2

## **F.3. Подход «клетка за клеткой» (Plug DP)**
* **Постановка:** вместо строк — проход по каждой клетке; профиль — состояние линии разлома (число рёбер между обработанной и необработанной частями)
* **Идея:** при обработке клетки (i, j) доступны два «входящих» ребра профиля (сверху и слева); клетка решает свою степень/метки, обновляя «исходящие» рёбра (вниз и вправо)
* **Почему корректно:** клетка взаимодействует только с двумя граничными ребрами — локальность перехода; полное покрытие доски — последовательность локальных решений
* **Сложность:** O(n·m·|состояния|) — |состояния| экспоненциально по ширине, но с метками компонент — полиномиально меньше, чем 2^(n·m)
* **Обобщение:** метки компонент (парность, связность) — F.11, F.13; гамильтоновы циклы — F.13
* **Реализация:** «клетка за клеткой» с метками — `count_hamiltonian_cycles` (F.13)
* **Связь:** паросочетания по маскам — e.md E.18; профиль строк — F.2

# **B. ЗАДАЧИ НА ЗАМОЩЕНИЕ**

## **F.4. Домино 2×N**
* **Постановка:** число замощений полосы 2×N домино
* **Рекуррентность:** F(n) = F(n−1) + F(n−2), F(0) = F(1) = 1 — последний столбец: вертикальное домино (остаток 2×(n−1)) или два горизонтальных (остаток 2×(n−2)) — числа Фибоначчи
* **Почему корректно:** разбиение по последнему столбцу полно и непересекаемо: вертикаль или пара горизонталей (a.md A.1)
* **Пример:** F(5) = 8; сверка: count_domino_tilings(2, 5) = 8
* **Сложность:** O(n) времени, O(1) памяти
* **Обобщение (поглощение констант):** разные наборы фигур (например, 1×2 и 2×1 и 2×2) — линейная рекуррентность с матричным переходом: вектор состояния × матрица переходов (F.4 — частный случай двух фигур)
* **Реализация:** `domino_tiling_2n(n)`
* **Связь:** Фибоначчи — b.md (B.9); сверка с профильной динамикой — F.5

## **F.5. Домино M×N**
* **Постановка:** число замощений доски m×n домино (профиль длины m)
* **Рекуррентность:** dp[row][mask] = Σ dp[row−1][prev] по совместимым prev (переходы — F.2); ответ dp после n строк при mask = 0 (ничего не выступает за доску)
* **Почему корректно:** последовательность профилей взаимно-однозначно задаёт замощение (F.2); финальная пустая маска — ровно замощения без «хвостов»
* **Пример:** 2×3 → 3, 4×4 → 36, 3×3 → 0 (нечётное число клеток)
* **Сложность:** O(n·2ᵐ·|trans|) времени, O(2ᵐ) памяти
* **Обобщение:** запреты — F.6; модуль — F.10; фигуры — F.7, F.8
* **Реализация:** `count_domino_tilings(m, n)`
* **Связь:** совместимость — F.2; 2×N — F.4

## **F.6. Замощение с дефектами (дырками)**
* **Постановка:** некоторые клетки запрещены (дырки); число замощений остального домино
* **Рекуррентность:** та же, но клетка-дырка считается занятой: вертикальное домино не может опереться на дырку (бит prev ∩ дырка → переход запрещён), горизонтальное не может покрыть дырку
* **Почему корректно:** дырки — фиксированная занятость строки; все остальные аргументы F.5 сохраняются
* **Пример:** 3×3 с центральной дыркой → 2; 2×2 с любой дыркой → 0 (3 клетки)
* **Сложность:** O(n·2ᵐ·|trans|) времени, O(2ᵐ) памяти
* **Обобщение:** произвольные фигуры с запретами — комбинация F.6 и F.8
* **Реализация:** `count_domino_tilings_blocked(m, n, blocked)`
* **Связь:** F.5 (частный случай без дырок); запрещённые позиции — e.md E.13

## **F.7. Тримино (L-образные)**
* **Постановка:** число замощений m×n L-тримино (3 клетки, уголком); замощение 2^k×2^k с одной дыркой (классическая «игра с дыркой»)
* **Рекуррентность (счёт):** 4 ориентации L в окне 2×2 (текущая + следующая строки): {c, c+1}×{next c}, {c, c+1}×{next c+1}, {c}×{next c, next c+1}, {c+1}×{next c, next c+1} — DFS по клеткам строки с маской следующей строки
* **Почему корректно:** каждая L-фигура задевает ровно одну клетку текущей строки и две клетки следующей (или наоборот) — при проходе строки фигура привязана к своей «верхней» клетке; перебор ориентаций полон
* **Пример:** 2×3 → 2 (две L-тройки), 4×4 → 0 (16 не делится на 3)
* **Рекурсия «игра с дыркой»:** доска 2^k×2^k с одной дыркой: делим на 4 квадранта; центральное тримино покрывает 3 центральные клетки, кроме квадранта с дыркой; каждый квадрант рекурсивно замощается со своей дыркой (центральная клетка соседнего квадранта становится дыркой) — база: доска 2×2 с дыркой покрывается одним тримино
* **Почему корректно (игра с дыркой):** индукция по k: в каждом квадранте ровно одна дырка после центрального хода — размеры 2^(k−1), индуктивное предположение применимо; число тримино = (2^(2k) − 1)/3
* **Сложность:** счёт O(n·2ᵐ·4); рекурсия O(4ᵏ) времени (по числу тримино)
* **Реализация:** `count_tromino_tilings(m, n)`, `tromino_covering(k, holeR, holeC)`
* **Связь:** фигуры как шаблоны переходов — F.8 (сверка симметрий)

## **F.8. Полимино (тетримино и др.)**
* **Постановка:** число замощений фиксированными фигурами — произвольными полимино, заданными наборами клеток (относительные смещения); перебор всех поворотов/отражений фигур
* **Рекуррентность:** фигура = список (dr, dc), dr ∈ {0, 1} (задевает текущую и следующую строки); при клетке c: проверить, что все клетки фигуры свободны (текущая строка — биты prev, следующая — биты next), и разместить; симметрии — 8 преобразований (dr, dc) → (±dr, ±dc) и перестановка осей с нормировкой
* **Почему корректно:** фигура привязана к своей клетке в текущей строке (каждая фигура задевает текущую строку); перебор всех размещений полон; нормировка и дедупликация симметрий исключают двойной счёт одной фигуры
* **Пример (сверки):** домино (2 фигуры) — то же число, что F.5: 2×3 → 3; L-тримино с симметриями — то же, что F.7: 2×3 → 2
* **Сложность:** O(n·2ᵐ·|фигуры|) времени, O(2ᵐ) памяти
* **Обобщение:** фигуры высотой > 2 строк — профиль из k строк (расширение состояния, F.13)
* **Реализация:** `count_shaped_tilings(m, n, shapes, useSymmetries)`
* **Связь:** тримино — F.7; домино — F.5

## **F.9. Обобщённое замощение: с учётом симметрий**
* **Постановка:** счёт классов эквивалентности замощений с точностью до поворотов/отражений (диагональная группа) — отождествляем замощения, переводящиеся друг в друга симметрией доски
* **Идея:** перечислить все замощения (малые доски), канонизировать каждое: минимальный (лексикографически) вид среди всех 8 (или меньшего набора для прямоугольных досок) преобразований; число классов = число канонических форм
* **Почему корректно:** каноническая форма — представитель орбиты; два замощения в одной орбите имеют одинаковый канонический вид и наоборот (минимум инвариантен относительно группы)
* **Пример:** 2×2 → 1 класс (вертикали и горизонтали — поворот); 2×3 → 2 класса; 2×4 → 4 класса
* **Сложность:** перебор замощений O(число замощений · (m·n)/2), канонизация O(8·(m·n)/2) на замощение
* **Обобщение:** формула Бёрнсайда — число орбит = (1/|G|)·Σ fix(g) — `math/combinatorics` (счёт орбит); перебор применим только к малым доскам
* **Реализация:** `count_domino_tiling_classes(m, n)`
* **Связь:** замощение — F.5; группы преобразований — `math/combinatorics`

## **F.10. Подсчёт числа способов покрытия в модуле**
* **Постановка:** число замощений по модулю M (олимпиадный стандарт — ответы растут экспоненциально)
* **Рекуррентность:** та же, что F.5, с редукцией по модулю при каждом сложении
* **Почему корректно:** модулярная арифметика коммутирует со сложением — рекуррентность сохраняется
* **Пример:** 4×4 mod (1e9+7) → 36; 2×10 → 89 = F(10)
* **Сложность:** O(n·2ᵐ·|trans|) времени, O(2ᵐ) памяти
* **Обобщение:** модуль параметром; запреты и фигуры — комбинируются с F.6, F.8
* **Реализация:** `count_domino_tilings_mod(m, n, mod)`
* **Связь:** модулярная арифметика — `math/number-theory`; подсчёты — c.md (C.28)

## **F.11. Задачи на мосты и соединения**
* **Постановка:** замощение «путями»/«мостами»: каждый ход связывает пару клеток; профиль хранит не только занятость, но и номера компонент (какие пары уже соединены)
* **Идея:** пары-мосты — это совершенное паросочетание соседних клеток (частный случай — домино, F.5); при более длинных путях профиль дополняется метками: открытые концы путей на границе помечаются номерами компонент; соединяя два конца — закрываем компоненту, разные метки — объединяем
* **Почему корректно:** состояние границы полно описывается множеством открытых концов и их взаимной связностью (метки); локальный переход клетки не зависит от внутренности обработанной части
* **Сложность:** O(n·m·|профили с метками|) — число меток ограничено числом открытых концов ≤ m+1
* **Обобщение:** парные метки (0/1 — чётность) — счёт паросочетаний; полные метки со связностью — F.13
* **Реализация:** пары без меток — F.5; метки компонент — `count_hamiltonian_cycles` (F.13)
* **Связь:** паросочетания — e.md (E.18); профиль с метками — F.13

# **C. ДРУГИЕ ЗАДАЧИ**

## **F.12. Minimum Squares To Represent A Number**
* **Постановка:** минимальное число квадратов (1², 2², ...), сумма которых равна n
* **Рекуррентность:** dp[i] = 1 + min(dp[i − k²]) по k² ≤ i — последний квадрат
* **Почему корректно:** любой способ представления i оканчивается квадратом k²; остаток представлен оптимально (a.md A.1)
* **Пример:** 12 → 3 (4+4+4), 13 → 2 (4+9), 10 → 2 (9+1)
* **Сложность:** O(n·√n) времени, O(n) памяти
* **Обобщение:** «ровно m слагаемых» — второе измерение (раздел I); мост из профильной темы — одномерная ДП, профильный аналог для доски n×n — «квадраты» как фигуры
* **Реализация:** `min_squares(n)`
* **Связь:** каркас «1 + min по предыдущим» — b.md (B.1, B.6), d.md (D.3)

## **F.13. Connected-компонентный профиль (связность замощений)**
* **Постановка:** профиль с номерами компонент связности; классическое применение — счёт гамильтоновых циклов на доске m×n (одна компонента, замкнутая в конце)
* **Рекуррентность (Plug DP):** состояние — массив меток рёбер линии разлома (m+1 слот); клетка (i, j): L = метка левого ребра, U = метка верхнего; случаи: (0,0) — новая компонента (рёбра вниз и вправо — новая метка); (0,U) и (L,0) — продолжить ребро вниз или вправо; (L ≠ U) — слияние компонент (переметить все L в U); (L = U) — замыкание цикла — допустимо только в последней клетке при пустом остальном профиле
* **Почему корректно:** каждая клетка цикла имеет степень 2; все случаи локальных конфигураций полны; замыкание раньше конца — отдельный цикл — запрещено; метки нормируются (нумерация по первому вхождению) — состояние канонично
* **Пример:** 2×2 → 1, 2×3 → 1 (периметр), 3×3 → 0 (нечётные клетки), 4×4 → 6
* **Сложность:** O(n·m·|состояния|) времени, |состояния| ≤ O(3ᵐ·m)
* **Обобщение:** связность замощений — метки компонент вместо битов; «ровно одна компонента» — модификация случаев слияния; применение к задачам с требованиями связности
* **Реализация:** `count_hamiltonian_cycles(m, n)`
* **Связь:** «клетка за клеткой» — F.3; мосты с метками — F.11

## **F.14. Замощение с цветами/рисунками**
* **Постановка:** профиль кодирует не только занятость, но и цвет клеток границы; типовой пример — число раскрасок доски в 2 цвета без одноцветного квадрата 2×2
* **Рекуррентность:** dp по строкам: состояние — цветовая маска строки (m бит); переход prev → next допустим, если для каждого столбца c блок 2×2 (prev c, prev c+1, next c, next c+1) не одноцветен
* **Почему корректно:** 2×2-блоки формируются соседними парами строк — вся информация для проверки в двух масках; перебор совместимых пар полон
* **Пример:** 2×3 → 50, 3×1 → 8 (нет блоков 2×2), 3×2 → 50
* **Сложность:** O(n·2ᵐ·2ᵐ·m) времени, O(2ᵐ) памяти
* **Обобщение (поглощение констант):** больше цветов — маска из многобитовых полей; рисунки с запретами на границе — расширение профиля
* **Реализация:** `count_colorings_no_monochrome_2x2(m, n)`
* **Связь:** профиль-маска — F.1, F.2; независимость — e.md (E.11)
