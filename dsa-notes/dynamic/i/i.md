**I. СПЕЦИАЛЬНЫЕ ВИДЫ И ТЕХНИКИ ДП**

> **Архитектура:** `SpecialDP` (i.cpp) — класс ветки dynamic, наследует `GraphDP` (h.cpp), а через него `TreeDP`, `ProfileDP`, `SubsetDP`, `SegmentDP`, `MatrixDP`, `LinearDP`, `DPBasics`. Раздел собирает шесть семейств, выходящих за рамки классической табличной динамики: цифровая динамика (A: состояние (pos, tight, leadingZero, свойство) — I.1–I.9), вероятностная (B: ожидания и цепи Маркова — I.10–I.17), комбинаторные игры (C: нимберы, Шпраг-Гранди — I.18–I.25), параметрическая (D: дополнительные измерения количества/суммы — I.26–I.30), временная (E: время как состояние — I.31–I.34), ленивая (F: вычисление по требованию — I.35–I.37). Переиспользуются, а не дублируются: `OpCost` (b.md B.5 — цены операций в I.36), `can_win_dag` (h.md H.12 — одиночная позиция в I.19), топологический порядок (h.md H.1 — каркас I.18, I.23, I.37), `digital_root_base` (math/number-theory c-folder — I.8), `partitions_pentagonal` (math/combinatorics b/b.md — сверка I.28), матричное возведение (h.md H.8 — обобщение I.30).
>
> **Связи:** расширение состояния — a.md (A.3); ожидание как взвешенная сумма — a.md (A.1); марковские цепи — матричные переходы (b.md B.9, h.md H.8); игры на DAG — h.md (H.12); производящие функции и разбиения — math/combinatorics; цифры, делимость, цифровой корень — math/number-theory (c-folder); системы линейных уравнений — math/linear-algebra.

### **Основные понятия и принципы**

* **Что это:** шесть семейств, где классическая «таблица по индексам» не работает — состояние кодируется иначе или вычисляется по-другому: цифровая ДП (позиция цифры + флаги tight/leadingZero), вероятностная (ожидания, цепи Маркова), комбинаторные игры (P/N-позиции, нимберы), параметрическая (дополнительные измерения: количество, сумма), временная (время как координата), ленивая (вычисление по требованию)
* **Почему выделяется в отдельный класс:** общие принципы ДП неизменны (состояние, переход, база, порядок), но каждая семья по-своему отвечает на вопрос «что является состоянием» — числа как последовательности цифр, вероятности как веса переходов, позиции игры как нимберы, время как ось таблицы; порядок вычисления тоже свой: разряды, обратная рекурсия, топологический порядок, системы линейных уравнений
* **Ключевые принципы:** расширение состояния (a.md A.3) — общий инструмент всех семейств; ожидание — взвешенная сумма по полной группе событий; игра — взаимная индукция N/P и mex, суммы игр через XOR (теорема Шпрага-Гранди); разрежённые большие состояния — ленивая мемоизация
* **Как распознать:** «числа с ограничением на цифры», «ожидание/вероятность», «два игрока — кто выиграет», «ровно k / с суммой S», «дедлайны и время», «огромные разрежённые пространства состояний»
* **Границы:** системы уравнений (цепи Маркова) требуют единственности решения; бесконечные ожидания вне рамок ДП; теоретические темы (partisan games) не реализуются; временная ось — сжатие координат при больших диапазонах

# **A. ЦИФРОВАЯ ДИНАМИКА (DIGIT DP)**

## **I.1. Основная идея и состояние (pos, tight, leadingZero)**
* **Постановка:** подсчёт чисел в [L, R] со свойством на цифры; числа длины ≤ n (n — число разрядов); состояние — (pos, tight, leadingZero): позиция, флаг «префикс равен префиксу границы», флаг «все цифры пока нули»
* **Рекуррентность:** dp(pos, tight, lz) = Σ_{dig ≤ limit} dp(pos+1, tight', lz') — перебор цифры: limit = tight ? граница[pos] : b−1 (b — основание); tight' = tight && dig == граница[pos]; lz' = lz && dig == 0; свойство достраивается дополнительным измерением (I.5–I.9)
* **Почему корректно:** разрядный перебор покрывает все числа один раз; tight отсекает числа, большие границы; leadingZero отделяет лидирующие нули от значащих (свойства про нули считаются только со значащих позиций); мемоизация по (pos, tight, lz) корректна — продолжение не зависит от конкретного префикса
* **Пример:** [1, 100] с цифрой 7: 19 чисел (7, 17, ..., 97 — 10, и 70..79 — 10, 77 посчитан дважды)
* **Сложность:** O(n·b·|состояние свойства|), память O(n·|состояние|)
* **Обобщение:** основание b произвольно (I.8); «ровно k цифр d», «не более», «хотя бы одна» — один флаг/счётчик в состоянии
* **Реализация:** `count_containing_digit(L, R, d)` — числа [L, R], содержащие цифру d (свойство-флаг в состоянии)
* **Связь:** расширение состояния — a.md (A.3); цифры числа — math/number-theory (c-folder)

## **I.2. Диапазон через f(R) − f(L−1)**
* **Постановка:** разбиение запроса [L, R] на два префиксных: f(x) — ответ для [1, x]; ответ = f(R) − f(L−1)
* **Почему корректно:** [1, R] = [1, L−1] ⊔ [L, R] — непересекающееся покрытие; число/сумма аддитивны — вычитание корректно
* **Пример:** [20, 40] с цифрой 7: f(40) − f(19) = 4 − 2 = 2 (27, 37)
* **Сложность:** два прогона префиксной динамики — удвоение константы
* **Обобщение:** тройной трюк для сумм по диапазону (аддитивность свойства); L = 1 — вырождается в один префикс
* **Реализация:** общий каркас `count_containing_digit(L, R, d)` = f(R) − f(L−1)
* **Связь:** префиксные суммы — a.md (A.1); Range Sum Query — I.3

## **I.3. Range Sum Query для цифровых свойств**
* **Постановка:** сумма значений свойства по всем числам [L, R]; пара (cnt, sum) в состоянии: cnt — число завершений, sum — сумма их значений
* **Рекуррентность:** переход по цифре dig на позиции pos: cnt' = Σ cnt; sum' = Σ (sum + cnt·dig·b^(n−1−pos)) — вклад цифры во все завершения; на листе (pos = n): (свойство ? 1 : 0, 0)
* **Почему корректно:** вклад цифры dig в число = dig·вес разряда; сумма по завершениям раскладывается на вклад текущей цифры (cnt·вес) и вклад хвоста (sum); пара (cnt, sum) замкнута относительно переходов
* **Пример:** [1, 20] с цифрой 7: сумма = 7 + 17 = 24
* **Сложность:** O(n·b), память O(n) — пара вместо скаляра
* **Обобщение:** свойство-значение — сумма цифр (I.4), само число (здесь); любой аддитивный вклад (квадрат, чётность); сумма чисел с остатком — I.6 + пара
* **Реализация:** `sum_containing_digit(L, R, d)` — сумма чисел [L, R], содержащих цифру d
* **Связь:** пара (cnt, sum) — общий приём ожиданий (B)

## **I.4. Сумма цифр всех чисел диапазона**
* **Постановка:** Σ (сумма цифр) по всем числам [L, R]; свойство — сам цифровой состав
* **Рекуррентность:** пара (cnt, sum): переход по dig: sum' = Σ (sum + cnt·dig) — вклад цифры без веса разряда; лист: (1, 0); ответ — sum корня
* **Почему корректно:** та же декомпозиция, что в I.3, с весами разряда = 1
* **Пример:** [1, 10]: 1+2+...+9+1 = 46
* **Сложность:** O(n·b), память O(n)
* **Обобщение:** цифровой корень — теорема dr(x) = x mod (b−1) (math/number-theory c-folder, `digital_root_base`); сумма цифр в системе b
* **Реализация:** `sum_of_digits_range(L, R)`
* **Связь:** каркас пары — I.3

## **I.5. Числа без повторяющихся цифр**
* **Постановка:** маска использованных цифр в состоянии: dp(pos, tight, lz, mask); цифра dig допустима, если mask не содержит dig (для значащих позиций)
* **Рекуррентность:** переход по dig: если lz && dig == 0 — mask не меняется; иначе dig ∈ mask — переход запрещён, иначе mask |= bit(dig); лист: 1
* **Почему корректно:** маска — ровно та информация о префиксе, от которой зависит допустимость продолжения; запрет повторной цифры — локальное свойство позиции
* **Пример:** [1, 100]: 9 (однозначные) + 9·9 (двузначные) = 90; [1, 10]: 10 (10 — цифры 1 и 0 различны)
* **Сложность:** O(n·b·2^b) — маска 2^b состояний; при b = 10: O(n·10·1024)
* **Обобщение:** «ровно k повторений», «не более двух подряд» — счётчик повторов вместо маски; перестановки цифр (b ≤ 20 → битмаска)
* **Реализация:** `count_distinct_digits(L, R)`
* **Связь:** битмаска как состояние — e.md (E.1)

## **I.6. Числа, делящиеся на K (остаток как состояние)**
* **Постановка:** dp(pos, tight, lz, mod) — остаток по модулю K: mod' = (mod·b + dig) mod K; лист: mod == 0
* **Почему корректно:** инвариант разрядов: значение префикса ≡ mod (mod K); приписывание цифры — переход mod → (mod·b + dig) mod K; число делится на K ⇔ остаток 0
* **Пример:** [1, 100] на 3: 33 числа (3, 6, ..., 99)
* **Сложность:** O(n·b·K), память O(n·K) — K в состояние
* **Обобщение:** свойство-остаток для любых периодических функций по цифрам (модуль — «период»); большие K — разреженная мемоизация (I.7)
* **Реализация:** `count_divisible_digits(L, R, K)`
* **Связь:** деление с остатком — math/number-theory; модуль как состояние — a.md (A.3)

## **I.7. Мемоизация со сложными состояниями (map/hash)**
* **Постановка:** комбинация свойств даёт состояние-кортеж (pos, sum, mod, tight, lz); при больших диапазонах параметров (K ~ 10^9) таблица невозможна — unordered_map по закодированному кортежу
* **Рекуррентность:** ключ = ((pos·(S+1) + sum)·K + mod)·4 + tight·2 + lz; мемо — только посещённые состояния (пространство разрежённое)
* **Почему корректно:** корректность состояний — I.4, I.6; map-мемо хранит те же значения, что таблица, но без зарезервированной памяти под все комбинации
* **Пример:** [1, 100], сумма цифр ≤ 9 и делимость на 5: 15 чисел (5, 10, 15, 20, 25, 30, 35, 40, 45, 50, 60, 70, 80, 90, 100)
* **Сложность:** O(n·b·(число посещённых кортежей)), память та же
* **Обобщение:** любое число параметров — кодирование кортежа в long long; хранение std::map при неупорядоченных ключах
* **Реализация:** `count_digit_sum_and_divisible(L, R, S, K)` — числа [L, R] с суммой цифр ≤ S и делящиеся на K
* **Связь:** ленивые вычисления — F (I.35–I.37)

## **I.8. Обобщения: ограничение суммы цифр, k единиц, основание b**
* **Постановка:** (1) dp(pos, tight, lz, sum) — сумма цифр ≤ S; (2) ровно k единиц в системе b = 2: dp(pos, tight, lz, ones); (3) произвольное основание b — общий каркас I.1 с заменой b
* **Рекуррентность:** sum' = sum + dig (≤ S); ones' = ones + (dig == 1); лист: (2) ones == k
* **Почему корректно:** сумма цифр монотонна по цифрам — отсечение sum + dig ≤ S; счётчик единиц — та же пара, что счётчик повторов в I.5; основание — параметр разрядного перебора
* **Пример:** [1, 100] с суммой цифр ≤ 5: 21 число; [1, 20] с ровно 2 единицами в двоичной записи: 9 (3, 5, 6, 9, 10, 12, 17, 18, 20)
* **Сложность:** O(n·b·S) / O(n·2·k) — сумма и счётчик как измерения
* **Обобщение:** цифровой корень — закрытая формула dr(x) = 1 + (x−1) mod (b−1) (math/number-theory c-folder, `digital_root_base`); числа с k единицами в b = 2 без границы — комбинаторика C(n, k)
* **Реализация:** `count_digit_sum_limit(L, R, S)`, `count_numbers_with_k_bits(L, R, k)`
* **Связь:** I.1 — каркас; I.7 — комбинация обоих

## **I.9. Динамика по цифрам + другие свойства (палиндромность)**
* **Постановка:** комбинация digit DP с нетривиальным свойством; палиндромность: число-палиндром определяется первой половиной цифр — строим половинку, зеркалим и сравниваем с границей
* **Идея:** палиндромы фиксированной ширины w взаимно однозначно соответствуют «половинкам» h длины ceil(w/2) (первая цифра h ≠ 0); подсчёт ≤ x: для w < n — все половинки; для w = n — половинки h ≤ upperHalf, зеркальное число проверяется на ≤ x (монотонность по h — одна корректирующая проверка)
* **Почему корректно:** палиндром однозначно восстановим по половинке; функция h → палиндром(h) монотонна — все h < верхней границы дают палиндромы ≤ x автоматически, кроме самой верхней (проверяется явно)
* **Пример:** [1, 1000]: 108 палиндромов (9 + 9 + 90); [1, 10]: 9
* **Сложность:** O(n²) на число — по ширине и по цифрам половинки; память O(n)
* **Обобщение:** простота — локального цифрового признака нет: проверка на листе перебором делителей/решето; «палиндром в системе b» — тот же каркас; зеркальные пары (x + reverse(x) = const)
* **Реализация:** `count_palindromic_range(L, R)`
* **Связь:** палиндромы — d.md (D.3, D.13); reverse — math/number-theory (c-folder)

# **B. ВЕРОЯТНОСТНАЯ ДИНАМИКА (PROBABILITY DP)**

## **I.10. Основы вероятностей в ДП**
* **Постановка:** ожидание E[X] = Σ pᵢ·xᵢ; вероятности переходов между состояниями: dp[state] = Σ p(state → next)·dp[next] — ДП по состояниям с весами-вероятностями
* **Почему корректно:** полная группа событий (Σ pᵢ = 1) — декомпозиция по первому переходу полна и непересекаема (a.md A.1); ожидание линейно
* **Пример:** бросок честной монеты: E[число орлов за 2 броска] = 2·0.5
* **Сложность:** O(|состояний|·|переходов|)
* **Обобщение:** веса-вероятности ничем не отличаются от весов-стоимостей (I.11); непрерывные распределения — те же суммы с интегралами (вне каркаса ДП)
* **Реализация:** каркас иллюстрируется в I.11–I.17
* **Связь:** взвешенные переходы — a.md (A.1), h.md (H.2)

## **I.11. Игровые задачи с вероятностями (кости)**
* **Постановка:** ожидание числа бросков честной d-гранной кости до достижения суммы S: dp[i] = 1 + Σ_{f=1..d} dp[i+f]/d, i < S; dp[i] = 0, i ≥ S
* **Почему корректно:** каждый бросок стоит 1; из i переходы в i+1..i+d равновероятны; состояния растут (i+f > i) — порядок вычисления обратный
* **Пример:** S = 2, d = 6: E[0] = 1 + E[1]/6 = 7/6 ≈ 1.1667 (первый бросок 2..6 — конец)
* **Сложность:** O(S·d), память O(S)
* **Обобщение:** нечестная кость — веса p_f; поглощение (I.15); карты/шахматные переходы — та же формула; «ровно S» с перелётом и без — разные условия останова
* **Реализация:** `expected_dice_rolls_to_sum(S, d)`
* **Связь:** ожидание числа шагов — I.12, I.15

## **I.12. Random Walks и мартингалы**
* **Постановка:** 1D-блуждание на [0, n] с поглощением на концах, равновероятные шаги: E[i] = 1 + (E[i−1] + E[i+1])/2, E[0] = E[n] = 0 — замкнутое решение E[i] = i·(n−i)
* **Почему корректно:** подстановка E[i] = i(n−i) в уравнение даёт 1 + ((i−1)(n−i+1) + (i+1)(n−i−1))/2 = 1 + (2i(n−i) − 2)/2 = i(n−i); решение единственно (трёхдиагональная система)
* **Пример:** n = 3: E = {0, 2, 2, 0} — из середины в среднем 2 шага
* **Сложность:** O(n) — формула без ДП; в общем виде — система (I.15)
* **Обобщение:** смещённое блуждание (p ≠ 0.5) — формула (q/p)-степеней (I.17); время возврата в 0: мартингал M_t = позиция — ожидание возврата бесконечно в 1D, конечно в 2D; связь с мартингалами — E[M_{t+1} | история] = M_t — инвариант для анализа
* **Реализация:** `expected_absorbing_steps_1d(n)` — вектор E[0..n]
* **Связь:** система линейных уравнений — I.15; разорение — I.17

## **I.13. Цепи Маркова: стационарное распределение**
* **Постановка:** матрица переходов P (P[i][j] — вероятность i → j); стационарное распределение π = π·P, Σπ = 1 — система линейных уравнений: Σ_j π[j]·P[j][i] = π[i] для всех i (одно уравнение зависимо) + нормировка
* **Почему корректно:** π·P = π — неподвижная точка; P^k → π для эргодических цепей; сумма строк P = 1 — одно уравнение лишнее, заменяем на Σπ = 1; единственность — для неразложимых апериодических цепей
* **Пример:** P = {{0.9, 0.1}, {0.4, 0.6}}: π = {0.8, 0.2} (0.8·0.9 + 0.2·0.4 = 0.8)
* **Сложность:** O(n³) — Гаусс; O(n²) на итерацию — степени P^k (матричные переходы — b.md B.9)
* **Обобщение:** поглощающие цепи — фундаментальная матрица N = (I − Q)^{-1}: ожидание посещений и время поглощения (I.15); π для цепей с несколькими классами — система вырождается (метод возвращает пусто)
* **Реализация:** `stationary_distribution(P)` — Гаусс с частичным выбором ведущего
* **Связь:** матричные переходы — b.md (B.9), h.md (H.8); линейные системы — math/linear-algebra

## **I.14. Алгоритм Витерби (скрытые марковские модели)**
* **Постановка:** скрытые состояния s₁..s_T, наблюдаемые символы obs; dp[t][s] = max_{s'} dp[t−1][s']·p(s'→s)·p(obs_t | s) — самый вероятный путь скрытых состояний
* **Рекуррентность:** dp[1][s] = π[s]·p(obs₁ | s); dp[t][s] = max_{s'} dp[t−1][s']·trans[s'][s]·emit[s][obs_t]; prev[t][s] — аргумент максимума; восстановление — обратный проход
* **Почему корректно:** вероятность пути — произведение переходов и эмиссий; максимум по последнему состоянию + оптимальность префикса (a.md A.1) — динамика по времени; численная устойчивость — логарифмическая шкала (сложение вместо умножения)
* **Пример:** два состояния, эмиссия детерминирована (s=0 → только символ 0): наблюдение {0, 0, 1} → путь {0, 0, 1}
* **Сложность:** O(T·|S|²), память O(T·|S|)
* **Обобщение:** логарифмическая шкала; k лучших путей; прогнозирование P(obs_{t+1}) — полная вероятностная динамика (суммы вместо max)
* **Реализация:** `viterbi(obs, trans, emit, init)` — пара (путь, вероятность)
* **Связь:** максимум по переходу — H.2; последовательности — раздел B

## **I.15. Ожидание шагов до поглощения (система уравнений)**
* **Постановка:** E[i] = 1 + Σ_j P[i][j]·E[j] для не-поглощающих i; E[i] = 0 для поглощающих; циклы в графе переходов делают рекурсию нетривиальной — система линейных уравнений
* **Рекуррентность:** неизвестные E[0..n−1]: для поглощающих — E[i] = 0; для остальных — (I − P)[i][·]·E = 1; решение — Гаусс
* **Почему корректно:** уравнение полной вероятности по первому шагу (I.10); единственность — если поглощение достигается с вероятностью 1 (иначе E = ∞ — вне рамок); DAG-частный случай решается без системы (I.11)
* **Пример:** цепь 0 → 1 → 2 (2 поглощающая): E[2] = 0, E[1] = 1, E[0] = 2
* **Сложность:** O(n³) — Гаусс; память O(n²)
* **Обобщение:** ожидания с весами шагов (1 → cost(i)); вероятность поглощения в каждой ловушке — замена правой части; случайные блуждания на графах — P = D^{-1}·A
* **Реализация:** `expected_steps_absorbing(P, start)` — E[start]
* **Связь:** Гаусс — I.13; DAG-каркас — I.11

## **I.16. Ожидание с ДП по вероятностям (сетка)**
* **Постановка:** вероятности попасть в состояния: dp[i][j] = p·dp[i][j+1] + (1−p)·dp[i+1][j] — блуждание по сетке с вероятностью p шага вправо; граница — провал
* **Рекуррентность:** dp[n−1][m−1] = 1 (цель); за пределами сетки dp = 0; обратный порядок от правого нижнего угла
* **Почему корректно:** полная группа из двух исходов шага (p + (1−p) = 1) — I.10; рекурсия завершается на границе
* **Пример:** 2×2, p = 0.5: dp[0][0] = 0.5 (успех: любой обход; провал — выход за границу)
* **Сложность:** O(n·m), память O(m) (скроллинг — раздел J)
* **Обобщение:** три и более исходов (Σ pᵢ = 1); вероятности перехода, зависящие от клетки; ожидание числа шагов на сетке — I.15
* **Реализация:** `grid_reach_probability(n, m, pRight)`
* **Связь:** пути в сетке — b.md (B.11); каркас вероятностных переходов — I.10

## **I.17. Разорение игрока (Gambler's Ruin)**
* **Постановка:** капитал i, цель n, вероятность выигрыша раунда p (q = 1−p); вероятность разорения (достижения 0): p = 0.5 → (n−i)/n; p ≠ 0.5 → ((q/p)^i − (q/p)^n) / (1 − (q/p)^n)
* **Почему корректно:** r(i) = q·r(i−1) + p·r(i+1), r(0) = 1, r(n) = 0 — рекурсия второго порядка; характеристическое уравнение (1−p)·λ² − λ + p = 0 → λ = 1, q/p; общее решение + граничные условия дают формулу
* **Пример:** i = 1, n = 3, p = 0.5: разорение 2/3 ≈ 0.6667; p = 0.6: 10/19 ≈ 0.5263
* **Сложность:** O(1) — формула; итеративно — O(n)
* **Обобщение:** «возврат» (с каждой ставки берётся доля); несимметричные шаги и границы; мартингал: ожидание капитала инвариантно (I.12)
* **Реализация:** `gambler_ruin_probability(capital, target, p)` — вероятность разорения
* **Связь:** рекурсия второго порядка — I.12; уравнения — I.15

# **C. КОМБИНАТОРНАЯ ИГРОВАЯ ДИНАМИКА (COMBINATORIAL GAME DP)**

## **I.18. Числа Гранди (нимберы)**
* **Постановка:** impartial-игра на DAG: g(x) = mex{ g(y) : x → y }; g = 0 ⇔ проигрышная позиция; mex — наименьшее неотрицательное, отсутствующее в наборе
* **Рекуррентность:** обратный топологический порядок (h.md H.1): g(v) = mex{g(to)}; лист: g = 0
* **Почему корректно:** определение нимбера — индукция по длине игры (DAG); g(x) = 0 ⇔ все ходы в ненулевые ⇔ P-позиция (I.19)
* **Пример:** 0→1, 0→2, 1→3, 2→3: g = {0, 1, 1, 0} — лист 3 (0), 1 и 2 (mex{0} = 1), 0 (mex{1, 1} = 0)
* **Сложность:** O(V + E) — mex O(степень) на вершину
* **Обобщение:** суммы игр — XOR (I.21); периодичность последовательностей Гранди (I.24); игры с циклами — вне рамок (нужны определённые функции)
* **Реализация:** `grundy_dag(adj)` — вектор g
* **Связь:** топологический порядок — h.md (H.1); выигрышные позиции — I.19

## **I.19. P- и N-позиции**
* **Постановка:** P (проигрышная для ходящего): все ходы в N; N (выигрышная): существует ход в P — взаимная индукция от листьев; win(v) = ∃(v,u): ¬win(u)
* **Рекуррентность:** win(v) ⇔ g(v) ≠ 0 (I.18); вектор всех позиций — обратный топологический порядок; одиночная позиция — DFS-мемоизация (h.md H.12, `can_win_dag`)
* **Почему корректно:** индукция по глубине: из N есть ход в P (ходящий отдаёт проигрыш), из P все ходы в N; эквивалентность g = 0 ⇔ P — из определения mex
* **Пример:** граф I.18: win = {0, 1, 1, 0} — позиции 0 и 3 проигрышные
* **Сложность:** O(V + E)
* **Обобщение:** одиночная позиция — h.md H.12 (переиспользуется); k-ходовая отсрочка, рейтинги позиций (расстояние до P)
* **Реализация:** `win_lose_positions(adj)` — vector<bool> (через `grundy_dag`)
* **Связь:** H.12 — частный случай; N/P — основа I.21

## **I.20. Классические игры**
* **Постановка:** Ним (n кучек, ход — уменьшить одну): xor всех размеров ≠ 0 ⇔ выигрышная; Kayles (ряд кеглей, ход — сбить 1 или 2 соседние): g(n) = mex{ g(a) ⊕ g(n−1−a), g(a) ⊕ g(n−2−a) }; Dawson's Kayles (только 2 соседние): g(n) = mex{ g(a) ⊕ g(n−2−a) }; Wythoff (две кучки, ход — уменьшить одну или обе на равное число): P-позиции (⌊k·φ⌋, ⌊k·φ²⌋), φ = (1+√5)/2
* **Рекуррентность:** Kayles — расщепление ряда на два независимых при удалении блока (сумма — XOR, I.21); Wythoff — проверка a = ⌊(b−a)·φ⌋ при a ≤ b
* **Почему корректно:** Ним — XOR-критерий (каждая кучка — компонента, I.21); Kayles/Dawson — расщепление: после удаления блока ряд распадается на два независимых (теорема Шпрага-Гранди); Wythoff — P-позиции порождаются «жадной» симметрией: (1,2), (3,5), (4,7), (6,10), ... с шагом ⌊k·φ⌋
* **Пример:** Ним {1, 2, 3}: xor = 0 — второй выигрывает; Wythoff (1, 2), (3, 5) — P; (2, 3) — N
* **Сложность:** Ним O(n); Kayles O(n²); Dawson O(n²); Wythoff O(1)
* **Обобщение:** варианты Нима (скромный Ним, мизер, k-кучки), Moore's Nim — модификации XOR-критерия; Kayles — периодичность нимберов с периодом 12 после g(71); Wythoff — обобщение (r-позиции, кучки с ограничениями)
* **Реализация:** `nim_winner(piles)`, `kayles_grundy(n)`, `dawson_kayles_grundy(n)`, `wythoff_winner(a, b)`
* **Связь:** XOR — I.21; периодичность — I.24

## **I.21. Теорема Шпрага-Гранди**
* **Постановка:** игра = сумма независимых компонент; нимбер суммы = XOR нимберов компонент; позиция проигрышная ⇔ XOR = 0
* **Рекуррентность:** g(G₁ ⊕ G₂ ⊕ ... ⊕ G_k) = g(G₁) ⊕ g(G₂) ⊕ ... ⊕ g(G_k); выигрыш первого игрока ⇔ XOR ≠ 0
* **Почему корректно:** требуется g(x) = mex{ g(y) } и g(x) = 0 ⇔ P — XOR-сумма нимберов обладает обоими свойствами (стандартный аргумент с ведущим битом XOR)
* **Пример:** компоненты с нимберами {1, 2, 3}: XOR = 0 — проигрыш; {2, 2, 1}: XOR = 1 — выигрыш
* **Сложность:** O(n) — XOR по компонентам
* **Обобщение:** доказательство для любого числа компонент; восстановление хода — компонента с ведущим битом (I.23); Гранди-периодичность (I.24)
* **Реализация:** `sprague_grundy_winner(grundies)` — XOR ≠ 0
* **Связь:** Ним — I.20; ходы — I.23

## **I.22. Partisan games (игры с разными правилами)**
* **Постановка:** у игроков разные множества ходов; теория комбинаторных игр (Winning Ways): игры = сюрреальные числа (значения «горячих»/«холодных» игр), сравнение игровых значений, температура
* **Идея:** hot games — преимущество хода (оба хотят ходить); cold games — ходить невыгодно (значение — число); сумма значений — обобщение чисел Гранди (целые нимберы — частный случай «холодных» игр)
* **Почему корректно:** теория сюрреальных чисел Конвея — частично упорядоченные игровые значения; вне рамок ДП-каркаса — теоретическая глава
* **Пример:** «Голодная игра» (Hackenbush с разными цветами) — значения 0, 1, −1, ...
* **Сложность:** — (теория; методы ДП неприменимы без полного дерева игры)
* **Обобщение:** понятие температуры; приложения — анализ эндшпилей; в олимпиадных задачах — редкий раздел, обычно сводится к Ним-вариантам (I.20)
* **Реализация:** не требуется — теоретическая тема (метод не реализуется в рамках ДП-библиотеки)
* **Связь:** нимберы — I.18; суммы игр — I.21

## **I.23. Применения: стратегия, ходы, DAG-игры**
* **Постановка:** по нимберам — не только исход, но и оптимальный ход: из N-позиции существует ход в P-позицию (в компоненту с ведущим битом XOR — I.21)
* **Рекуррентность:** для DAG: winning move из v — любое ребро v → u с g(u) = 0; для сумм: выбрать компоненту с g_i > (g_i ⊕ XOR) и уменьшить до g_i' = g_i ⊕ XOR
* **Почему корректно:** определение P/N (I.19): ход в позицию с g = 0 гарантирован из выигрышной позиции; единственность — g(u) = 0 — критерий
* **Пример:** граф 0→1, 0→2, 1→3, 2→3: из 0 выигрышного хода нет (−1); с ребром 0→3: ход в 3
* **Сложность:** O(V + E) — один проход после `grundy_dag`
* **Обобщение:** восстановление хода в Ним по ведущему биту; стратегия «отдай P-позицию» — общий приём конечных игр
* **Реализация:** `winning_move_dag(adj, s)` — вершина-цель выигрышного хода или −1 (через `grundy_dag`)
* **Связь:** P/N — I.19; XOR — I.21

## **I.24. Subtraction Games: периодичность нимберов**
* **Постановка:** из кучки размера i можно убрать m ∈ S (S — конечное множество допустимых вычитаний): g(i) = mex{ g(i−m) : m ≤ i, m ∈ S }
* **Рекуррентность:** g[0] = 0; g[i] = mex по всем m; последовательность g периодична — известный факт для конечных S
* **Почему корректно:** определение Гранди (I.18) для прямой игры; периодичность: состояния зависят от фиксированного числа предыдущих значений (max S) — по принципу Дирихле последовательность входит в цикл
* **Пример:** S = {1, 3, 4}: g: 0, 1, 0, 1, 2, 3, 2, 0, 1, 0, ... — g[7] = 0 (проигрыш), g[10] = 1
* **Сложность:** O(n·|S|), память O(n)
* **Обобщение:** период и предпериод — поиск циклом (малые max S); бесконечные S — другие классы; приложения — игра «камикадзе», деление (mul-варианты)
* **Реализация:** `subtraction_grundy(n, moves)` — вектор g[0..n]
* **Связь:** Гранди — I.18; Kayles — I.20 (расщепление — не вычитание)

## **I.25. Игры с копками: Green Hackenbush**
* **Постановка:** дерево (копка) с корнем в земле; ход — срубить ребро, всё выше ребра удаляется; нимбер позиции: g(v) = (v — корень ? 0 : 1) ⊕-накопление: g(v) = [v ≠ root] + ⊕_детей g(детей) — «бамбук длины L = ним L»
* **Рекуррентность:** лист: g = 1; внутренняя вершина: g(v) = 1 + XOR(g(детей)); корень: XOR(g(детей)) (без +1 — у корня нет ребра к земле); теорема колонизации (colon principle): ветка = бамбук длины g(ветки)
* **Почему корректно:** срез ребра удаляет поддерево — разложение на независимые компоненты (I.21); проверка на малых деревьях по определению mex: бамбук L → L; «вилка» из 2 рёбер → 0; бамбук с вилкой наверху → длина + 0
* **Пример:** бамбук длины 3: g = 3; вилка (2 ребра от корня): g = 1⊕1 = 0; корень с детьми-бамбуками 2 и 1: g = 2⊕1 = 3
* **Сложность:** O(V) — обход дерева; память O(V)
* **Обобщение:** coloured Hackenbush — partisan-значения (I.22); циклы — fusion-принцип (сворачивание циклов в узлы)
* **Реализация:** `green_hackenbush_value(children, root)` — нимбер дерева
* **Связь:** XOR — I.21; расщепление — I.20 (Kayles)

# **D. ПАРАМЕТРИЧЕСКАЯ ДИНАМИКА**

## **I.26. DP с ограничением на количество элементов**
* **Постановка:** dp[i][k] — ровно/не более k элементов среди первых i; переходы с фиксацией k; классика — выбор k элементов без соседних
* **Рекуррентность:** dp[i][k] = dp[i−1][k] + dp[i−2][k−1] (не берём i-й / берём, пропустив i−1-й); база dp[i][0] = 1; замкнутая форма C(n−k+1, k)
* **Почему корректно:** декомпозиция по «берём/не берём» (a.md A.1) полна; измерение k — размер выбора — инвариант перехода
* **Пример:** n = 5, k = 2: C(4, 2) = 6 способов
* **Сложность:** O(n·k), память O(k) (скроллинг по i)
* **Обобщение:** «не более k» — префиксные суммы по k; взвешенная версия — максимум вместо подсчёта (dp[i][k] = max(...)); k фиксировано мало — измерение обязательно
* **Реализация:** `count_select_k_non_adjacent(n, k)`
* **Связь:** расширение состояния — a.md (A.3); сумма как измерение — I.27

## **I.27. DP с ограничением на сумму**
* **Постановка:** добавление измерения «сумма» к состоянию: dp[j] — число способов набрать сумму j: dp[j] += dp[j−w] по предметам
* **Рекуррентность:** по каждому предмету w: j от S вниз до w (обратный порядок — 0/1-выбор, j вверх — без ограничения); база dp[0] = 1
* **Почему корректно:** сумма — аддитивный инвариант перехода; обратный проход исключает повторное использование предмета
* **Пример:** S = 5, a = {1, 2, 3}: 1 способ ({2, 3}); a = {1, 2, 3, 4}: 2 ({1, 4}, {2, 3})
* **Сложность:** O(n·S), память O(S)
* **Обобщение:** минимум/максимум по сумме — те же переходы с другой операцией; сумма с кратностями; разность — фиксированный сдвиг суммы (подмножества с разностью d: dp[j] ↔ dp[j+d]); связанные измерения (I.26 + I.27 — число и сумма одновременно)
* **Реализация:** `count_subsets_with_sum(S, a)`
* **Связь:** подмножества по маскам — e.md (E.1); рюкзак — J (In-place, J.4)

## **I.28. Integer Partition: разбиения числа на слагаемые**
* **Постановка:** p(n, k) — число разбиений n на ровно k положительных слагаемых (порядок не важен): p(n, k) = p(n−1, k−1) + p(n−k, k)
* **Рекуррентность:** слагаемое 1 есть ⇔ остальные k−1 слагаемых разбивают n−1; единиц нет ⇔ вычитаем 1 из каждого из k слагаемых — разбиение n−k на k; базы p(0, 0) = 1, p(n, 0) = 0 (n > 0)
* **Почему корректно:** два случая (содержит 1 / не содержит 1) покрывают все разбиения без пересечений; биекции на обе ветви — стандартные
* **Пример:** p(5, 2) = 2 (4+1, 3+2); p(6, 3) = 3 (4+1+1, 3+2+1, 2+2+2)
* **Сложность:** O(n·k), память O(n·k)
* **Обобщение:** производящая функция 1/∏(1−x^m) (math/combinatorics b/b.md, `partitions_pentagonal` — сверка); разбиения на различные части — p(n,k) с запретом повторов; ограничение размера части
* **Реализация:** `count_partitions_exactly_k(n, k)`
* **Связь:** производящие функции — math/combinatorics; I.26 — частный случай параметра k

## **I.29. Minimum Size Subarray Sum**
* **Постановка:** минимальная длина подотрезка с суммой ≥ S: двухуказательная/деque-оптимизация
* **Рекуррентность:** два указателя: r растёт, l подтягивается пока сумма ≥ S: len = min(len, r−l+1), сумма −= a[l], l++; ответ — минимум длин; O(n)
* **Почему корректно:** при фиксированном r оптимальный l — максимальный с суммой ≥ S (монотонность неотрицательных a — подтягивание l не теряет решений); длина монотонна по l
* **Пример:** S = 7, a = {2, 3, 1, 2, 4, 3}: минимум 2 ([4, 3])
* **Сложность:** O(n) времени, O(1) памяти
* **Обобщение:** «сумма ≥ S» → «≤ S» — зеркальный указатель; отрицательные элементы — префиксные суммы + деque (J.12); максимум длины с суммой ≤ S — тот же каркас
* **Реализация:** `min_subarray_len_ge_sum(S, a)`
* **Связь:** деque-оптимизация — J.12; префиксные суммы — a.md (A.1)

## **I.30. Техника «DP с K измерениями»**
* **Постановка:** обобщение состояний на произвольное число параметров: (pos, count, sum, mod, run, ...) — каждое свойство — измерение; размер таблицы — произведение диапазонов
* **Рекуррентность:** пример — двоичные строки длины n без k единиц подряд: dp[i][run] — число строк длины i, оканчивающихся серией из run единиц: dp[i][0] = Σ dp[i−1][run], dp[i][run] = dp[i−1][run−1] (run < k)
* **Почему корректно:** run — полная информация о хвосте (последняя серия); декомпозиция по последней цифре полна; измерение k — порог серии
* **Пример:** n = 3, k = 2: 5 строк (000, 001, 010, 100, 101)
* **Сложность:** O(n·k) — состояния (i, run)
* **Обобщение:** большой n — матричное возведение по слою run (h.md H.8); три и более измерений — прямое расширение таблицы; «бесконечные» диапазоны — ленивая динамика (F)
* **Реализация:** `count_binary_strings_without_k_ones(n, k)`
* **Связь:** матричные переходы — h.md (H.8); измерение суммы — I.27

# **E. ВРЕМЕННАЯ ДИНАМИКА**

## **I.31. Scheduling: максимум прибыли по временам**
* **Постановка:** интервальные работы (start, end, profit), непересекающиеся выборы: dp[i] — лучшая прибыль по первым i работам (сортировка по end)
* **Рекуррентность:** dp[i] = max(dp[i−1], profit[i] + dp[p(i)]), p(i) — последняя работа с end ≤ start[i] (бинарный поиск); ответ dp[m]
* **Почему корректно:** оптимальное решение либо не берёт i-ю (dp[i−1]), либо берёт — тогда допустимы только работы до p(i); декомпозиция по последней работе полна (a.md A.1)
* **Пример:** (1,3,5), (2,5,6), (4,6,5), (6,7,4): 14 ((1,3) + (4,6) + (6,7))
* **Сложность:** O(m·log m) — сортировка + бинарные поиски
* **Обобщение:** восстановление набора работ (prev[i]); взвешенные интервалы на оси с дедлайнами — I.33; покрытие — I.34
* **Реализация:** `max_profit_weighted_intervals(jobs)`
* **Связь:** «последний элемент» — a.md (A.1); LIS-каркас сортировки — d.md (D.14)

## **I.32. Time-dependent стоимости**
* **Постановка:** вес ребра зависит от момента перехода: dp[t][v] — минимум до v за ≤ t шагов, стоимость ребра (u,v) в момент t — c(u,v,t)
* **Рекуррентность:** dp[t][v] = min(dp[t−1][v], min_{(u,v)} dp[t−1][u] + c(u,v,t−1)) — шаг по времени
* **Почему корректно:** момент перехода фиксирован шагом t — состояние содержит всё необходимое; релаксация как в H.6 с зависящими от t весами
* **Пример:** 0→1: {1, 10}, 1→2: {10, 1}, 0→2: {5, 5}, T = 2: dp[2][2] = 2 (0→1 при t=0 за 1, 1→2 при t=1 за 1)
* **Сложность:** O(T·E), память O(T·V) (скроллинг — J)
* **Обобщение:** веса зависят от пары (t, v) — состояние (t, v) уже есть; временные окна — I.33; периодические тарифы — сжатие по периоду
* **Реализация:** `time_dependent_shortest_path(n, edges, T, s)` — edges (u, v, vector стоимости по t)
* **Связь:** релаксация — h.md (H.6, H.7)

## **I.33. Задачи с временными окнами (дедлайны)**
* **Постановка:** работы с дедлайном (единичная длительность): dp[t] — максимум прибыли, используя моменты 1..t; сортировка по дедлайну, проход с обновлением вниз
* **Рекуррентность:** по работам (d, p) в порядке d: for t = d..1: dp[t] = max(dp[t], dp[t−1] + p) — работа встаёт в момент t; ответ max dp
* **Почему корректно:** в момент t может стоять только работа с d ≥ t; обновление сверху вниз — каждая работа используется не более раза (аналог 0/1-рюкзака, J.4)
* **Пример:** (2, 100), (1, 50), (2, 10): 150 (работа 2 в момент 1, работа 1 в момент 2)
* **Сложность:** O(m·D) — D — горизонт (сжатие — I.34); память O(D)
* **Обобщение:** длительности > 1 — рюкзак по времени; дизъюнктные окна — интервальное ДП; минимизация опозданий — жадность по дедлайнам
* **Реализация:** `max_profit_deadline_jobs(jobs)` — пары (deadline, profit)
* **Связь:** 0/1-рюкзак — a.md; сжатие времени — I.34

## **I.34. Дискретизация временной оси (координатное сжатие)**
* **Постановка:** большие координаты интервалов: работаем только с конечными точками; классика — минимальное число интервалов для покрытия [L, R]
* **Рекуррентность:** сортировка по началу; жадный шаг: из текущей позиции cur выбираем интервал с l ≤ cur и максимальным r; cur = r; недостижимо — −1; ДП-эквивалент: dp[x] = 1 + min dp[y] по предшествующим позициям (сжатая ось — точки переключения)
* **Почему корректно:** выбор максимального r доминирует (любой другой интервал с l ≤ cur не продвигает дальше); сжатие корректно — между конечными точками структура не меняется
* **Пример:** [0, 10], интервалы {0,3}, {3,5}, {5,10}: 3; без {3,5}: −1 (дыра 3–5)
* **Сложность:** O(m·log m) — сортировка; память O(m)
* **Обобщение:** взвешенное покрытие (стоимости интервалов) — ДП по сжатой оси с деревом отрезков; покрытие точек множеством интервалов — то же сжатие
* **Реализация:** `min_intervals_to_cover(L, R, intervals)`
* **Связь:** сжатие — общий приём (graph); sweep line — h.md (H.9)

# **F. ЛЕНИВАЯ ДИНАМИКА (LAZY DP)**

## **I.35. Отложенные вычисления (мемоизация по требованию)**
* **Постановка:** состояние вычисляется только когда требуется (рекурсивная мемоизация); классика — оптимальная игра «возьми с конца»: dp[l][r] = max(a[l] − dp[l+1][r], a[r] − dp[l][r−1]) — разность счёта первого и второго
* **Рекуррентность:** мемо-таблица dp[l][r] (l ≤ r); переход — взять левый или правый конец; лениво — вычисляются только состояния, достижимые из запроса
* **Почему корректно:** разность счёта: после хода первого игроки меняются — вычитание dp следующего состояния; полная декомпозиция по первому ходу (a.md A.1)
* **Пример:** a = {1, 2, 3, 4}: разность 2 (первый берёт 4, второй 3, ...)
* **Сложность:** O(n²) состояний, вычисляются только посещённые — часто заметно меньше
* **Обобщение:** любой интервальный ДП по требованию (d.md — каркас); рекурсия глубокая — стек (n ≤ ~10^5 без оптимизаций)
* **Реализация:** `optimal_pick_game(a)` — разность счёта
* **Связь:** интервальная ДП — d.md (D.1); ленивая инициализация — I.36

## **I.36. Динамика с кэшированием (map-состояния)**
* **Постановка:** большие разрежённые пространства состояний: unordered_map по ключу вместо таблицы; классика — минимальные операции до 1 (вычитание, деление) при n ~ 10^18
* **Рекуррентность:** f(n) = min по операциям (cost + f(результат)); мемо-карта; посещаются только n, n/2, n/3, (n−1)... — логарифм глубины
* **Почему корректно:** те же рекуррентности, что в b.md B.5 (`min_ops_to_one`), но таблица O(n) невозможна — разрежённая мемоизация хранит только достижимые состояния
* **Пример:** ops = {−1, /2, /3} (цены 1), n = 10: 3 (10 → 9 → 3 → 1)
* **Сложность:** O(|ops|·глубина·log) — глубина O(log n); память — посещённые
* **Обобщение:** B.5 — плотный O(n) аналог (переиспользуется тип `OpCost`); хеш-кодирование кортежей (I.7); ленивое ДП на зависимостях — I.37
* **Реализация:** `min_ops_to_one_lazy(n, ops)` — та же сигнатура, что b.md B.5
* **Связь:** B.5 — плотный вариант; I.7 — кодирование ключей

## **I.37. Ленивое ДП на графах зависимостей**
* **Постановка:** вычисление только достижимых состояний: top-down по списку зависимостей (мемоизированный DFS по обратным рёбрам)
* **Рекуррентность:** dp(v) = max_{(v,u)} (w(v,u) + dp(u)) с мемо; обратный вызов из запрошенной вершины — посещаются только достижимые
* **Почему корректно:** DAG — рекурсия завершается (h.md H.1); те же значения, что у полного прохода (H.2), без обработки недостижимых вершин
* **Пример:** 0→1:4, 0→2:1, 1→3:2, 2→3:4: из 0 — dp[0] = 6 (путь 0-1-3); dp[3] = 0 (сток)
* **Сложность:** O(V + E) по достижимой части; память — достижимые вершины
* **Обобщение:** большие разрежённые DAG — только запрошенные подграфы; комбинация с I.36 (map-мемо) для гигантских состояний
* **Реализация:** `dag_longest_path_lazy(adj, s)` — вектор dp только по достижимым (остальные — NEG)
* **Связь:** полный проход — h.md (H.2); мемоизация — I.35
