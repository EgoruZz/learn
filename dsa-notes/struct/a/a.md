# **A. МАССИВЫ И ПОСЛЕДОВАТЕЛЬНЫЕ КОНТЕЙНЕРЫ**

## **1. Статические массивы**

### **1.1. C-style массивы и `std::array`**
* **Определение:** массив — контейнер из `n` элементов одного типа, размещённых подряд в памяти; обращение `a[i]` — базовая операция за O(1)
* **Статические массивы:** фиксированный размер, известный на этапе компиляции (`T a[n]`, `std::array<T, n>`); память на стеке — нет аллокаций, кэш-локальность максимальная
* **Почему O(1):** адрес элемента = базовый адрес + `i·sizeof(T)` — одна арифметическая операция
* **Границы:** размер `n` фиксирован — расширение требует новой копии; для динамики — раздел A.2
* **Связь:** представление статического массива — частный случай «кучной» индексации (обходы деревьев массивом — II.A)

### **1.2. Индексация многомерных массивов (Index 2D Array In 1D)**
* **Идея:** двумерный массив размера `n×m` можно хранить одной линейной последовательностью длины `n·m`; соответствие `(r, c) ↔ k` задаёт порядок раскладки
* **Row-major:** `k = r·m + c` — строка за строкой (стандарт C/C++); **Column-major:** `k = c·n + r` — столбец за столбцом (Fortran)
* **Почему важно:** доступ по строке в row-major идёт по соседним адресам — кэш-локальность (соседние клетки в одной строке кэша); при обходах выбирают направление по порядку раскладки
* **Обобщение на `d` измерений:** массив размеров `(n₀, n₁, ..., n_{d−1})`, индексы `(i₀, ..., i_{d−1})`; шаг (stride) измерения `j` — число элементов между соседними индексами этого измерения:
  * row-major: `stride_j = ∏_{t>j} n_t`, `k = Σ_j i_j·stride_j`
  * column-major: `stride_j = ∏_{t<j} n_t`
* **Сложность:** O(d) на индекс — при фиксированном `d` это O(1)
* **Пример:** `A[2][3]`, row-major: `A[1][0]` → `k = 1·3 + 0 = 3`
* **Реализация:** `index_kd` — индекс `k`-мерного массива по векторам размеров и индексов (параметр порядка: row-major/column-major); `index_2d` — частный случай для `d = 2`
* **Связь:** ссылочные структуры со страйдом используются в матрицах (линейная алгебра) и изображениях (раздел «картинки»)

### **1.3. Расположение в памяти (locality of reference) и пулы аллокации**
* **Определение:** локальность — обращения к близким адресам выполняются быстрее: кэш-линия (обычно 64 байта) подтягивает соседние элементы за одну загрузку, TLB ускоряет доступ к близким страницам
* **Последовательный обход массива:** максимальная пространственная локальность (каждый следующий элемент — уже в кэше); обход списка на указателях — случайные прыжки по памяти
* **Пуловый аллокатор (пул страниц / арена):** заранее выделенный блок памяти раздаётся по элементам за O(1) без системных вызовов и без фрагментации; «удаление» — возврат индекса в свободный список
* **Почему для олимпиад:** массовые вставки/удаления через `malloc` медленны и недетерминированы; арена фиксированного размера — константное время на аллокацию
* **Обобщение:** размер пула `N` и тип элемента параметрами; арена как общий приём для всех структур с узлами (деревья II, кучи IV)
* **Реализация-эталон:** арена `CursorList` из B.6 (пул узлов + свободный список); здесь фиксируется постановка
* **Связь:** SSO (A.2.2) — частный случай «без аллокаций»; кэш-политики — X

## **2. Динамические массивы**

### **2.1. `std::vector`: рост и амортизация**
* **Определение:** динамический массив — блок памяти `capacity ≥ size`; при переполнении выделяется новый блок и старое содержимое копируется
* **Схема роста:** при `size == capacity` новая ёмкость `capacity' = capacity·f`, фактор роста `f > 1` (практика: `f = 2` — компромисс память/скорость, `f = 1.5` — экономия памяти ценой копий); обобщение: `f` — параметр
* **Амортизация `push_back` = O(1):** суммарная стоимость `n` вставок при росте `f > 1`
  `Σ_{k} capacity_k = Σ_{k} capacity₀·fᵏ = O(capacity₀·f^K / (f−1)) = O(n)` — геометрическая прогрессия: каждая копия приходит «после» `f−1` бесплатных вставок
* **Почему работает:** работает «банковский метод»: каждая вставка платит 1 за себя + `1/(f−1)` в копилку; при росте копилка покрывает копирование (подробный амортизационный анализ — `analysis.md`)
* **Метод `reserve`:** задать `capacity` заранее — избежать копий при известных размерах
* **Сложность:** `push_back` O(1) амортизированно, `pop_back` O(1), доступ O(1), память O(capacity)
* **Пример:** при `f = 2` и стартовой ёмкости 1: ёмкости 1, 2, 4, 8, ... — копий суммарно `n − 1` всего на `n` вставок
* **Реализация:** `DynArray` — демонстрационный динамический массив с параметром фактора роста `f` (методы `push_back`, `pop_back`, `at`, `size`, `capacity`)
* **Связь:** те же оценки для кольцевого буфера (E), очереди на двух стеках (D.3)

### **2.2. Small Vector Optimization (SSO)**
* **Идея:** крошечные объекты не должны аллоцировать кучу: малые `n ≤ k` хранятся прямо в объекте (внутренний буфер), большие — в куче
* **Параметр:** порог `k` (для строк обычно 15–22 байта); переход между режимами — переключение указателя на внутренний буфер
* **Почему важно для олимпиад:** массовое создание мелких строк/векторов (`std::string` с SSO) резко снижает число аллокаций
* **Связь:** `std::string` — динамический массив символов с SSO (подробно — `string.md`)

# **B. СПИСКИ И ЦЕПОЧКИ**

## **1. Односвязные списки (Singly Linked List)**
* **Определение:** цепочка узлов, каждый хранит значение и ссылку на следующий; доступ только с головы
* **Фундаментальные операции:** вставка в голову O(1), вставка после данного узла O(1), удаление после узла O(1), поиск O(n), вставка в хвост O(n) (без хвостового указателя)
* **Построение из последовательности:** прямая сборка (новая голова) или с хвостовым указателем; обход — шаг по `next`
* **Print Reverse:** рекурсия (стек вызовов) или явный стек — способ переворота вывода
* **Middle Element:** два указателя «быстрый и медленный»: при `fast` с шагом 2, `slow` оказывается в середине — O(n), O(1)
* **Has Loop / Floyd's Cycle Detection:** «заяц и черепаха» встречаются ⟺ есть цикл; длина цикла и вход в цикл — дополнительный проход после встречи
* **Реализация:** структура узла `SNode`; функции `slist_build`, `slist_print`, `slist_print_reverse`, `slist_middle`, `slist_has_loop` (построение, печать в прямом/обратном порядке, середина, петля)
* **Связь:** базовая структура для стека (C.1) и курсорных списков (B.6); `std::forward_list` — односвязный список STL с семантикой операций
* **Применение:** смежные списки графов (`graph.md`), окна алгоритмов на указателях

## **2. Двусвязные списки (Doubly Linked List)**
* **Определение:** узел с двумя связями (`prev`, `next`) — обход в обе стороны, удаление без знания предыдущего
* **Операции:** вставка/удаление по позиции за O(1) при наличии указателя на узел; `prepend/append`
* **Вариант «Doubly Linked List Two»:** обобщение — кольцевой двусвязный список с сентинельным узлом (упрощает граничные случаи); параметризация на `k` списков в омни-структуре
* **Реализация:** `DNode`, класс `DList` (вставка/удаление/печать в обе стороны, pop с обоих концов)
* **Связь:** фундамент LRU-кэша (X) и deque (D.5); `std::list` — двусвязный список STL

## **3. Кольцевые списки (Circular Linked List)**
* **Определение:** хвост ссылается обратно на голову — из любого узла достижимы все
* **Операции:** вставка в кольцо (после узла), удаление узла, поворот (сдвиг головы), слияние двух колец за O(1)
* **Список с хвостовым указателем (`tail`):** храним ссылку и на голову, и на хвост — `push_back` и `append` двух списков за O(1)
* **Почему кольцо:** календарные/циклические процессы (RR-планировщик), как внутренняя форма deque
* **Сложность:** вставка/удаление по узлу O(1), поиск O(n)
* **Реализация:** `CircularList` на указателях (добавление, удаление, поворот, печать; переиспользует узел `SNode` из B.1), `TailList` (`push_back` и `append` за O(1))
* **Связь:** кольцевой буфер — E.1 — та же идея на массиве

## **4. XOR Linked List (память-эффективный)**
* **Определение:** в двусвязном списке хранится одно поле `both = ptr(prev) XOR ptr(next)` — второй сосед восстанавливается из текущего и `both`
* **Почему работает:** XOR-свойство: `prev = both XOR next` — при обходе знаем один сосед, восстанавливаем другой
* **Границы:** обход только с известного конца (с головы или с хвоста); невозможность случайного доступа в середину; ограничения на выравнивание указателей
* **Сложность:** O(1) памяти на узел (одно поле вместо двух), операции те же
* **Реализация:** `XorList` — обход с головы, вставка головы
* **Связь:** экономия памяти — тема X (суккентные структуры)

## **5. Unrolled Linked List (кэш-эффективный)**
* **Определение:** узлы содержат блоки из `B` элементов (массив) и ссылку на следующий блок; «список» из «страниц»
* **Почему лучше:** O(n/B) узлов — меньше переходов по указателям, лучше кэш-локальность; вставка — сдвиг внутри блока O(B)
* **Обобщение:** параметр размера блока `B` (типично 16–64); балансировка блоков при переполнении/опустошении (разделение/слияние)
* **Сложность:** поиск O(n), вставка O(B + сдвиги)
* **Реализация:** `UnrolledList` (вставка, удаление, поиск, пересборка блоков)
* **Связь:** Chunked Sequence (F.4) — та же блочность в функциональном обличье; rope — `string.md`

## **6. Курсорные списки и арена-память**
* **Определение (курсорный список):** узлы живут в едином массиве, ссылки — индексы массива (курсоры) вместо адресов
* **Определение (арена):** пул узлов фиксированного размера + свободный список — аллокация O(1) без вызова `malloc` и без фрагментации
* **Почему для олимпиад:** индексы сериализуемы, компактны, кэш-дружественны; арена исключает медленные и недетерминированные аллокации; «удаление» — возврат в свободный список
* **Операции:** вставка/удаление/поиск как у указательного; свободный список — стек доступных индексов
* **Обобщение:** размер пула `N` параметром; арена как общий приём для деревьев (II), кучи (IV)
* **Реализация:** `CursorList` — массив узлов `nodes[N]`, голова-индекс, свободный список `free`
* **Связь:** этот приём переиспользуется во всех последующих структурах ветки

## **7. Сложные операции над списками**
* **Merge Two Sorted Lists:** слить две отсортированные цепочки — сравнение голов, приём «сентинельная голова»
* **Is Palindrome:** середина (fast/slow) + разворот второй половины + сравнение; обобщение на k-палиндромность
* **Reverse K Group:** разворот по группам размера `k` (остаток `< k` — без разворота); приём — разворот подотрезка со сцепкой соседей
* **Rotate To The Right:** сдвиг на `k` — найти `k mod n`, отсоединить хвост, прицепить к голове
* **Swap Nodes:** обмен значений или обмен ссылками (осторожно с соседями); параметр — позиции `i, j`
* **Сложность:** все за O(n) времени, O(1) памяти
* **Реализация:** `cursor_merge_sorted`, `cursor_is_palindrome`, `cursor_reverse_k_group`, `cursor_rotate_right`, `cursor_swap_nodes`
* **Связь:** развороты — A.3.10; k-группы — обобщение на k

## **8. Self-Organizing List**
* **Определение:** список сам перестраивается после обращений: Move-to-Front (доступный элемент — в голову) или Transpose (меняется с предшественником)
* **Почему работает:** если доступ к элементам неравномерен (Zipf-распределение), часто используемые — в начале
* **Сложность:** Move-to-Front: доступ O(n), но амортизированно O(log n) для стационарного распределения (частотная эвристика); Transpose — медленнее сходится, но устойчивее к паттернам
* **Обобщение:** параметр эвристики (MTF/Transpose/Counter — счётчики); работа с онлайн-потоком запросов
* **Реализация:** `self_organizing_mtf` — MTF на курсорном списке (последовательность запросов как параметр)
* **Связь:** локальность обращений — идея, родственная кэш-политикам (X) и splay-деревьям (II)

# **C. СТЕКИ (LIFO - LAST IN, FIRST OUT)**

## **1. Базовые реализации**
* **Определение:** LIFO: последний добавленный извлекается первым; операции `push`, `pop`, `top`, `size`
* **Массивный стек:** вектор/фиксированный массив + индекс вершины — O(1) на операцию, кэш-отыгрывает
* **Списочный стек (односвязный):** голова односвязного списка `SNode` (B.1) — O(1), без переаллокаций, но с развитой аллокацией (арена — B.6)
* **Списочный стек (двусвязный):** переиспользует `DList` из B.2 — операции на голове (`push_front`/`pop_front`) — O(1); выбор между односвязным/двусвязным — параметр задачи
* **Два стека в одном массиве:** массив `n`, стек A растёт слева, стек B — справа; переполнение лишь при полном заполнении — суммарно вся ёмкость делится динамически
* **Stack On Pseudo Stack:** стек поверх уже существующего стека: базовый стек хранит элементы, параллельный «псевдо-стек» — метаданные (например, минимумы) — абстракция, из которой строятся Min/Max-стеки (3)
* **Сложность:** все операции O(1)
* **Реализация:** `ArrayStack`, `ListStack` (на `SNode` из B.1), `DLStack` (на `DList` из B.2), `TwoStacks` (один массив, оба направления)
* **Связь:** стек из двух очередей — 2; арена — B.6

## **2. Stack Using Two Queues**
* **Определение:** смоделировать LIFO через две FIFO-очереди
* **Подход:** `push` — кладём в активную очередь; `pop` — переносим все, кроме последнего, во вторую очередь, последний удаляем, очереди меняются местами — O(n)
* **Обратный вариант:** `push` со сдвигом (новый элемент — в голову) — pop за O(1) — выбор за O(n)
* **Сложность:** один из вариантов: push O(1)/pop O(n) или push O(n)/pop O(1)
* **Реализация:** `StackTwoQueues` (оба режима — параметр `fast_push`)
* **Связь:** обратная связка «очередь из двух стеков» — D.3

## **3. Минимум/максимум в стеке (Min/Max/All-Operations Stack)**
* **Определение:** дополнительно поддерживать `getMin()` (или `getMax()`) за O(1)
* **Идея:** «псевдо-стек» метаданных: параллельный стек значений-экстремумов; при `push(x)` в него входит `min(x, prev_min)`; синхронный `pop`
* **Почему работает:** текущий минимум монотонен по глубине — его достаточно хранить в одной копии на уровень
* **All-Operations-Stack:** три стека (значения, минимумы, максимумы) — `getMin` и `getMax` одновременно за O(1)
* **Обобщение:** параметр операции (min/max); обобщение на сумму/произведение текущего состояния; на очередь — D.3 (и в dynamic J)
* **Сложность:** все операции O(1) времени, O(n) памяти
* **Пример:** `push 3,1,2` → min-стек: `3,1,1`; после `pop` минимум снова 3
* **Реализация:** `MinMaxStack` (на трёх стеках)
* **Связь:** Persistent Stack — раздел VII; то же на deque — D.7

## **4. Монотонный стек**
* **Определение:** стек, в котором значения строго монотонны (возрастают/убывают по выбранной метрике); при нарушении — элементы выталкиваются
* **Ключевое свойство:** каждый элемент входит в стек один раз и выходит один раз — суммарно O(n) на весь массив
* **Применения (все параметризуются предикатом):** ближайший следующий больший/меньший, ближайший предыдущий больший/меньший; пары «кто следующий выше»
* **Алгоритм (для next greater):** идём справа налево, выталкиваем меньшие — вершина после выталкивания — искомый; вариант слева направо — поддержание убывающего стека
* **Сложность:** O(n) времени, O(n) памяти
* **Реализация:** `mono_scan` — единый движок с параметрами (направление, greater/less, строгость) → обёртки `nge`, `nse`, `pge`, `pse`
* **Связь:** приложения 5–6 ниже; очередь-аналог — D.7

# **D. ОЧЕРЕДИ (FIFO - FIRST IN, FIRST OUT)**

## **1. Базовые реализации**
* **Определение:** FIFO: первый добавленный извлекается первым; операции `enqueue`, `dequeue`, `front`, `size`
* **Массивная очередь:** два индекса (голова/хвост); при достижении конца массива — сдвиг или кольцо (см. 2); параметр ёмкости `cap`
* **Списочная очередь:** головной узел для `dequeue`, хвостовой для `enqueue` — обе операции O(1)
* **Queue On Pseudo Stack:** очередь поверх пары «псевдо-стеков» — предшественник D.3 (два стека)
* **Сложность:** все операции O(1)
* **Реализация:** `ArrayQueue` (кольцевое использование массива), `LinkedQueue`
* **Связь:** Producer-Consumer

## **2. Кольцевая очередь (Circular Queue)**
* **Определение:** массив используется кольцом: `tail = (tail + 1) mod cap`; голова и хвост «догоняют» друг друга
* **Состояния:** пусто — `head == tail`; полно — `(tail + 1) mod cap == head` (одна ячейка запаса) или счётчик размера (`size`), параметр — выбор стратегии
* **Варианты:** `Circular Queue` (фиксированная), на списке — связные версии; расширяемая — при заполнении копирование в больший массив (амортизация — A.2)
* **Сложность:** O(1) на операцию
* **Реализация:** `CircularQueue` (параметры cap, счётчик размера)
* **Связь:** кольцевой буфер (E.1) — то же со сценарием перезаписи

## **3. Очередь из двух стеков (Queue By Two Stacks)**
* **Определение:** FIFO на двух LIFO-стеках: in-стек для `enqueue`, out-стек для `dequeue`
* **Идея:** при пустом out-стеке — переливаем все элементы из in (порядок инвертируется → FIFO)
* **Амортизация:** каждый элемент дважды перемещается (в out и из out) — O(1) амортизированно на операцию; та же оценка, что у вектора (A.2)
* **Связь с Banker's Queue (F):** та же идея с «физическим» и «логическим» представлениями
* **Реализация:** `QueueTwoStacks` (переливная дисциплина: переливание только при пустом out-стеке)
* **Связь:** обращения стек↔очередь — C.2; персистентная версия — VII

## **4. Приоритетная очередь на списке (Priority Queue Using List)**
* **Определение:** очередь, из которой извлекается максимальный (минимальный) элемент — примитивная приоритетная очередь на линейном списке; полные реализации (кучи) — раздел IV
* **Режим A (несортированная):** вставка в голову O(1); извлечение экстремума — проход по списку O(n)
* **Режим B (сортированная):** вставка в позицию, сохраняющую порядок, O(n); извлечение экстремума с головы O(1) (порядок подстраивается под направление экстремума)
* **Обобщение:** параметр режима (A/B) и направление экстремума (max/min — параметр сравнения); переход к куче (IV) — когда нужны обе операции быстрые
* **Сложность:** одна из операций O(1), другая O(n) — асимметрия, снимаемая в IV
* **Реализация:** `PriorityQueueList` (параметр режима A/B и направления экстремума; переиспользует узел `SNode` из B.1)
* **Связь:** мост в IV (бинарная куча — O(log n) на обе операции); Bucket Queue (D.8) — диапазонные приоритеты

## **5. Деки (Deque — Double Ended Queue)**
* **Определение:** двусторонняя очередь: `push/pop` с обоих концов — все O(1)
* **Кольцевой массив:** головной и хвостовой указатели с `mod cap` — `CircularDeque`
* **Кольцевой список:** двусвязное кольцо — `DequeDoubly` (переиспользует `DList`, B.2)
* **`std::deque`:** карта блоков + блоки фиксированной длины — вставка на краях O(1), произвольный доступ O(1) (два уровня индексации), кэш-локальность средняя; обобщение — параметр размера блока
* **Catenable Deque:** конкатенация деков — наивно O(n); эффективно — через Finger Tree (F.1)
* **Ограниченные деки (Deque с ограниченными операциями):** input-restricted (вставка только слева, извлечения с обеих сторон) / output-restricted (извлечение только слева) — подклассы для задач планирования
* **Сложность:** базовые операции O(1)
* **Реализации:** `CircularDeque` (массив, параметр cap; схема «проверка-откат» — фактическая ёмкость cap−1, как в D.2), `DequeDoubly` (список)
* **Связь:** монотонная очередь (6) строится на деке; std::deque — the swiss army container

## **6. Стеко-очередь (Steque)**
* **Определение:** структура «стек с очередью на конце»: `push`/`pop` на одном конце (LIFO-сторона), `enqueue` на другом
* **Реализация:** двусвязный список с обоими концами; операции O(1)
* **Применение:** гибридные планировщики, обходы с локальным шагом
* **Реализация:** `Steque` (переиспользует `DList`, B.2)
* **Связь:** варианты контейнеров — семейство, обобщаемое пальцевыми деревьями (F.1)

## **7. Монотонная очередь**
* **Определение:** deque, в которой значения на одной стороне строго монотонны; при вставке новые элементы выталкивают «старые худшие» с противоположного правила
* **Построение (окно max длины k):** перед вставкой выталкиваем с хвоста все `≤` нового (они никогда не станут максимумом, пока новое окно живёт); голова — максимум; при выходе из окна — удаление с головы
* **Почему корректно:** вытолкнутый элемент «хуже» нового и по значению, и по времени жизни — он не может стать ответом
* **Применение:** Sliding Window Maximum/Minimum из A.3.14 — теперь O(n) на все окна; оптимизация интервального ДП (переход только из окна) — `dynamic.md` (J)
* **Обобщение:** параметр окна `k`, параметр max/min (обёртки над единым движком); обобщение на ленивое окно (по времени — E.2)
* **Сложность:** каждый элемент входит и выходит один раз — O(n) суммарно
* **Пример:** `a = [1,3,-1,-3,5]`, `k = 3` → максимумы `3, 3, 5`
* **Реализация:** `sliding_window_extrema` (движок + обёртки `sliding_max`, `sliding_min`)
* **Связь:** близнец монотонного стека (C.4); буферы скользящего окна (E.2)

## **8. Специализированные очереди**
* **Catenable Queue:** объединение очередей за O(1)/O(log n) — решение через Finger Tree (F.1) или дерево сегментов; наивно — O(n)
* **Calendar Queue:** очередь дискретных событий с ячейками по времени (воронка времени) — вставка/взятие следующего события около O(1) ожидаемо; применяется в дискретно-событийных симуляциях
* **Bucket Queue:** приоритеты из малого диапазона `P` — массив бакетов (deque по приоритету): вставка O(1), извлечение максимума — поиск следующего непустого бакета; обобщение — параметр числа бакетов; мост в IV (Radix Heap)
* **Banker's Queue / Physicist's Queue:** функциональные очереди из двух стеков с амортизационными доказательствами (банковский/физический методы) — персистентные версии D.3
* **Hood-Melville Queue:** real-time вариант: переливание выполняется «лениво», по элементам при каждой операции — наихудшее время O(1) (без амортизации)
* **Bootstrapped Queue:** рекурсивная конструкция «очередь из очередей» (bootstrap) — основа функциональных источниках
* **Сложность:** Bucket Queue: O(1) вставка, O(P) поиск максимума / O(1) с бегунком
* **Реализация:** `BucketQueue` (параметр числа приоритетов)
* **Связь:** Radix Heap — IV; Catenable — F.1; real-time потоки — IX

# **E. СПЕЦИАЛИЗИРОВАННЫЕ БУФЕРЫ**

## **1. Кольцевые буферы (Ring / Circular Buffers)**
* **Определение:** кольцевой массив фиксированной ёмкости `cap` с головой и хвостом; два режима: блокирующий (запись при полном буфере — ждать/ошибка) и перезаписывающий (overwriting — новые данные вытесняют старые)
* **Fixed-size:** классические producer-consumer очереди сообщений
* **Overwriting:** телеметрия, логи «последние N событий», кэш скользящих данных
* **Сложность:** O(1) на операцию
* **Реализация:** `RingBuffer` (параметр cap и флаг `overwrite`)
 * **Связь:** CircularQueue (D.2) — полный набор операций

## **2. Буферы скользящего окна**
* **Count-based sliding window:** окно последних `k` элементов: кольцевой буфер + агрегат (сумма — поддерживается вычитанием выходящего); Moving Average — среднее = сумма/`k`
* **Time-based sliding window:** события `(t, value)`; окно длины `τ`: агрегат поддерживается выталкиванием протухших событий по времени — два указателя по отсортированным по `t` событиям
* **Exponential Moving Average (обобщение):** `ema' = α·x + (1−α)·ema` — веса убывают экспоненциально; параметр `α ∈ (0,1)`
* **Обобщение:** агрегат как параметр (сумма, произведение, min/max — для min/max монотонная очередь D.7)
* **Сложность:** O(1) на событие
* **Реализации:** `MovingAverage` (count-based c окном `k`), `time_sliding_sum` (time-based, окно `τ`; события — тип `TimeEvent {t, val}`)

# **F. ГИБРИДНЫЕ, ФУНКЦИОНАЛЬНЫЕ И ЛЕНИВЫЕ СТРУКТУРЫ**

## **1. Finger Tree (обобщённые последовательности)**
* **Определение:** дерево с «пальцами» (голова/хвост хранятся отдельно), узлы — моноиды-агрегаты
* **Возможности:** конкатенация, разделение, индексация — амортизированно O(log n); константно‑лучшие константы, чем у дерева отрезков
* **Почему выделяется:** единая структура даёт deque, упорядоченные последовательности, приоритетные очереди (через агрегат-моноид)
* **реализация:** считается тяжёлой (функциональные трюки с типами) — в конспекте даётся описание и связи; практические категории — Catenable Deque (D.5) и Catenable Queue (D.8)
* **Связь:** Catenable (D.8), Chunked (F.4), RRB (F.2)

## **2. RRB-Vector (Relaxed Radix Balanced Vector)**
* **Определение:** персистентный вектор с радикс-балансировкой (32-поток-деревья); операции O(log₃₂ n + «релаксация»)
* **Возможности:** вставка/удаление в середине, конкатенация; копирование с изменением (path copying) — персистентность
* **Почему:** логарифм с основанием 32 на практике — константа; эффективная память
* **Связь:** персистентные векторы — VII; rope конкатенации в `string.md`

## **3. Zipper**
* **Определение:** функциональная структура с «фокусом» — текущим элементом — и контекстом (все позиции до/после в виде стеков)
* **Операции:** `left/right` — перемещение фокуса (O(1)), `insert_at/move/modify/delete_at` — локальные правки без копирования всего (персистентность)
* **Почему:** навигация по дереву/списку без разрушения — будущие состояния делимы
* **Обобщение:** зиппер списка (здесь) и дерева (II) — одна схема «фокус + контекст»
* **Реализация:** `ListZipper` (фокус, левые/правые как обратные стеки)
* **Связь:** стеки контекста — C; VII (персистентные правки)

## **4. Chunked Sequence**
* **Определение:** последовательность из блоков фиксированного размера `B` — «массив массивов»; блочность для кэша
* **Операции:** поиск по блокам, вставка — сдвиг/разделение блока, удаление — схлопывание; пересборка при деградации
* **Сложность:** вставка O(B), поиск O(n) (или O(log(n/B)) при словаре блоков), память O(n)
* **Реализация:** `ChunkedSeq` (параметр `B`)
* **Связь:** Unrolled List (B.5); rope (string.md)

## **5. Ленивые вычисления (Lazy Evaluation)**
* **Thunk:** отложенное вычисление — функция‑замыкание, вычисляемое при первом обращении (с мемоизацией результата)
* **Promise:** контракт будущего значения
* **Stream/Generator:** ленивые бесконечные последовательности: следующий элемент порождается по требованию; классика — числа Фибоначчи «по требованию»
* **Почему:** экономия вычислений, поддержка бесконечных структур, композиция без материализации
* **Реализация:** `Thunk` (шаблон отложенного вычисления с мемоизацией при первом обращении), `LazyFibStream` (итератор-генератор: `hasNext`/`next` порождают члены по требованию; параметр — число членов)
* **Связь:** мемоизация (6); ленивое ДП — `dynamic.md` (I)

## **6. Мемоизация и кэширование**
* **Определение:** запоминание результатов чистых функций — каждое состояние считается один раз
* **Memoization Tree:** дерево вызовов с кэшем узлов — структурная мемоизация
* **Таблицы ДП как деревья:** таблица состояния = кэш-структура (массив/дерево) — мост между ДП и структурами данных
* **Реализация:** `MemoizedFn` — общая обёртка для функций с одним целочисленным аргументом (map-кэш); `MemoizedFib` — мемоизация чисел Фибоначчи; канонические примеры ДП — `dynamic.md` (раздел A: `fib_memo`)
* **Связь:** ДП (dynamic), кэш-политики (X)
