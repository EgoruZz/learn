# **Основные понятия и принципы**

* **Что это:** структуры, сохраняющие прошлые состояния: каждая операция порождает новую версию, старые остаются читаемыми (частичная персистентность) и даже модифицируемыми (полная) или сливаемыми (конфлюэнтная); общий приём — path copying: неизменяемые узлы, при изменении копируется только путь от корня, остальное разделяется между версиями
* **Почему выделяется в отдельный класс:** обычные структуры уничтожают прошлое при модификации; персистентные решают задачи «истории»: k-я порядковая статистика на отрезке офлайн (B.2), запросы к произвольным моментам времени (B.3), откаты без пересоздания (D.1), версии для ДП и графов (мосты в `dynamic.md`, `graph.md`); логарифмическая цена — память O(log n) на изменение
* **Ключевые принципы:** неизменяемость узлов — версии разделяют поддеревья (A.2); версия = корень — дерево версий (A.1); разность версий — спуск по двум корням (B.2); журнал изменений — откат в обратном порядке (D.1); версия = узел списка — O(1) на изменение (D.2); две неизменяемые половины — очередь (D.3); хребет + блоки — память O(B) на изменение (G.1)
* **Как распознать:** «k-я порядковая статистика на отрезке» (офлайн, частоты) — PST (B.2); «запросы к прошлым состояниям», «история изменений» — PST (B.3), персистентный treap (C.1); «откатиться к снимку» — Rollback DSU (D.1); «версии стека/очереди» — D.2, D.3; «функциональные, иммутабельные структуры» — G; «обновить состояние в момент t» — полная персистентность (E)
* **Границы:** память — O(log n) (B, C) или O(√n) (G.1) на изменение против O(n) при полном копировании; откаты (D.1) — только к снимкам в порядке стека, не к произвольным версиям; частичная персистентность не позволяет модифицировать старые версии (E — полная); конфлюэнтность (F) — DAG версий, память растёт с числом слияний; B.2 требует офлайн-диапазон значений (сжатие координат — II)

# **A. ОСНОВЫ ПЕРСИСТЕНТНОСТИ**

## **1. Классификация (частичная / полная / конфлюэнтная)**
* **Определение:** частичная персистентность — чтение старых версий, модификация только последней (граф версий — цепочка); полная — модификация любой версии (граф — дерево); конфлюэнтная — дополнительно слияние версий (граф — DAG)
* **Идея:** версия — состояние после последовательности операций; форма графа версий отражает доступные переходы: цепочка — только «вперёд», дерево — ветвление, DAG — слияние
* **Почему работает:** любой способ доступа реализуется неизменяемыми узлами (path copying); различия — какие корни можно продолжать и комбинировать
* **Сложность:** частичная — O(log n) памяти на изменение; полная — то же (корень любой версии продолжается); конфлюэнтная — O(log n) на слияние, память зависит от разделения поддеревьев
* **Обобщение:** уровень персистентности выбирается задачей: история запросов — частичная; ветвление сценариев — полная; слияние данных — конфлюэнтная
* **Реализация:** анализ; частичная — PST (B.1), PersistentDSU (III.A.7); полная — PersistentArray (A.2), PersistentStack (D.2); конфлюэнтная — merge версий treap (F.1)
* **Связь:** откаты (более слабый приём — только стек снимков) — D.1; время как координата — VI.B.2

## **2. Persistent Array (path copying) — базовый примитив**
* **Определение:** массив с версиями: `set_value(v, pos, x)` → новая версия; `get(v, pos)` — значение в любой версии; обновление копирует путь от корня до листа (O(log n) новых узлов), остальные поддеревья разделяются
* **Идея:** двоичное дерево над [0, n): версия = корень; копируется путь — старые узлы не трогаются; разделяемые поддеревья безопасны по неизменяемости
* **Почему работает:** любая версия — валидное дерево: её путь не пересекается с изменёнными (те — новые узлы); get — спуск по версии O(log n)
* **Сложность:** set — O(log n) времени и памяти; get — O(log n); суммарная память O(n + V·log n), V — число версий
* **Обобщение:** примитив всех персистентных структур: агрегат в узлах — PST (B.1); неявное дерево — treap (C.1); блочный вариант (хребет) — G.1
* **Реализация:** `PersistentArray` — частный случай готового `PersistentSegmentTree` (V.D.11): точечный доступ query(p, p + 1); версии — список корней
* **Связь:** path copying vs Fat Node — A.3; дерево отрезков — V.D.11

## **3. Path Copying против Fat Node**
* **Определение:** path copying — при изменении копируется путь (неизменяемые узлы, O(log n) памяти на операцию); Fat Node — каждый узел хранит список пар (версия, значение): запись добавляет пару, чтение — последняя запись ≤ v
* **Идея:** path copying платит глубиной (копии), Fat Node — историей узла (записи); чтение в Fat Node — бинарный поиск по версиям
* **Почему работает:** trade-off память/время: path copying — O(log n) памяти и времени; Fat Node — O(1) памяти на запись, O(log история) на чтение
* **Сложность:** path copying — O(log n) на операцию; Fat Node — O(log h) на чтение (h — число записей в узле), O(1) на запись
* **Обобщение:** Fat Node удобен при большой глубине и малом числе версий; ячейки DSU — PersistentDSU (III.A.7)
* **Реализация:** анализ; примеры — `PersistentSegmentTree` (V.D.11), `PersistentDSU` (III.A.7)
* **Связь:** PersistentDSU — III.A.7; откаты — D.1 (стек вместо хронологий)

# **B. ПЕРСИСТЕНТНОЕ ДЕРЕВО ОТРЕЗКОВ**

## **1. Persistent Segment Tree (копирование пути)**
* **Определение:** дерево отрезков с версиями: точечное обновление копирует путь (O(log n) новых узлов), запрос — по любой версии O(log n)
* **Идея:** схема A.2 с агрегатом в узле: версия = корень; query(root_v, l, r) — обычный спуск; агрегаты на пути пересчитываются
* **Почему работает:** неизменяемость узлов сохраняет старые версии; копия пути пересчитывает агрегаты только на нём
* **Сложность:** update и query — O(log n); память — O(log n) на версию
* **Обобщение:** агрегат — любая ассоциативная операция (сумма, min/max, gcd); частотное применение — B.2; снимки истории — B.3
* **Реализация:** готовая `PersistentSegmentTree` (V.D.11) — используется напрямую, нового кода нет
* **Связь:** Persistent Array — A.2; дерево отрезков — V.D.11; персистентность в ДП — мост в `dynamic.md`

## **2. Приложение: k-я порядковая статистика на отрезке**
* **Определение:** частотное PST: версия roots[i] — счётчики значений префикса [0, i); k-е значение на [l, r) — спуск по паре корней (root_r, root_l)
* **Идея:** разность версий: счётчик значения v на [l, r) = cnt_r(v) − cnt_l(v); спуск: влево, пока счётчик левого поддерева ≥ k, иначе — вправо с вычитанием
* **Почему работает:** префиксные версии — персистентный аналог префиксных сумм (V.A): распределение на отрезке = разность двух префиксов
* **Сложность:** построение O(n log σ), запрос O(log σ), σ — диапазон значений; память O(n log σ)
* **Обобщение:** count ≤ x (rank) — тем же спуском; сжатие координат при больших σ (II); версии как окна — сочетание с Мо с обновлениями (VI.B.2)
* **Реализация:** `PersistentSegmentTreeKth` — поверх готового `PersistentSegmentTree` (V.D.11), kth-спуск по пулу
* **Связь:** префиксные суммы — V.A; k-я статистика — Merge Sort Tree (V.E.5), Wavelet Tree (II.G.1), PersistentMap (G.2)

## **3. Приложение: запросы по истории**
* **Определение:** каждая версия — снимок состояния; запрос «каким было состояние в момент t» — обычный запрос к корню t за O(log n)
* **Идея:** корни версий хранятся списком; история — последовательность снимков, любой доступен
* **Почему работает:** версии неизменяемы и независимы; момент t соответствует корню, созданному после t операций
* **Сложность:** O(log n) на запрос к любой версии; O(log n) памяти на версию
* **Обобщение:** задачи «до/после операции», персистентный DSU (III.A.7), версионные значения для ДП и графов (мосты в `dynamic.md`, `graph.md`)
* **Реализация:** на готовом `PersistentSegmentTree` (V.D.11) — список корней
* **Связь:** PersistentDSU — III.A.7; время как координата — VI.B.2

# **C. ПЕРСИСТЕНТНОЕ ДЕКАРТОВО ДЕРЕВО**

## **1. Persistent Treap (split/merge без модификации старых версий)**
* **Определение:** декартово дерево с версиями: split/merge клонируют узлы на пути спуска — старые корни остаются корректными; insert/erase возвращают новый корень
* **Идея:** те же примитивы split/merge (II.F), но вместо модификации узла — его копия; приоритеты — детерминированный генератор (II.F)
* **Почему работает:** клонирование пути — O(log n) новых узлов в среднем; разделяемые поддеревья неизменяемы; порядок и размеры на копиях пересчитываются
* **Сложность:** insert/erase/kth/rank — O(log n) в среднем; память O(log n) на операцию
* **Обобщение:** неявный персистентный treap — персистентные последовательности (мост в `string.md`); ключ-значение — G.2; merge версий — конфлюэнтность (F.1)
* **Реализация:** `PersistentTreap` (пул узлов {key, pr, sz, l, r}; split/merge клонируют; приоритеты `next_priority` (II.F); insert существующего ключа — без изменений — set-семантика)
* **Связь:** Treap — II.F.1; PST — B.1; Persistent Map — G.2; деревья разбора — мост в IX

# **D. СТРУКТУРЫ С ОТКАТАМИ**

## **1. Rollback DSU (стек изменений + откат)**
* **Определение:** DSU с откатами: перед изменением старое значение пишется в стек; snapshot — длина стека; rollback_to(snap) — восстановление обратным проходом
* **Идея:** сжатие путей запрещено (пишет в прошлое), union by size сохраняет O(log n); каждая запись — (индекс, старое значение)
* **Почему работает:** откат в обратном порядке записей возвращает ячейки к прежним значениям; маркеры no-op сохраняют парность
* **Сложность:** unite/find — O(log n); rollback — O(число изменений после снимка)
* **Обобщение:** журнал изменений — любой структуры; офлайн-запросы с откатами — мост в `technique.md`; мост к Мо (VI.B)
* **Реализация:** готовая `RollbackDSU` (III.A.6) — используется напрямую
* **Связь:** PersistentDSU — III.A.7 (хронологии вместо стека); откаты и персистентность — A.1

## **2. Persistent Stack (списки версий)**
* **Определение:** стек с версиями: версия = индекс вершины односвязного списка; push создаёт новый узел, pop — переход по next; старые версии неизменяемы
* **Идея:** path copying на списке: пул узлов {value, next}; 0 — пустой стек; push(v, x) — новый узел со next = v
* **Почему работает:** узлы неизменяемы; версии разделяют хвосты; pop — O(1) без копирования
* **Сложность:** push/pop/top — O(1); память O(1) на push
* **Обобщение:** полностью персистентен по построению (любую версию можно продолжать — E.1); основа очереди (D.3); версии-индексы — мотив списков версий в технике
* **Реализация:** `PersistentStack` (пул узлов {val, next})
* **Связь:** очередь — D.3; полная персистентность — E.1; скобочные последовательности — мост в `string.md`

## **3. Persistent Queue (реализация на двух стеках)**
* **Определение:** очередь на двух персистентных стеках (D.2): front — начало, back — перевёрнутый хвост; push — в back, pop — из front
* **Идея:** при пустом front — переворот back в front поэлементным push (O(длина) разово); инвариант: front непуст при непустой очереди
* **Почему работает:** каждый элемент переносится из back в front не более одного раза — амортизированно O(1); обе части неизменяемы — версии корректны
* **Сложность:** O(1) амортизированно на операцию; память O(1) на push
* **Обобщение:** функциональная очередь (G.3) — тот же механизм; двухстековые схемы — мост в I.A
* **Реализация:** `PersistentQueue` (пара стеков `PersistentStack` (D.2))
* **Связь:** стеки — D.2; функциональные структуры — G.3; персистентные списки — мост в `hashing.md` IV

# **E. FULLY PERSISTENT СТРУКТУРЫ**

## **1. Полная персистентность (модификация любой версии)**
* **Определение:** полная персистентность: любая версия доступна для модификации; граф версий — дерево (ветвление)
* **Идея:** path copying автоматически даёт полную персистентность: продолжение любой версии = копирование пути от её корня; Fat Node — временные метки в записях
* **Почему работает:** модификация старой версии не трогает её узлы (копируются новые); остальные ветви не затрагиваются
* **Сложность:** как у базовой структуры — O(log n) на операцию; память O(log n)
* **Обобщение:** PersistentArray (A.2), PersistentStack (D.2), PersistentTreap (C.1) полностью персистентны по построению; ветвление сценариев — задачи «альтернативные истории»
* **Реализация:** анализ + демо на готовых A.2/D.2 (set/push от не-последней версии)
* **Связь:** классификация — A.1; конфлюэнтная персистентность — F.1

# **F. CONFLUENTLY PERSISTENT СТРУКТУРЫ**

## **1. Конфлюэнтная персистентность (слияние версий)**
* **Определение:** конфлюэнтная персистентность: слияние двух версий в новую; граф версий — DAG (общие поддеревья между ветвями)
* **Идея:** слияние — тот же примитив, что и базовая операция: merge декартовых деревьев (C.1), конкатенация списков (D.2)
* **Почему работает:** неизменяемые узлы разделяются между ветвями без копирования; слияние создаёт новый корень над общими поддеревьями
* **Сложность:** merge treap — O(log n); память — O(log n) на слияние плюс разделение
* **Обобщение:** объединение версий данных (параллельные ветки вычислений); DAG версий — память ограничена общими поддеревьями
* **Реализация:** анализ + демо: merge двух версий `PersistentTreap` (C.1) с непересекающимися диапазонами ключей
* **Связь:** полная персистентность — E.1; treap merge — C.1

# **G. FUNCTIONAL СТРУКТУРЫ**

## **1. Persistent Vector (RRB-родственный, мост из I.F)**
* **Определение:** персистентный вектор: версия — «хребет» (массив указателей на блоки) + число элементов; изменение копирует хребет O(n/B) и один блок O(B)
* **Идея:** sqrt-персистентность: блоки неизменяемы и разделяются; копия изменяемого блока — безопасность разделения; push_back — копия последнего блока или новый
* **Почему работает:** хребет и блоки разделяются между версиями; любая операция трогает один блок — память O(B)
* **Сложность:** get — O(1); update/push_back — O(B + n/B) = O(√n) при B = ⌈√n⌉; память O(B) на изменение
* **Обобщение:** сбалансированное дерево хребта (RRB-vector, I.F) — O(log n); refcount-блоки — без копирования при единственной ссылке; персистентные строки — мост в `string.md`
* **Реализация:** `PersistentVector` (пул блоков; B — параметр, ⌈√n⌉ по умолчанию — `ceil_sqrt` (VI))
* **Связь:** RRB-Vector, Finger Tree — I.F; блоки и хвосты — VI.A.1; сукцинктное хранение — III.B.7

## **2. Persistent Map/Set (персистентный treap)**
* **Определение:** персистентное отображение ключ → значение на декартовом дереве: insert/erase возвращают новый корень, find — по любой версии; set — частный случай (значение = ключ)
* **Идея:** те же split/merge, что C.1, узел дополнительно хранит значение; замена значения — split на две границы и вставка нового узла на место старого
* **Почему работает:** path copying — старые версии неизменяемы; порядок по ключу сохраняется
* **Сложность:** O(log n) в среднем на операцию; память O(log n)
* **Обобщение:** rank/kth по ключам — приложения C.1; персистентный красно-чёрный — та же схема path copying (мост в II)
* **Реализация:** `PersistentMap` (пул узлов {key, val, pr, sz, l, r})
* **Связь:** treap — C.1; PST частот — B.2; деревья поиска — II

## **3. Persistent Queue (функциональная, два стека)**
* **Определение:** функциональная очередь — та же конструкция D.3: две неизменяемые части, операция не изменяет вход, а строит новую очередь
* **Идея:** обе половины — персистентные стеки (D.2); push/pop возвращают новую пару, вход остаётся
* **Почему работает:** неизменяемость позволяет переиспользовать хвосты; амортизация — как в D.3
* **Сложность:** O(1) амортизированно на операцию
* **Реализация:** `PersistentQueue` (D.3) — то же
* **Связь:** очередь — D.3; функциональные последовательности (Finger Tree, Zipper) — I.F
