# **Основные понятия и принципы**

* **Что это:** класс структур, организующих множество или последовательность в виде дерева — направленного ациклического графа с одним корнем; ключевая цель — быстрый поиск (и типично вставка/удаление) через сведение полного диапазона к пути к корню
* **Почему выделяется в отдельный класс:** деревья дают O(h) на операцию (h — высота), а балансировка превращает h в O(log n); на одном и том же дереве решаются задачи упорядоченного множества (search/insert/erase/floor/ceil), порядковые статистики (rank/select — G), отрезковые запросы (V) и представления произвольных иерархий (A)
* **Ключевые принципы:** представление в памяти (A) определяет стоимость всех операций (указатели — динамика, курсоры — компактность и сериализуемость, массив — кэш); инвариант поиска (C) — дерево остаётся таким, что сравнение ключа ведёт к одному ребру; инвариант баланса (D) — высота ограничена логарифмом, что и даёт гарантии; вероятностная геометрия (F) — случайный приоритет даёт ожидаемый баланс без явной балансировки
* **Как распознать:** нужны динамические упорядоченные множества (std::set-задачи), префиксные статистики, иерархические структуры, отрезковые запросы с обновлениями — всё это деревья; фиксированная вселенная и только поиск — хеш-таблицы (`hashing.md`)
* **Границы:** без балансировки высота BST деградирует до O(n) на отсортированных вставках; деревья не заменяют хеш-таблиц для равенства-задач; многопутевые (E) выигрывают на диске (B+) и в кэш-линиях, но сложнее реализуются

# **A. ПРЕДСТАВЛЕНИЯ ДЕРЕВЬЕВ В ПАМЯТИ**

## **1. Узлы с указателями**
* **Определение:** каждый узел — структура `{val, left, right}` (указатели/ссылки); пустое поддерево — `nullptr`
* **Почему для олимпиад:** естественная динамика — вставка/удаление локальны (пересвязывание указателей), рекурсивные алгоритмы переносятся в код один в один
* **Цена:** каждый узел аллоцируется в куче — недетерминированное время, фрагментация, плохая кэш-локальность
* **Обобщение:** `TreeNode` — единая форма узла для B/C/D/F; для типов с разными ключами — параметризация полем
* **Реализация:** `TreeNode` (val, left, right; конструктор от значения)
* **Связь:** арена (A.3) снимает цену аллокаций; `string.md` (rope) — узлы-блоки

## **2. Бинарное дерево в массиве (куча-индексация)**
* **Определение:** полное бинарное дерево хранится в массиве: корень — `a[0]`, левый ребёнок `i` — `a[2i+1]`, правый — `a[2i+2]`, родитель — `a[(i-1)/2]`
* **Почему работает:** полное заполнение уровней слева направо гарантирует, что индексная арифметика держит все связи — без указателей вовсе
* **Сложность:** доступ к родителю/детям O(1), память — плотный массив (максимальная кэш-локальность)
* **Обобщение:** требование полноты — не всякое дерево так хранится; годится для куч (IV) и внешнеплоских структур
* **Реализация:** `HeapIndexedTree` (построение из вектора, `left/right/parent`, обходы за счёт индексов), `is_complete_from_array`
* **Связь:** бинарная куча (IV.D) и дерево отрезков (V.D) — прямые наследники представления

## **3. Арена и курсорные деревья (индексы вместо указателей)**
* **Определение:** узлы живут в фиксированном массиве-арене, ссылки на детей — индексы массива (курсоры); свободные индексы — в свободном списке
* **Почему для олимпиад:** аллокация узла — O(1) из свободного списка (без `malloc`); узлы сериализуемы (индексы стабильны), компактны и кэш-дружественны — мост из I.B (`CursorList`)
* **Обобщение:** размер арены `N` параметром; тот же приём в кучах (IV) и персистентных деревьях (VII)
* **Реализация:** `CursorTree` (массив узлов `{val, left, right}` + свободный список; `alloc/free`, вставки/удаления как в указательском варианте)
* **Связь:** арена-память — «общий приём» ветки, заложенный в `LinearStructures` (a.cpp, I.B)

## **4. Parent Array (массив родителей)**
* **Определение:** для корневого дерева хранится `parent[v]` — предок каждой вершины (у корня — −1); дети находят обходом
* **Почему работает:** достаточно для подъёмов (LCA-заделы), подсчёта глубин и ДП на дереве; экономит память (одно поле на вершину)
* **Сложность:** O(n) построение по рёбрам, O(1) доступ к предку; подъём на k — O(k) наивно, O(log n) двоичными подъёмами (B.10)
* **Обобщение:** параметр — направление (parent/children); векторизация глубин для ДП на дереве (`dynamic.md` G)
* **Реализация:** `ParentArray` (построение из списка рёбер, `depth`, `kth_ancestor` — наивный и двоичные подъёмы)
* **Связь:** двоичные подъёмы — полный разбор в `graph.md` (LCA); ДП на деревьях — `dynamic.md` (G)

## **5. First-child / next-sibling (первый ребёнок — следующий брат)**
* **Определение:** n-арное дерево кодируется бинарно: у каждого узла два поля — `first_child` и `next_sibling`; обход детей — шаги по `next_sibling` от `first_child`
* **Почему работает:** произвольная арность без массивов детей; обход n-арного дерева сводится к обходам бинарного (left = первый ребёнок, right = следующий брат)
* **Сложность:** память 2 указателя на узел независимо от арности; поиск k-го ребёнка — O(число детей)
* **Обобщение:** преобразование «массив детей ↔ FCNS» — прямой и обратный
* **Реализация:** `FCNS` (узел `{val, first_child, next_sibling}`; построение из списка «родитель→дети», обход в глубину, преобразование в бинарное представление `to_binary` и обратно `from_binary`)
* **Связь:** левый сдвиг/правый сдвиг — те же повороты, что в BST (C.6); представления деревьев в графах — `graph.md`

## **6. Нитяные деревья (Threaded Binary Tree)**
* **Определение:** «пустые» правые указатели несут ссылку на inorder-преемника (нитку); левые пустые — на предшественника; обход без стека и без рекурсии
* **Почему работает:** нить реконструирует потерянный маршрут — inorder-обход становится линейным перешагиванием
* **Сложность:** O(n) обход, O(1) дополнительной памяти; вставка/удаление должны поддерживать нити
* **Обобщение:** morris-обход (A.7) — тот же приём «временная нить» без постоянного хранения
* **Реализация:** `ThreadedTree` (флаги `has_left/has_right` thread; inorder без стека)
* **Связь:** мост к Morris (следующий пункт); нити — приём, родственный нитям в графах

## **7. Morris Traversal**
* **Определение:** inorder (и preorder) за O(n) времени и O(1) памяти: временная нить от inorder-предшественника к текущему узлу, которая стирается при возврате
* **Идея:** при спуске в правое поддерево запоминаем его inorder-предшественника (самый правый узел левого поддерева): идём влево, пока есть левый ребёнок; если нить уже есть — печатаем и восстанавливаем исходное дерево (обрезаем нить)
* **Почему корректно:** каждый узел посещается дважды (до и после нити), дерево к концу восстановлено в исходном виде
* **Сложность:** O(n) времени (каждая нить строится и стирается один раз), O(1) памяти — рекорд по памяти среди обходов
* **Обобщение:** preorder-версия той же идеи; на нитяных деревьях (A.6) обход ещё проще
* **Реализация:** `morris_inorder(TreeNode*)`, `morris_preorder(TreeNode*)` — методы классы работают с `TreeNode*`
* **Связь:** преемник/предшественник — нити; приём «временная модификация структуры» появляется и в алгоритмах на графах

# **B. БАЗОВЫЕ БИНАРНЫЕ ДЕРЕВЬЯ**

## **1. Построение и терминология**
* **Определение:** бинарное дерево — каждый узел с 0–2 детьми; типовые конструкции: полное, совершенное, сбалансированное по высоте; размер, глубина, высота, листы
* **Почему для олимпиад:** база всех древовидных решений; построение из массива (уровневый порядок, A.2) — стандартный вход задач
* **Сложность:** построение O(n)
* **Реализация:** `build_from_level_order` (массив levels → `TreeNode*`), `height`, `count_nodes`, `count_leaves`
* **Связь:** представления — раздел A

## **2. Обходы (рекурсивные)**
* **Определение:** inorder (Л-К-П), preorder (К-Л-П), postorder (Л-П-К) — три канонических порядка; DFS-семейство (левый и правый ребёнок — «соседи»)
* **Почему важно:** preorder — сериализация до/после (B.11), inorder в BST даёт отсортированную последовательность (C.3), postorder — естественный порядок для ДП на дереве (`dynamic.md` G) и удалений
* **Сложность:** O(n) времени, O(h) стека (h — высота)
* **Реализация:** `inorder_rec`, `preorder_rec`, `postorder_rec`
* **Связь:** DFS на графах — `graph.md`; порядки дерева — контексты выражений (раздел IX)

## **3. Обходы (итеративные, стек)**
* **Определение:** те же порядки без рекурсии — явный стек
* **inorder:** идём до упора влево, кладя узлы в стек; на выходе — узел, затем спуск в правое поддерево
* **preorder:** стек; вытащили — печатаем, кладём правого, затем левого (правый вышел позже)
* **postorder:** два стека (или стек пар `(узел, посещён ли)`); второй проход печатает после детей
* **Почему:** явный стек исключает переполнение рекурсии при больших h (глубокие деревья)
* **Сложность:** O(n) времени, O(h) памяти
* **Реализация:** `inorder_iter`, `preorder_iter`, `postorder_iter`
* **Связь:** стек — I.C; связь рекурсии и стека — та же, что в DFS

## **4. Обход в ширину (Level-order / BFS)**
* **Определение:** послойный обход: сначала все узлы глубины d, потом d+1; очередь — рабочие вершины
* **Почему для олимпиад:** естественный вывод дерева (печать по уровням), построение из массива (B.1), замок «заполнить по уровням»
* **Сложность:** O(n) времени, O(w) памяти (w — ширина уровня)
* **Обобщение:** обход по уровням с разбиением на слои (длина очереди в начале каждого уровня)
* **Реализация:** `level_order(TreeNode*)`, `level_order_layers` (вектор слоёв)
* **Связь:** BFS на графах — `graph.md`; очередь — I.D

## **5. Mirror и Symmetric Tree**
* **Определение:** mirror — дерево, у которого левое и правое поддеревья поменяны местами во всех узлах; дерево симметрично, если совпадает со своим mirror (сравнение через зеркальные пары)
* **Почему работает:** рекурсия «пара узлов»: l.left == r.right и l.right == r.left для всех уровней
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** mirror как преобразование (перестановка детей) и как предикат (симметричность); k-арная симметрия — обобщение пар
* **Реализация:** `invert_tree` (mirror на месте), `is_symmetric`
* **Связь:** симметрия — частный случай изоморфизма деревьев; обходы сопоставляют уровни

## **6. Diameter Of Binary Tree**
* **Определение:** диаметр — длина (число рёбер) самого длинного пути между двумя узлами; путь проходит через общий предок
* **Почему работает:** диаметр = max(диаметр левого, диаметр правого, высота_левого + высота_правого + 2) — либо целиком в поддереве, либо пересекает корень
* **Сложность:** O(n) одним проходом (высота+диаметр в одной рекурсии)
* **Обобщение:** взвешенный вариант; диаметр как максимум суммы «двух самых длинных ветвей вниз»
* **Реализация:** `diameter`
* **Связь:** высота — B.1; rerooting-идеи — `dynamic.md` (G)

## **7. Binary Tree Node Sum / Path Sum**
* **Определение:** сумма узлов дерева; сумма пути — сумма значений вдоль пути от корня до листа; Path Sum — существует ли путь с заданной суммой target
* **Почему работает:** рекурсия по поддеревьям; для пути — вычитание значения узла при спуске (цель: дойти до листа, когда остаток = 0)
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** пути от любого узла вниз (вариант «от каждого узла»), число путей с суммой target — prefix-суммы по пути (map-техника из `hashing.md`)
* **Реализация:** `node_sum`, `root_to_leaf_path_sum`
* **Связь:** префиксные суммы (V.A) — та же идея на путях дерева

## **8. Distribute Coins**
* **Определение:** на узлах — монеты (сумма = число узлов); за один ход монета переехала на соседний узел; минимальное число ходов так, чтобы на каждом узле была ровно одна монета
* **Почему работает:** для каждого поддерева «излишек/дефицит» = сумма монет − размер; эти монеты обязаны пересечь ребро к родителю — ходы считаются по модулю
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** целевые значения не единицы — параметр target
* **Реализация:** `distribute_coins(root, target = 1)`
* **Связь:** балансировка по поддеревьям — та же схема, что дерево отрезков с отложенной работой (V.D); суммы на дереве

## **9. Lowest Common Ancestor (LCA)**
* **Определение:** ближайший общий предок двух узлов; подходы: рекурсивный обход (тип результата узла), подъёмы
* **Рекурсивный подход:** узел — LCA, если левое и правое поддеревья содержат по одному из запрошенных (или сам является одним из них)
* **Сложность:** O(n) на запрос (наивно), O(1) после Euler+RMQ / O(log n) двоичными подъёмами
* **Обобщение:** двоичные подъёмы — из A.4 (`ParentArray::kth_ancestor`); расстояние между узлами = depth(u) + depth(v) − 2·depth(lca)
* **Реализация:** `lca_naive(TreeNode*, u, v)`
* **Связь:** полная теория LCA — `graph.md` (задел здесь); ДП на дереве переиспользует глубины

## **10. Serialize / Deserialize**
* **Определение:** сериализация — строка/порядок, по которому дерево восстанавливается однозначно; десериализация — восстановление `TreeNode*`
* **Level-order вариант:** значения с маркерами пустых детей (−1/`#`), восстановление очередью
* **Почему работает:** маркеры пустоты фиксируют форму дерева — однозначность восстановления
* **Сложность:** O(n) в обе стороны
* **Обобщение:** preorder с маркерами — компактнее для записей; на BST — без маркеров (C.1); формат — параметры marker и разделитель sep
* **Реализация:** `serialize_level_order(root, marker = "#", sep = " ")`, `deserialize_level_order` (формат: значения и маркер)
* **Связь:** сериализуемость курсорных представлений — A.3; строковые форматы — `string.md`

## **11. Merge Two Binary Trees**
* **Определение:** покомпонентное слияние: при наложении узлов значения складываются; отсутствующий узел — берётся как есть
* **Почему рекурсия:** слияние параллельных поддеревьев — независимые подзадачи
* **Сложность:** O(min(n, m)) времени, O(min(h)) стека
* **Обобщение:** параметр бинарной операции op (сумма, max, min — сворачиваемые моноиды)
* **Реализация:** `merge_trees(TreeNode*, TreeNode*, op = сумма)`
* **Связь:** операция-параметр — то же, что в V.D (дерево отрезков)

# **C. БИНАРНЫЕ ДЕРЕВЬЯ ПОИСКА (BST)**

## **1. Операции: поиск, вставка, удаление**
* **Инвариант BST:** для каждого узла все ключи в левом поддереве < ключа узла < все ключи в правом
* **Поиск:** сравнение ключей — спуск влево/вправо; O(h)
* **Вставка:** поиск места + подвешивание нового листа; O(h)
* **Удаление (случаи 0/1/2 детей):** 0 детей — отцепить; 1 ребёнок — поднять на место узла; 2 ребёнка — заменить inorder-преемником (минимум правого поддерева) и удалить его (сведено к случаям 0/1)
* **Почему работает:** преемник — единственный ключ, который можно поднять без нарушения инварианта (он > всех левых и < всех правых)
* **Сложность:** O(h) на операцию; на отсортированных вставках h = n (деградация → D)
* **Обобщение:** параметр сравнения — произвольный строгий порядок; дубликаты — счётчик в узле или `≤` в правом поддереве
* **Реализация:** `bst_search` (итеративный) / `bst_search_recursive`, `bst_insert` (рекурсивный) / `bst_insert_iter`, `bst_erase`, `bst_min`, `bst_max` — методы работают с `TreeNode*` (возврат нового корня)
* **Связь:** инвариант — фундамент floor/ceil (C.2), валидаций (C.3–C.5), балансировок (D)

## **2. Floor And Ceiling**
* **Определение:** floor(key) — наибольший ключ ≤ key; ceil(key) — наименьший ключ ≥ key в дереве
* **Поиск:** спуск по BST: если ключ совпал — ответ; при невозможном спуске — последний «кандидат» по пути (рекурсивно, через возврат)
* **Сложность:** O(h)
* **Обобщение:** lower_bound/upper_bound семантика — правая/строгая граница
* **Реализация:** `bst_floor(TreeNode*&, int)`, `bst_ceil`
* **Связь:** lower/upper bound — `technique.md`; порядковые статистики — G.2

## **3. Is Sorted (валидация BST)**
* **Определение:** проверить, что дерево удовлетворяет инварианту BST
* **Подход A (inorder):** inorder-обход обязан дать строго возрастающую последовательность — при нарушении порядок ломается
* **Подход B (границы):** рекурсия с допустимым интервалом (min, max) для каждого поддерева; мост к обходам итеративным — стек
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** нестрогий вариант (дубликаты слева) — параметр `strict` в обоих подходах
* **Реализация:** `is_bst_sorted` (inorder, `strict = true`), `is_bst_bounds` (границы, `strict = true`)
* **Связь:** inorder = сортировка (B.2); BST ↔ сортированный массив (С.5)

## **4. Is Sum Tree**
* **Определение:** узел — sum-узел, если val = сумма всех значений левого и правого поддеревьев; проверить всё дерево (листья остаются свободными)
* **Почему для олимпиад:** классическая задача на постордер-свертку: снизу вверх считаем суммы, сверяем с val
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** операция-параметр (сумма, xor, произведение); проверка одного узла — вариант
* **Реализация:** `is_sum_tree`
* **Связь:** постордер как порядок свёртки — B.2; суммы на дереве — B.7

## **5. Maximum Sum BST**
* **Определение:** найти поддерево (не обязательно все) с максимальной суммой значений, само являющееся валидным BST
* **Идея:** постордер-свертка с тройкой `(сумма, min, max, валидно)` — для каждого поддерева: валидно = обе части валидны и левый max < val < правый min; сумма — для ответа
* **Почему работает:** при валидности поддерева рекурсивное сведение корректно; максимум обновляется на каждом узле
* **Сложность:** O(n) времени, O(h) стека
* **Обобщение:** отрицательные суммы — «пустое поддерево (сумма 0)» в качестве кандидата
* **Реализация:** `max_sum_bst`
* **Связь:** тройка (сумма, min, max, валидно) — общий паттерн постордер-свёрток (B.6–B.8, C.4)

## **6. Поворот как примитив**
* **Определение:** локальная перестройка поддерева: `rotate_left(у)` делает правого ребёнка `x` корнем, `у` — его левым ребёнком; `rotate_right` — симметрично; inorder-последовательность не меняется
* **Почему для олимпиад:** повороты — атом балансировки (D): любая балансировка AVL/RB/splay строится из поворотов
* **Сложность:** O(1) — только пересвязывание трёх указателей
* **Обобщение:** параметр (left/right) унифицируется через обмен направлений; высоты поддеревьев обновляются после поворота
* **Реализация:** `rotate_right(TreeNode*&)`, `rotate_left(TreeNode*&)` — пересвязывание на месте, возврат нового корня
* **Связь:** фундамент раздела D — там же доказательство сохранения inorder-порядка

# **D. СБАЛАНСИРОВАННЫЕ ДЕРЕВЬЯ**

## **1. Общая идея балансировки**
* **Определение:** после каждой вставки/удаления дерево восстанавливает инвариант, гарантирующий высоту O(log n); в классе — баланс-фактор (AVL), цвета (RB), перестройка (scapegoat), амортизация (splay)
* **Почему важно:** без баланса BST деградирует: вставка n элементов по возрастанию даёт цепь высотой n — все операции O(n)
* **Доказательство высоты:** AVL: рекуррентность h(n) = h(n−1) + h(n−2) + 1 → h ≤ 1.44·log₂(n+2) (числа Фибоначчи-границы); RB: чёрная высота ≥ дерева/2 → h ≤ 2·log₂(n+1); общая идея — на каждом уровне «работает» минимум константная доля узлов
* **Повороты как примитив:** из C.6 — единственный инструмент перестройки локальных структур
* **Сложность:** O(log n) на операцию (вставка/удаление/поиск)
* **Реализация:** `TreeBalanced` — общий каркас (высота/баланс-фактор, обновление высот); конкретные деревья ниже
* **Связь:** амортизация — `analysis.md`; доказательство через рекуррентности там же

## **2. AVL-дерево**
* **Определение:** у каждого узла |balance| = |h(left) − h(right)| ≤ 1; инвариант восстанавливается поворотами
* **Балансировка после вставки/удаления:** четыре случая: LL (правый поворот), RR (левый), LR (левый+правый), RL (правый+левый); баланс-фактор пересчитывается после поворотов
* **Почему работает:** |balance| ≤ 1 ограничивает высоту минимальной рекуррентностью Фибоначчиевых деревьев
* **Сложность:** O(log n) вставка/удаление (до O(log n) поворотов по пути); поиск O(log n) без перестройки
* **Обобщение:** сравнение — параметр; вставка дубликатов — счётчик
* **Реализация:** `AVLTree` (`insert`, `erase`, `search`, `height`, баланс-фактор, `rotate_left/right` из C.6)
* **Связь:** повороты — C.6; сравнение с RB — D.3

## **3. Красно-чёрное дерево**
* **Инварианты:** корень чёрный; красные узлы имеют чёрных детей; каждый путь от узла содержит одинаковое число чёрных (чёрная высота); листья (null) — чёрные
* **Вставка:** новые узлы красные; нарушения: два красных подряд — исправление случаями (перекраска дяди / повороты LL, LR, RL, RR); цель — сохранить чёрную высоту
* **Удаление:** сложнее вставки: удаление чёрного требует «двойного чёрного» и переделки через брата/племянников (случаи поворотов и перекрасок)
* **Почему работает:** из чёрной высоты: h_rb ≤ 2·log₂(n+1); красные узлы впитывают отклонения, чёрные дают баланс
* **Сравнение с AVL:** AVL строже балансирует (h ≈ 1.44·log n против 2·log n) — быстрее поиск, но больше поворотов при вставке/удалении; RB — меньше перестроек, лучше в динамике
* **Сложность:** O(log n) на все операции
* **Обобщение:** инварианты — единый язык с 2-3-4 деревьями (E.5): красные узлы = «слитые» узлы 2-3-4
* **Реализация:** `RedBlackTree` (вставка по случаям, удаление по случаям, валидация инвариантов)
* **Связь:** std::map/set — RB внутри (H); эквивалентность 2-3-4 — E.5

## **4. Splay-дерево**
* **Определение:** каждый доступ (search/insert/erase) «сплайсит» узел к корню последовательностью поворотов (zig, zig-zig, zig-zag)
* **Почему работает (амортизация):** потенциальная функция Φ = Σ log(размер поддерева); сплайс даёт амортизированные O(log n) на операцию; кэш-локальность — часто используемые узлы у корня
* **Сложность:** O(log n) амортизированно; худший случай O(n) (но последовательность деградации единична)
* **Обобщение:** интервальные операции (неявный ключ) — мост к F.3; split/merge через сплайс
* **Реализация:** `SplayTree` (`splay`, `insert`, `erase`, `search` — сплайсит найденный узел)
* **Связь:** амортизационный анализ — `analysis.md`; потенциальная функция — та же, что у биномиальных куч (IV)

## **5. AA-дерево**
* **Определение:** упрощение красно-чёрного: только правые красные рёбра (уровни), балансировка двумя операциями: skew (локальный разворот) и split (перекраска/поворот при двойной правой связи)
* **Почему проще:** инвариант уровней сводит случаи RB к двум операциям — код короче и легче доказуем
* **Сложность:** O(log n) на все операции
* **Обобщение:** уровни — поле узла (аналог чёрной высоты)
* **Реализация:** `AATree` (`insert` с skew/split, `erase` с деградацией уровней)
* **Связь:** упрощение RB (D.3) — «тот же продукт, меньше случаев»

## **6. Scapegoat-дерево**
* **Определение:** дерево с параметром α (обычно 0.75): узел нарушает α-баланс (размер ребёнка > α·размер узла) — вся подструктура перестраивается заново (rebuild в сбалансированное дерево)
* **Почему работает:** суммарная стоимость перестроек амортизированно O(log n): каждый узел участвует в O(log n) перестройках за всё время
* **Сложность:** O(log n) амортизированно, поиск O(log n) худшем случае (дерево всегда «почти сбалансировано»); без удалений высота ≤ log_{1/α} n
* **Обобщение:** параметр α — торговля высотой/перестройками; удаление с отложенной перестройкой (keeps большой непустой)
* **Реализация:** `ScapegoatTree` (вставка с поиском нарушителя, `rebuild`, удаление)
* **Связь:** перестройка — идея «амортизированная перестройка» (вектор с удвоением, analysis.md); полный пересбор — дерево отрезков переиспользует массовые построения

# **E. МНОГОПУТЕВЫЕ ДЕРЕВЬЯ**

## **1. B-дерево**
* **Определение:** дерево порядка t: узел хранит от t−1 до 2t−1 ключей и от t до 2t детей; все листья на одной глубине — рост дерева происходит наверх (расщеплением корня)
* **Почему работает:** ветвление t уменьшает высоту логарифмически: h = O(log_t n) — в t раз меньше переходов, чем в бинарном; узел — блок (страница диска/кэш-линия)
* **Операции:** поиск — бинарный по ключам узла + спуск; вставка — спуск вниз с предварительным расщеплением полных узлов (2t−1 → середина уходит наверх); удаление — спуск с подкреплением (заимствование/слияние), сложные случаи слияния двух детей
* **Сложность:** O(log_t n) на все операции; узел — O(t) за операцию внутри
* **Обобщение:** порядок t параметром: t = 1 → 2-3-дерево; t = 2 → 2-3-4-дерево (E.5); твёрдые листья — B+ (E.2)
* **Реализация:** `BTree` (узлы — векторы ключей/детей, разбиение, заимствование, слияние)
* **Связь:** блоки — кэш/диск (X кэш-политики); волновые структуры — cache-oblivious (XI)

## **2. B+-дерево**
* **Определение:** данные (значения) только в листьях; внутренние узлы — чистые разделители; листья связаны списком для последовательного скана
* **Почему выигрывает:** сканы диапазонов — обход связанных листьев (без возвратов наверх); внутренние узлы плотнее (больше ключей на узел) — меньше уровней
* **Операции:** поиск — спуск до листа; вставка — в лист + расщепление вверх; удаление — заимствование/слияние листьев + перестройка разделителей
* **Сложность:** O(log_t n) на операцию; диапазонный запрос — O(log_t n + k) (k — размер ответа)
* **Обобщение:** параметр порядка; первичный/вторичный индексы БД (мост в X)
* **Реализация:** `BPlusTree` (листья с `next`, внутренние — разделители, вставка с расщеплением, поиск диапазона)
* **Связь:** индексы СУБД — X; здесь закладывается структура

## **3. B*-дерево**
* **Определение:** модификация B-дерева: при переполнении ключи распределяются между двумя соседними узлами (а не split на две части); узел заполнен до 2t
* **Почему:** лучшая заполняемость (меньше расщеплений — меньше высота, экономия памяти и записей на диск)
* **Сложность:** O(log_t n), но с меньшим числом расщеплений (амортизированно)
* **Реализация:** B* как параметр распределения при вставке (в `BTree` — флаг `redistribute`)
* **Связь:** семейство B-деревьев — вариации одной схемы (расщепление/распределение/слияние)

## **4. 2-3 дерево**
* **Определение:** B-дерево порядка 3: узлы с 1–2 ключами и 2–3 детьми; эквивалент AA (D.5) через уровни
* **Почему вводится:** простейшая сбалансированная многопутевая структура — учебный мост между BST и B-деревом
* **Операции:** вставка с расщеплением тройки (2 ключа → 1+1 с подъемом середины); удаление — заимствование/слияние
* **Сложность:** O(log n); высота ≤ log₃(n+1)
* **Реализация:** `TwoThreeTree` = `BTree` с t = 1 (узлы до 2 ключей)
* **Связь:** B-дерево (E.1) — обобщение; 2-3-4 (E.5) — следующий шаг

## **5. 2-3-4 дерево и эквивалентность RB**
* **Определение:** B-дерево порядка 4: узлы с 1–3 ключами и 2–4 детьми; «плоская» форма — узлы 2-3-4 соответствуют чёрным узлам RB, красные дети — «дополнительным ключам»
* **Почему важно:** биекция 2-3-4 ↔ RB: любое 2-3-4 дерево кодируется красно-чёрным (красные связи = слитые ключи); вставка/удаление в RB — «теневые» операции 2-3-4 — единое понимание
* **Сложность:** O(log n) на все операции
* **Реализация:** `TwoThreeFourTree` = `BTree` с t = 2 (узлы до 3 ключей); связь с RB — в комментариях
* **Связь:** RB (D.3) — «то же дерево»; B-дерево (E.1) — общий каркас

# **F. ДЕКАРТОВЫ И РАНДОМИЗИРОВАННЫЕ ДЕРЕВЬЯ**

## **1. Treap (BST + куча)**
* **Определение:** бинарное дерево, где по ключу — BST, по случайному приоритету — куча (max-heap по приоритетам); дерево содержимо парой инвариантов
* **Почему работает (вероятность):** приоритеты i.i.d. → дерево — случайная перестановка; ожидаемая высота O(log n) — баланс «бесплатно», без поворотов-балансировок
* **Операции через split/merge:** split(root, key) → (дерево с ключами < key, ≥ key); merge(a, b) — слияние (при a.max_priority > b.max_priority справа прикрепляется); insert — split+merge; erase — merge детей
* **Сложность:** O(log n) ожидаемо на все операции
* **Обобщение:** приоритеты — генератор `rng` (параметр конструктора); размер поддерева — G.2 (дерево порядковых статистик)
* **Реализация:** `Treap` (узел `{key, pr, left, right, size}`, `split`, `merge`, `insert`, `erase`, `kth`; генератор приоритетов — параметр, по умолчанию детерминированный)
* **Связь:** рандомизированный BST (F.4) — та же идея без явной кучи; персистентность — VII

## **2. Неявный ключ (implicit treap)**
* **Определение:** ключ — позиция в последовательности (индекс); дерево хранит размеры поддеревьев; операции над отрезками — split по размеру и merge
* **Операции:** `split_at(t, k)` → первые k элементов и остаток; вставка в позицию — split + merge; удаление диапазона — два split; разворот отрезка — с lazy-флагом reverse
* **Почему работает:** позиции не хранятся явно — они выводятся из размеров; сдвиги индексов при вставке «бесплатны» (структурно)
* **Сложность:** O(log n) ожидаемо на операцию над отрезком
* **Обобщение:** lazy-агрегаты (сумма, min) на отрезках — общий приём с деревом отрезков (V.D)
* **Реализация:** `ImplicitTreap` (размеры, `split_at`, `merge`, `insert_at`, `erase_range`, `reverse_range` с lazy)
* **Связь:** операции над отрезками — заменяют дерево отрезков в динамике; персистентный treap — VII

## **3. Reverse на отрезке**
* **Определение:** разворот подотрезка [l, r) за O(log n): split на три части, swap детей + toggle lazy-флаг на средней части
* **Почему работает (lazy):** разворот не спускается немедленно — флаг «перевернуть» применяется при разборе дерева (push), суммарно O(log n)
* **Сложность:** O(log n) ожидаемо; push при каждом спуске
* **Реализация:** `ImplicitTreap::reverse_range(l, r)`, `_push` при обходе
* **Связь:** lazy-propagation — тот же приём в дереве отрезков (V.D); задачи на перестановки

## **4. Randomized Binary Search Tree**
* **Определение:** BST, где вставка происходит в случайную позицию (по весам/вероятности) — «treap без явных приоритетов»
* **Почему работает:** рандомизация позиции вставки даёт ожидаемую высоту O(log n) — та же математика, что у treap
* **Сложность:** O(log n) ожидаемо; слияние двух деревьев — случайно по размерам
* **Реализация:** RandomBST — treap как частный случай (приоритеты — веса); мост, реализация — `Treap`
* **Связь:** вероятностный анализ — `analysis.md` (вероятностный анализ); F.1

# **G. СПЕЦИАЛИЗИРОВАННЫЕ ДЕРЕВЬЯ**

## **1. Wavelet Tree**
* **Определение:** двоичное дерево по битам значений: каждый узел разбивает диапазон значений пополам, хранит префиксные счётчики «0/1»; запросы: k-я порядковая статистика и частота на отрезке за O(log σ) (σ — алфавит/размер диапазона)
* **Почему работает:** спуск по битам — каждый уровень отвечает на «посчитать элементы ≤ mid в [l, r)» за O(1) через префиксные счётчики; числа «улетают» влево/вправо по битам
* **Сложность:** O(log σ) на запрос (kth, rank, count в диапазоне); построение O(n log σ) памяти — O(n log σ) бит (суккентный вариант — Wavelet Matrix, G.4)
* **Обобщение:** параметр — максимальное значение (σ = 2^bits); произвольные ключи — координатное сжатие
* **Реализация:** `WaveletTree` (векторы счётчиков на узлах, `kth(l, r, k)`, `count_leq`, `count_eq`)
* **Связь:** суккентные структуры — III.B.7 (rank/select, FID); порядковые статистики на отрезках вместо Merge Sort Tree (V.E.4); Wavelet Matrix — G.4

## **2. Order-Statistic Tree (дерево порядковых статистик)**
* **Определение:** BST/treap с размерами поддеревьев: `select(k)` — k-й элемент по порядку (O(log n)), `rank(x)` — позиция ключа (O(log n))
* **Почему работает:** размер поддерева — свёртка по левым детям; select — «ищем k-й в отсортированном порядке» с вычитанием левых размеров
* **Сложность:** O(log n) на select/rank/insert/erase (в связке с балансировкой D или рандомизацией F)
* **Обобщение:** STL-аналог — `__gnu_pbds::tree` (order_of_key/find_by_order); здесь — treap-версия (F.1)
* **Реализация:** `OrderStatTree` — методы `kth`/`rank` на `Treap` (размеры уже есть)
* **Связь:** F.1; Fenwick с поиском k-го (V.B) — массивная версия той же идеи

## **3. Ссылки на Fenwick и Segment Tree**
* **Определение:** деревья запросов над массивами — адресуются индексами (A.2), живут в разделе V (RangeQueries): Fenwick (V.B) — битовые узлы, дерево отрезков (V.D) — полное бинарное с lazy-propagation
* **Почему здесь:** та же идея «дерево как иерархия диапазонов», но по позиции, а не по ключу; построение — наследники представления A.2
* **Реализация:** полностью в разделе V (`e/e.cpp`); здесь — только связь
* **Связь:** V.B (Фенвик), V.D (дерево отрезков), V.E.4 (Merge Sort Tree)

## **4. Wavelet Matrix**
* **Определение:** сукцинктный вариант Wavelet Tree: битовые векторы по разрядам — ряд `levels[bit]` хранит i-й бит значений (после стабильной сортировки по старшим битам), поддержан rank на блоках (III.B.7); запросы k-й статистики и частот — спуск по уровням через rank вместо векторов счётчиков на узлах
* **Почему выигрывает:** те же запросы за O(log σ), но память ≈ n·log σ бит (энтропийный предел данных) — без копий значений и счётчиков на каждый узел; ряд битов — один на разряд, а не два поддерева на узел
* **Сложность:** O(log σ) на запрос (kth, rank, count); построение O(n log σ) времени; память — сукцинктная, O(n log σ) бит
* **Обобщение:** rank — общий примитив (III.B.7), параметр; алфавит σ и число разрядов — параметры; Wavelet Tree (G.1) — «наивная» версия с префиксными счётчиками
* **Реализация:** `WaveletMatrix` (битовые векторы уровней с rank на блоках — суперблоки + блоки, `kth`, `count_leq`, `count_eq`; select — общий примитив III.B.7)
* **Связь:** Wavelet Tree — G.1; rank/select и FID — III.B.7; сукцинктность — III.B.7

# **H. ДЕРЕВЬЯ В STL**

## **1. std::map**
* **Определение:** упорядоченное ассоциативное множество (ключ → значение); внутри — красно-чёрное дерево (D.3); операции O(log n): `find`, `insert`, `erase`, `lower_bound`, `upper_bound`, `operator[]`
* **Почему для олимпиад:** балансировка и итераторы «бесплатны»; итераторы сохраняются при вставке/удалении (кроме удаляемого)
* **Реализация:** `stl_extrema` (демонстрационные запросы к std::map)
* **Связь:** RB — D.3; выбор между map и unordered_map — `hashing.md`

## **2. std::set / std::multiset**
* **Определение:** упорядоченное множество (значения) / с дубликатами; те же гарантии O(log n); мульти-вариант — многократные ключи
* **Итераторы и статистики:** `begin/rbegin`, `lower_bound/upper_bound`; k-я статистика — отсутствует в std (→ pb_ds tree или treap, G.2)
* **Реализация:** демонстрационные `stl_set_minmax`, `stl_multiset_count`
* **Связь:** G.2 (order-statistics — вне STL)

## **3. std::multimap**
* **Определение:** ключ → несколько значений; дубликаты ключей; `equal_range` — весь диапазон значений ключа
* **Реализация:** `stl_multimap_range` (equal_range демо)
* **Связь:** map/set семейство — одна реализация RB внутри

## **4. std::priority_queue**
* **Определение:** max-куча по умолчанию (бинарная куча — IV); операции O(log n): `push`, `pop`, O(1) `top`; без итераторов и удаления произвольного
* **Почему здесь:** кучи — деревья с представлением A.2 (массив + индексация); полное устройство — раздел IV
* **Реализация:** упоминание; полная — `d/d.cpp` (Heaps)
* **Связь:** IV (бинарная куча), A.2 (представление массивом), E.1 (B-деревья — те же «блочные» структуры на диске)
