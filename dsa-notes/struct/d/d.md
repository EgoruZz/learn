**IV. КУЧИ (PRIORITY QUEUES)**

> **Архитектура:** `Heaps` (d.cpp) — класс ветки struct, наследует `SetStructures` (c.cpp). Вводит приоритетные очереди — кучи: бинарную кучу на массиве (A), семейство сливаемых куч на двоичных деревьях (B: биномиальная, фибоначчиева, парная, левосторонняя, косая, рандомизированная), радикс-кучу для целочисленных ключей (C) и двусторонние кучи с извлечением и минимума, и максимума (D). Переиспользует из базы: куча-индексацию `HeapIndexedTree` (II.A.2) как базовый класс бинарной кучи — индексы `left/right/parent` не переписываются; бакетную схему `BucketQueue` (I.D.8) как мост для радикс-кучи (C, диапазонные приоритеты); амортизационный анализ (I.A, `analysis.md`) — потенциальные функции фибоначчиевой, косой и парной куч; приём «потенциал к корню» из Weighted DSU (III.A.5) — та же механика, что decrease-key в кучах с указателями; рандомизацию (`mt19937`, как в II.F) — для рандомизированной кучи. Закладывает приёмы, переиспользуемые дальше: decrease-key/increase-key — для Дейкстры и Прима (`graph.md`); сливаемость (merge) — для meldable-структур и персистентных вариантов (VII); радикс-куча — для Дейкстры на целочисленных весах (`graph.md`); парная/фибоначчиева кучи — как практические альтернативы друг другу. Собственной арифметики не имеет.
>
> **Связи:** амортизационные оценки и потенциальные функции — `analysis.md`; куча-индексация полного дерева — II.A.2; Дейкстра/Прим с decrease-key — `graph.md`; приоритетные очереди на списках (режим A/B) — I.D.4; Bucket Queue — I.D.8; рюкзак и ДП-рекуррентности — `dynamic.md`; дерево отрезков как «куча по сумме» — V.D; splay-амортизация — II.D.4; слияние деревьев в DSU — III.A.3.

# **Основные понятия и принципы**

* **Что это:** очередь, из которой извлекается экстремум по приоритету: операции `insert` (положить с ключом) и `extract_min` (извлечь элемент с минимальным ключом) + `min_key` (посмотреть без извлечения); дополнительно: `merge` (слить две кучи — нужен не всем), `decrease_key` (уменьшить ключ элемента — для Дейкстры/Прима), извлечение максимума (двусторонние кучи, D)
* **Почему выделяется в отдельный класс:** приоритетные очереди — «движок» жадных алгоритмов (Дейкстра, Прим, Хаффман), событийных симуляций и поточных агрегатов; частичный порядок (корень — экстремум, остальное не упорядочено) — это ровно то, что нужно очередям и на порядок дешевле полной сортировки
* **Ключевые принципы:** структурный инвариант — экстремум в корне, каждый ребёнок «не лучше» родителя (частичный порядок); представление — полное дерево в массиве (A, кэш) или двоичные деревья на указателях (B, сливаемость); ленивая консолидация — откладывать слияние и восстановление инварианта, платя амортизированно (B.2, B.3, B.5); `decrease_key` — изменение ключа с восстановлением инварианта по пути вверх (A.4) или вырезкой и подвешиванием (B.1–B.3)
* **Как распознать:** «каждый раз доставать минимальный/максимальный», «сортировать по мере поступления», «сливать приоритетные потоки», «уменьшать вес и переставлять» — куча; «все элементы по порядку» — сортировка/деревья (II); «нужен и минимум, и максимум» — двусторонняя куча (D); «веса — малые целые» — радикс-куча (C)
* **Границы:** куча не умеет искать произвольный элемент (нет поиска по ключу — деревья II) и не даёт порядок обхода; `decrease_key` требует позицию элемента (A.4 — массив позиций) или указатель на узел (B); куча на массиве не сливается за O(log n) без пересборки — для слияния нужны деревья (B)

# **A. БИНАРНАЯ КУЧА**

## **1. Heap: массив + sift-up / sift-down**
* **Определение:** полное бинарное дерево в массиве (куча-индексация II.A.2): корень — `a[0]`, дети узла `i` — `2i+1`, `2i+2`, родитель — `(i−1)/2`; инвариант: `a[parent] ≤ a[child]` (min-куча) — корень всегда минимален
* **Идея:** вставка кладёт элемент в конец и «всплывает» (sift-up): меняется с родителем, пока инвариант не восстановлен; извлечение меняет корень с последним и «топит» (sift-down): меняется с меньшим из детей
* **Почему работает:** высота полного дерева из `n` вершин — `⌊log₂ n⌋`, каждый обмен сдвигает элемент на уровень; после каждого обмена инвариант восстанавливается локально, остальные части дерева не затронуты
* **Сложность:** `push`/`pop` — O(log n), `top` — O(1), память O(n); вставка в конец вектора — O(1) амортизированно (I.A.2)
* **Обобщение:** компаратор — параметр (см. 3); на месте массива — in-place сортировка пирамидой (куча + `pop` в хвост)
* **Реализация:** `BinaryHeap` — наследует `HeapIndexedTree` (II.A.2), добавляет `sift_up`, `sift_down`, `push`, `pop`, `top`
* **Связь:** индексация полного дерева — II.A.2; `std::priority_queue` — 5

## **2. Построение кучи за O(n) (heapify)**
* **Определение:** из произвольного массива собрать кучу быстрее, чем `n` вставок по O(log n)
* **Алгоритм:** `sift_down` для всех узлов, начиная с последнего родителя (`n/2 − 1`) и до корня — снизу вверх по уровням
* **Почему O(n):** стоимость sift-down узла = его высота; суммарно `Σ_{h} (n/2^{h+1})·h = O(n)` (на каждом уровне почти все узлы — листья, глубоко «тонут» только верхние) — та же геометрическая оценка, что в амортизации вектора (I.A)
* **Сложность:** O(n) времени, O(1) дополнительной памяти
* **Обобщение:** построение — параметр от компаратора (см. 3); sift-down снизу вверх — общий приём для массивных структур
* **Реализация:** `BinaryHeap::build(vals)` (присваивает массив + `heapify` снизу вверх)
* **Связь:** амортизация и геометрическая прогрессия — `analysis.md`; пирамидальная сортировка — `technique.md`

## **3. Heap Generic: параметризация компаратора; Max/Min Heap**
* **Определение:** вид экстремума — параметр: min-куча (по умолчанию), max-куча (компаратор `a > b`), произвольный приоритет `key(x)`
* **Почему:** один движок вместо двух классов: всё отличие — направление сравнения; обёртки-конкретизации делают намерение явным в точке вызова
* **Сложность:** та же, что у A.1: O(log n) на операцию
* **Обобщение:** компаратор — параметр конструктора (`std::function<bool(int, int)>`); приоритет по ключу `w(x)` — обёртка компаратора (задача «извлекать максимальный вес»)
* **Реализация:** `BinaryHeap(cmp)` — компаратор параметром; `MaxHeap` — обёртка с обратным компаратором
* **Связь:** параметр-компаратор — тот же приём, что предикаты в монотонном стеке (I.C.4) и DSU-агрегаты (III.A.4)

## **4. Index Heap: куча с позиционным массивом (decrease-key / increase-key)**
* **Определение:** элементы нумерованы `0..n−1`; дополнительный массив `pos[v]` — позиция элемента `v` в куче; ключи живут в `key[v]`
* **Операции:** `decrease_key(v, k)` — уменьшить ключ и всплыть с позиции `pos[v]`; `increase_key(v, k)` — увеличить и утопить; `pop_min` возвращает номер элемента
* **Почему работает:** `pos` даёт точку входа в кучу для произвольного элемента — sift-up/down из неё восстанавливает инвариант; обмены в куче синхронно обновляют `pos`
* **Сложность:** все операции O(log n); `contains(v)` — O(1) (`pos[v] != −1`)
* **Обобщение:** ключи — параметр (стартовые значения, дальше уменьшаются); удаление произвольного элемента — `decrease_key(v, −∞)` + `pop_min` (приём «вычеркнуть через −∞»)
* **Реализация:** `IndexHeap` (массивы `key`, `pos`, `heap`; `sift_up/sift_down` с синхронным обновлением `pos`)
* **Связь:** Дейкстра/Прим — `graph.md` (decrease-key — операция номер один там); `std::priority_queue` не поддерживает decrease-key — своя реализация нужна; приём «−∞ и извлечь» — тот же ход, что `erase` у сливаемых куч (B.2)

## **5. `std::priority_queue` (STL)**
* **Определение:** бинарная куча стандартной библиотеки: `push`, `pop`, `top`, `size`, `empty`; компаратор — параметр шаблона (по умолчанию max-куча)
* **Почему:** готовая куча для задач без decrease-key и без слияния; min-куча — компаратор `greater<T>`; для произвольного приоритета — обёртка с `operator()`
* **Границы:** нет `decrease_key`, нет `merge`, нет итерации; позиции элементов не видны
* **Реализация:** демонстрация в main (max и min-варианты, сравнение с `BinaryHeap`)
* **Связь:** когда нужен decrease-key — A.4; когда merge — B

# **B. СЛИВАЕМЫЕ КУЧИ (MERGEABLE HEAPS)**

* **Общее:** двоичные деревья на указателях, корень — минимум; `merge(a, b)` — слить две кучи за O(log n) и меньше, не пересобирая массивы (в отличие от A); вставка — слияние с одноузловой кучей; извлечение — слияние детей корня; `decrease_key` — вырезка узла из своего дерева и слияние его поддерева с кучей
* **Почему деревья:** слияние массивов требует копирования O(n); деревья перевешиваются по ссылкам — платится только за «сшивание» путей
* **Обобщение:** узел — параметр каждой кучи (поля отличаются: ранг, степень, метка, партнёр); все сливаемые кучи — «дерево + merge-инвариант»

## **1. Биномиальная куча (Binomial Heap)**
* **Определение:** лес биномиальных деревьев `B_k` (дерево степени `k`: корень с детьми-корнями `B_0..B_{k−1}`, размер `2^k`); не более одного дерева каждой степени — «бинарное представление размера» кучи: `n` деревьев ⇔ биты числа `n`
* **Идея merge:** сложение лесов как двоичных чисел: деревья одинаковой степени сцепляются (корень с меньшим ключом — отец большего) — переносы в старшую степень; после слияния инвариант «не более одного дерева степени `k`» восстановлен
* **Почему работает:** размер дерева степени `k` — `2^k`, слияние двух `B_k` даёт `B_{k+1}`; число деревьев — O(log n), каждый перенос уменьшает число деревьев
* **Сложность:** `insert`/`merge` — O(log n) (O(1) амортизированно для insert — добавление единицы в двоичный счётчик), `extract_min` — O(log n), `decrease_key` — O(log n) (вырезка узла из дерева и повторное слияние его поддерева), память O(n)
* **Обобщение:** `decrease_key` — через указатель на узел (узел — «ручка» элемента, как `pos` в A.4); степень дерева — параметр структуры
* **Реализация:** `BinomialHeap` (массив корней по степеням `roots[d]`, узел `{val, degree, parent, child, sibling}`; `push`, `merge`, `pop_min`, `decrease_key`)
* **Связь:** бинарное представление числа — комбинаторика/анализ; «переносы» — те же, что в двоичном счётчике (`analysis.md`)

## **2. Фибоначчиева куча (Fibonacci Heap)**
* **Определение:** лес деревьев (не обязательно биномиальных) с корневым списком; вершины помечены (`mark` — потеряла ребёнка); степень дерева ~ `log_φ n` — отсюда и название
* **Идея:** максимально ленивая куча: `insert`/`merge`/`decrease_key` — O(1) (просто подвесить/вырезать), платим при `extract_min` (консолидация — слияние деревьев равной степени, как в B.1); «каскадная вырезка»: при потере второго ребёнка вершина тоже вырезается и поднимается — степень деревьев ограничена логарифмом
* **Почему работает (потенциал):** потенциальная функция Φ = число корней + 2·число помеченных вершин; дешёвые операции меняют Φ на O(1), дорогая консолидация оплачена накопленным потенциалом — амортизированная стоимость всех операций: insert/merge/decrease_key O(1), extract_min O(log n)
* **Сложность:** `insert` O(1), `merge` O(1), `decrease_key` O(1) амортизированно, `extract_min` O(log n) амортизированно; `erase(v)` — `decrease_key(v, −∞)` + `extract_min`
* **Обобщение:** метка-`mark` и каскадная вырезка — параметр ленивой стратегии; парная куча (B.3) — тот же ленивый дух без полей `mark`
* **Реализация:** `FibonacciHeap` (двунаправленный корневой список, узлы `{val, parent, child, left, right, degree, mark}`; `push`, `merge`, `pop_min` с консолидацией, `decrease_key` с каскадной вырезкой, `erase`)
* **Связь:** потенциальная функция и амортизация — `analysis.md`; ленивая консолидация — тот же мотив, что отложенные операции дерева отрезков (V.D) и ленивое слияние в косой куче (B.5)

## **3. Парная куча (Pairing Heap)**
* **Определение:** практическая альтернатива фибоначчиевой: однонаправленные списки детей, никаких `mark`/`degree`; merge — подвесить меньший корень под больший за O(1)
* **Идея extract_min:** дети корня объединяются «двухпроходным» слиянием: первый проход — попарно слева направо, второй — справа налево; амортизированная сложность выходит логарифмической
* **Почему работает:** двухпроходное слияние «укорачивает» пути — каждый элемент платит O(log n) амортизированно за извлечение (потенциал — логарифм размеров поддеревьев)
* **Сложность:** `insert`/`merge`/`decrease_key` — O(1) амортизированно, `extract_min` — O(log n) амортизированно (те же оценки, что у фибоначчиевой, но с меньшими константами и без служебных полей)
* **Обобщение:** число проходов слияния — параметр (2 — канон); `decrease_key` — вырезка узла (через `prev`-ссылки в списке детей) + merge с корнем
* **Реализация:** `PairingHeap` (узел `{val, parent, first, next, prev}`; `link` — подвешивание, `push`, `pop_min` с двухпроходным слиянием, `decrease_key` с вырезкой)
* **Связь:** ленивость и потенциал — B.2, `analysis.md`; списки детей с `prev`-меткой — приём курсорных ссылок (I.B.6)

## **4. Левосторонняя куча (Leftist Heap)**
* **Определение:** куча-дерево с рангом узла — длиной кратчайшего пути до NULL (null-path length); инвариант: `rank(left) ≥ rank(right)` — правое поддерево всегда «короче»
* **Идея merge:** рекурсивно: корень с меньшим ключом остаётся, к его правому поддереву приклеивается другая куча; после слияния — обмен детей, если `rank(left) < rank(right)`
* **Почему работает:** инвариант гарантирует, что правый путь — кратчайший: длина правого пути ≤ log₂(n+1), рекурсия merge идёт только по правым путям — O(log n) строго (не амортизированно)
* **Сложность:** `merge`/`insert`/`extract_min` — O(log n) в худшем случае (детерминированно), память O(n)
* **Обобщение:** ранг — параметр определения (путь до NULL — кратчайший/длиннейший); левосторонняя куча — детерминированный прототип для косой (B.5) и рандомизированной (B.6) — они снимают «жёсткий» инвариант ради простоты
* **Реализация:** `LeftistHeap` (узел `{val, rank, left, right}`; рекурсивный `meld`)
* **Связь:** высота и рекуррентности — `analysis.md`; правый путь — тот же приём, что спуск по правым краям в B-деревьях (II.E)

## **5. Косая куча (Skew Heap)**
* **Определение:** левосторонняя куча без инварианта рангов: после рекурсивного merge дети корня просто меняются местами
* **Почему работает (амортизация):** безусловный обмен детей «случайно» укорачивает пути; потенциальная функция — число «тяжёлых» правых рёбер — даёт O(log n) амортизированно на операцию, хотя отдельное слияние может быть O(n)
* **Сложность:** `merge`/`insert`/`extract_min` — O(log n) амортизированно (рекурсия только по правым путям)
* **Обобщение:** обмен детей — параметр стратегии (всегда / по рангу B.4 / случайно B.6); косая куча — «дешёвый левосторонний» вариант без хранения рангов
* **Реализация:** `SkewHeap` (узел `{val, left, right}`; `meld` с безусловным обменом детей)
* **Связь:** амортизация через потенциальную функцию — `analysis.md`; случайная альтернатива — B.6, рандомизированный treap (II.F)

## **6. Рандомизированная куча (Randomized Heap)**
* **Определение:** та же схема, но выбор ребёнка для рекурсии — случайный (монетка): вместо инварианта ранга — вероятностный баланс
* **Почему работает:** рекурсия идёт по случайно выбранным путям — ожидаемая длина пути O(log n) независимо от порядка вставок (в худшем случае дерево может выродиться, но с вероятностью ~0 при большой глубине)
* **Сложность:** `merge`/`insert`/`extract_min` — O(log n) ожидаемо; память O(n)
* **Обобщение:** монетка — параметр (генератор и зерно); рандомизация вместо инварианта — общий приём: рандомизированный BST (II.F), QuickSelect (I.A.3.3)
* **Реализация:** `RandomizedHeap` (узел `{val, left, right}`; `meld` с монеткой `mt19937`, зерно — параметр конструктора)
 * **Связь:** вероятностный баланс — мост в `hashing.md` IV (вероятностные структуры); зерно генератора — параметр тестируемости

# **C. РАДИКС-КУЧА (RADIX HEAP) / BUCKET HEAP**

## **1. Радикс-куча: приоритеты из малого диапазона**
* **Определение:** куча для целочисленных неотрицательных ключей, разделённых по бакетам: бакет `b` хранит ключи с битовой длиной `⌈log₂(key − last_min)⌉`; `last_min` — последний извлечённый минимум
* **Идея:** после извлечения минимума `m` все ключи `key < m + 2^b` гарантированно лежат в бакетах `≤ b`; `extract_min` находит первый непустой бакет, берёт его минимум, а остальные ключи бакета перераспределяет в меньшие бакеты — они «умещаются» по битовой длине
* **Почему работает:** каждый ключ переносится в меньший бакет не более `⌈log₂ ключ⌉` раз — перераспределение амортизировано; число бакетов — битовая длина ключа: при ключах ≤ `S` их `⌈log₂S⌉ + 1`
* **Сложность:** `insert` — O(1) (амортизированно), `extract_min` — O(бит) на поиск бакета + амортизированные переносы; для Дейкстры с целыми весами — O((V+E)·log C) практически линейно
* **Обобщение:** число бакетов — параметр (битовая длина ключа); если диапазон приоритетов совсем мал `P` — достаточно `BucketQueue` (I.D.8): O(1) вставка, O(P) извлечение; радикс-куча — битовое уточнение той же бакетной схемы
* **Реализация:** `RadixHeap` (массив `deque` бакетов; `push(key, val)`, `pop_min(key, val)`, битовая длина — `bucket_of(x ^ last_min)`)
* **Связь:** бакеты — мост из I.D.8 (Bucket Queue) и мост в IV; целочисленные веса Дейкстры — `graph.md`; битовые длины — приёмы discrete-and-logic

# **D. ДВУСТОРОННЯЯ КУЧА (DOUBLE-ENDED PRIORITY QUEUE)**

## **1. Min-Max Heap**
* **Определение:** полное дерево в массиве, уровни чередуются: чётные (корень — 0-й) — min-уровни, нечётные — max-уровни; инвариант: узел min-уровня ≤ всех потомков, узел max-уровня ≥ всех потомков
* **Идея:** вставка — в конец, затем подъём «по уровням»: сравниваем с родителем противоположного уровня (если порядок нарушен — обмен и подъём как на своём уровне), иначе — подъём к деду по своему уровню; извлечение минимума/максимума — корень (min) или больший из детей уровня 1 (max), восстановление — спуск по своему уровню с обменами через внуков
* **Почему работает:** уровни чередуются по глубине — любой элемент «знает» свою роль по паритету уровня; инварианты уровней независимы, восстановление не пересекает границу уровня
* **Сложность:** `insert`/`extract_min`/`extract_max` — O(log n); `min_key` — O(1), `max_key` — O(1)
* **Обобщение:** уровень — параметр (чётный/нечётный); спуск «через внуков» — мотив, общий с A.2 (построение снизу вверх)
* **Реализация:** `MinMaxHeap` (`is_min_level(i)`, `bubble_up_min/max`, `restore_min/max`)
* **Связь:** полное дерево в массиве — A.1, II.A.2; двусторонние стеки/деки — I.C.3, I.D.5

## **2. Interval Heap**
* **Определение:** массив интервалов `[lo[k], hi[k]]`, `lo[k] ≤ hi[k]`; `lo`-части образуют min-кучу, `hi`-части — max-кучу над тем же деревом; глобальный минимум — `lo[0]`, максимум — `hi[0]`
* **Идея:** каждый узел — пара «минимум и максимум поддерева»; вставка — в свободный слот (lo нового или hi последнего интервала), затем подъём: если интервал целиком ниже/выше родителя — обмен пар, если нарушена одна из половин — обмен значения
* **Почему работает:** инварианты (lo-куча, hi-куча, `lo ≤ hi` в узле) замкнуты относительно обменов пар — подъём сохраняет все три
* **Сложность:** `insert`/`extract_min`/`extract_max` — O(log n); память O(n)
* **Обобщение:** интервалы — параметр ширины (пара — вырожденный случай); пара значений как моноид — связь с агрегатами (III.A.4, V.D)
* **Реализация:** `IntervalHeap` (массивы `lo`, `hi`; `push` с подъёмом пар, `pop_min`/`pop_max`)
* **Связь:** две кучи в одном дереве — D.1; деки (I.D.5) — «интервальность» как представление

## **3. Deap**
* **Определение:** полное дерево, разделённое на две половины: левая — min-куча, правая — max-куча; каждому элементу правой половины соответствует «партнёр» в левой на том же уровне; инвариант: `a[partner] ≤ a[i]`
* **Идея:** вставка — в свободную позицию, сверка с партнёром: если нарушен порядок — обмен и подъём в куче партнёра, иначе — подъём в своей куче; извлечение минимума — корень левой половины, восстановление спуском с партнёрскими сверками
* **Почему работает:** партнёрская связь гарантирует, что минимум левой половины не больше любого элемента правой — минимум всей кучи живёт в левой, максимум — в правой
* **Сложность:** `insert`/`extract_min`/`extract_max` — O(log n)
* **Обобщение:** половины — параметр размера (сдвиг на степень двойки уровня); Deap — компактный конкурент D.1/D.2
* **Реализация:** постановка (структура, инварианты и оценки зафиксированы; рабочие варианты двусторонних куч — `MinMaxHeap` (D.1) и `IntervalHeap` (D.2))
* **Связь:** партнёрство — та же идея, что «потенциал к корню» (III.A.5) и связка min/max в `MinMaxStack` (I.C.3)

# **E. ОБЩЕЕ: выбор кучи**

* **Операции:** `insert`, `extract_min`, `min_key`, `merge`, `decrease_key`, `extract_max` — поддерживаются не всеми: массивные кучи (A, D) — без merge; сливаемые (B) — с merge; decrease-key — A.4 (по позиции), B (по указателю)
* **Представления:** массив (A, D — кэш-локальность, нет слияния) / указатели-деревья (B — слияние, служебные поля) / бакеты (C — целые ключи); выбор — параметр задачи
* **Амортизированные оценки:** строго O(log n) — бинарная (A), левосторонняя (B.4); амортизированно O(log n) — косая (B.5), парная (B.3); фибоначчиева (B.2) — O(1) insert/merge/decrease_key; ожидаемо O(log n) — рандомизированная (B.6); O(1) амортизированно — радикс-куча на целых (C)
* **Применимость по типам ключей:** произвольные сравнимые (A, B, D) / малые целые диапазоны (C; ещё проще — BucketQueue I.D.8)
* **Практическое правило:** обычные задачи — `std::priority_queue` (A.5); нужен decrease-key — `IndexHeap` (A.4); нужен merge и ленивость — `PairingHeap` (B.3) или `FibonacciHeap` (B.2); целые веса — `RadixHeap` (C); и минимум и максимум — `MinMaxHeap`/`IntervalHeap` (D)
* **Реализация:** сравнительная сводка в main (общие серии операций на разных кучах, сверка с `std::multiset`)
* **Связь:** структуры «все операции» — дерево отрезков (V.D); k-я статистика с обновлениями — II.G.2; событийные симуляции — применение очередей приоритетов
