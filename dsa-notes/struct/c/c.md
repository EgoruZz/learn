**III. СТРУКТУРЫ ДЛЯ МНОЖЕСТВ**

> **Архитектура:** `SetStructures` (c.cpp) — класс ветки struct, наследует `SearchTrees` (b.cpp). Вводит две полярные модели множества: систему непересекающихся множеств (DSU) — разбиения через представителей и леса (A), и битсеты — подмножества универсума через индикаторные векторы, слова как множества (B). Переиспользует из базы: примитивы множеств на машинном слове `set_union/set_intersection/set_difference/set_symmetric_difference/set_complement/set_cardinality/is_subset` из `SetsAndRelations` (`math/discrete-and-logic`) — DynamicBitset применяет их по словам (B.3–B.4); образец хранения слов — `BitBoard` (I.A.3.17); амортизированный анализ (I.A) — обоснование сжатия путей в DSU; стеки и векторы (I) — стек изменений для Rollback DSU. Закладывает приёмы, переиспользуемые дальше: откаты (стек изменений) — раздел VII (персистентность), роллбэк-время (обратный обход оффлайн) — VII и XI (динамическая связность), префиксные суммы битов (rank) — III.B.7 (суккентные структуры), сдвиг-по-словам `dp |= dp << x` — dynamic.md (рюкзак). Собственной арифметики не имеет.
>
> **Связи:** булевы маски и включения-исключения — `math/discrete-and-logic` (a-folder); множества в хешах и вероятностные множества (Bloom) — `hashing.md`; упорядоченные множества (деревья) — раздел II; динамическая связность (Link-Cut Tree, ETT) — раздел XI и `graph.md`; рюкзак битмасками — `dynamic.md` (J.2); rank/select — раздел III.B.7; префиксные суммы — раздел V.A; откаты и персистентность — раздел VII.

# **Основные понятия и принципы**

* **Что это:** класс структур, моделирующих множество в двух полярных формах: (1) разбиение на непересекающиеся классы эквивалентности (DSU: динамика связности, объединение компонент) и (2) подмножества фиксированного универсума `{0..n−1}` (битсеты: индикаторная функция `χ(i) ∈ {0, 1}`); между ними — структурная двойственность: классы эквивалентности «склеивают» элементы, битовый вектор «различает» их
* **Почему выделяется в отдельный класс:** и то, и другое — фундамент остальных структур: DSU — «связность» любого графа/процесса слияний, битсеты — сжатие в `w` раз (`w` — бит в машинном слове) и битовая параллельность; обе модели не требуют упорядоченности и поиска — поэтому не деревья и не хеши
* **Ключевые принципы:** представитель (каждый класс — корень леса, элемент знает своего представителя через подъёмы); амортизация (сжатие путей даёт «практически O(1)» — обратная функция Аккермана `α(n)`); слово как атом (одно машинное слово несёт `w` булевых признаков — операции множеств становятся побитовыми инструкциями)
* **Как распознать:** «компоненты связности», «объединить группы», «число цветов/классов» — DSU; «множества над универсумом умеренного размера `n` (битсет — `n/w` слов)», «маски подмножеств», «все ли элементы из X» — битсеты; рюкзак «возможно ли набрать сумму» — `dp |= dp << x`
* **Границы:** DSU не умеет удалять рёбра (→ роллбэк-оффлайн, динамическая связность XI); битсеты ограничены размером универсума и не умеют перечислять элементы множества быстрее `O(popcount)`; для упорядоченных множеств (поиск по ключу) нужны деревья II

# **A. СИСТЕМА НЕПЕРЕСЕКАЮЩИХСЯ МНОЖЕСТВ (DSU / UNION-FIND)**

## **1. Disjoint Set (базовый)**
* **Определение:** `n` элементов, операции: `find(x)` — представитель класса эквивалентности, `unite(x, y)` — объединить классы; инвариант: классы всегда образуют разбиение
* **Идея:** лес с родительскими указателями: `parent[x]` — отец узла `x`, корень — представитель (`parent[root] == root`); `find` поднимается к корню, `unite` вешает корень одного дерева под корень другого
* **Почему работает:** свойство представителя транзитивно — корень леса однозначен для класса; корректность не зависит от порядка подвешивания
* **Сложность (наивно):** `find` — O(h) (h — высота леса), в худшем случае цепь O(n) на запрос — требуется оптимизация (A.3)
* **Обобщение:** элементы — произвольный тип (нумерация `0..n−1` — перенумерация словарём); операции — параметр (см. варианты A.4–A.8)
* **Реализация:** `DisjointSet` (массив `parent`; `find` рекурсивный, `unite` без эвристик — демонстрация деградации)
* **Связь:** лес — частный случай деревьев (II.A); отношения эквивалентности — `math/discrete-and-logic` (a-folder)

## **2. Alternate Disjoint Set (альтернативная реализация)**
* **Определение:** тот же контракт, другая механика: `find` без рекурсии — два прохода (подъём до корня, затем переподвешивание всех узлов пути к корню) — полное сжатие пути итеративно
* **Почему:** рекурсивный `find` на глубоких цепях переполняет стек; итеративный вариант неуязвим по глубине и даёт ту же асимптотику
* **Сложность:** O(h) на первый запрос к узлу, далее O(1) на повторные (после сжатия)
* **Обобщение:** сжатие пути — независимый приём (применим к любому лесному представлению); возврат «корня и глубины пути» — мост к A.5 (потенциалы)
* **Реализация:** `find` (двухпроходный, без рекурсии) в классе `AlternateDSU` — базовый класс для A.3
* **Связь:** итеративные обходы деревьев — II.B.3 (тот же мотив «без рекурсии»)

## **3. Оптимизации: Union by Size / Rank и Path Compression**
* **Определение:** две независимые эвристики: **сжатие путей** — при `find` все узлы пути переподвешиваются к корню; **union by size** — корень меньшего дерева вешается под корень большего (by rank — по высоте без сжатия)
* **Почему работает (амортизация):** с only-union-by-size высота ≤ `log₂ n` (каждая вершина, чей корень меняется, увеличивает размер дерева вдвое); сжатие путей дополнительно «сплющивает» — совместно дают амортизацию `O(α(n))` на операцию, где `α` — обратная функция Аккермана (для любых реальных `n`: ≤ 4)
* **Сложность:** `find`/`unite` — `O(α(n))` амортизированно (практически константа), память O(n)
* **Обобщение:** выбор эвристики — параметр (по размеру/по рангу); сжатие отключается, когда нужны откаты (A.6); размер как данные компоненты — A.4
* **Реализация:** `DSU` — основной класс раздела: наследует `AlternateDSU` (A.2) — итеративный `find` со сжатием переиспользуется, добавляется `unite` by size и агрегаты размера; все дальнейшие варианты строятся на нём
* **Связь:** амортизационный анализ — `analysis.md`; потенциальная функция — тот же приём, что у вектора (I.A) и splay-деревьев (II.D.4)

## **4. DSU с данными в компоненте**
* **Определение:** компонента несёт агрегаты — размер, сумма, минимум/максимум, xor, счётчики по признаку; данные хранятся в корне (`aggr[root]`), при `unite` пересчитываются за O(1)
* **Почему работает:** инвариант «агрегат корня = агрегат класса»: при слиянии `aggr = f(aggr_a, aggr_b)`; любые запросы «по всей компоненте» — чтение корня
* **Сложность:** O(α(n)) на операцию; агрегаты — O(1) дополнительно на запрос
* **Обобщение:** агрегат — параметр (бинарная операция `f` + нейтральный элемент: сумма, произведение, min, max, xor — любой моноид); «значения узлов» обновляются как потенциалы — A.5
* **Реализация:** `DSUWithAgg` — наследует `DSU` (A.3): `find`/`same`/`size` переиспользуются, `unite` переопределяется для пересчёта агрегата; агрегация — параметр конструктора + `aggregate(x)`
* **Связь:** моноиды и параметр операции — II.G.2 (дерево порядковых статистик), V.D (дерево отрезков); размеры компонент — подсчёт числа компонент по корням

## **5. Weighted DSU (потенциалы к корню)**
* **Определение:** каждое ребро леса несёт вес — разность потенциалов: `pot[x]` — значение `x` относительно `parent[x]`; `find` возвращает пару `(корень, накопленный потенциал)` — значение узла относительно корня
* **Задачи:** паритет (чёт/нечёт по mod k), взвешенные равенства (`val[x] + w == val[y]`), относительные порядки (классы по остаткам)
* **Формулы:** значение `x` относительно корня — сумма потенциалов по пути; при `unite(x, y, w)` с известными корнями `rx, ry`: `pot[rx] = pot[y] − pot[x] + w` (в аддитивной группе; знаки — по направлению подвешивания)
* **Сложность:** O(α(n)) амортизированно; сжатие путей требует пересчёта потенциалов вдоль пути (сумма накапливается при подъёме)
* **Обобщение:** группа потенциалов — параметр (постановка): аддитивная (целые; по модулю k — брать остатки от весов), мультипликативная (произведение, деление — обратный элемент); в реализации — аддитивная группа целых, обобщение на произвольную группу — подстановкой операции и обратной к ней
* **Реализация:** `WeightedDSU` (`find` → `(корень, потенциал)`, `unite(x, y, w)`, `query(x, y)` → `(связаны ли, разность потенциалов)`)
* **Связь:** паритет-задачи — графы с 2-цветной раскраской (`graph.md`); потенциалы — тот же приём, что расстояния в графе от корня

## **6. Rollback DSU (откат объединений)**
* **Определение:** операции `unite` протоколируют изменения в стеке; `rollback()` отменяет последнее объединение за O(1); снимок — размер стека
* **Почему работает:** каждое объединение меняет ≤ 2 ячейки (родитель корня и размер) — запись старых значений позволяет вернуть состояние; инвариант — стек операций (LIFO) в точности обратим
* **Ограничение:** сжатие путей запрещено (меняет многие ячейки) — только union by size: высота O(log n), откат по-прежнему корректен
* **Сложность:** `unite` O(log n), `rollback` O(1), `snapshot`/`rollback_to(snap)` O(1) (стек версий)
* **Обобщение:** стек изменений — общий приём отката (мост VII); роллбэк-время — обратный обход оффлайн (A.8); не только DSU, но и другие структуры (мост VII)
* **Реализация:** `RollbackDSU` (стек изменений `{индекс, старое_значение}`, `snapshot()`, `rollback_to(snapshot)`; размеры — в отдельном массиве)
* **Связь:** откаты — раздел VII (Rollback DSU там — полный разбор); дерево отрезков по времени — V.D

## **7. Persistent DSU (частичная персистентность)**
* **Определение:** версии структуры: `unite(a, b, v)` создаёт новую версию из версии `v`; запросы — к произвольной версии; частичная персистентность (старые версии только читаются)
* **Идея:** каждый массив `parent`/`sz` заменяется на «хронологию» ячеек: `timeline[x]` — вектор пар `(версия, значение)`; чтение ячейки в версии `v` — последняя запись с версией ≤ `v` (бинарный поиск); запись — добавление пары в конец
* **Почему работает:** path copying на уровне ячеек: каждая запись не разрушает прошлое — старые версии «видят» только свои записи
* **Сложность:** `find(x, v)` O(log n · log версий) (подъёмы + бинарный поиск в хронологии); память — O(записей)
* **Обобщение:** хронологии — частный случай персистентного массива (VII: path copying, fat node — здесь «fat node» по ячейкам); полностью персистентный DSU — обобщение на модификацию любой версии (VII)
* **Реализация:** `PersistentDSU` (`timelines` для parent и sz, `find(x, v)`, `unite(a, b, v) → новая_версия`)
* **Связь:** классификация персистентности — VII; персистентный массив — VII (Persistent Array)

## **8. DSU оффлайн с временными метками; Dynamic Connectivity**
* **Определение:** рёбра живут на интервалах времени `[l, r)`; запросы по времени (число компонент, связность пары) — оффлайн; динамическая связность онлайн (добавление И удаление) — мост XI
* **Приём «обратное время»:** если операции только удаляют рёбра — проходим время назад: удаления становятся добавлениями; каждый шаг — один `unite` (с данными из A.4 считаем компоненты)
* **Приём «дерево отрезков по времени»:** интервал жизни ребра кладётся в дерево отрезков (V.D) как ленивая пометка; DFS по дереву с rollback-структурой (A.6) даёт состояние в каждой точке времени — полное оффлайн-решение задач «рёбра живут на отрезках»
* **Сложность:** обратное время — O((m + q)·α(n)); дерево времени — O((m + q)·log m · α(n))
* **Обобщение:** «жизнь ребра» — параметр (интервалы по времени); запросы — произвольные агрегаты компонент (A.4)
* **Реализация:** демонстрация `components_after_removals_offline` (обратное время: удаления читаются назад и становятся `unite` на `DSU` из A.3); роллбэк-вариант (A.6) — для дерева отрезков по времени (V.D/VII, мост)
* **Связь:** динамическая связность онлайн — XI (Link-Cut Tree, Euler Tour Tree); откаты — A.6, VII; дерево отрезков с ленивыми пометками — V.D

# **B. БИТСЕТЫ**

## **1. Множество как битовый вектор; std::bitset**
* **Определение:** подмножество универсума `U = {0..n−1}` кодируется индикаторным вектором длины `n`: бит `i` = 1 ⟺ `i ∈ S`; операции множеств — побитовые над векторами; `std::bitset<N>` — встроенный контейнер (размер `N` — константа компиляции)
* **Почему работает:** одно машинное слово хранит `w` булевых признаков (`w` — бит в слове; на типовой платформе 64) — операции выполняются инструкциями процессора (битовая параллельность Word-RAM): `&, |, ^, ~, <<, >>` по словам
* **Операции:** `test(i)`, `set(i)`, `reset(i)`, `flip(i)`, `any/all/none`, `count` (число единиц), `to_string/to_ullong`
* **Сложность:** побитовые операции O(n/w) (`w` — бит в слове), `count` O(n/w); доступ к биту O(1)
* **Обобщение:** `n` и `w` — параметры: `w` бит для машинных слов, произвольный `n` — динамический битсет (B.2); маски до `w` бит — `unsigned long long` (discrete-and-logic)
* **Реализация:** демонстрация `std::bitset` в main (доступ, операции, count); маски в `SetsAndRelations`
* **Связь:** маски подмножеств и включения-исключения — `math/discrete-and-logic`; rank/select над битовыми векторами — B.7

## **2. Dynamic Bitset (собственный класс)**
* **Определение:** битсет с размером `n` — параметром (вводится в рантайме): `⌈n/w⌉` машинных слов; бит `i` — слово `i/w`, смещение `i mod w`
* **Почему свой:** `std::bitset` требует compile-time `N`; динамический — для задач с вводом `n`, роста размера и частичных операций
* **Устройство:** последнее слово маскируется до `n mod w` битов (выход за границы обнуляется); доступ к биту — `(word[i/w] >> (i mod w)) & 1`
* **Сложность:** установка/сброс/чтение бита O(1), операции над всем множеством O(n/w)
* **Обобщение:** слово и число слов — параметры (`w` — бит в слове, размер маски); пустой/полный битсет — параметр fill (false/true)
* **Реализация:** `DynamicBitset` (`set/reset/flip/test`, `all/any/none`, маскирование хвоста)
* **Связь:** образец хранения слов — `BitBoard` (I.A.3.17); индексация «слово + смещение» — та же, что в многомерных массивах (I.A.1.2)

## **3. Операции с множествами (union / intersection / difference)**
* **Определение:** поразрядные операции над индикаторными векторами: `∪, ∩, \`, симметрическая разность `Δ`, дополнение `¬`, включение `⊆`; выполняются по словам — каждый бит обрабатывается одновременно
* **Почему работает:** индикаторная функция композируется побитово: `χ_{A∪B} = χ_A | χ_B` и т.д. — корректность на уровне битов, скорость на уровне слов
* **Сложность:** O(n/w) на операцию — в `w` раз быстрее поштучной обработки
* **Обобщение:** операции — параметр; примитивы слова из `SetsAndRelations` (`set_union`, `set_intersection`, `set_difference`, `set_symmetric_difference`, `is_subset`) применяются к каждому слову; дополнение — побитовое `~` по словам с обрезкой хвоста (там `set_complement` корректен для масок до `w` бит)
* **Реализация:** функции `bit_union/bit_intersection/bit_difference/bit_symmetric_difference/bit_complement/bit_is_subset` над `DynamicBitset` (переиспользуют `SetsAndRelations` по словам; дополнение и включение — с учётом размера `n`)
* **Связь:** примитивы слова — `math/discrete-and-logic`; FID и битовые операции — B.7

## **4. Bit Count: popcount и rank**
* **Определение:** `popcount(S)` — число элементов множества (число единиц); `rank(i)` — число единиц на префиксе `[0, i)` — порядок `i`-го бита среди установленных
* **Почему работает:** popcount слова — инструкция процессора (`__builtin_popcountll` / `SetsAndRelations::set_cardinality`); rank — префиксные суммы по словам (та же идея, что V.A) плюс popcount частичного слова
* **Сложность:** popcount O(n/w); rank наивный O(n/w) на запрос; rank по таблице префиксных сумм слов — O(1) на запрос (полные слова из таблицы + popcount хвостового слова); суперблоки дают O(1) и по битам — B.7
* **Обобщение:** rank — «номер установленного бита в отсортированном множестве» (мост к select и порядковым статистикам); popcount — размер класса (A.4) и метрика близости
* **Реализация:** `bit_popcount`, `bit_rank_prefix(i)` (наивная сумма слов), `RankTable` (префиксные суммы слов, `rank(i)` за O(1))
* **Связь:** префиксные суммы — V.A; rank/select структуры — B.7; `dp |= dp << x` — B.6

## **5. Перебор единиц (следующий установленный бит)**
* **Определение:** итерация по установленным битам множества за O(popcount), а не O(n): младший установленный бит слова — `lsb = w & −w`, его позиция — `ctz`; следующий — сбросить lsb и повторить
* **Почему работает:** `w & −w` извлекает младший бит (двоичное дополнение), `ctz` даёт его позицию за одну инструкцию; число итераций = число единиц
* **Сложность:** O(popcount) на полный перебор; следующий установленный после позиции `i` — O(1) на слово
* **Обобщение:** перебор нулей — перебор единиц дополнения (B.3); перебор подмножеств маски — `submasks_of` (discrete-and-logic); select(k) — k-й установленный бит — B.7
* **Реализация:** `for_each_set_bit(f)` (обратный вызов по установленным битам), `next_set_bit(from)` (первый установленный ≥ `from`), `collect_set_bits`
* **Связь:** сжатие множеств (перечисление элементов без сканирования всего универсума); выборка элементов по маске — комбинаторные переборы

## **6. Применения**
* **Рюкзак `dp |= dp << x`:** достижимость сумм: `dp` — битсет достижимых сумм; переход — сдвиг битсета влево на `x` и побитовое ИЛИ (по словам: сдвиг + `set_union`); параметры — множество весов и предел суммы
* **Сжатие множеств:** битсет вместо `vector<bool>`/`set` — в `w` раз меньше памяти, побитовые массовые операции (например, «все элементы X уже обработаны» — one AND)
* **Динамические булевы маски:** достижимость в графе (Warshall: `reach |= reach & adj` — по строкам битсетов, мост graph.md), memoization на битмаску в переборах `2^n` (параметр `n`), фильтры признаков (AND/OR по атрибутам)
* **Сложность:** рюкзак O(n·S/w) (вместо O(n·S)); Warshall на битсетах O(n³/w)
* **Обобщение:** операции сдвига и ИЛИ — параметры (сдвиг вправо для «деления», сдвиг по словам для больших пределов); предел рюкзака — параметр S
* **Реализация:** `knapsack_bitset` (сдвиг по словам `shift_left_bitset` + ИЛИ по словам), `transitive_closure_bitset` (Warshall), демо достижимых сумм
* **Связь:** рюкзак — `dynamic.md` (J.2); достижимость в графе — `graph.md`; супермножества подмножеств (zeta) — discrete-and-logic

## **7. Rank/Select и сукцинктное хранение (FID)**
* **Определение:** над битовым вектором (в духе B.2) строятся две операции: `rank(i)` — число единиц на префиксе `[0, i)`, `select(k)` — позиция k-й единицы (1-индексированная); битовый вектор с поддержкой rank/select и близким к энтропийному пределу хранением называется FID (Fully Indexable Dictionary) — базовый примитив сукцинктных структур (Wavelet Matrix — II.G.4)
* **Почему работает:** «крупные счётчики + мелкие поправки»: префиксные суммы по суперблокам (каждый ~`B` бит, поправка на слово через popcount) дают rank за O(1) по нескольким словам; select — спуск по суперблокам с указателями на первые единицы + двоичный поиск внутри
* **Сложность:** rank — O(1) на запрос; select — O(1) на запрос (спуск по двум уровням блоков); память — сукцинктная: сам вектор + o(n) бит таблиц
* **Обобщение:** размеры блоков `B` — параметр (компромисс памяти и константы); мультиплексируемые слова (несколько бит на элемент) — та же схема с подблоками; `popcount`-примитивы слова — B.4
* **Принцип сукцинктности:** память ≈ информации (энтропия данных) — хранение близко к теоретическому пределу, асимптотика в битах на элемент, а не в словах
* **Реализация:** `RankSelect` (битовый вектор + префиксные таблицы суперблоков/блоков, `rank`, `select`, `count`); `FID` = `RankSelect` как базовый примитив (та же схема)
* **Связь:** rank/select для Wavelet Matrix — II.G.4; порядковые статистики на деревьях — II.G.2; префиксные суммы — V.A
