## **A. БАЗОВЫЕ ПОНЯТИЯ, ПРЕДСТАВЛЕНИЯ И ОБХОДЫ**
> `a/a.md` · `a/a.cpp` · `struct GraphBasics` — базовый класс всей ветки graph

### **A. Основные определения и классификация**
*   **Типы графов (обобщение на параметры):**
    *   `Directed` / `Undirected` (ориентированные/неориентированные): параметр направления рёбер
    *   `Weighted` / `Unweighted` (взвешенные/невзвешенные): тип веса `W` (целый/вещественный)
    *   `Simple` / `Multigraph` (простые/мультиграфы): допустимость кратных рёбер
    *   `Complete K_n` / `Empty` (полные/пустые): число рёбер `|E| = n(n−1)/2` (неориент.)
    *   `Bipartite` / `General` (двудольные/общие): двухцветная раскраска как критерий
    *   `Connected` / `Disconnected` (связные/несвязные): число компонент связности
    *   `Acyclic` / `Cyclic` (ациклические/циклические): DAG (ориент.), лес (неориент.)
    *   `Dense` / `Sparse` (густые/разреженные): `|E| ≈ |V|²` vs `|E| ≈ |V|`
*   **Параметры графа:** `|V| = n` (число вершин), `|E| = m` (число рёбер), `deg(v)` (степень вершины), `δ(G)` (мин. степень), `Δ(G)` (макс. степень), суммарная степень `Σ deg(v) = 2m` (лемма о рукопожатиях)
*   **Свойства:** регулярность (`k`-регулярный: все степени = `k`), коэффициент кластеризации `C = 3·|треугольники| / |треойники|`, диаметр `diam(G) = max_{u,v} dist(u,v)`, плотность `m / (n(n−1)/2)`
*   **Связь:** классификация определяет применимость алгоритмов (разделы II–XIII); двудольность — критерий через раскраску (II.D); ацикличность — через DFS (I.C)

### **B. Представления графов в памяти**
*   **Списки смежности (Adjacency List):**
    *   `vector<vector<pair<int,W>>>` или `vector<vector<int>>` — для каждого узла список соседей с весами
    *   Space: `O(n + m)`, проверка ребра `O(deg(v))`, перебор соседей `O(deg(v))`
    *   Динамические списки (vector), сжатые списки (CSR/CSC), индексированные списки
    *   **Применение:** обходы (BFS/DFS), поиск кратчайших путей — основное представление для разреженных графов
*   **Матрица смежности (Adjacency Matrix):**
    *   `vector<vector<W>> adj` размера `n × n` — `adj[i][j] = вес` или `INF`/`0` (нет ребра)
    *   Space: `O(n²)`, проверка ребра `O(1)`, умножение матриц `O(n³)`
    *   Битовая матрица: `vector<bitset<N>>` для невзвешенных — `O(n²/64)` на проверку
    *   **Применение:** Floyd-Warshall (III.B), умножение матриц для числа путей, полные графы
*   **Список рёбер (Edge List):**
    *   `vector<tuple<int,int,W>>` — все рёбра подряд
    *   Space: `O(m)`, сортировка `O(m log m)` — база для Крускала (IV.A)
    *   **Применение:** Kruskal, алгоритм Кагера (минимальный разрез), offline-задачи
*   **Специализированные представления:**
    *   **CSR/CSC** (Compressed Sparse Row/Column): два массива (offsets + edges) — компактность + кэш-локальность; `O(n + m)` памяти, `O(1)` доступ к первому соседу, `O(deg(v))` полный перебор
    *   **Forward Star:** аналог CSR для онлайн-построения (динамические добавления рёбер)
    *   **Incidence Matrix:** `n × m` матрица (вершина × ребро) — для теоретических конструкций (матрица Кирхгофа — IV.C)
    *   **Implicit Graph:** граф задаётся функцией `neighbors(v)` — для больших графов, генерируемых на лету (пазлы, игры)
*   **Сравнение представлений:**

| Операция | Adj List | Adj Matrix | Edge List | CSR |
|---|---|---|---|---|
| Проверка ребра (u,v) | O(deg(u)) | O(1) | O(m) | O(log deg(u)) |
| Перебор соседей v | O(deg(v)) | O(n) | O(m) | O(deg(v)) |
| Добавление ребра | O(1)* | O(1) | O(1)* | O(n+m)** |
| Память | O(n+m) | O(n²) | O(m) | O(n+m) |

\* амортизированно; ** пересборка

### **C. Поиск в глубину (DFS)**
*   **Базовый DFS:**
    *   Рекурсивный: `dfs(v)`: пометить `v`, для каждого соседа `u`: если не посещён — `dfs(u)`
    *   Итеративный (стек): имитация рекурсии через explicit stack — избегает переполнения стека при `n ~ 10⁵–10⁶`
    *   Сложность: `O(n + m)` — каждая вершина и каждое ребро рассматриваются один раз
    *   Порядок обхода зависит от порядка соседей в представлении
*   **Метки времени (timestamping):**
    *   `tin[v]` — время входа, `tout[v]` — время выхода; глобальный таймер
    *   `v` — предок `u` ⟺ `tin[v] < tin[u] && tout[u] < tout[v]` — проверка за O(1)
    *   Дерево DFS (DFS Tree): рёбра дерева (tree edges) + обратные (back), прямые (forward), поперечные (cross) — классификация всех рёбер
    *   **Применение:** поиск циклов (обратное ребро), проверка двудольности (двухцветность), топологическая сортировка (обратный порядок выхода)
*   **Применения DFS:**
    *   **Проверка на циклы:** ориентированные — обратное ребро (не в дерево); неориентированные — посещённый не-родитель
    *   **Компоненты связности:** число запусков DFS = число компонент
    *   **Топологическая сортировка:** обратный порядок `tout` (или Kahn's algorithm через BFS — II)
    *   **Точки сочленения и мосты:** `low[v] = min(tin[v], tin[обратные рёбра], tin[детей с low ≥ tin[v]])` — раздел B.B
    *   **Копирование графов (Deep Clone):** DFS/BFS + хеш-таблица маппинга старых→новых узлов
*   **Продвинутые техники DFS:**
    *   **Iterative Deepening DFS (IDDFS):** BFS-качество + DFS-память; `O(b^d)` времени, `O(d)` памяти; для графов с неизвестной глубиной
    *   **DFS Tree/Forest:** дерево + обратные/прямые/поперечные рёбра — фундамент для анализа (II, III)
    *   **Backtracking как DFS:** перебор с возвратом — стек решений, проверка на листе

### **D. Поиск в ширину (BFS)**
*   **Базовый BFS:**
    *   Очередь `q`: пометить начальную вершину, положить в `q`; пока `q` не пуста: извлечь `v`, для каждого непосещённого соседа `u`: пометить, положить в `q`
    *   Слои: `dist[v]` = расстояние от источника; все вершины на расстоянии `d` обрабатываются до вершин на расстоянии `d+1`
    *   Сложность: `O(n + m)` — как DFS
*   **BFS для кратчайших путей:**
    *   В невзвешенных графах: `dist[v]` = минимальное число рёбер от источника
    *   Восстановление пути: `prev[v]` — предыдущая вершина в BFS-дереве
*   **Продвинутые варианты BFS:**
    *   **Bidirectional BFS:** два фронтира (от источника и цели), встреча в середине; `O(b^{d/2})` вместо `O(b^d)` — выигрыш при большом `d` и известной цели
    *   **0-1 BFS:** граф с весами `{0, 1}`; deque: вес 0 — в начало, вес 1 — в конец; `O(n + m)` — как BFS
    *   **BFS 0-k:** граф с ограниченными весами `0 ≤ w ≤ k`; `k+1` очередей — циклическое переключение; `O(k·(n + m))`
    *   **Multi-source BFS:** несколько источников одновременно; инициализация `q` всеми источниками — для задач «распространение» (волновой алгоритм)
    *   **BFS на implicit graphs:** граф генерируется на лету; память — только фронтир
*   **Применения BFS:**
    *   Shortest path в невзвешенных графах
    *   Connected components (альтернатива DFS)
    *   Bipartite checking (двухцветность через уровни)
    *   Web crawling, Level-order traversal деревьев

## **B. СВЯЗНОСТЬ В ГРАФАХ**
> `b/b.md` · `b/b.cpp` · `struct ConnectivityAlgorithms : GraphBasics`

### **A. Компоненты связности**
*   **Для неориентированных графов:**
    *   Connected Components: DFS/BFS от каждой непосещённой вершины — `O(n + m)`
    *   **Биекция:** число компонент = число запусков DFS/BFS
    *   **Biconnected Components** (двусвязные компоненты):
        *   Двусвязность: граф остаётся связным после удаления любой вершины
        *   Через точки сочленения (articulation points) — см. II.B
        *   Алгоритм Тарьяна для biconnected components через стек рёбер DFS
    *   **Edge Biconnected Components:** через мосты (удаление мостов разбивает на компоненты)
*   **Для ориентированных графов:**
    *   **Strongly Connected Components (SCC):**
        *   Kosaraju's Algorithm: два DFS (прямой + обратный граф) — `O(n + m)`
        *   Tarjan's Algorithm: один DFS + стек + `lowlink` — `O(n + m)`
        *   Condensation graph (конденсация графа): DAG из SCC — ациклический граф компонент
    *   **Weakly Connected Components:** связность при замене ориентированных рёбер на неориентированные
*   **Union-Find для динамической связности:**
    *   Добавление рёбер: `union(u, v)` — амортизированно `O(α(n))` (обратная функция Акермана)
    *   Связь: полная реализация — `struct.md` (III.A); здесь — только применение

### **B. Мосты и точки сочленения (Bridges and Articulation Points)**
*   **Мосты (Bridges):**
    *   Определение: ребро `(u,v)`, удаление которого увеличивает число компонент
    *   Алгоритм Тарьяна: один DFS, `low[v] = min(tin[v], tin[обратные], tin[детей с low > tin[v]])`; мост ⟺ `low[to] > tin[v]`
    *   Сложность: `O(n + m)`
    *   Мосты в ориентированных графах: определение через компоненты сильной связности
*   **Точки сочленения (Articulation Points):**
    *   Определение: вершина, удаление которой увеличивает число компонент
    *   Критерий (корень DFS-дерева): ≥ 2 детей в DFS-дереве
    *   Критерий (не корень): `low[to] ≥ tin[v]` для хотя бы одного ребёнка
    *   Сложность: `O(n + m)`
*   **Online-алгоритмы для мостов:**
    *   Динамическое поддержание: добавление/удаление рёбер с поддержкой мостов
    *   Euler Tour Trees (ETT) — `struct.md` (XI.F)
    *   Link-Cut Trees — `struct.md` (XI.F)
    *   Holm-de Lichtenberg-Thorup: амортизированный `O(log² n)` на операцию

### **C. k-связность и минимальные разрезы**
*   **Вершинная связность (Vertex Connectivity):**
    *   k-вершинная связность: граф остаётся связным после удаления любых `k−1` вершин
    *   Теорема Менгера: k-связность эквивалентна существованию `k` независимых путей между любой парой вершин
    *   Алгоритм поиска минимального вершинного разреза: `O(n · maxflow)`
*   **Рёберная связность (Edge Connectivity):**
    *   k-рёберная связность: удаление любых `k−1` рёбер не разрывает граф
    *   Минимальный разрез по рёбрам = максимальный поток между любой парой (теорема о max-flow min-cut — VIII.B)
    *   **Алгоритм Кагера (Karger's Algorithm):**
        *   Рандомизированный: случайное стягивание рёбер, повторение `O(n² log n)` раз
        *   Karger-Stein: рекурсивное разбиение, `O(n² log n)` детерминированно
    *   **Stoer-Wagner:** глобальный min-cut для неориентированных графов за `O(n³)` или `O(nm + n² log n)`
*   **Глобальная минимальная связность:**
    *   Нахождение k-связности графа: бинарный поиск по `k` + проверка `k`-связности
    *   Проверка k-вершинной/рёберной связности: через max-flow между парами

### **D. Двудольные графы и раскраски**
*   **Проверка двудольности:**
    *   BFS/DFS с двухцветкой: `color[v] ∈ {0, 1}`; ребро `(u,v)` → `color[v] = 1 − color[u]`; конфликт ⟺ не двудолен
    *   Сложность: `O(n + m)`
*   **Раскраски графов (обобщение):**
    *   **Vertex Coloring:**
        *   Greedy coloring: `O(n + m)` — по порядку вершин, первый доступный цвет
        *   Welsh-Powell: сортировка по убыванию степени + greedy
        *   Хроматическое число `χ(G)`: NP-трудно в общем случае; для двудольных `χ = 2`
    *   **Edge Coloring:**
        *   Vizing's theorem: `χ'(G) ≤ Δ(G) + 1` (точность ±1)
        *   Для двудольных: `χ'(G) = Δ(G)` (теорема Кёнига — VII.D)
    *   **Особые раскраски:** acyclic, star, harmonious — ограничения на циклы/подграфы
*   **Теоремы о раскрасках:**
    *   Four Color Theorem: `χ(G) ≤ 4` для планарных графов (доказано компьютером, 1976)
    *   Five Color Theorem: `χ(G) ≤ 5` — элементарное доказательство
    *   Brooks' Theorem: `χ(G) ≤ Δ(G)` кроме полных графов `K_{n+1}` и нечётных циклов
    *   Lower bound: `χ(G) ≥ n / α(G)` где `α(G)` — размер максимального независимого множества

### **E. Динамическая связность**
*   **Incremental Connectivity:** добавление рёбер — DSU `O(α(n))` на операцию
*   **Decremental Connectivity:** удаление рёбер — offline через обратный ход времени + DSU с откатами
*   **Fully Dynamic Connectivity:**
    *   Euler Tour Trees (ETT): деревья на связных компонентах — `O(log² n)` на операцию
    *   Link-Cut Trees: `O(log n)` на операцию — `struct.md` (XI.F)
    *   Holm-de Lichtenberg-Thorup: амортизированный `O(log² n)` — верхняя граница `m` обновлений

### **F. 2-SAT и конденсация графа импликаций**
*   **2-SAT Problem:**
    *   Формулировка: набор дизъюнкций `(a ∨ b)` из двух литералов; satisfiability за `O(n + m)`
    *   Сведение к графу: каждая дизъюнкция `(a ∨ b)` → рёбра `(¬a → b)` и `(¬b → a)`
    *   Построение: `2n` вершин (литералы и их отрицания), `2m` рёбер (импликации)
*   **Решение 2-SAT:**
    *   Поиск SCC в графе импликаций: компонента содержит `x` и `¬x` ⟺ UNSAT
    *   Построение решения: компоненты в топологическом порядке; `x` ∈ компоненте с меньшим `order` → `false`
    *   Сложность: `O(n + m)` через Kosaraju/Tarjan
*   **Применения 2-SAT:**
    *   Scheduling (расписание с ограничениями: «если A, то не B»)
    *   Circuit design (схемотехника)
    *   Resource allocation (ограничения на совместимость)
    *   Обобщение: k-SAT — NP-полна при `k ≥ 3`

## **C. КРАТЧАЙШИЕ ПУТИ В ГРАФАХ**
> `c/c.md` · `c/c.cpp` · `struct ShortestPaths : ConnectivityAlgorithms`

### **A. Одноисточниковые кратчайшие пути (SSSP)**
*   **Для невзвешенных графов:** BFS — `O(n + m)` (уже в разделе I.D)
*   **Для неотрицательных весов (Dijkstra):**
    *   **Алгоритм Дейкстры:**
        *   Идея: жадный выбор ближайшей непосещённой вершины; релаксация `dist[v] = min(dist[v], dist[u] + w(u,v))`
        *   **Реализация (binary heap):** priority queue + decrease-key (или вставка дубликатов); `O((n + m) log n)`
        *   **Реализация (Fibonacci heap):** `O(m + n log n)` — лучшая асимптотика; практически — pairing heap (`struct.md` IV)
        *   **Реализация (Dial's):** для целых весов `0 ≤ w ≤ C`: bucket queue `O(n + m + C)` — `struct.md` (IV, Radix/Bucket Heap)
    *   **Восстановление пути:** `prev[v]` при релаксации
    *   **Корректность:** инвариант — при извлечении `v` из PQ, `dist[v]` оптимален (доказательство через обмен аргументов)
    *   **Границы:** не работает с отрицательными весами (отрицательный цикл ломает жадность)
    *   **Биекционная Дейкstra (Bidirectional Dijkstra):** два направления, встреча в середине; выигрыш вдвое по пространству
*   **Для произвольных весов (Bellman-Ford):**
    *   **Алгоритм Беллмана-Форда:**
        *   Идея: `n−1` проходов по всем рёбрам; релаксация `dist[v] = min(dist[v], dist[u] + w(u,v))`; после `n−1` итераций — проверка на отрицательные циклы
        *   Сложность: `O(nm)` — для каждого ребра проверяем `n−1` раз
        *   Отрицательные циклы: ещё один проход — если релаксация возможна, цикл существует
    *   **Shortest Path Faster Algorithm (SPFA):**
        *   Оптимизация: в очередь попадают только изменённые вершины; в среднем `O(m)`, худший `O(nm)`
    *   **Алгоритм Левита:** три очереди (0-weight, 1-weight, rest) — `O(nm)` в худшем, лучше на практике
*   **Для DAG (Directed Acyclic Graph):**
    *   Топологическая сортировка + релаксация в топологическом порядке: `O(n + m)`
    *   Longest path в DAG: `−w` вместо `w` → shortest path; или `dist[v] = max(dist[u] + w(u,v))`
    *   **Применение:** критический путь в диаграммах Ганта, оптимизация цепочек зависимостей

### **B. Кратчайшие пути между всеми парами (APSP)**
*   **Алгоритм Флойда-Уоршелла:**
    *   ДП по промежуточным вершинам: `dp[k][i][j] = min(dp[k−1][i][j], dp[k−1][i][k] + dp[k−1][k][j])`
    *   Сложность: `O(n³)`, память `O(n²)` (оптимизация: один 2D-массив, `k` — внешний цикл)
    *   Восстановление пути: `next[i][j]` — первая вершина после `i` на пути в `j`
    *   Транзитивное замыкание: замена `min` на `|` (логическое ИЛИ)
    *   Обнаружение отрицательных циклов: `dp[i][i] < 0` для некоторой `i`
*   **Алгоритм Джонсона (Johnson's Algorithm):**
    *   Для разреженных графов с отрицательными весами: добавление виртуальной вершины `s`, Bellman-Ford от `s` для перезахвата весов, затем `n` запусков Дейкстры
    *   Сложность: `O(nm + n² log n)` — лучше `O(n³)` при `m = o(n²)`
*   **Специальные алгоритмы:**
    *   **Matrix Multiplication method:** `dp[k][i][j] = min(dp[k−1][i][j], dp[k/2][i][t] + dp[k/2][t][j])` через min-plus matrix multiplication; `O(n³ log n)` через возведение в степень
    *   **Подсчёт путей фиксированной длины:** степень матрицы смежности `A^k` — `O(n³ log k)` возведением в степень
*   **Для разреженных графов:** `n` запусков Dijkstra `O(n(m + n) log n)` или Johnson `O(nm + n² log n)`

### **C. Эвристические алгоритмы поиска пути**
*   **A* Search Algorithm:**
    *   Функция оценки: `f(v) = g(v) + h(v)`, где `g(v)` — стоимость от старта, `h(v)` — эвристика до цели
    *   **Admissible heuristic:** `h(v) ≤ h*(v)` (реальная стоимость) — гарантия оптимальности
    *   **Consistent heuristic:** `h(v) ≤ c(v,u) + h(u)` —更强的 условие, не требует reopen
    *   Сложность: `O(b^d)` в худшем, на практике экспоненциально лучше BFS при хорошей эвристике
*   **Greedy Best First Search:** `f(v) = h(v)` — только эвристика; не оптимален, но быстр
*   **IDA* (Iterative Deepening A*):** порог `f ≤ limit`, увеличение порога; `O(b^d)` времени, `O(d)` памяти
*   **D* и D* Lite:** для динамических сред (робототехника): пересчёт пути при изменении карты

### **D. Специальные виды путей**
*   **k-кратчайших путей:**
    *   Yen's algorithm: `k` shortest loopless paths за `O(kn(m + n log n))`
    *   Eppstein's algorithm: `O(m + n log n + k)` через suffix structures на дереве путей
*   **Наиболее надёжные пути (Most Reliable):** `max Π pᵢ` через `−log pᵢ` → shortest path
*   **Пути с ограничениями:** по времени, ресурсам — расширенное состояние `(вершина, остаток)` → BFS/Dijkstra

## **D. ОСТОВНЫЕ ДЕРЕВЬЯ (SPANNING TREES)**
> `d/d.md` · `d/d.cpp` · `struct SpanningTrees : ShortestPaths`

### **A. Минимальное остовное дерево (MST)**
*   **Алгоритм Крускала (Kruskal):**
    *   Сортировка рёбер по весу `O(m log m)`, перебор: если `(u,v)` в разных компонентах — добавить, объединить через DSU
    *   Сложность: `O(m log m)` (или `O(m α(n))` с DSU)
    *   Корректность:.cut property — для любого разреза самое лёгкое ребро принадлежит MST
    *   Связь: DSU — `struct.md` (III.A)
*   **Алгоритм Прима (Prim):**
    *   Дейкстра-подобный: начиная с одной вершины, всегда добавляем минимальное ребро к посещённым
    *   Сложность: `O((n + m) log n)` с binary heap; `O(m + n log n)` с Fibonacci heap
*   **Алгоритм Борувки (Boruvka):**
    *   Итеративно: каждая компонента выбирает минимальное исходящее ребро — объединение
    *   Сложность: `O(m log n)` — каждый шаг сокращает число компонент вдвое
    *   Параллелизм: шаги параллелизуемы — хорошо для распределённых вычислений
*   **Сравнение алгоритмов:** все три дают одно и то же MST для графов с уникальными весами; при равных весах — множество MST

### **B. Второе по минимальности остовное дерево**
*   **Second-best MST:**
    *   Алгоритм за `O(m log n)`: построить MST, для каждого не-MST-ребра найти максимум на пути в MST (LCA + sparse table), минимизировать разницу
    *   Связь: LCA — `struct.md` (VI.B); Sparse Table — `struct.md` (V.C)
*   **Minimum Bottleneck Spanning Tree (MBST):** дерево, минимизирующее максимальный вес ребра; совпадает с MST по bottleneck-свойству
*   **Minimum Spanning Forest:** для несвязных графов — MST на каждой компоненте

### **C. Теоретические основы**
*   **Матричная теорема Кирхгофа:**
    *   Laplacian matrix `L = D − A` (D — диагональ степеней, A — матрица смежности)
    *   Число остовных деревьев = любой минор `n−1`-го порядка матрицы `L` (определитель)
    *   Подсчёт через `det(L')` за `O(n³)` (Гаусс)
*   **Код Прюфера:**
    *   Биекция: деревья на `n` вершинах ↔ последовательности Прюфера длины `n−2`
    *   Построение кода: `O(n log n)` (множество доступных листьев)
    *   Восстановление дерева по коду: `O(n log n)` или `O(n)` с кучей
*   **Формула Кэли:** `n^{n−2}` деревьев на `n` маркированных вершинах (обобщение через Кирхгофа/Прюфер)

### **D. Обратные задачи и оптимизации**
*   **Steiner Tree Problem:**
    *   Задача: соединить заданное подмножество `T ⊆ V` (терминалы) минимальным деревом
    *   NP-трудна; приближённый алгоритм за `O(3^k · poly(n))` где `|T| = k` (DP по подмножествам терминалов)
    *   Метрический случай: 2-приближение через MST на терминалах
*   **Degree-constrained MST:** MST с ограничением на степени вершин — NP-трудна; эвристики
*   **Capacitated MST:** MST с ограничением на пропускную способность поддеревьев

## **E. ЭЙЛЕРОВЫ И ГАМИЛЬТОНОВЫ ГРАФЫ**
> `e/e.md` · `e/e.cpp` · `struct EulerHamilton : SpanningTrees`

### **A. Эйлеровы пути и циклы**
*   **Основные определения:**
    *   Эйлеров цикл: проходит через каждое ребро ровно один раз и возвращается в начальную вершину
    *   Эйлеров путь: проходит через каждое ребро ровно один раз (может заканчиваться в другой вершине)
*   **Критерии эйлеровости:**
    *   Неориентированные: эйлеров цикл ⟺ граф связен и все степени чётны; эйлеров путь ⟺ связен и ровно 2 вершины с нечётной степенью
    *   Ориентированные: эйлеров цикл ⟺ граф слабо связен и для каждой вершины `in(v) = out(v)`; эйлеров путь ⟺ связен и ≤ 2 вершин с `in(v) ≠ out(v)`
*   **Алгоритмы поиска:**
    *   **Алгоритм Флёри (Fleury):** «не пересекай мост, если есть альтернатива» — `O(m²)`
    *   **Алгоритм Хьерхольцера (Hierholzer):** циклическое слияние циклов — `O(m)` — оптимальный
*   **Применения:**
    *   **Задача китайского почтальона (Chinese Postman):** найти кратчайший путь, проходящий через каждое ребро ≥ 1 раз; решение: удвоение рёбер нечётного разреза → MST на нечётных вершинах; `O(n³)` (Floyd-Warshall + DP по подмножествам нечётных)
    *   ДНК-секвенирование (суперстроки), маршрутизация в сетях

### **B. Гамильтоновы пути и циклы**
*   **Основные определения:**
    *   Гамильтонов цикл: проходит через каждую вершину ровно один раз и возвращается
    *   Гамильтонов путь: проходит через каждую вершину ровно один раз
*   **Достаточные условия (теоремы):**
    *   Теорема Дирака: если `deg(v) ≥ n/2` для всех `v` → существует гамильтонов цикл
    *   Теорема Оре: если `deg(u) + deg(v) ≥ n` для всех не смежных `u, v` → существует гамильтонов цикл
    *   Теорема Поша: если `|N(u) ∪ N(v)| ≥ n` для любых не смежных `u, v` → гамильтонов цикл
    *   Теорема Бонди-Хватала: обобщение через s-процедуру
*   **Алгоритмы поиска:**
    *   **Алгоритм Робертса-Флореса:** backtracking — `O(n!)` худший, с обрезками
    *   **Алгоритм Хелда-Карпа (DP with bitmask):** `dp[mask][v]` — прошли маску, текущая вершина `v`; `O(2^n · n²)` времени, `O(2^n · n)` памяти — `dynamic.md` (E)
    *   Метод ветвей и границ
*   **NP-полнота:** проверка существования гамильтонова цикла — NP-полна; приближённые алгоритмы для метрического TSP

### **C. Обобщённые задачи**
*   **Longest Path Problem:**
    *   В произвольных графах: NP-hard
    *   В DAG: полиномиально через топологическую сортировку + DP `O(n + m)` — раздел C.A
*   **Traveling Salesman Problem (TSP):**
    *   Классическая формулировка: гамильтонов цикл минимальной стоимости
    *   Метрический TSP: неравенство треугольника → 3/2-приближение (Christofides)
    *   Точное решение: Held-Karp `O(2^n · n²)` — `dynamic.md` (E)

## **F. ДЕРЕВЬЯ И ИХ ДЕКОМПОЗИЦИИ**
> `f/f.md` · `f/f.cpp` · `struct TreeAlgorithms : EulerHamilton`

### **A. Базовые запросы на деревьях**
*   Diameter of tree: два DFS (от произвольной → самая дальняя → от неё) или однопроходное DP; `O(n)`
*   Центр(ы) дерева: середина диаметра; `O(n)`
*   Minimum Path Sum, Even Tree (удаление рёбер для равных поддеревьев)

### **B. Наименьший общий предок (Lowest Common Ancestor - LCA)**
*   **Бинарные подъёмы (Binary Lifting):**
    *   Предподсчёт: `up[v][j]` — `2^j`-й предок `v`; `O(n log n)` время и память
    *   Запрос LCA: выравнивание глубин + подъём на `log n` шагов; `O(log n)`
    *   Поддержка: min/max/sum на пути через `dp[v][j]` (атомарное значение на отрезке длины `2^j`)
    *   Связь: реализация — `struct.md` (VI.B); здесь — применение
*   **Сведение к RMQ:**
    *   Euler Tour + RMQ: `O(n)` предподсчёт (Sparse Table), `O(1)` запрос — `struct.md` (V.C)
    *   **Алгоритм Фарах-Колтона и Бендера:** RMQ за `O(n)` предподсчёт, `O(1)` запрос; ±1 RMQ для деревьев
*   **Метод эйлерова обхода:**
    *   Euler Tour Technique: преобразование дерева в массив через DFS; диапазон поддерева `[tin[v], tout[v]]`
*   **Tarjan's Offline LCA:** `O(n + Q)` для оффлайн запросов через Union-Find — `struct.md` (III.A)
*   **Динамическое LCA:** Link-Cut Trees для динамически изменяющихся деревьев — `struct.md` (XI.F)

### **C. Декомпозиции деревьев**
*   **Heavy-Light Decomposition (HLD):**
    *   Разбиение дерева на тяжёлые/лёгкие пути: каждый путь — непрерывный отрезок в массиве
    *   Запросы на путях: `O(log² n)` через дерево отрезков на HLD (один запрос = `O(log n)` отрезков × `O(log n)` на дереве отрезков)
    *   Связь: дерево отрезков — `struct.md` (V.D); здесь — применение
*   **Центроидная декомпозиция (Centroid Decomposition):**
    *   Разбиение: центроид текущего дерева → рекурсия на компонентах; высота `O(log n)`
    *   Применение: задачи «все пути через центроид», подсчёт пар с расстоянием ≤ `k`
*   **Лестничная декомпозиция (Ladder Decomposition):** для LCA и запросов на путях
*   **Моноидная декомпозиция:** обобщение на произвольные моноидные операции

### **D. Продвинутые алгоритмы на деревьях**
*   **DSU on Tree (Sack):**
    *   Merge small-to-large: при слиянии поддеревьев перебираем меньшее; `O(n log n)` суммарно
    *   Запросы на поддеревьях: подсчёт частот, «тяжёлый ребёнок» сохраняется
*   **Rerooting DP:**
    *   Переподвешивание корня: `down[v]` (ответ в поддереве), `up[v]` (вне поддерева); перенос через ребро
    *   Пример: сумма расстояний до всех вершин; ответ для каждого корня за `O(n)` суммарно
    *   Связь: `dynamic.md` (G)
*   **Virtual Trees:**
    *   Построение virtual tree по набору `k` вершин: сортировка по `tin`, стек; `O(k log k)`
    *   Сжатие: путь между ключевыми вершинами заменяется одним ребром
*   **Tree Isomorphism:**
    *   AHU algorithm: каноническое представление через рекурсивную сортировку подписей; `O(n log n)`
    *   Нехрёшное хеширование деревьев: `hash(v) = f(size(v), sort([hash(child)]))` — `O(n log n)` или `O(n)` с полиномиальным хешем

## **G. ПАРОСОЧЕТАНИЯ В ГРАФАХ**
> `g/g.md` · `g/g.cpp` · `struct MatchingAlgorithms : TreeAlgorithms`

### **A. Двудольные паросочетания**
*   **Теорема Холла (Hall's Marriage Theorem):** в двудольном графе `G = (L ∪ R, E)` существует完美 паросочетание ⟺ для любого `S ⊆ L`: `|N(S)| ≥ |S|`
*   **Алгоритм Куна (Kuhn's Algorithm):**
    *   DFS/BFS поиск augmenting path (путь увеличения) от каждой свободной вершины
    *   Сложность: `O(VE)` — худший случай
*   **Алгоритм Хопкрофта-Карпа (Hopcroft-Karp):**
    *   BFS построение уровней + DFS поиск максимального набора augmenting paths за один проход
    *   Сложность: `O(E√V)` — оптимально для невзвешенных двудольных графов
*   **Maximum matching в двудольных графах:**
    *   Gale-Shapley (Stable Marriage): стабильное паросочетание за `O(n²)`
    *   Взвешенное двудольное паросочетание — Hungarian algorithm (VII.C)

### **B. Паросочетания в общих графах**
*   **Теорема Татта (Tutte's Theorem):** граф имеет完美 паросочетание ⟺ для любого `S ⊆ V`: о(G − S) ≤ |S| (число нечётных компонент)
*   **Алгоритм Эдмондса (Blossom Algorithm):**
    *   Сжатие нечётных циклов («цветов») в «цветы» — устранение «Stranget cycles»
    *   Сложность: `O(V³)` реализация
*   **Матрица Татта (Tutte Matrix):** `T[i][j] = x_{ij}` если `(i,j) ∈ E`, `0` иначе; `det(T) ≠ 0` ⟺完美 паросочетание; рандомизированный алгоритм за `O(V^ω)`

### **C. Взвешенные паросочетания**
*   **Взвешенное паросочетание в двудольных графах:**
    *   Hungarian Algorithm: `O(V³)` — оптимальное назначение
    *   ДП по маскам подмножеств: `O(2^{n/2} · n)` через meet-in-the-middle для малых `n`
*   **Взвешенное паросочетание в общих графах:**
    *   Edmonds' algorithm for weighted matching
    *   Blossom V algorithm: практические оптимизации

### **D. Смежные понятия**
*   **Вершинные покрытия:**
    *   Matching Min Vertex Cover: в двудольных графах через теорему Кёнига `|M*| = |VC*|`
*   **Покрытие путями в DAG:**
    *   Dilworth's theorem: макс. число элементов антицепи = мин. число цепей, покрывающих всё множество
    *   Minimum Path Cover в DAG: `n − max matching` (сведение к двудольному паросочетанию)
*   **Maximum Independent Set:**
    *   В двудольных графах: `α = n − |M*|` (через вершинное покрытие)
    *   В общих графах: NP-hard; эвристики и точные алгоритмы для специальных классов

## **H. ПОТОКИ В СЕТЯХ (NETWORK FLOW)**
> `h/h.md` · `h/h.cpp` · `struct NetworkFlow : MatchingAlgorithms`

### **A. Максимальный поток (Max-Flow)**
*   **Алгоритм Форда-Фалкерсона (Ford-Fulkerson):**
    *   Итеративно: ищем augmenting path в residual graph, увеличиваем поток; пока路径 нет
    *   Сложность: `O(E · |f*|)` где `|f*|` — величина максимального потока (целочисленные capacities)
*   **Алгоритм Эдмондса-Карпа (Edmonds-Karp):**
    *   BFS для поиска кратчайшего augmenting path → `O(VE²)`
*   **Алгоритм Диница (Dinic's Algorithm):**
    *   Level graph + blocking flow за один проход; `O(V²E)` или `O(√V E)` для unit capacities
    *   Практически: один из самых быстрых
*   **Push-Relabel (Goldberg-Tarjan):**
    *   Метод проталкивания предпотока: `O(V³)` или `O(V²√E)` с highest-label
    *   FIFO push-relabel: `O(V³)` в худшем, хорошо на практике

### **B. Минимальный разрез (Min-Cut)**
*   **Теорема о максимальном потоке и минимальном разрезе:** `max flow = min cut` — фундаментальная теорема
*   **s-t Min-Cut:** через max-flow; разрез — рёбра с ненулевым потоком между достижимыми и недостижимыми вершинами
*   **Global Min-Cut (Stoer-Wagner):** `O(V³)` или `O(VE + V² log V)` для неориентированных графов без source/sink
*   **Приложения:** Image segmentation, Project selection, Bipartite matching (как частный случай max-flow)

### **C. Поток минимальной стоимости (Min-Cost Flow)**
*   **Successive Shortest Path:**
    *   Итеративно: ищем кратчайший augmenting path (с потенциалами/Johnson) → `O(F · E log V)` где `F` — величина потока
*   **Cycle Canceling:**
    *   Начинаем с произвольного потока; ищем отрицательные циклы в residual graph → уменьшаем стоимость
*   **Minimum Cost Maximum Flow:**先 max-flow, потом min-cost; или combined
*   **Cost Scaling:** асимптотически лучшие алгоритмы для больших сетей

### **D. Специальные виды потоков**
*   **Циркуляция:** поток с demands `d(v)`: `Σ in(v) − Σ out(v) = d(v)` — сведение к max-flow через виртуальные source/sink
*   **Мультипотоки (Multicommodity Flow):** несколько commodities; NP-hard в общем случае, полиномиально для планарных графов
*   **Потоки с ограничениями:** lower bounds на рёбрах — сведение к обычному потоку через трансформацию
*   **Потоки в планарных графах:** min-cut за `O(N log N)` через dual graph

### **E. Применения потоков**
*   **Задача о назначениях (Assignment Problem):** сведение к min-cost flow; Hungarian algorithm как частный случай
*   **Maximum Bipartite Matching:** сведение к max-flow (source → L, R → sink, capacity = 1)
*   **Minimum Path Cover в DAG:** `n − max matching` через сведение к двудольному паросочетанию
*   **Baseball Elimination:** определение, может ли команда выиграть лигу через max-flow
*   **Airline Scheduling:** назначение рейсов через потоки

## **I. ПЛАНАРНЫЕ ГРАФЫ И АЛГОРИТМЫ**
> `i/i.md` · `i/i.cpp` · `struct PlanarGraphs : NetworkFlow`

### **A. Основные свойства планарных графов**
*   **Определения и критерии:**
    *   Планарный граф: граф, который можно нарисовать на плоскости без пересечений рёбер
    *   **Теорема Эйлера:** `V − E + F = 2` (для связных планарных графов); следствие: `E ≤ 3V − 6` (для простых, без треугольников `E ≤ 2V − 4`)
    *   **Теорема Куратовского:** граф планарен ⟺ не содержит подграф, гомеоморфный `K₅` или `K₃,₃`
    *   Алгоритмы проверки планарности: `O(V)` (Hopcroft-Tarjan, Boyer-Myrvold)
*   **Представления планарных графов:**
    *   Planar embedding: порядок рёбер вокруг каждой вершины
    *   Dual graph: вершины — грани, рёбра — смежные грани; свойства: `E* = E`, `V* = F`, `F* = V`
    *   Straight-line drawing: Fáry's theorem — любой планарный граф можно нарисовать прямыми отрезками
*   **Разделение планарных графов:**
    *   Planar separator theorem (Lipton-Tarjan): для любого `n`-вершинного планарного графа существует разделитель `O(√n)` вершин — `O(√n log n)` поисковый алгоритм

### **B. Алгоритмы на планарных графах**
*   **Кратчайшие пути:** Dijkstra с special heaps для планарных графов — `O(n log n)`
*   **Минимальный разрез:** через dual graph — `O(n log n)` для планарных графов
*   **Maximum flow:** сведение к shortest path в dual graph
*   **Planar embedding algorithms:** проверка, построение встраивания

### **C. Графы на поверхностях**
*   **Графы на торе и других поверхностях:** обобщение Эйлера на поверхность genus `g`: `V − E + F = 2 − 2g`
*   **Графы с ограниченным genus:** алгоритмы, специфичные для фиксированного genus

## **J. СПЕЦИАЛЬНЫЕ КЛАССЫ ГРАФОВ И АЛГОРИТМЫ**
> `j/j.md` · `j/j.cpp` · `struct SpecialGraphs : PlanarGraphs`

### **A. Графы с ограниченными параметрами**
*   **Графы с ограниченной treewidth:**
    *   Tree decomposition: ширина `tw` — макс. размер bag − 1; полиномиальные DP на tree decomposition для NP-трудных задач
    *   Courcelle's theorem: MSO₂-определяемые свойства решаются за `O(f(tw, φ) · n)` для фиксированной формулы `φ` и ширины `tw`
*   **Графы с ограниченной clique-width:** обобщение treewidth; полиномиальные алгоритмы для фиксированной clique-width
*   **Графы с ограниченной степенью (degree-bounded):** параметрическая сложность по `Δ`
*   **Интервальные графы:** пересечение интервалов;Maximum clique/independent set за `O(n log n)`; проверка интервальности за `O(n + m)`
*   **Графы перестановок:** инверсии; проверка — `O(n log n)` через merge sort

### **B. Гиперграфы и мультиграфы**
*   **Гиперграфы:** рёбра — подмножества вершин; представления, transversal/hitting set (NP-hard)
*   **Мультиграфы:** кратные рёбра; алгоритмы адаптируются через схлопывание или взвешивание
*   **Directed hypergraphs:** ориентированные гиперрёбра

## **K. ВЕРОЯТНОСТНЫЕ И ЭВРИСТИЧЕСКИЕ МЕТОДЫ**
> `k/k.md` · `k/k.cpp` · `struct ProbabilisticGraph : SpecialGraphs`

### **A. Вероятностные алгоритмы**
*   **Random Walks:**
    *   Марковские цепи: матрица переходов, стационарное распределение `π = π·P`
    *   Mixing time: время сходимости к стационарному распределению
    *   Применение: оценка размера графа, клик
*   **PageRank:**
    *   Формула: `PR(v) = (1−d)/n + d · Σ_{u→v} PR(u)/deg(u)`, `d` — damping factor
    *   Итеративное вычисление через power method — `O(m · iterations)`
    *   Применение: ранжирование в web-поиске
*   **Случайные графы:**
    *   Erdős–Rényi model `G(n, p)`: каждое ребро с вероятностью `p`; порог связности `p = ln(n)/n`
    *   Properties: фазовые переходы, giant component при `p = 1/n`

### **B. Метаэвристики и поиск с ограничениями**
*   **Ant Colony Optimization:** феромоны на рёбрах, обновление через лучшие решения; для TSP, routing
*   **Genetic Algorithms:** популяция решений, кроссовер, мутация, отбор
*   **Simulated Annealing:** случайные переходы с вероятностью принятия худших решений (temperature schedule)
*   **Tabu Search:** запрет на возврат к недавним состояниям

## **L. ДИНАМИЧЕСКИЕ И ОНЛАЙН АЛГОРИТМЫ**
> `l/l.md` · `l/l.cpp` · `struct DynamicGraphAlgorithms : ProbabilisticGraph`

### **A. Динамические графовые алгоритмы**
*   **Dynamic Connectivity:**
    *   Fully dynamic connectivity: добавление/удаление рёбер с поддержкой компонент
    *   Holm-de Lichtenberg-Thorup: амортизированный `O(log² n)` — best known
*   **Dynamic Shortest Paths:**
    *   Incremental (только добавление): Dijkstra-like обновления
    *   Decremental (только удаление): D* Lite, reverse search
    *   Fully dynamic: пересчёт при каждом изменении
*   **Dynamic MST:** поддержка MST при добавлении/удалении рёбер — `O(log² n)` через Link-Cut Trees

### **B. Онлайн алгоритмы**
*   **Online Matching:** вершины/рёбра появляются один за другим; competitive ratio vs offline optimum
*   **Online Steiner Tree:** постепенное добавление терминалов; competitive ratio
*   **Competitive analysis:** сравнение онлайн-алгоритма с оптимальным оффлайн; competitive ratio `c` означает «не хуже в `c` раз»
