> **Архитектура:** `ConnectivityAlgorithms` (b.cpp) — наследует `GraphBasics` (a.cpp). # **A. КОМПОНЕНТЫ СВЯЗНОСТИ**

## **1. Компоненты в неориентированных графах**

### **1.1. Через DFS/BFS (уже в a.md)**
* **Алгоритм:** число запусков DFS/BFS от непосещённых вершин = число компонент; маркировка `component_id[v]`
* **Сложность:** `O(n + m)` суммарно
* **Связь:** полная реализация — `graph/a` (C.6)

### **1.2. Через Union-Find (DSU)**
* **Идея:** каждая вершина — отдельная компонента; при обработке ребра `(u,v)` — объединяем компоненты `u` и `v`
* **Структура данных:** DSU с `find(v)` (поиск корня с path compression) и `union(u, v)` (объединение по рангу/размеру)
* **Сложность:** `O(m · α(n))` суммарно, где `α(n)` — обратная функция Акермана ( amortized `O(1)` )
* **Почему лучше DFS для offline:** при добавлении рёбер по одному — DSU отвечает «связны ли u и v» за `O(α(n))`; DFS требует полного графа
* **Связь:** полная реализация DSU — `struct.md` (III.A); здесь — встроенная упрощённая версия для зависимостей

## **2. Сильные компоненты связности (SCC) в ориентированных графах**

### **2.1. Определения**
* **SCC (Strongly Connected Component):** maximal подграф, где между любыми двумя вершинами существует ориентированный путь в обе стороны
* **Конденсация графа (Condensation):** DAG, где вершины — SCC, рёбра — между различными SCC; ациклический по построению
* **Свойство конденсации:** если `SCC₁ → SCC₂` в конденсации, то нет пути из `SCC₂` в `SCC₁` ( topLevel конденсации — DAG)

### **2.2. Алгоритм Косарайу (Kruskal's SCC)**
* **Идея (два DFS):**
    1. Запустить DFS от всех вершин, записать порядок выхода (обратный порядок `tout`)
    2. Построить обратный граф `G^R` (каждое ребро `(u,v)` → `(v,u)`)
    3. Запустить DFS от вершин в порядке убывания `tout` по обратному графу; каждое дерево DFS = одна SCC
* **Почему работает:** если `u` достижима из `v` в `G`, но не наоборот, то в `G^R` `v` не достижима из `u`; порядок `tout` гарантирует, что стартовый DFS в `G^R` начинает из «конечной» SCC
* **Сложность:** `O(n + m)` — два DFS + построение обратного графа
* **Реализация:** два прохода DFS; первый — определение порядка, второй — разбиение на компоненты

### **2.3. Алгоритм Тарьяна для SCC**
* **Идея (один DFS):** `lowlink[v] = min(tin[v], tin[обратные рёбра], tin[детей в стеке])`; если `lowlink[v] = tin[v]` — `v` является корнем SCC; извлекаем из стека до `v`
* **Структура:** один DFS + стек (для хранения вершин текущей SCC); `on_stack[v]` — вершина в стеке
* **Ключевое свойство:** в стеке хранятся вершины текущого пути в DFS-дереве; SCC «замыкается» когда `lowlink[v] = tin[v]`
* **Сложность:** `O(n + m)` — один DFS
* **Преимущество над Косарайу:** один проход, не нужен обратный граф

### **2.4. Конденсация графа**
* **Построение:** после Kosaraju/Tarjan каждая вершина получает `scc_id[v]`; конденсация — DAG из компонент
* **Свойства:** конденсация ациклическа; топологический порядок конденсации — обратный порядок обхода Kosaraju или порядок «закрытия» SCC в Тарьяне
* **Применение:** 2-SAT (раздел F), упрощение задач на ориентированных графах

## **3. Слабые компоненты связности**
* **Определение:** компоненты связности при замене всех ориентированных рёбер на неориентированные
* **Алгоритм:** обычный DFS/BFS на неориентированном «отражении» графа
* **Сложность:** `O(n + m)`

# **B. МОСТЫ И ТОЧКИ СОЧЛЕНИЯ**

## **1. Мосты (Bridges)**

### **1.1. Определение**
* **Мост:** ребро `(u,v)`, удаление которого увеличивает число компонент связности
* **Эквивалент:** `(u,v)` — мост ⟺ нет цикла, содержащего `(u,v)` ⟺ `(u,v)` не принадлежит ни одному элементарному циклу

### **1.2. Алгоритм Тарьяна для мостов**
* **Определения:**
    * `tin[v]` — время входа в `v` при DFS
    * `low[v] = min({tin[v]} ∪ {tin[u] : (v,u) — обратное ребро} ∪ {low[u] : (v,u) — ребро дерева})`
    * Интерпретация: `low[v]` — минимальное время входа, достижимое из поддерева `v` через одно обратное ребро (не более одного)
* **Критерий моста:** ребро `(v, to)` (tree edge) является мостом ⟺ `low[to] > tin[v]`
    * Почему: если `low[to] ≤ tin[v]`, то из поддерева `to` можно вернуться выше `v` → `(v,to)` не мост
    * Если `low[to] > tin[v]` — из поддерева `to` нет обратного ребра выше `v` → удаление `(v,to)` разрывает граф
* **Сложность:** `O(n + m)` — один DFS + вычисление `low` за амортизированное время

### **1.3. Реализация (рекурсивный DFS)**
* Для каждого `(v, to)` tree edge: после обхода `to` проверяем `low[to] > tin[v]`
* Обновление `low[v]`: при обработке `(v, to)` — `low[v] = min(low[v], low[to])`; при обратном ребре `(v, to)` ( `to` посещён и не родитель) — `low[v] = min(low[v], tin[to])`

## **2. Точки сочленения (Articulation Points)**

### **2.1. Определение**
* **Точка сочленения:** вершина `v`, удаление которой увеличивает число компонент связности
* **Связь с мостами:** концы мостов — всегда точки сочленения (но не все точки сочленения — концы мостов)

### **2.2. Критерии (алгоритм Тарьяна)**
* **Корень DFS-дерева:** `v` — точка сочленения ⟺ `v` имеет ≥ 2 детей в DFS-дереве
    * Почему: если 1 ребёнок — удаление `v` не разрывает (ребёнок связан с предками через обратные рёбра); если ≥ 2 — поддеревья не связаны между собой без `v`
* **Не корень:** `v` — точка сочленения ⟺ существует ребёнок `to` такое, что `low[to] ≥ tin[v]`
    * Почему: `low[to] ≥ tin[v]` означает, что из поддерева `to` нельзя вернуться выше `v` → удаление `v` изолирует поддерево `to`
* **Сложность:** `O(n + m)` — один DFS

## **3. Biconnected Components (двусвязные компоненты)**

### **3.1. Определение**
* **Biconnected component:** maximal подграф, в котором нет точек сочленения; между любыми двумя вершинами ≥ 2 независимых путей
* **Свойство:** biconnected components пересекаются ровно в точках сочленения (точка сочленения может принадлежать нескольким компонентам)

### **3.2. Алгоритм Тарьяна для biconnected components**
* **Идея:** при DFS храним рёбра на стеке; при обнаружении точки сочленения (критерий выше) — извлекаем рёбра с стека до текущего ребра; каждая извлечённая группа = одна biconnected component
* **Реализация:** DFS + стек рёбер `(v, to)`; при `low[to] ≥ tin[v]` — pop рёбер до `(v, to)` включительно
* **Сложность:** `O(n + m)`

## **4. Edge Biconnected Components**
* **Определение:** maximal подグラф без мостов; удаление мостов разбивает граф на edge-biconnected components
* **Алгоритм:** DFS + `low[v]` (аналогично мостам); группы вершин с `low[v] < tin[v]` (достижимы без обратного ребра) — одна компонента
* **Связь:** мост — ребро между различными edge-biconnected components

# **C. k-СВЯЗНОСТЬ И МИНИМАЛЬНЫЕ РАЗРЕЗЫ**

## **1. Вершинная связность (Vertex Connectivity)**

### **1.1. Определения**
* **k-вершинная связность (k-connected):** граф остаётся связным после удаления любых `k−1` вершин; `κ(G)` — вершинная связность графа (минимальное число вершин, чьё удаление разрывает граф)
* **k-рёберная связность (k-edge-connected):** удаление любых `k−1` рёбер не разрывает граф; `λ(G)` — рёберная связность
* **Связь:** `κ(G) ≤ λ(G) ≤ δ(G)` (мин. степень); полные графы `K_n`: `κ(K_n) = λ(K_n) = n−1`

### **1.2. Теорема Менгера (Menger's Theorem)**
* **Версионная (vertex):** между любыми двумя не смежными вершинами `u, v`: минимальное число вершин, чьё удаление разъединяет `u` и `v` = максимальное число внутренне независимых `u-v` путей (путей, не имеющих общих вершин кроме `u` и `v`)
* **Рёберная:** минимальное число рёбер, чьё удаление разъединяет `u` и `v` = максимальное число рёберно-независимых `u-v` путей
* **Применение:** определение k-связности через потоки (раздел H)

## **2. Минимальный разрез в неориентированных графах**

### **2.1. Stoer-Wagner Algorithm**
* **Задача:** найти глобальный минимальный разрез (без фиксированных source/sink)
* **Идея:** итеративное «сжатие» пар вершин: на каждом шаге — Phases of Prim-like процесса; последняя присоединённая вершина `t`, предпоследняя `s` — кандидаты на разрез; `cut(s,t)` — потенциальный min-cut
* **Алгоритм:** `n−1` фаз; на каждой фазе — `n` шагов «наиболее связанная вершина» (как в Prim, но по суммарным весам); `O(n³)` или `O(nm + n² log n)` с Fibonacci heap
* **Корректность:** min-cut между `s` и `t` на последней фазе — глобальный min-cut (доказательство через cut property)

### **2.2. Karger's Algorithm (рандомизированный)**
* **Идея:** случайное стягивание рёбер: выбираем случайное ребро, сливаем его концы; повторяем до 2 вершин; оставшееся ребро — потенциальный min-cut
* **Сложность:** одна попытка `O(n + m)`, вероятность успеха `≥ C(n,2)^{−1}` (где `C(n,2)` — число пар); `O(n² log n)` попыток → детерминированный `O(n² log n · (n + m))`
* **Karger-Stein:** рекурсивное разбиение: разделяем граф пополам, рекурсивно ищем min-cut в каждой половине; `O(n² log n)` — оптимальный рандомизированный

## **3. Глобальная минимальная связность**
* **Бинарный поиск по `k`:** для проверки k-связности — проверяем, что для каждой пары `(u,v)` min-cut ≥ `k`; через max-flow `O(n · maxflow)`
* **Практика:** для малых графов (`n ≤ 50`) — перебор пар + max-flow; для больших — Stoer-Wagner (глобальный min-cut без source/sink)

# **D. ДВУДОЛЬНЫЕ ГРАФЫ И РАСКРАСКИ**

## **1. Проверка двудольности**

### **1.1. Через BFS/DFS (уже в a.md)**
* **Алгоритм:** двухцветка: `color[v] ∈ {0, 1}`; ребро `(u,v)` → `color[v] = 1 − color[u]`; конфликт ⟺ не двудолен
* **Свойство:** граф двудолен ⟺ нет нечётных циклов
* **Сложность:** `O(n + m)`
* **Связь:** полная реализация — `graph/a` (D.3, C.8)

## **2. Раскраски графов (Vertex Coloring)**

### **2.1. Greedy Coloring**
* **Алгоритм:** для каждой вершины (в фиксированном порядке) — назначить первый доступный цвет, не использованный соседями
* **Сложность:** `O(n + m)` (при проверке цветов соседей через boolean array)
* **Гарантия:** `χ(G) ≤ Δ(G) + 1` (где `Δ(G)` — макс. степень); на практике намного лучше
* **Зависимость от порядка:** оптимальный порядок (Welsh-Powell) даёт лучшие результаты

### **2.2. Алгоритм Уэлша-Пауэлла (Welsh-Powell)**
* **Идея:** сортировка вершин по убыванию степени; greedy coloring в этом порядке
* **Почему лучше:** вершины с высокой степенью окрашиваются первыми, когда больше «свободных» цветов
* **Сложность:** `O(n log n + m)` (сортировка + greedy)

### **2.3. Хроматическое число χ(G)**
* **Определение:** минимальное число цветов для proper vertex coloring (смежные вершины — разные цвета)
* **Сложность вычисления:** NP-трудно в общем случае
* **Нижняя граница:** `χ(G) ≥ n / α(G)` где `α(G)` — размер максимального независимого множества (раздел G)
* **Верхняя граница:** `χ(G) ≤ Δ(G) + 1` (greedy); Brooks: `χ(G) ≤ Δ(G)` кроме `K_{n+1}` и нечётных циклов

## **3. Edge Coloring**

### **3.1. Определение и теорема Визинга**
* **Edge coloring:** назначение цветов рёбрам, чтобы смежные рёбра имели разные цвета; `χ'(G)` — chromatic index
* **Теорема Визинга (Vizing):** для простого графа: `Δ(G) ≤ χ'(G) ≤ Δ(G) + 1`; класс I (`χ' = Δ`) или класс II (`χ' = Δ + 1`)
* **Для двудольных:** `χ'(G) = Δ(G)` (теорема Кёнига — через max matching, раздел G)

## **4. Теоремы о раскрасках**

### **4.1. Four Color Theorem**
* **Утверждение:** любой планарный граф можно раскрасить в 4 цвета: `χ(G) ≤ 4`
* **Доказательство:** компьютерное (Appel-Haken, 1976); проверено на ~2000 конфигурациях
* **Применение:** картография, тайлинг

### **4.2. Five Color Theorem**
* **Утверждение:** `χ(G) ≤ 5` для планарных графов
* **Доказательство:** элементарное, через индукцию по числу вершин; всегда можно найти вершину со степенью ≤ 5

### **4.3. Brooks' Theorem**
* **Утверждение:** если `G` — не полный граф `K_{n+1}` и не нечётный цикл, то `χ(G) ≤ Δ(G)`
* **Значение:** улучшает жадную оценку `Δ + 1` → `Δ` для большинства графов

# **E. ДИНАМИЧЕСКАЯ СВЯЗНОСТЬ**

## **1. Incremental Connectivity (только добавление рёбер)**
* **Структура:** DSU (Union-Find)
* **Операции:** `union(u, v)` за амортизированно `O(α(n))`; `connected(u, v)` за `O(α(n))`
* **Связь:** полная реализация — `struct.md` (III.A)

## **2. Decremental Connectivity (только удаление рёбер)**
* **Offline подход:** обратный ход времени: начинаем с финального графа, добавляем рёбра в обратном порядке; DSU с откатами (rollback DSU)
* **Rollback DSU:** стек изменений; `undo()` — откат последнего `union` за `O(1)`; `O(log n)` на откат через хранение рангов
* **Сложность:** `O(m log m + q log q)` где `q` — число запросов

## **3. Fully Dynamic Connectivity (добавление + удаление)**
* **Euler Tour Trees (ETT):**
    * Представление каждой компоненты как Euler tour (последовательность рёбер) в balanced BST
    * Операции: `link(u,v)`, `cut(u,v)`, `connected(u,v)` за `O(log n)`
    * Связь: `struct.md` (XI.F)
* **Link-Cut Trees:**
    * Динамическое дерево: `link`, `cut`, `find_root`, `path query` за `O(log n)` амортизированно
    * Применение: динамические min/max на путях
    * Связь: `struct.md` (XI.F)
* **Holm-de Lichtenberg-Thorup (HLT):**
    * Идея: ETT + level structure; каждое ребро имеет «уровень»; удаление — снижение уровня; `O(log² n)` амортизированно на операцию
    * Граница: `m` обновлений суммарно

# **F. 2-SAT И КОНДЕНСАЦИЯ ГРАФА ИМПЛИКАЦИЙ**

## **1. Постановка задачи 2-SAT**

### **1.1. Формулировка**
* **Дано:** `n` булевых переменных `x₁, ..., xₙ`; `m` дизъюнкций (клауз) вида `(a ∨ b)`, где `a`, `b` — литералы: `xᵢ` или `¬xᵢ`
* **Найти:** булеву оценку `x₁, ..., xₙ`, удовлетворяющую всем клаузам; или определить, что оценки нет (UNSAT)
* **Пример:** `(x₁ ∨ ¬x₂) ∧ (¬x₁ ∨ x₃) ∧ (¬x₃ ∨ ¬x₂)` — UNSAT? ( depends )

### **1.2. Сведение к графу импликаций**
* **Каждая клауза `(a ∨ b)`** эквивалентна двум импликациям: `¬a → b` и `¬b → a`
* **Граф импликаций:** `2n` вершин ( `xᵢ` и `¬xᵢ` для каждого `i`); рёбра — импликации
* **Ключевое свойство:** если `x` и `¬x` принадлежат одной SCC → UNSAT (нет оценки, где оба истинны)
* **Почему:** `x → ¬x` и `¬x → x`意味着 `x ⟺ ¬x` — невозможно

## **2. Решение 2-SAT через SCC**

### **2.1. Алгоритм**
1. Построить граф импликаций: `2n` вершин, `2m` рёбер
2. Найти SCC (Kosaraju или Tarjan)
3. Проверить: если `scc_id[xᵢ] = scc_id[¬xᵢ]` для некоторого `i` → UNSAT
4. Иначе: построить оценку — для каждой переменной `xᵢ`: `xᵢ = true` если `scc_id[xᵢ] < scc_id[¬xᵢ]` (topological order: SCC с меньшим номером «раньше» в DAG)

### **2.2. Почему работает**
* Конденсация графа — DAG; `xᵢ → ¬xᵢ`意味着 в DAG `scc_id[xᵢ]` стоит «после» `scc_id[¬xᵢ]` (иначе цикл → UNSAT)
* Выбор `scc_id[xᵢ] < scc_id[¬xᵢ]` гарантирует: все импликации из `xᵢ` ведут в компоненты с бо́льшим номером → оценка консистентна

### **2.3. Сложность**
* `O(n + m)` — построение графа + SCC (Kosaraju/Tarjan) + проверка + построение оценки

## **3. Применения 2-SAT**
* **Scheduling:** ограничения «если A, то не B» → `(¬A ∨ ¬B)`
* **Circuit design:** логические схемы с ограничениями
* **Resource allocation:** «если используем ресурс X, то не используем Y»
* **Обобщение:** k-SAT (k ≥ 3) — NP-полна; 2-SAT — полиномиальна через SCC
* **Разрешимость с дополнительными ограничениями:** «ровно k из n переменных true» — расширение через дополнительные клаузы
