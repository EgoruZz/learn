# **A. ДИНАМИЧЕСКИЕ ГРАФОВЫЕ АЛГОРИТМЫ**

## **1. Динамическая связность (Dynamic Connectivity)**

### **1.1. Incremental connectivity (только добавление рёбер)**
* **Структура:** DSU (Union-Find) с path compression и union by rank
* **Операции:** `add_edge(u, v)` → `union(u, v)` за `O(α(n))` амортизированно
* **Запрос:** `connected(u, v)` → `find(u) == find(v)` за `O(α(n))`
* **Сложность:** `O(m · α(n))` суммарно на `m` добавлений

### **1.2. Decremental connectivity (только удаление рёбер)**
* **Offline подход:** обратный ход времени
    1. Начать с финального графа (все рёбра, которые останутся)
    2. Обрабатывать удаления в обратном порядке (= добавления)
    3. Использовать DSU с откатами (Rollback DSU)
* **Rollback DSU:** стек изменений; `undo()` — откат последнего `union` за `O(1)`; поддержка рангов через стек
* **Сложность:** `O(m log m + q log q)` где `q` — число запросов

### **1.3. Fully dynamic connectivity**
* **Euler Tour Trees (ETT):** деревья на компонентах; `link/cut/connected` за `O(log n)`
* **Link-Cut Trees:** `O(log n)` амортизированно на все операции
* **Holm-de Lichtenberg-Thorup (HLT):** ETT + level structure; `O(log² n)` амортизированно на операцию; лучший известный для fully dynamic

## **2. Динамические кратчайшие пути**

### **2.1. Incremental (только добавление рёбер)**
* Добавление ребра `(u,v)`: если `dist[u] + w < dist[v]` → обновить `dist[v]` и BFS/DFS от `v`
* **Сложность:** `O(n + m)` в худшем, на практике быстрее

### **2.2. Decremental (только удаление рёбер)**
* Удаление ребра может сломать многие кратчайшие пути; полный пересчёт
* **D* Lite:** для робототехники; пересчёт только затронутых вершин

### **2.3. Fully dynamic**
* Пересчёт при каждом изменении; общая сложность зависит от числа изменений

## **3. Динамическое MST**

### **3.1. Задача**
* Поддерживать MST при добавлении/удалении рёбер
* **Свойство:** если `(u,v)` удалено из MST, замена — минимальное ребро, замыкающее цикл

### **3.2. Алгоритм**
* **Добавление ребра `(u,v)`:** если `(u,v)` не создаёт цикл → добавить; иначе: если `w(u,v) < max_edge_on_path(u,v)` → заменить
* **Удаление ребра `(u,v)`:** найти минимальное ребро, замыкающее цикл → заменить
* **Сложность:** `O(log² n)` через Link-Cut Trees для хранения максимумов на путях

# **B. ОНЛАЙН АЛГОРИТМЫ**

## **1. Online Matching**

### **1.1. Постановка задачи**
* Вершины/рёбра появляются один за другим; алгоритм должен принять решение немедленно (без знания будущего)
* **Competitive ratio:** `c` означает `online_algorithm ≥ c · offline_optimum` для любого входа

### **1.2. Greedy online matching**
* При появлении вершины/рёбра — немедленно добавить в паросочетание
* **Competitive ratio:** `1/2` (для невзвешенных двудольных графов)

## **2. Competitive Analysis**

### **2.1. Определение**
* Сравнение онлайн-алгоритма с оптимальным оффлайн; `c` = `ALG / OPT`
* **Лучшие оценки:** для online matching — `1/2` (det.), `1 − 1/e ≈ 0.632` (рандомизированный)

## **3. Online Steiner Tree**
* Постепенное добавление терминалов; competitive ratio `O(log k)` где `k` — число терминалов
