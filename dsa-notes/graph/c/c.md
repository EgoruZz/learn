**C. КРАТЧАЙШИЕ ПУТИ В ГРАФАХ**

> **Архитектура:** `ShortestPaths` (c.cpp) — наследует `ConnectivityAlgorithms` (b.cpp). Реализует три класса задач: одноисточниковые (SSSP), между всеми парами (APSP) и эвристические (A*). Покрывает: Dijkstra (неотрицательные веса), Bellman-Ford/SPFA (произвольные веса, отрицательные циклы), Floyd-Warshall (APSP), Johnson (APSP для разреженных), A* (эвристика). Восстановление путей через `prev[]`/`next[]`.
>
> **Связи:** BFS (кратчайшие пути в невзвешенных графах) — `graph/a` (D); топологическая сортировка — `graph/a` (C.7) и `graph/b` (SCC); приоритетные очереди — `struct.md` (IV); Dijkstra/Floyd как база для MST (раздел D), потоков (раздел H); Bellman-Ford как детектор отрицательных циклов — связь с `dynamic.md` (H); Johnson = Bellman-Ford + n×Dijkstra — комбинирует SSSP-алгоритмы.

# **A. ОДНОИСТОЧНИКОВЫЕ КРАТЧАЙШИЕ ПУТИ (SSSP)**

## **1. BFS для невзвешенных графов (уже в a.md)**
* **Сложность:** `O(n + m)`
* **Связь:** полная реализация — `graph/a` (D.1)

## **2. Алгоритм Дейкстры (Dijkstra)**

### **2.1. Условия и идея**
* **Условие:** все веса рёбер `w(u,v) ≥ 0`; отрицательные веса ломают жадность
* **Идея:** жадный выбор: на каждом шаге берём непосещённую вершину `v` с минимальным `dist[v]`; «фиксируем» её — оптимальное расстояние найдено; релаксация соседей
* **Релаксация:** если `dist[u] + w(u,v) < dist[v]` → `dist[v] = dist[u] + w(u,v)`, `prev[v] = u`

### **2.2. Инвариант корректности**
* При извлечении `v` из приоритетной очереди `dist[v]` уже оптимален
* **Доказательство (обмен аргументов):** предположим, что оптимальный путь в `v` идёт через непосещённую вершину `u`; тогда `dist[u] ≥ dist[v]` (извлечение); но тогда путь через `u` не короче `dist[v]` → противоречие

### **2.3. Реализация (binary heap)**
* **Структура:** priority queue `(dist[v], v)`, `visited[]`, `dist[]`, `prev[]`
* **Почему без decrease-key:** в STL priority queue нет decrease-key; вместо этого — вставка нового `(new_dist, v)` с пропуском устаревших записей при извлечении
* **Сложность:** `O((n + m) log n)` — каждая вершина извлекается один раз `O(log n)`, каждое ребро вызывает potential вставку `O(log n)`
* **Связь:** pairing/fibonacci heap — `struct.md` (IV); decrease-key доступен там

### **2.4. Реализация (с decrease-key)**
* Если priority queue поддерживает `decrease-key` за `O(log n)` (или `O(1)` для Fibonacci heap) — вставка только один раз, decrease-key при релаксации
* **Сложность:** `O(m log n)` с binary heap; `O(m + n log n)` с Fibonacci heap

### **2.5. Восстановление пути**
* `prev[v]` обновляется при релаксации: `prev[v] = u`
* Путь от `s` до `t`: идём от `t` по `prev` до `s`, затем разворачиваем
* **Сложность:** `O(длина пути)` на восстановление

### **2.6. Bidirectional Dijkstra**
* **Идея:** два направления — от источника `s` и от цели `t`; встреча в середине; останавливаемся когда `dist_s[u] + dist_t[u] ≥ текущий_лучший`
* **Выигрыш:** вдвое по пространству и (практически) по времени

## **3. Алгоритм Беллмана-Форда (Bellman-Ford)**

### **3.1. Условия и идея**
* **Условие:** произвольные веса (включая отрицательные); может обнаружить отрицательный цикл
* **Идея:** `n−1` проходов по всем рёбер; на каждом проходе — релаксация каждого ребра `(u,v)`: `dist[v] = min(dist[v], dist[u] + w(u,v))`
* **Почему n−1:** кратчайший путь без циклов содержит не более `n−1` рёбер; после `n−1` проходов все кратчайшие пути найдены

### **3.2. Сложность**
* `O(nm)` — `n−1` итераций × `m` рёбер

### **3.3. Обнаружение отрицательных циклов**
* После `n−1` проходов: ещё один проход; если хотя бы одна релаксация произошла → отрицательный цикл достижим из источника
* **Восстановление цикла:** `prev[v]` образует дерево; цикл → обратный проход по `prev` до повторения вершины

### **3.4. Восстановление пути**
* Аналогично Dijkstra: `prev[v]` при релаксации

## **4. Shortest Path Faster Algorithm (SPFA)**

### **4.1. Идея**
* Оптимизация Bellman-Ford: в очередь попадают только изменённые вершины (когда `dist[v]` обновилось)
* **Почему быстрее:** на практике большинство рёбер не вызывают релаксацию; в среднем `O(m)`; худший `O(nm)` (для специальных графов)

### **4.2. Структура**
* Очередь `q`; начальная инициализация: `dist[s] = 0`, `q.push(s)`
* При обработке `v` из `q`: для каждого `(v,u)`: если `dist[u] > dist[v] + w(v,u)` → обновить, `q.push(u)` если `u` не в `q`

## **5. DAG Shortest Path**

### **5.1. Алгоритм**
* Топологическая сортировка + релаксация в топологическом порядке
* **Почему работает:** при обработке `v` все предшественники `u` ( `u → v` ) уже обработаны → `dist[v]` финализируется
* **Сложность:** `O(n + m)`

### **5.2. Longest path в DAG**
* Замена весов `w → −w` → shortest path через Bellman-Ford/Floyd (не Dijkstra — отрицательные веса)
* Или: `dist[v] = max(dist[u] + w(u,v))` в топологическом порядке

# **B. КРАТЧАЙШИЕ ПУТИ МЕЖДУ ВСЕМИ ПАРАМИ (APSP)**

## **1. Алгоритм Флойда-Уоршелла (Floyd-Warshall)**

### **1.1. ДП по промежуточным вершинам**
* **Состояние:** `dp[k][i][j]` = кратчайшее расстояние из `i` в `j`, используя только вершины `{0, 1, ..., k}` как промежуточные
* **Рекуррентность:** `dp[k][i][j] = min(dp[k−1][i][j], dp[k−1][i][k] + dp[k−1][k][j])`
* **База:** `dp[0][i][j] = w(i,j)` если ребро есть, `0` если `i = j`, `∞` иначе
* **Ответ:** `dp[n−1][i][j]` для всех пар

### **1.2. Оптимизация памяти**
* `k` — внешний цикл; `dp[i][j]` перезаписывается на месте: `dp[i][j] = min(dp[i][j], dp[i][k] + dp[k][j])`
* **Почему работает:** при обновлении `dp[i][j]` через `k` используются только `dp[i][k]` и `dp[k][j]`; `dp[i][k]` не меняется на текущей итерации `k` ( `dp[i][k] = min(dp[i][k], dp[i][k] + dp[k][k])` = `dp[i][k]` так как `dp[k][k] = 0`)
* **Память:** `O(n²)`

### **1.3. Сложность**
* `O(n³)` время, `O(n²)` память

### **1.4. Восстановление пути**
* `next[i][j]` = первая вершина после `i` на пути в `j`; инициализация: `next[i][j] = j` если ребро `(i,j)` есть
* При обновлении `dp[i][j]` через `k`: `next[i][j] = next[i][k]`
* Путь: `i → next[i][j] → next[next[i][j]][j] → ... → j`

### **1.5. Транзитивное замыкание**
* Замена `min` на `|` (логическое ИЛИ): `adj[i][j] |= (adj[i][k] & adj[k][j])`; `O(n³)`

### **1.6. Обнаружение отрицательных циклов**
* После Floyd-Warshall: `dp[i][i] < 0` для некоторой `i` ⟺ существует отрицательный цикл, достижимый из `i`
* Для всех пар: также проверять `dp[i][k] + dp[k][j] < dp[i][j]` после завершения

## **2. Алгоритм Джонсона (Johnson)**

### **2.1. Идея**
* Для разреженных графов (`m = o(n²)`) с отрицательными весами: `O(nm + n² log n)` вместо `O(n³)`
* **Этапы:**
    1. Добавить виртуальную вершину `s`, рёбра `(s, v)` с весом `0` для всех `v`
    2. Bellman-Ford от `s`: если отрицательный цикл → граф не подходит
    3. Перезахват весов: `w'(u,v) = w(u,v) + h(u) − h(v)`, где `h(v) = dist(s,v)`; все `w' ≥ 0`
    4. `n` запусков Dijkstra с весами `w'`

### **2.2. Почему w' ≥ 0**
* Для ребра `(u,v)`: `dist(s,u) + w(u,v) ≥ dist(s,v)` (свойство shortest path); → `w'(u,v) = w(u,v) + dist(s,u) − dist(s,v) ≥ 0`

### **2.3. Восстановление исходных расстояний**
* `dist(i,j) = dist'(i,j) − h(i) + h(j)`, где `dist'` — расстояние с весами `w'`

### **2.4. Сложность**
* Bellman-Ford: `O(nm)`; `n` Dijkstra: `O(n(m + n) log n)` суммарно; итого `O(nm + n² log n)`

# **C. ЭВРИСТИЧЕСКИЕ АЛГОРИТМЫ ПОИСКА ПУТИ**

## **1. A* Search Algorithm**

### **1.1. Функция оценки**
* `f(v) = g(v) + h(v)`, где:
    * `g(v)` — стоимость пути от старта до `v` (известна точно)
    * `h(v)` — эвристика (оценка стоимости от `v` до цели)
* **Admissible heuristic:** `h(v) ≤ h*(v)` (реальная стоимость до цели) → гарантия оптимальности
* **Consistent heuristic:** `h(v) ≤ c(v,u) + h(u)` для всех рёбер `(v,u)` → не требует переоткрытия вершин

### **1.2. Алгоритм**
* Как Dijkstra, но приоритет определяется `f(v)`, а не `g(v)`; open set — приоритетная очередь по `f`
* Если `h(v) = 0` → Dijkstra (garbage эвристика); если `h(v) = h*(v)` → прямой путь к цели без лишних вершин

### **1.3. Сложность**
* Худший: `O(b^d)` ( `b` — коэффициент ветвления, `d` — глубина решения)
* При хорошей эвристике — экспоненциально быстрее Dijkstra

## **2. Greedy Best First Search**
* `f(v) = h(v)` — только эвристика; не оптимален, но часто быстр
* **Применение:** когда оптимальность не важна, нужно быстрое приближённое решение

## **3. IDA* (Iterative Deepening A*)**
* **Идея:** DFS с порогом `f ≤ limit`; увеличение порога до минимума `f` вершин, превысивших предыдущий лимит
* **Память:** `O(d)` (как DFS) вместо `O(b^d)` (как A*)
* **Сложность:** `O(b^d)` времени (как A*)

# **D. СПЕЦИАЛЬНЫЕ ВИДЫ ПУТЕЙ**

## **1. k-кратчайших путей**

### **1.1. Yen's Algorithm**
* **Идея:** найти `k` кратчайших путей без циклов; основной путь — Dijkstra; затем для каждой вершины на пути — «отщепление» + Dijkstra с ограничениями
* **Сложность:** `O(kn(m + n log n))`

### **1.2. Eppstein's Algorithm**
* **Идея:** построение дерева всех путей через suffix structures; `k` кратчайших — `k` первых в порядке
* **Сложность:** `O(m + n log n + k)`

## **2. Наиболее надёжные пути (Most Reliable Path)**
* **Задача:** максимизировать `Π pᵢ` (произведение вероятностей); через замену `w = −log p` → shortest path (Dijkstra если `pᵢ > 0`)

## **3. Пути с ограничениями**
* **Расширенное состояние:** `(вершина, остаток_ресурса)` → Dijkstra/BFS в расширенном графе; сложность `O(n · R · (m + n log n))` где `R` — макс. ресурс
