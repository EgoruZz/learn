# **A. БАЗОВЫЕ ЗАПРОСЫ НА ДЕРЕВЬЯХ**

## **1. Построение дерева**
* **Вход:** `n` вершин, `n−1` рёбер (pairs `(u, v)`)
* **Представление:** `vector<vector<int>> adj(n)` — список смежности; корень — фиксирован (обычно `0`)
* **Предподсчёт:** `parent[v]`, `depth[v]`, `sz[v]` (размер поддерева) — через один DFS

## **2. Диаметр дерева (Diameter)**
* **Определение:** `diam = max_{u,v} dist(u,v)` — наибольшее расстояние между любыми двумя вершинами
* **Два DFS:** (1) DFS от произвольной вершины `s` → самая дальняя `a`; (2) DFS от `a` → самая дальняя `b`; `diam = dist(a, b)`
* **Почему работает:** свойство деревьев: путь через центр дерева является диаметром
* **Однопроходное DP:** `down[v]` — макс. длина пути в поддереве `v` (через одного ребёнка); `up[v]` — макс. длина пути «наверх»; ответ `max(down[v] + up[v])` — `O(n)`
* **Сложность:** `O(n)` (оба варианта)

## **3. Центр(ы) дерева**
* **Определение:** вершина, минимизирующая максимальное расстояние до любой другой вершины: `min_v max_u dist(v,u)`
* **Через диаметр:** центр — середина пути диаметра; при нечётной длине — одна вершина, при чётной — две
* **Сложность:** `O(n)` (из диаметра)

## **4. Even Tree (удаление рёбер)**
* **Задача:** макс. число рёбер, которые можно удалить, чтобы каждое поддерево имело чётное число вершин
* **Решение:** DFS подсчёт `sz[v]`; ребро `(v, parent[v])` удаляется если `sz[v]` чётно; `O(n)`

# **B. НАИМЕНЬШИЙ ОБЩИЙ ПРЕДОК (LCA)**

## **1. Binary Lifting (двоичные подъёмы)**

### **1.1. Предподсчёт**
* **Структура:** `up[v][j]` — `2^j`-й предок вершины `v`; `dp[v][j]` — агрегированное значение на пути длины `2^j` от `v` к предку (минимум, максимум, сумма — зависит от задачи)
* **Инициализация:** `up[v][0] = parent[v]`; `up[v][j] = up[ up[v][j−1] ][j−1]`
* **Сложность:** `O(n log n)` время и память

### **1.2. Запрос LCA(u, v)**
1. Привести `u` и `v` к одной глубине: поднимать более глубокую вершину на `depth[u] − depth[v]` шагов (побитово)
2. Если `u == v` → `u` и есть LCA
3. Поднимать обе вершины с最大的 `j` (от `log n` до 0): если `up[u][j] ≠ up[v][j]` → поднять обе
4. Ответ: `parent[u]` (= `parent[v]`)
* **Сложность:** `O(log n)` на запрос

### **1.3. Запрос на пути (min/max/sum)**
* `dp[v][j]` = min/max/sum на пути от `v` до `up[v][j]`
* При выравнивании глубин: агрегируем `dp` по пройденным шагам
* При совместном подъёме: агрегируем `dp` если `up[u][j] ≠ up[v][j]`
* Затем агрегируем `dp` для последнего шага до `parent[u]`

## **2. Euler Tour + RMQ**

### **2.1. Метод**
* **Euler Tour:** обход дерева с записью каждой вершины при входе и при возврате из ребёнка; массив `euler[]` длины `2n − 1`
* **Глубины:** массив `depth[euler[i]]`
* **LCA(u, v):** минимум `depth` в подотрезке `euler` между первыми вхождениями `u` и `v`
* **Предподсчёт:** Sparse Table по `depth[]` за `O(n log n)`, запрос `O(1)`

### **2.2. Farach-Colton and Bender**
* **±1 RMQ:** для деревьев разность смежных элементов в `euler` = ±1
* **Предподсчёт:** блочный + таблица внутри блоков; `O(n)` предподсчёт, `O(1)` запрос

## **3. Tarjan's Offline LCA**
* **Идея:** один DFS + Union-Find; для запроса `(u, v)`: LCA — последний общий предок, обработанный после обоих
* **Сложность:** `O(n + Q)` суммарно ( `Q` — число запросов)

## **4. Динамическое LCA**
* **Link-Cut Trees:** `find_root`, `lca`, `path_query` за `O(log n)` амортизированно
* **Применение:** деревья с операциями `link` (добавление ребра), `cut` (удаление ребра)

# **C. ДЕКОМПОЗИЦИИ ДЕРЕВЬЕВ**

## **1. Heavy-Light Decomposition (HLD)**

### **1.1. Определение**
* **Тяжёлое ребро:** `(v, parent[v])` где `sz[child]` maximizes среди всех детей `v`; лёгкие — остальные
* **Путь:** разбиение на `O(log n)` непрерывных отрезков (heavy paths); каждый heavy path — непрерывный отрезок в массиве

### **1.2. Построение**
1. DFS для подсчёта `sz[v]` и определения heavy child для каждой вершины
2. DFS для назначения `pos[v]` (позиция в массиве) и `head[v]` (начало текущего heavy path)
3. Каждый heavy path → непрерывный отрезок в массиве `base[]`

### **1.3. Запросы на пути (u, v)**
* Пока `head[u] ≠ head[v]`: поднимаем глубокую вершину (обрабатываем отрезок от `pos[head[u]]` до `pos[u]`), затем `u = parent[head[u]]`
* Когда `head[u] = head[v]`: обрабатываем отрезок между `u` и `v`
* **Сложность:** `O(log n)` отрезков × `O(log n)` на каждый (segment tree) = `O(log² n)`

### **1.4. Обновления на пути**
* Аналогично: `O(log² n)` через lazy segment tree на `base[]`

## **2. Центроидная декомпозиция (Centroid Decomposition)**

### **1.1. Определение**
* **Центроид:** вершина `c`, удаление которой разбивает дерево на компоненты размера ≤ `n/2`
* **Декомпозиция:** найти центроид → рекурсия на каждой компоненте; высота декомпозиционного дерева `O(log n)`

### **1.2. Построение**
1. Найти центроид текущего дерева (DFS: `max(sz[детей], n − sz[c]) ≤ n/2`)
2. Удалить центроид, рекурсия на каждую компоненту
3. Центроидная декомпозиция — дерево с `O(log n)` уровнями

### **1.3. Применение**
* **Задачи «все пути через центроид»:** на каждом уровне — подсчёт пар через текущий центроид
* **Подсчёт пар с `dist(u,v) ≤ k`:** для каждого центроода —收集 расстояния в поддеревьях + two-pointer
* **Раскраска / подсчёт поддеревьев:** DSU on tree на центроидном дереве

## **3. Моноидная декомпозиция**
* **Обобщение:** на каждом уровне — моноидная операция (min, sum, gcd); запросы через агрегацию по heavy path

# **D. ПРОДВИНУТЫЕ АЛГОРИТМЫ НА ДЕРЕВЬЯХ**

## **1. DSU on Tree (Sack)**

### **1.1. Идея**
* При слиянии поддеревьев: перебираем меньшее поддерево, обновляя глобальные данные
* «Тяжёлый ребёнок»:-largest subtree — его данные сохраняются, лёгкие — сбрасываются
* **Сложность:** `O(n log n)` суммарно (каждая вершина перебирается `O(log n)` раз)

### **1.2. Применение**
* Запросы «число различных элементов в поддереве» за `O(1)` после `O(n log n)` предподсчёта
* Подсчёт частот, min/max в поддеревьях

## **2. Rerooting DP (переподвешивание корня)**

### **2.1. Идея**
* `down[v]` — ответ для поддерева `v` (с фиксированным корнем)
* `up[v]` — ответ «вне поддерева» (вклад от родителя и сестёр)
* **Ответ для каждого корня:** `ans[v] = combine(down[v], up[v])` — `O(n)` суммарно

### **2.2. Пример: сумма расстояний до всех вершин**
* `down[v] = Σ_{u ∈ subtree(v)} dist(v, u)`
* `up[v] = ans[parent] − down[v] − sz[v] + (n − sz[v])`
* **Перенос через ребро `(v, to)`:** `ans[to] = ans[v] + n − 2·sz[to]`
* **Сложность:** `O(n)`

## **3. Virtual Trees**

### **3.1. Определение**
* По заданному набору `k` «ключевых» вершин — построить дерево, сохраняющее структуру LCA между ними
* Путь между ключевыми вершинами заменяется одним ребром

### **3.2. Построение**
1. Сортировка ключевых вершин по `tin` (время входа DFS)
2. Стек: добавляем вершины; при добавлении — LCA с вершиной на стеке
3. `O(k log k)` время (сортировка + LCA)

## **4. Tree Isomorphism**

### **4.1. AHU Algorithm (канонические подписи)**
* **Идея:** рекурсивно для каждой вершины — собрать подписи детей, отсортировать, объединить в подпись текущей вершины
* **Подпись листа:** `"()"`
* **Подпись внутренней вершины:** `"(" + sort([подписи_детей]) + ")"`
* **Два изоморфных дерева:** имеют одинаковые подписи корней
* **Сложность:** `O(n log n)` (сортировка подписей)

### **4.2. Хеширование деревьев**
* `hash(v) = f(sz[v], sort([hash(child)]))` через полиномиальный хеш
* **Столкновения:** маловероятны при хорошем хеше; для детерминированности — AHU
* **Сложность:** `O(n log n)` или `O(n)` с полиномиальным хешем
