**A. БАЗОВЫЕ ПОНЯТИЯ, ПРЕДСТАВЛЕНИЯ И ОБХОДЫ**

> **Архитектура:** `GraphBasics` (a.cpp) — базовый класс всей ветки graph. Вводит определения графов, их представления в памяти (Adjacency List, Adjacency Matrix, Edge List, CSR) и два фундаментальных обхода: DFS и BFS. Все последующие разделы (связность, кратчайшие пути, остовные деревья и т.д.) строятся на этих примитивах. Собственной арифметики не имеет; переиспользует стандартные контейнеры STL.
>
> **Связи:** DFS и BFS — фундамент для раздела B (связность: компоненты, мосты, точки сочленения, SCC); представления графов — база для C (кратчайшие пути), D (остовные деревья), G (паросочетания), H (потоки); проверка на циклы и топологическая сортировка через DFS — мост в `dynamic.md` (H); двухцветность (проверка двудольности) — мост в B (двудольные графы); копирование графов (Deep Clone) — практика рекурсивного DFS.

# **A. ОПРЕДЕЛЕНИЯ И КЛАССИФИКАЦИЯ ГРАФОВ**

## **1. Фундаментальные понятия**

### **1.1. Граф — формальное определение**
* **Определение:** граф — упорядоченная пара `G = (V, E)`, где `V` — конечное множество вершин (vertices/nodes), `E ⊆ V × V` (для ориентированных) или `E ⊆ {{u,v} : u,v ∈ V, u ≠ v}` (для неориентированных) — множество рёбер (edges)
* **Параметры:** `|V| = n` (число вершин), `|E| = m` (число рёбер)
* **Соседи:** вершина `u` — сосед вершины `v`, если `(u,v) ∈ E` или `{u,v} ∈ E`; `N(v) = {u : (v,u) ∈ E}` — множество соседей `v`
* **Степень вершины:** `deg(v) = |N(v)|` (неориентированный граф); для ориентированных: `in(v)` (входящая степень), `out(v)` (исходящая степень)
* **Лемма о рукопожатиях:** `Σ_{v ∈ V} deg(v) = 2|E|` (каждое ребро вкладывает 2 в суммарную степень); следствие: число вершин с нечётной степенью чётно

### **1.2. Типы графов**
* **По направлению рёбер:**
    * **Ориентированный (Directed):** рёбра упорядочены `(u,v) ≠ (v,u)`; пример: граф зависимостей задач, социальная сеть «подписался на»
    * **Неориентированный (Undirected):** рёбра неупорядочены `{u,v} = {v,u}`; пример: граф дорог, граф friendships
* **По весам:**
    * **Невзвешенный (Unweighted):** все рёбра равны; расстояние = число рёбер
    * **Взвешенный (Weighted):** каждое ребро имеет вес `w(u,v) ∈ W`; тип веса `W` — параметр (целый, вещественный, модулярный)
* **По структуре:**
    * **Простой (Simple):** нет петель `(v,v)` и кратных рёбер
    * **Мультиграф (Multigraph):** допускаются кратные рёбра (несколько рёбер между одной парой вершин)
    * **Полный (Complete `K_n`):** каждая пара вершин соединена рёбром; `|E| = n(n−1)/2`
    * **Пустой (Empty):** `|E| = 0`
* **По связности:**
    * **Связный (Connected):** между любыми двумя вершинами существует путь; число компонент связности = 1
    * **Несвязный (Disconnected):** `≥ 2` компонент связности; компонента — maximal connected subgraph
    * **Слабо связный (Weakly Connected):** ориентированный граф, ставший связным при замене всех рёбер на неориентированные
* **По циклам:**
    * **Ациклический (Acyclic):** нет циклов; DAG (Directed Acyclic Graph) — ориентированный ациклический; лес (forest) — неориентированный ациклический
    * **Циклический (Cyclic):** содержит хотя бы один цикл
* **По плотности:**
    * **Разреженный (Sparse):** `m = O(n)` или `m = O(n log n)`; большинство алгоритмов оптимизированы для разреженных
    * **Густой (Dense):** `m = Θ(n²)`; матрица смежности более естественна

### **1.3. Дополнительные свойства**
* **k-регулярный граф:** `deg(v) = k` для всех `v ∈ V`; число рёбер `m = kn/2`
* **Двудольный (Bipartite):** `V = L ∪ R`, `L ∩ R = ∅`; каждое ребро соединяет вершину из `L` с вершиной из `R`; эквивалентно: нет нечётных циклов; проверка — двухцветность (раздел D)
* **Плоский (Planar):** может быть нарисован на плоскости без пересечений рёбер; `m ≤ 3n − 6` (для простых связных, `n ≥ 3`) — раздел I
* **Кограф (Cograph):** не содержит `P₄` (путь из 4 вершин) как подграфа; полиномиальные алгоритмы для NP-трудных задач
* **Интервальный граф:** пересечение интервалов на прямой; Maximum clique/independent set за `O(n log n)`
* **Дерево:** связный ациклический граф; `m = n − 1`;|unique path между любой парой вершин

### **1.4. Числовые характеристики**
* **Диаметр:** `diam(G) = max_{u,v ∈ V} dist(u,v)` (最长最短路径); `diam ≤ n − 1`
* **Радиус:** `rad(G) = min_{v ∈ V} max_{u ∈ V} dist(v,u)` (центр графа минимизирует максимальное расстояние)
* **Эксцентриситет:** `ecc(v) = max_{u ∈ V} dist(v,u)`
* **Плотность:** `ρ = m / (n(n−1)/2)` (для неориентированных); `ρ = m / (n(n−1))` (для ориентированных)
* **Кластеризация:** `C = 3 · |треугольники| / |треойники|` (отношение замкнутых треугольников ко всем тройкам)
* **Связь:** классификация определяет применимость алгоритмов (разделы B–M)

# **B. ПРЕДСТАВЛЕНИЯ ГРАФОВ В ПАМЯТИ**

## **1. Списки смежности (Adjacency List)**

### **1.1. Базовое представление**
* **Идея:** для каждой вершины храним список её соседей; `n` списков суммарной длины `2m` (неориент.) или `m` (ориент.)
* **Реализация на C++:**
    * Невзвешенный: `vector<vector<int>> adj(n)` — `adj[v]` содержит соседей `v`
    * Взвешенный: `vector<vector<pair<int,W>>> adj(n)` — `adj[v]` содержит пары `(сосед, вес)`
* **Сложность операций:**
    * Проверка ребра `(u,v)`: `O(deg(u))` — линейный поиск в `adj[u]`
    * Перебор всех соседей `v`: `O(deg(v))`
    * Добавление ребра: `O(1)` амортизированно (push_back в vector)
    * Удаление ребра: `O(deg(v))` (поиск + удаление)
* **Память:** `O(n + m)` — оптимально для разреженных графов
* **Применение:** обходы (DFS, BFS), поиск кратчайших путей (Dijkstra, Bellman-Ford), топологическая сортировка, поиск компонент — основное представление для `m = O(n log n)`

### **1.2. Динамические списки**
* **Вариант с `list`:** `vector<list<int>> adj(n)` — `O(1)` удаление по итератору, но хуже кэш-локальность
* **Вариант с `set`:** `vector<set<int>> adj(n)` — `O(log deg(v))` проверка/удаление, поддержка порядка
* **Выбор:** `vector<pair<int,W>>` — дефолт для олимпиад (максимальная кэш-локальность, `push_back` амортизированно O(1))

## **2. Матрица смежности (Adjacency Matrix)**

### **2.1. Базовое представление**
* **Идея:** квадратная матрица `n × n`; `adj[i][j] = вес` если ребро `(i,j)` существует, иначе `0` / `INF` / `−1`
* **Реализация на C++:**
    * `vector<vector<W>> adj(n, vector<W>(n, INF))` — для взвешенных
    * `vector<bitset<N>> adj(n)` — для невзвешенных (битовая матрица)
* **Сложность операций:**
    * Проверка ребра `(u,v)`: `O(1)`
    * Перебор соседей `v`: `O(n)` — нужно проверить весь столбец/строку
    * Добавление/удаление ребра: `O(1)`
* **Память:** `O(n²)` — не зависит от `m`; при `m << n²` пустые ячейки = пустая память
* **Применение:** Floyd-Warshall (раздел C), умножение матриц для числа путей (раздел C), полные графы, алгоритмы на плотных графах (`m = Θ(n²)`)

### **2.2. Битовая матрица (Bit Matrix)**
* **Идея:** `vector<bitset<N>>` — каждая строка `bitset` размера `n`; проверка `(u,v)` — `adj[u][v]`, `O(1)` через битовый доступ
* **Преимущество:** `O(n²/64)` на операции над строками (побитовые AND/OR/XOR двух строк — `n/64` слов)
* **Применение:** проверка двудольности (двухцветность через BFS), BFS на невзвешенных графах

## **3. Список рёбер (Edge List)**

### **3.1. Базовое представление**
* **Идея:** один массив/список всех рёбер; `vector<tuple<int,int,W>> edges` — каждый элемент `(u, v, w)`
* **Сложность:** `O(m)` память; перебор всех рёбер `O(m)`, проверка конкретного ребра `O(m)`
* **Применение:** сортировка по весу — база для Крускала (раздел D); алгоритм Кагера для минимального разреза (раздел B.C); offline-задачи

## **4. Специализированные представления**

### **4.1. CSR/CSC (Compressed Sparse Row/Column)**
* **CSR (Row):** два массива: `offsets[n+1]` (куда начинаются соседи каждой вершины) + `edges[2m]` (сами соседи); `adj[v]` = `edges[offsets[v] .. offsets[v+1])`
* **CSC (Column):** аналогично для входящих рёбер
* **Сложность:** `O(n + m)` память, `O(1)` доступ к первому соседу, `O(deg(v))` полный перебор; кэш-дружественен (последовательный доступ к памяти)
* **Построение:** `O(n + m)` — подсчёт степеней → префиксные суммы → заполнение
* **Применение:** параллельные алгоритмы на графах, GPU-вычисления, большие графы

### **4.2. Forward Star**
* **Идея:** аналог CSR, но для онлайн-построения: рёбра добавляются по одному, `offsets` обновляется динамически
* **Применение:** графы, которые строятся по мере решения задачи

### **4.3. Incidence Matrix (Матрица инцидентности)**
* **Идея:** `n × m` матрица `B`; `B[v][e] = 1` если вершина `v` инцидентна ребру `e` (или `±1` для ориентированных)
* **Свойства:** `B · B^T = D + A` (для неориентированных, `D` — диагональ степеней, `A` — матрица смежности); `B · B^T = D − A` (для ориентированных) = Laplacian
* **Применение:** матричная теорема Кирхгофа (раздел D), теоретические конструкции

### **4.4. Implicit Graph (Неявный граф)**
* **Идея:** граф задаётся функцией `neighbors(v)` — генерируется на лету; не хранится явно
* **Память:** только текущий фронтир BFS/DFS; полезен когда `n` очень велико ( `> 10⁸`) или граф определяется правилами (пазлы, игры)
* **Применение:** задачи на сетках `n × m`, генерация позиций в играх, большие состояния

## **5. Сравнение представлений**

| Операция | Adj List | Adj Matrix | Edge List | CSR |
|---|---|---|---|---|
| Проверка ребра (u,v) | O(deg(u)) | O(1) | O(m) | O(log deg(u)) |
| Перебор соседей v | O(deg(v)) | O(n) | O(m) | O(deg(v)) |
| Добавление ребра | O(1)* | O(1) | O(1)* | O(n+m)** |
| Удаление ребра | O(deg(v)) | O(1) | O(m) | O(n+m)** |
| Память | O(n+m) | O(n²) | O(m) | O(n+m) |

\* амортизированно; ** пересборка CSR

**Правило выбора:** `m = O(n log n)` → Adjacency List; `m = Θ(n²)` → Adjacency Matrix; сортировка рёбер → Edge List; параллельные вычисления → CSR

# **C. ПОИСК В ГЛУБИНУ (DFS)**

## **1. Базовый DFS**

### **1.1. Рекурсивный DFS**
* **Идея:** от начальной вершины `s`: пометить `s`, для каждого соседа `u`: если `u` не посещён — рекурсивно вызвать `dfs(u)`
* **Порядок обхода:** зависит от порядка соседей в представлении; обход «вглубь» — рекурсия идёт по одному пути до листа, затем возврат
* **Сложность:** `O(n + m)` — каждая вершина обрабатывается один раз (пометка), каждое ребро проверяется один раз (при обходе из обеих вершин — в неориентированном графе)
* **Почему O(n + m), а не O(n²):** хотя наивно проверяем всех соседей, суммарно `Σ deg(v) = 2m`, поэтому суммарная работа по всем вершинам = `O(n + m)`
* **Реализация:** `dfs_recursive(v, adj, visited)` — стандартная; `visited[v] = true` при входе; рекурсия по непосещённым соседям

### **1.2. Итеративный DFS (через стек)**
* **Идея:** замена рекурсии на explicit stack: кладём `(v, индекс_следующего_соседа)`; на каждом шаге — если есть непосещённый сосед, пометить и положить его; иначе — pop
* **Почему:** избегает переполнения стека при `n ~ 10⁵–10⁶` (рекурсивный стек ограничен `~10⁴` вызовами на typical systems)
* **Сложность:** `O(n + m)` — как рекурсивный
* **Различие в порядке:** итеративный DFS без явного хранения индекса может обходить в ином порядке (depens от реализации); с индексом — идентичен рекурсивному

## **2. Метки времени (Timestamping)**

### **2.1. Времена входа и выхода**
* **Определение:** `tin[v]` — момент входа в вершину `v` (глобальный таймер++; при первом посещении); `tout[v]` — момент выхода из `v` (таймер++ при завершении обхода поддерева)
* **Свойство предков:** `v` — предок `u` в DFS-дереве ⟺ `tin[v] < tin[u] && tout[u] < tout[v]` — проверка за O(1)
* **Свойство: интервалы не пересекаются:** для любых двух вершин `u, v`: либо `[tin[u], tout[u]] ⊂ [tin[v], tout[v]]`, либо `[tin[v], tout[v]] ⊂ [tin[u], tout[u]]`, либо интервалы не пересекаются (свойство вложенности)
* **Применение:** проверка «is ancestor» за O(1); определение subtree-size: `sz[v] = (tout[v] − tin[v]) / 2` (в неориентированном графе)

### **2.2. Классификация рёбер DFS-дерева**
* **Tree edge (рёбра дерева):** `(v, u)` где `u` — непосещённый при обходе из `v`; образуют дерево DFS
* **Back edge (обратное ребро):** `(v, u)` где `u` — уже посещён и является предком `v` (не родителем); наличие обратного ребра ⟺ цикл
* **Forward edge (прямое ребро):** `(v, u)` где `u` — потомок `v` (не ребёнок), уже посещён
* **Cross edge (поперечное ребро):** `(v, u)` где `u` — neither ancestor nor descendant; только в ориентированных графах (в неориентированных — нет)
* **Применение:** поиск циклов (обратное ребро), топологическая сортировка (обратный порядок `tout`), проверка двудольности (двухцветность)

## **3. Применения DFS**

### **3.1. Проверка на циклы**
* **Неориентированный граф:** цикл ⟺ при обходе из текущей вершины встречается уже посещённый сосед, который не является родителем текущей вершины
* **Ориентированный граф:** цикл ⟺ встречается обратное ребро (вершина в состоянии «в процессе обработки»)
* **Сложность:** `O(n + m)`

### **3.2. Компоненты связности**
* **Алгоритм:** запуск DFS от каждой непосещённой вершины; число запусков = число компонент
* **Маркировка:** `component_id[v] = номер_запуска` для каждого `v`
* **Сложность:** `O(n + m)` суммарно (каждая вершина и каждое ребро — один раз)

### **3.3. Топологическая сортировка (DFS-based)**
* **Определение:** линейная упорядоченность вершин DAG: для каждого ребра `(u,v)` — `u` стоит раньше `v`
* **DFS-based алгоритм:** запустить DFS, в список результатов добавлять вершину при **выходе** из неё (после обхода всех потомков);反转 списка → топологический порядок
* **Почему работает:** обратный порядок `tout` гарантирует: если `(u,v)` — ребро, то `tout[u] > tout[v]` (DFS завершает `v` раньше `u`), значит `u` добавлен позже → в反转ированном списке стоит раньше
* **Проверка DAG:** если при DFS обнаружено обратное ребро — граф не является DAG (содержит цикл)
* **Сложность:** `O(n + m)`
* **Альтернатива:** Kahn's algorithm (BFS-based) — раздел D

### **3.4. Копирование графов (Deep Clone)**
* **Задача:** по данному графу (возможно, с произвольными узлами) создать полную копию
* **Подход:** DFS/BFS + хеш-таблица `map<old_node*, new_node*>`: при посещении нового узла создаём копию, копируем соседей через маппинг
* **Сложность:** `O(n + m)` время, `O(n)` память (маппинг)

### **3.5. Проверка двудольности (двухцветность)**
* **Алгоритм:** BFS или DFS с двухцветкой: `color[v] ∈ {0, 1}`; при обходе ребра `(u,v)`: `color[v] = 1 − color[u]`; конфликт (оба конца одного цвета) ⟺ граф не двудолен
* **Свойство:** граф двудолен ⟺ нет нечётных циклов; DFS проверяет это через цвета
* **Сложность:** `O(n + m)`

## **4. Продвинутые техники DFS**

### **4.1. Iterative Deepening DFS (IDDFS)**
* **Идея:** запуски DFS с увеличением глубины `limit = 0, 1, 2, ...`; на каждом запуске — обход до глубины `limit`
* **Сложность:** `O(b^d)` времени ( `b` — средний коэффициент ветвления, `d` — глубина решения); `O(d)` память
* **Применение:** графы с неизвестной глубиной; при `b` большом — BFS потребляет экспоненциально памяти, IDDFS — линейно

### **4.2. DFS Tree/Forest**
* **DFS Tree:** дерево из tree edges; обратные/прямые/поперечные рёбра — дополнительные
* **Свойства:** обратное ребро `(v,u)` → `u` предок `v`; прямое ребро `(v,u)` → `u` потомок `v`; поперечное ребро `(v,u)` → `u` уже обработан, не потомок
* **Применение:** фундамент для анализа графов (разделы B, C)

### **4.3. Backtracking как DFS**
* **Паттерн:** рекурсивный DFS с «решением» на каждом уровне; если решение невалидно — возврат (backtrack); если валидно и полное — запись ответа
* **Сложность:** `O(分支因子^{глубина})` в худшем; pruning сокращает
* **Применение:** расстановка фигур (N-Queens), перестановки, подмножества

# **D. ПОИСК В ШИРИНУ (BFS)**

## **1. Базовый BFS**

### **1.1. Алгоритм**
* **Идея:** обход по «слоям»: начинаем с `s`, все вершины на расстоянии `0` → затем все на расстоянии `1` → и так далее
* **Структура данных:** очередь `q` (FIFO); при обработке `v` из `q` — всех непосещённых соседей `u` помечаем и кладём в `q`
* **Порядок:** вершины на расстоянии `d` обрабатываются до вершин на расстоянии `d+1`; BFS выдаёт вершины в порядке неубывания расстояния от источника
* **Сложность:** `O(n + m)` — как DFS (каждая вершина и каждое ребро — один раз)
* **Почему O(n + m):** суммарно `Σ deg(v) = 2m`; каждое ребро проверяется один раз при обработке его концов

### **1.2. Кратчайшие пути в невзвешенных графах**
* **Свойство BFS:** `dist[v]` = минимальное число рёбер от источника `s` до `v`
* **Восстановление пути:** `prev[v]` — предыдущая вершина на кратчайшем пути; путь от `s` до `t` — `s → prev[... → prev[t]] → t`, развернуть
* **Инициализация:** `dist[v] = ∞` для всех `v ≠ s`; `dist[s] = 0`; `prev[s] = −1`

## **2. Продвинутые варианты BFS**

### **2.1. Bidirectional BFS**
* **Идея:** два фронтира — от источника `s` и от цели `t`; на каждом шаге расширяем меньший фронтир; встреча ⟺ пересечение фронтиров
* **Сложность:** `O(b^{d/2})` вместо `O(b^d)` — экспоненциальный выигрыш по времени и памяти
* **Применение:** поиск пути в больших графах при известной цели

### **2.2. 0-1 BFS**
* **Условие:** граф с весами `{0, 1}` (два типа рёбер)
* **Алгоритм:** deque: ребро веса `0` → в начало deque (приоритет); ребро веса `1` → в конец
* **Почему работает:** вершины обрабатываются в порядке неубывания расстояния (как в Dijkstra, но за `O(n + m)`)
* **Сложность:** `O(n + m)` — как обычный BFS

### **2.3. BFS 0-k (ограниченные веса)**
* **Условие:** веса рёбер `0 ≤ w ≤ k` (ограниченный диапазон)
* **Алгоритм:** `k+1` очередей; текущая очередь — циклический сдвиг по весам
* **Сложность:** `O(k · (n + m))`

### **2.4. Multi-source BFS**
* **Идея:** несколько источников одновременно; инициализация `q` всеми источниками с `dist = 0`
* **Применение:** задачи «распространение» (волновой алгоритм): волна от множества центров, расстояние до ближайшего центра

### **2.5. BFS на неявных графах (Implicit Graph)**
* **Идея:** граф генерируется на лету функцией `neighbors(v)`; хранить нужно только фронтир (set/queue)
* **Память:** `O(размер_фронтира)` вместо `O(n + m)`
* **Применение:** задачи на сетках `n × m` (где `n, m ~ 10⁹`), 15-puzzle, генерация позиций

## **3. Kahn's Algorithm (Topological Sort через BFS)**

### **3.1. Алгоритм**
* **Идея:** BFS-подобный: кладём в очередь все вершины с `in_degree = 0`; при обработке `v` — уменьшаем `in_degree` соседей; если `in_degree[u] = 0` → кладём `u` в очередь
* **Порядок:**出来的 порядок = топологический порядок
* **Проверка на цикл:** если вышло < `n` вершин → граф содержит цикл
* **Сложность:** `O(n + m)`
* **Преимущество над DFS-based:** не требует меток `tin/tout`; естественный порядок «обновления» входящих степеней

## **4. Применения BFS**
* Shortest path в невзвешенных графах (кратчайший путь по числу рёбер)
* Connected components (альтернатива DFS)
* Bipartite checking (двухцветность через уровни)
* Level-order traversal деревьев (BFS на дереве)
* Wavefront algorithms (распространение от множества источников)
